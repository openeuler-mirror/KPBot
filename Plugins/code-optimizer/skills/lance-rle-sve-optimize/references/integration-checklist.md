# RLE 接入与验收记录

## 先确定一次调用的契约

记录值类型、次数类型、run 数、请求值数、输出容量、strict/clamp 入口以及 values/lengths 的子编码。次数求和或元素到字节换算先做溢出检查；不能先溢出再与容量比较。零次 run 是否合法以当前入口为准。

候选需要声明“拒绝且未写入”“成功且写满”“错误且已写连续前缀”的区别。维护前缀的单位为元素，每条返回路径均须准确；成功但长度不足、未知状态和超限前缀不能交给调用者作为正常结果。

## 避免把向量宽度当作固定参数

分别记录 u32/u64 的执行线程 VL、每向量元素数和尾谓词。线程上下文发生变化时，不沿用未经确认的其他线程 VL。SVE/SVE2 支持和运行系统能力均符合后，才允许调用读取 VL 的可选指令辅助函数。

## 记录执行和验证范围

按实际入口、值类型、次数宽度、子布局及分布记录候选调用、原版调用、错误调用、run 数和展开元素数；注明错误计数与调用数的关系。Flat 场景没有实质子解压时，不把其准备耗时命名为 BP 解压。

至少核对同一输入的候选关闭、候选适用、候选不适用及原生错误。计数审计与正式计时分开，正式计时保留原有适用性检查。

`evals/evals.json` 仅定义模型审查场景，不执行 SVE。逐项交付直接内核、RleDecompressor、压缩子缓冲、decode_batch 与 SQL 的已测/未测状态；未测 VL、非 SVE 平台和业务收益单列。
