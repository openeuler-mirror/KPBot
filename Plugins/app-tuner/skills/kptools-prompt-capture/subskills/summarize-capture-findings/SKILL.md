# Prompt 采集与分析汇总

## 操作流程

1. 清点用户提供的 `run.json`、采集目录、请求分布、会话、分词核验和日志关联产物。核对时间范围与采集对象，来自不同窗口或样本的统计分别标明。已有分析产物仍可用于报告，原始分段缺失时注明无法复算。
2. 按下表整理已取得的结果。只做报告时，不为补齐栏目而开启采集、访问 proxy 或恢复服务。

| 内容 | 证据 |
|---|---|
| 环境、采集范围和改造验证 | `run.json`、测试记录、worker 状态 |
| 请求分布与会话 | `summary.csv`、`requests.csv`、`fleet.json`、会话报告 |
| 分词与日志关联 | golden 核验结果、日志关联覆盖率及耗时分布 |
| 采集关闭与恢复 | worker 有效开关、文件核验及运行入口核验 |

3. 将结论、数据范围、结果、局限和产物位置写入新的受限目录中的中文 `REPORT.md`。每个数值标明来源、时间、样本及测量层级。注明“未执行”“未采到”“未测”或“不支持”的原因，不用零代替；没有有效数据时不给性能结论。

## 输出

报告默认不包含原文及凭证。分别记录采集、代码和运行实例状态；没有状态证据就注明未确认，不从“采集关闭”推断已恢复。向用户返回报告路径和关键结论。
