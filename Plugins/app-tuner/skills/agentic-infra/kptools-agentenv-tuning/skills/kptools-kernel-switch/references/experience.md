# 从三类实际问题选择检查

| 场景 | 实际观测 | 可用于其他内核的做法 |
|---|---|---|
| 950，Ubuntu Host 试运行基于 openEuler 的 ARM64 内核 | Host 用独立的 `O=` 编译 `Image modules`，模块先装入 staging。Guest 只编 `Image`。一次冷启动已挂载根盘并执行 `/init`，但 envd 超时。串口提示无法识别 `ip=`，在 Guest 配置启用 `CONFIG_IP_PNP` 及所需协议并重编 Guest 后，沙箱成功冷启动。 | 根据串口区分内核引导、根盘挂载和 Guest 网络就绪问题。Host 的 initramfs 另查根卷及管理网卡驱动。950 当时通过一次性引导运行候选，旧内核是下次默认项。 |
| 920C，openEuler Host 的 HZ、DVMBM 与 Guest PV 组合 | 两份 Host 内核分别为 HZ250 和 HZ1000。每份用参数切两种 DVMBM 状态，各 Host 状态内用同一 Guest 镜像冷启 PV 开、关。四次候选启动覆盖八种组合，最后启动原发行版内核，复核已加载外置 ublk 模块的 `srcversion`、控制设备属组和权限，并在 Guest 暂停恢复后读回数据标记。 | 按 Host 镜像及启动参数分组，再在组内切 Guest。回退时确认服务以原二进制和运行身份持续提供服务。该环境的守护进程依赖父进程存活，启动后还需复验沙箱设备和实际 I/O。 |
| Guest 页回报配置 | 一个冷启动候选的 cmdline 请求 order 6，驱动注册后 sysfs 实际仍为 9。调整写入时机后读回 6。快照恢复保留了捕获时的运行值。 | 针对新补丁定义独立于配置文本的观测。把“产物已构建”“选中并运行”“机制生效”“业务检查通过”分别写入记录。 |

对新的调度、驱动或文件系统补丁，替换输入的基线、补丁、期望符号、启动依赖和功能探针即可。例如块设备补丁可以检查设备读写、回读一致性及关闭后清理。通用流程仍以具体目标的运行状态和恢复结果交付。

## 把待测选项排成一次试验

每个选项先写一行，填实际拥有它的一层和使改动生效的最小动作。以下用 920C 对照中的三项以及一个新驱动举例。

| 待测变量 | 最小动作 | 生效依据 |
|---|---|---|
| Host 的 HZ250 / HZ1000 | 用同一源码和工具链分别构建并启动两份 Host 镜像 | 当前 Host 的完整 release 和有效 `CONFIG_HZ` |
| Host 的 DVMBM 开 / 关 | 对同一 Host 镜像分别使用对应启动参数 | Host 的 cmdline 与该版 KVM 提供的使能日志或状态 |
| Guest 的 PV 开 / 关 | 复用 Guest 镜像，在当前 Host 上用两组参数冷启动 Guest | Guest 内读回参数与机制日志。Host 提供相应 tracepoint 时，可在同一负载下核对事件计数 |
| 新驱动的队列参数 | 根据该版本接口选运行时写入、模块加载、启动参数或编译配置 | 从设备或驱动读回有效值，完成一次指定的数据读写 |

先列出要比较的有效组合，按 Host 构建产物、Host 启动参数、Guest 镜像与参数依次分组，最后排运行时开关。920C 的三项全因子试验由两份 Host 镜像、四个 Host 启动状态覆盖八组。若目标是单项归因，可以只选基线与单项候选。做重复测量时把独立启动批次和同次启动内的重复分别记录。
