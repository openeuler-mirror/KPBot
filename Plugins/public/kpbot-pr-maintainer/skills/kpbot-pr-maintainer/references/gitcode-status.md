# 核对 GitCode PR 状态

## 每轮读取

1. 用 `GET https://api.gitcode.com/api/v5/repos/{owner}/{repo}/pulls/{number}` 读取 PR 的 `state`、`head`、`base`、标签和合入检查。记录源与目标的仓库、分支及 SHA。
2. 用同一路径下的 `comments?page=1&per_page=100` 获取评论，逐页读取直到返回空列表。逐条检查普通评论、行内讨论、回复以及可见的解决状态。用评论 ID 和更新时间识别新增或改写的意见。
3. 核对评审决定、阻塞讨论、必需检查和对应日志。接口缺少详情时到 PR 页面补查。按提交 SHA、门禁轮次或时间辨别过期的机器人结论，无法对应到当前 head 的结果标为待核实。

## 目标分支上的并行改动

另一个 PR 也更新技能计数时，先以最新目标分支为基线，只对包含本 PR 的候选树实测。合入前重新获取目标分支 SHA。如果另一项改动已合入，将本 PR 变基到新目标，在独立检出中重新运行安装器和计数测试，并将实测结果同步到 fixture 和文档。两个 PR 写入相同数值时，Git 可能自动合并这些行，仍需重测。

## 跟踪终点

| 观察到的状态 | 判断和后续动作 |
| --- | --- |
| `state == "open"`，门禁或评审未完成 | 记录当前 head、具体缺口和下次检查时间。分别报告已推送的修复与已通过的检查。 |
| `state == "open"` 且可合入 | 同一轮核实无冲突、当前 head 满足仓库要求的检查及 CLA、AI 披露、有效批准和讨论处理条件。再次读取 head，若有变化则重新核查。报告 PR 链接、SHA、测试和评审结论。用户仅要求达到可合入时结束，要求实际合入时继续跟踪。 |
| `state == "merged"` | 确认已合并，记录 PR 链接、平台提供的合并时间 `merged_at` 及可查的合并提交。结束该 PR 的跟踪。 |
| `state == "closed"` 且 `merged_at` 为空 | 记录为关闭未合并，结束该 PR 的跟踪。已合并的 PR 也可能有 `closed_at`。 |
| 用户取消 | 记录取消并结束该 PR 的跟踪。 |

字段矛盾或状态未知时重新读取详情，到 PR 页面核对并保留待确认状态。结束跟踪时仅停用该 PR 对应的任务。
