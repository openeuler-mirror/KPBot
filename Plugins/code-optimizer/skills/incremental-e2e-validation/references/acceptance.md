# 验收案例

## 运行测试

```sh
python3 -B -m unittest discover -s tests -v
```

自动测试采用合成数据。
真实业务试点使用用户项目的框架和环境。

## 矩阵检查

| 输入 | 预期 |
|---|---|
| 单项 | 两个配置，一对对照 |
| 两项 | 四个配置，四对对照 |
| 五项 | 十个配置，十三对对照 |
| 三十项 | 完整矩阵，无固定三项限制 |
| B 依赖 A | B 单独不可执行，AB 合法 |
| A 与 B 互斥 | 全开行保留原因 |
| 顺序改变 | 增量引用新前序配置 |

## 结果检查

| 场景 | 预期 |
|---|---|
| 100 ms 到 90 ms | +10% |
| 100 QPS 到 110 QPS | +10% |
| 88 ms 到 89 ms | 约 −1.136% |
| 各块方向跨零 | 可能存在波动 |
| 缺少噪声证据 | 波动依据不足 |
| 环境漂移 | 方向未确定 |
| 正确性失败 | 该格无收益数值 |
| 额外参数改变 | 条件不可比 |
| 开关未生效 | 未确认生效 |
| 缺全开测量 | 全开行显示未运行 |

## 项目试点

选用已有至少两项可切换优化的业务。
检查原版、单项、组合的实际运行身份。
使用用户选定的测试框架。
任取独立格，追溯原版与单项记录。
任取增量格，核对只增加当前项。
检查全组合中每项是否真正生效。
核对小幅变化的格内标注。
核对所有缺测、失败和复测记录。
确认实验后有效配置和恢复结果。

## 修改后回归

矩阵修改检查数量、去重和单变量差异。
计算修改检查指标方向与无效值。
报告修改检查各格引用和状态。
契约修改同步输入示例。
技能正文的能力描述与工具行为一致。
