# RLE 原生接口与初始化协议补充

## 输入支持范围

历史内核适用于 u32/u64 值与 U8 次数，不允许将 U16/U32 次数按字节伪装成 U8。其他条件保留原路径或分别实现、验证。严格 block 与 clamp miniblock、Flat 与压缩子缓冲分别覆盖。

## 初始化和错误

调用前检查元素/字节大小及输出容量，保持简单值 Vec 长度为零，初始化前缀参数置零。C 维护连续已写元素数，并在每一条返回路径按协议发布，错误不能留下不准确的前缀。

Rust 接收后验证状态、前缀未超出 N，成功还要求恰好写满 N，然后才设置输出长度。未知状态、超限或成功但长度不足均不能直接暴露结果。计数是元素数，不是字节数。

u32/u64 的长度零 Vec 在错误时直接丢弃，不必额外建 Drop guard 或为了清理设置部分长度。返回值检查无法补救已经发生的原生越界，需要证明存储边界并在目标上进行适当内存检查。

正常不适用回退发生在原生执行前。原生失败后若为重建错误调用 Rust，而 Rust 成功，就应报告候选问题，不能将其变成成功候选成绩。

## 具体输入输出示例

以下是**按 run 检查、超量 run 在写入前拒绝**的候选 FFI 契约示例，`OK`、`ERROR` 是说明用的状态名，不是 Lance 上游或现有 C ABI 的常量。strict 不允许超过请求数；clamp 可以截断最后一段。两种模式在输入用尽仍不足 N 时均报错。实际入口若在写入前统一校验全部输入，应按其行为记录，此时失败前缀可以为 0。

固定 values=`[7, 9]`、lengths=`[2, 4]`、输出容量至少 N；initialized 是连续已写的**元素数**。

| 模式与请求数 | 处理过程 | 返回 | initialized | 已初始化内容 |
| --- | --- | --- | --- | --- |
| strict，N=5 | 写完首段 2 个；第二段 4 个超过剩余 3 个，在写第二段前拒绝 | ERROR | 2 | `[7, 7]` |
| clamp，N=5 | 首段写 2 个；第二段只写剩余 3 个 | OK | 5 | `[7, 7, 9, 9, 9]` |
| strict 或 clamp，N=6 | 两段都完整写入 | OK | 6 | `[7, 7, 9, 9, 9, 9]` |
| strict 或 clamp，N=7 | 两段写完但只得到 6 个，请求未填满 | ERROR | 6 | `[7, 7, 9, 9, 9, 9]` |

再核对写入前拒绝：values=`[7]`、lengths=`[4]`、N=3。strict 返回 ERROR、initialized=0；clamp 返回 OK、initialized=3、内容 `[7, 7, 7]`。若容量小于 N，适配层在调用原生函数前拒绝，不发生写入。

### 截断写满与恰好写满的区别

固定提交 `123245f2085a164b1e70751eb784aa77046dab46` 的 [RleDecompressor::decode_generic](https://github.com/lancedb/lance/blob/123245f2085a164b1e70751eb784aa77046dab46/rust/lance-encoding/src/encodings/physical/rle.rs) 在写入前记录 remaining，只在当前原始 length > remaining 时截断并退出 run 循环；length == remaining 仍检查后续 run。不能一律在已写数量等于 N 时退出，也不能截断后继续处理原版未检查的 run。

固定 values=`[7, 9]`、N=2，后续 run 次数为 0：

| 模式 | lengths | 返回 | initialized | 原因 |
| --- | --- | --- | --- | --- |
| clamp | `[3, 0]` | OK | 2 | 首段 3>剩余 2，截断后退出，不检查下一段 |
| clamp | `[2, 0]` | ERROR | 2 | 首段恰好写满，继续后遇到零次数而报错 |
| strict | `[3, 0]` | ERROR | 0 | 首段超量，在写入前拒绝 |
| strict | `[2, 0]` | ERROR | 2 | 首段合法，后续零次数仍须报错 |

前缀列描述相应按 run 写入的候选接口；上游错误结果不向调用者交付这个部分输出。候选不能额外预扫描原版截断后会跳过的 run，再将原本成功的 clamp 输入改成错误。`cases/prefix-contract/run.py` 用标量模型检查这些返回差异及前文例子，不执行真实 SVE。

在 u64 的 clamp N=5 示例中，initialized=5，不是 40；40 是输出字节数。Rust 仅在 OK 且 initialized==N 且 N<=capacity 时设置 Vec 长度。ERROR 时不能把已写前缀当作成功结果；长度保持为零的简单值 Vec 可以直接释放分配，不能读取余下未初始化区域。

具体核对所有返回：失败发生在首段或后续段、错误但已经写入前缀、成功却不足 N、超限前缀和未知状态。若原生错误后为了构造一致错误调用原版，而原版成功，应保留候选失败记录，不能改记为成功的候选命中。

## 指令与线程向量长度

检测实际需要的 SVE/SVE2 与系统能力。AArch64 不代表 SVE，SVE 不自动代表 SVE2，获取长度的辅助函数也不能在检测前执行可选指令。全局编译参数需要单独核查。

SVE 长度可能因线程而异，应在执行上下文得到通道数量。每个已测试长度分别覆盖 u32/u64、向量边界、末段不足、U8 的 255、合法空输入、次数异常及部分写入后错误。没有测到的长度或回退平台明确标为未测。
