# Faiss 访存延迟优化

## 输入

访问模式（按 id 取行、图邻居、倒排码字块）、miss 计数与命中率、带宽利用率、向量维度与行长、id 有效性约束（负值/越界）、NUMA 与绑核方案。

## 执行步骤

1. 判据先行：miss 高且带宽未饱和才考虑预取；带宽已饱和时预取无效，转向布局重排或批量访问。
2. 访问时序：确认"预取点 → 使用点"的迭代距离；距离过短预取未完成，过长被逐出。按场景选 ahead，见 [场景处方](references/prefetch-recipes.md)。
3. 预取参数：行长 = min(向量字节数, 上限)；行内按缓存行步进；先确认 i+ahead 落在当前列表内，再读取目标 ID 并核对其数据行有效——读取越界 ID 本身就是越界访问；尾段无可预取目标时直接跳过预取。
4. 规模 guard：行数低于阈值不开预取（固定开销不摊销）；阈值实测。
5. 局部性替代：批量取行后重排为连续访问、图邻居按块预取、倒排码字顺序扫描交给硬件预取器。
6. 对照：预取指令开销与收益一起测；NUMA、绑核、页缓存状态与基线一致。

## 输出

访问模式与判据数据、预取参数与 guard、布局/批量替代方案、对照结果与适用范围。

## 约束

- 预取地址必须有效；越界预取是未定义行为，负 id 分支先判。
- 顺序流不要软件预取：交给硬件预取器，软件预取只用于不可预测地址。
- 预取改变缓存占用，可能伤害同进程其他负载；对照覆盖目标负载全集。
- 收益以冻结对照判定；miss 下降不是收益承诺。
