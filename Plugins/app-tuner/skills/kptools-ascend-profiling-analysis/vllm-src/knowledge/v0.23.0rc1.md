## 执行模式决策链（P2 语义判别的源码依据）

1. `_determine_batch_execution_and_padding`（rc1@2876）：
   `is_all_decode = all(num_computed_tokens_cpu[:num_reqs] > 0)`；
   `uniform_decode = (is_all_decode if spec_decode else True) and
   max_num_scheduled_tokens == uniform_decode_query_len and
   num_tokens == max_num_scheduled_tokens * num_reqs`
   （`uniform_decode_query_len = 1 + num_spec_tokens`，gpu_model_runner.py:814——
   spec decode 下每个 decode 请求调度 1+draft 数个 token）
2. `cudagraph_dispatcher.dispatch(num_tokens, has_lora, uniform_decode, ...)` →
   FULL / PIECEWISE / NONE（cascade attention 或 encoder 输出时禁 FULL）
3. `ACLGraphWrapper.__call__`（compilation/acl_graph.py:138）：
   - 运行时模式 == NONE 或 ≠ wrapper 模式 → **直接 `self.runnable(...)` 内联执行**
     （prefill 步的 428~450ms 全在 `__call__` 时长内）
   - 模式匹配且 batch_descriptor 已有捕获图 → `current_stream().synchronize()`（仅
     FULL + 非 eagle-draft）→ `entry.aclgraph.replay()`（trace 帧
     `torch_npu/npu/graphs.py(638): replay`）
   - 首次遇到 batch_descriptor → 捕获（`torch.npu.graph` 上下文）——**捕获发生在
     引擎初始化 dummy run，通常在 profiler 启动前，trace 不可见**
4. runnable 内部（torch.compile 路径）：`npu_fx_compiler` → torch_npu
   `dynamo/npugraph_ex/_acl_concrete_graph/acl_graph.py(895): fx_run_eagerly` →
   `<string>(19): forward` **逐算子 eager 执行 FX 图**（动态形状不吃整图）——
   名字里没有 replay，别叫"图回放"
5. `_model_forward`（rc1@2781）固定顺序：`run_model()` 先，然后
   `_update_full_graph_params_if_needed`（rc1@2756）——仅在 FULL 且非捕获时执行，
   经 `update_full_graph_params`（acl_graph.py:270）→ `attention_v1.py(454):
   update_graph_params` 在 **update_stream** 上更新 KV-cache 地址等动态参数，
   `graph_task_update_begin/end`（graphs.py:95/99）成对提交（本例 ×16 ≈ 注意力层数）

## 批成分判定（混合批 vs 纯 decode，从 trace 取证）

vLLM v1 是 continuous batching：**一个 step 的批可同时含 prefill 与 decode（混合批），
不是二选一**。从 worker trace 判定（无调度器进程帧时的方法）：

| 证据 | 含义 |
|---|---|
| `update_req_spec_token_ids` 慢路径（≥6µs，写 token_ids_cpu） | 带 draft 的 decode 请求（该请求本步调度 1+draft 数 token） |
| `update_req_spec_token_ids` 快路径（~4µs 早退） | 无 spec token 的请求（通常= 新 prefill 请求） |
| `add_request`（gpu_input_batch.py:335） | 新加入批的请求（prefill 到达） |
| `_build_non_spec_chunked_prefill_metadata` | **仅 `num_prefills > 0` 才调**（gdn_attn_builder.py:661），×3=GDN 组数 |
| `_execute_mm_encoder` ms 级 | 有新图像请求要跑视觉编码；µs 级（~3µs）= 空调用早退 |

本 trace 实测：批内每步 32 请求 = 慢路径数 + add_request 数；step0/1/3 =
31/29/31 decode + 1/3/1 新图像 prefill（混合批）；step2 = 32 纯 decode（4 token/请求）
→ 整图回放。引擎在 profiler 启动前已服务（step0 批内已有 31 个 decode 请求，
与图捕获同在 profiling 之前）。

| 阶段 | 锚点 | 帧（python_function） |
|---|---|---|
| 步边界 | ProfilerStep#N | ProfilerStep |

| P1-D | 注意力元数据 | `_build_attention_metadata` → `_build_attn_group_metadata` ×4 → `attention_v1.py(276): build` / `gdn_attn_builder.py: build` |
| P1-E | VLM 视觉编码 | `_preprocess` → `_execute_mm_encoder` → `Qwen3_VisionTransformer`（VisionBlock ×27） |
| **P2** | **模型前向（通用锚点）** | **`model_runner_v1.py(3011): _model_forward`**（eager / FX eager / 整图回放步都存在） |
| P3-A | logits | `qwen3_vl.py(2844): compute_logits` → `qwen3_5.py(515)` |
| P3-B | 采样+draft | `_sample_tokens_orig`(2581) → `_sample` → `propose_draft_token_ids`(2646/1820) → `_run_merged_draft`（3 轮 MTP forward） |
| P3-C | 步收尾 | `end_step` → `npu/utils.py(62): synchronize`（设备级，host/device bound 指示器） |

**P2 锚点规则**：优先 `_model_forward`；模型级 `qwen3_5.py(626): forward` 只在
eager/FX-eager 步存在，**整图回放步没有模型级 forward python 帧**（图回放不进 python），
用旧锚点会误回退到 `_execute_model_orig`（其窗口混入 P1 输入准备）。

```

   ├ _propose: set_inputs_first_pass → embed_input_ids → attn build/build_for_drafting ×2
```

## trace 可见性注意

1. **图捕获不可见**：发生在 profiler 启动前的引擎初始化（dummy run）；trace 里只有
   replay 和 graph_task_update_*，没有 capture 帧
2. **整图回放步无模型级 forward 帧**：P2 锚点用 `_model_forward`
3. **部署版行号漂移**：见"部署版差异"映射表；`*_orig` 包装函数（`_execute_model_orig`、
   `_sample_tokens_orig`）是内部补丁特征，tag 里没有
4. `_model_forward` 与模型级 forward 窗口在 eager 步几乎重合（差 ~30µs）；
   在回放步仅 ~3-6ms（host 侧）
