# 业务汇总与历史案例

四模式比较、阶段加速比、统计开关影响和占比解释见 [SKILL.md](../SKILL.md)。本文补充汇总记录的组织方式，以及文中历史占比的来源。

## 汇总时保留哪些关联

每份原始业务样本至少关联查询或请求场景、实验身份、数据摘要、构建身份、轮次、模式、统计状态和样本编号。同一组内编号唯一，关联具体的会话结果及审计记录。

先按计划核对组数和样本数，确认正确性、实际工作量和会话有效性，再计算轮内统计。无效样本保留并写明原因，不以数值高低决定是否删除。若预先允许重试，同时保存原始失败尝试和替代记录的关联。

阶段比较使用开启统计的同轮样本，业务比较使用关闭统计的同轮样本。报告保留比较前后耗时及加速比，不能只给比值。跨轮汇总同时保留逐轮结果，并写明算术平均、几何平均或中位数等具体定义。

占比先按每次样本的阶段时间除以同次业务时间，再取轮内中位数。若继续取各轮中位数的中位数，应明确这是轮次等权汇总；它与合并所有样本后直接取中位数不一定相同。每轮中位数的分布也不能解释为全部请求的 P99。

## Lance BP/RLE 案例

实验使用同一份 SF1 重排行布局数据、Q1/Q6 SQL 和四模式构建。审计核对候选命中，诊断计时覆盖 InlineBitpacking::unchunk、RleDecompressor block/miniblock 及其内层阶段。统计开关对照单独采集。

首六轮和追加六轮合并后，每个查询、每模式有十二轮开启统计数据，每轮十次。每次算完整解码除以同次查询总时间，取轮内中位数，再取十二轮中位数。

```text
查询    模式        去重后的BP/RLE合计完整解码占比
Q1      original    1.310%
Q1      both        1.025%
Q6      original    1.495%
Q6      both        1.234%
```

这些数值说明该场景的已计时解码占比较低，局部收益传递到查询时可能较小。是否确实优化、业务是否变快，仍要结合阶段和关闭统计的业务对照，不能只由占比下降得出。

占比来自开启统计的数据，包含计时开销，只覆盖已插桩入口，工作负载是该重排行布局。复用本例时需要自己的源码、构建、审计和原始测量，不将这些历史百分比当作其他数据集的先验结论。

## 证据摘录的范围

[历史计时摘录](../assets/tpch-fractions-evidence.json) 保留两批数据中上述查询和模式的 480 个开启统计样本，含每次查询及合计解码纳秒数、原文件名、源文件 SHA-256、扩展摘要和数据集摘要。`cases/protocol-contract/run.py` 重新计算轮内、跨轮中位数并核对表中四项。

摘录没有服务端跟踪、审计日志和二进制，支持核对数值汇总，不能代替真实入口命中或硬件复现证据。追加采集时使用新实验身份，并保存完整证据。
