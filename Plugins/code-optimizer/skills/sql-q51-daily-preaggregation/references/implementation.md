# 部分日聚合、投影与 Shuffle

检查各分支在 `Exchange` 前后是否已有 partial/final 日聚合，按真实 Shuffle 位置决定改动。保持金额类型、精度、小数位和空值语义，避免仅凭抽样峰值猜测长尾热点。

1. 若 `Exchange` 前仍发送大量同商品同日期的行，检查就地部分聚合，并只发送日聚合键、金额状态和下游所需列。记录输入行、聚合组数、状态宽度和每 task Shuffle 字节。若已有高压缩率的 partial 阶段，检查剩余的 spill 和分区倾斜，确认日聚合位置仍有调整空间。
2. SQL 可改且希望在日期连接前按 `(item_sk,sold_date_sk)` 预聚合时，先证明维表键唯一、事实连接倍率与金额合并行为一致。不同日期键可能映射到同一 `d_date`，此时仍需在连接后按 `(item_sk,d_date)` 合并。保持发生在分组前的选择性条件，并在前置聚合收益与对不匹配日期的额外工作间做对照。
3. 精度或溢出行为无法证明等价时保留原聚合边界。在实际 Spark/Velox 配置下验证 decimal `SUM` 类型、ANSI 或非 ANSI 溢出、全 NULL 和负金额。对热点商品单列任务耗时及分区长度。

## 源码定位

### 实施记录与回退

| 路线 | 实施前证明 | 不成立时 |
| --- | --- | --- |
| 现有连接后局部聚合 | partial 状态可合法合并，键为实际日历日期 | 保留原聚合阶段 |
| 事实侧先聚合再连维表 | SQL 可改、维键与谓词已核对、状态重组不改变错误 | 保留连接前后的原边界 |
| 裁剪交换列 | 下游表达式、键、状态和有效性已列全 | 保留未证明可删的列 |

将事实键映射到日历日期后，再核对实际 final 键。不要因输入已按代理键聚合就删除日历日期 final。未知维表关系应回退；维键唯一是本流程采用的充分守卫，不声称是所有可能重写的必要条件。

类型证明包括输入 decimal、partial 状态、合并累加器与最终精度，不能只对最终字段类型做比较。一个有界加法模型中 `(80+80)+(-80)` 可在中间溢出，而 `80+(80-80)` 不溢出，说明改变括号可能改变错误；它不是对 Spark decimal 实现的模拟结论。

检查跨越的整个投影和原本必须逐行求值的其他表达式，而不只检查分组键和金额本身。若前移会跳过原本应报错的转换，或提前求值原条件分支不会计算的表达式，保留原边界。

### 验证和计数

双分支各自保留原 SQL 入口，按所有日结果行比较键、值、NULL 和重数，再比较完整 SQL51。测试覆盖月份上下界及界外、无对应日期、商品 NULL、日期别名和全 NULL 组；守卫拒绝时记录原路径结果。

计数分开命名：扫描/连接输入行、连接输出行、partial 输入行、每 task 状态输出记录、final 日组数、Shuffle 序列化字节和 spill 字节。N/G 中 G 是真实局部记录，不是全局 distinct。交换列裁剪和聚合前移需要单独消融，再测合并效果。

本地用例和 `evals/evals.json` 分别表示语义模型与评估规格。真实规则命中、金额状态和错误必须在目标构建验证，不能把 SQLite 通过写成完整引擎通过。

从 `HashAggregateExecBaseTransformer.scala` 核对 Gluten 的聚合阶段，再到 Velox `HashAggregation.cpp` 和对应金额类型的 `SUM` 实现定位。以实际节点的分组键、聚合模式和中间状态类型为准。
