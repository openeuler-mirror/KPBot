# A/B 协议、指标与判定

## 1. 指标定义

| 指标 | 定义 | 采集 |
| --- | --- | --- |
| TPS | 每秒完成事务数 | sysbench `transactions` / time |
| QPS | 每秒查询数 | sysbench `queries` / time |
| latency | 单事务延迟 | sysbench min/avg/max/P95 |
| errors | 失败事务数 | sysbench `errors` |
| 服务端 CPU | mysqld 进程 CPU% | `pidstat -p $(pidof mysqld) 1` |
| 整机 CPU | 各核/汇总 | `mpstat -P ALL 1` |
| IRQ | 网卡中断增量与核分布 | `/proc/interrupts` 前后差 |
| iowait | IO 等待 | `mpstat`、`iostat -x` |
| 客户端 CPU | sysbench/压测机 | `top`、`mpstat` |

注意：

- `avg` 会掩盖长尾；至少给 P95，必要时 P99/max。
- TPS 与 QPS 不可混用；读写场景一个事务含多条语句。
- CPU% 在容器/虚机中可能按 cpuset/vCPU 归一化，需注明口径。

## 2. A/B 前置条件

- 同一数据快照（同一 prepare 结果或同一备份恢复）。
- 同一 my.cnf（除被测变量）、同一二进制（除被测变量）、同一部署形态/绑核。
- 同一客户端位置、线程数、时长、预热、每轮间隔。
- 记录两腿的 md5/commit、编译参数、内核/固件、CPU/NUMA。
- 只改一个变量；组合变更必须拆分归因或明确标注“组合收益”。

## 3. 轮次与噪声

- 每腿 ≥3 轮；取中位数（推荐）或均值，并给出波动。
- 轮间波动 >5%：视为无效重测，先排查数据/预热/邻居/温度/频率。
- 收益 <5% 通常落在噪声内；不要用单轮峰值下结论。
- 写场景每轮前等刷脏/checkpoint 结束；否则上一轮尾延迟污染下一轮。
- 交替执行 A/B/A/B 可降低时间漂移（温度、频率、缓存）影响。

## 4. 判定规则

| 结果 | 判定 |
| --- | --- |
| 正确性失败 | 直接否决，不看性能 |
| 某场景提升、另一场景回退 | 分场景判定；不能用单场景均值掩盖回退 |
| 提升 <5% 且波动 >5% | 无效/噪声，不保留 |
| 提升 ≥5% 且多轮稳定 | 有效，保留并记录 |
| 负收益 | 回滚并记录负结果 |
| 只有 query-mix/线程变化带来提升 | 标注“运行点/负载变化”，不算配置/源码收益 |

## 6. 常见误判

| 误判 | 纠正 |
| --- | --- |
| 单轮 TPS 高就认为优化有效 | 多轮 + 波动 + 同口径 |
| 把线程数变化当配置收益 | 线程是运行点，需单列 |
| 把 query-mix 变化当服务器收益 | 标注 workload 变化/诊断发现 |
| 客户端先瓶颈却调服务端 | 先看客户端 CPU/网卡 |
| 写场景不比 P99 只看 TPS | 写延迟/长尾更敏感 |
| 换二进制不跑正确性 | 先 MTR/冒烟，再性能 |
| 不同数据集横比 | 数据集身份必须一致 |
| 容器/虚机结果直接对比物理机 | 部署形态不同，需注明 |

## 7. 归档

- 原始 sysbench 输出、`pidstat`/`mpstat`/`iostat`、`/proc/interrupts` 前后快照。
- my.cnf、二进制 md5、MTR 日志、冒烟输出。
- 每轮命令与时间戳；失败/回滚记录。
- 对外报告脱敏：IP/账号/路径用占位符，保留技术结论。
