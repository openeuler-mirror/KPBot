# HNSW 候选规划

## 输入与选择

读取当前源码、[热点检查项](hnsw-performance-hotspots.md)、冻结 manifest 和可用实验记录。按可移除成本、实现范围、数值/平台风险及验证成本排序，选择一个主要机制。

| 方向 | 适用证据 | 验证重点 |
| --- | --- | --- |
| visited 管理 | 清理或分配占比显著 | epoch 回绕、首次/复用、并发与足迹 |
| 候选容器 | 实际读写比例支持减少维护或搜索成本 | tie、满容器替换、容量和访问顺序 |
| 距离/邻接访问 | 距离或随机访存支配查询 | storage 精度、标签、层级与 prefetch |
| 构建路径 | 训练/插入而非查询是优化目标 | 随机性、图连通、线程、质量及保存兼容 |

## 每个候选需要说明

1. 目标调用链、文件/符号、实测占比及机制假设。
2. guard、默认关闭的特性宏、fallback 和最小改动范围。
3. 是否改变布局、距离、候选集合、比较顺序或精排；纯实现优化保留既定语义。
4. 基于占比的理论上限和额外成本。上限不是收益预测。
5. 实际路径的 UT/ST、开关与边界矩阵、冻结性能对照及停止条件。
6. 已有记录的来源与适用差异；缺少资料时说明依据，不虚构已验证/已否定状态。

## 结果

结论来自本次证据，记录到 `run_dir/candidates/<id>/VERDICT.md`。不把某个数据集、处理器或单次候选的结果改写为通用技能的固定推荐或禁令。
