# Lance RLE SVE 解码优化

先确认值、重复次数、子缓冲和输出规则，再实现保持现有结果的 SVE 路径。先验证数据与错误行为，再确认真正执行了候选，最后分别报告展开、完整解码和业务收益。

## 与现有技能配合

本技能负责 RLE 表示、SVE 展开和错误前缀协议。Rust/C 的构建隔离与分派可参考 `rust-native-simd-integration`；配对实验可参考 `kernel-paired-benchmark`，完整查询归因可参考 `kernel-business-performance-validation`。这些是可选辅助，不要求安装源包中的其他 Lance 技能。

移植前读取[接入检查](references/integration-checklist.md)，分别记录入口模式、次数宽度、子缓冲布局、向量长度及实际验证状态。

## 输入

```text

优化对象      RleDecompressor入口、展开函数、Rust原版、SVE候选及开关

子缓冲        values与lengths的实际编码，Flat或需进一步解压的布局
运行环境      CPU/系统指令支持、执行线程向量长度、CPU/NUMA、线程及缓存
测试依据      独立预期结果、原版结果、官方与自建用例、实际命中和原始耗时
优化目标      目标类型及分布、需要改善的计时范围、允许的回退及退化条件
```

先从当前源码和记录核对条件。缺失信息时明确哪些结论不能成立，继续完成已有授权范围内可做的审查，不把未获得的硬件证据写成已通过。

## 执行步骤

### 1. 确认当前实现及入口

遵循目标仓库的开发规范、工具链和 Cargo profile。核对当前 RLE 是否已经存在向量实现、候选开关和试验补丁，不把 Rust 填充默认当作标量，也不把中间态当作官方原版。

优先从下列位置追踪实际版本中的函数和数据流：

```text
rust/lance-encoding/src/encodings/physical/rle.rs
rust/lance-encoding/src/compression.rs
rust/lance-encoding/src/encodings/logical/primitive/
rust/lance-encoding/build.rs
```

若已有 C 文件或 Rust 适配模块，同步查看编译条件、链接对象和调用点。记录实际程序、加载库和源码身份。

### 2. 核对RLE表示及原有行为

RLE 用一个值和对应次数表示相同值的连续段，例如：

```text
值缓冲      [7, 9, 8]
次数缓冲    [3, 2, 3]
展开结果    [7, 7, 7, 9, 9, 8, 8, 8]
```

核对值与次数是否一一对应、次数是否允许为零、请求值数的来源，以及重复次数不足或超过预期输出时的处理。

分别确认实际入口的严格模式与 clamp 模式。严格模式下超出预期输出的 run 可能需要报错；clamp 模式可能按现有约定只写剩余需要的值。必须保持当前语义，不能把所有入口统一处理，也不在新公共边界上偷偷修正无效数据。

检查两个子缓冲是否为 Flat。Flat 只有相应准备或视图处理，没有实质子解压；压缩子缓冲可能再调用 BP 等算法，需要另外覆盖。

### 3. 明确SVE支持范围和原版回退

列清值类型、次数类型、入口模式、子缓冲条件和 CPU/系统要求。历史候选支持 u32/u64 值与 U8 次数；其他条件保留原路径，除非本次单独实现并验证。

不能把 U16 次数缓冲按字节解释成 U8 来调用既有内核。u32 测试不能证明 u64 正确，Flat 测试不能替代压缩子缓冲验证。

```text
入口检查      类型、缓冲长度、run数量、请求输出数和模式
平台检查      候选对象是否存在，实际依赖SVE还是SVE2
候选执行      全部适用条件成立后进入对应u32/u64内核
原版回退      不适用时，在候选执行和写入之前选择原实现
```

### 4. 实现按run的SVE批量展开

每个重复段按下面的顺序处理：

1. 读取当前值与次数，完成原有检查，按入口语义算出本段实际应写数量。
2. 将当前值广播到向量寄存器，使各通道得到相同的值。
3. 按剩余数量生成谓词，只启用本批允许写入的位置。
4. 写入有效通道并推进输出位置；本段未完成则继续，完成后处理下一个值。

每次容纳的值数由执行线程的实际 SVE 长度和元素位宽决定。历史机器上的“32 字节向量，一次 8 个 u32 或 4 个 u64”只能作为该环境信息，不能写死为算法条件。

最后一批不足向量长度时，用谓词禁止多余位置写入。次数累计、输出位置和元素/字节换算都要防止溢出，并在访问前保证输入和输出的可访问范围。

### 5. 单独处理初始化长度发布

“SVE 批量写相同值”和“减少初始化长度写回”是不同优化点。若将每个 run 写回长度改为返回时统一发布，需说明该变化并验证每一条成功和错误出口。

u32/u64 输出在原生写入期间可以保持 Vec 长度为零，只分配容量，通过原有原始指针或未初始化空间写入。不能在 C 真正写满之前将 Vec 长度设置为预期值。

```text
调用前        检查元素/字节大小及容量，将initialized置零
执行中        只写合法范围，维护连续已初始化前缀的元素数
任何返回      按约定返回状态和准确前缀，错误路径也不能遗漏
接收返回      验证状态与前缀范围，不能超过预期数量或输出容量
成功暴露      成功且初始化数量等于预期值数后，才发布完整输出长度
失败清理      不读取未写区域，不向调用者暴露部分无效结果
```

initialized 表示元素数量，不是字节数，也不能描述存在空洞的写入。后续 run 无效时，仍按约定报告前面已经写入的准确前缀。

长度一直为零的 u32/u64 Vec 在错误时直接丢弃即可释放分配，不必须额外创建自定义 Drop guard，也不必为了清理而发布部分长度。若真实 API 保存需析构对象或允许部分结果，按它的独立所有权约定处理。

返回后的范围检查不能修复 C 中已经发生的越界写入。除了证明谓词和存储边界，还应在支持的目标环境中使用合适的内存检查、哨兵或保护页验证。

### 6. 核对Rust/C调用、指令集和错误回退

核对函数签名、整数宽度、状态值、指针生命周期、对齐、别名和容量。原生实现不能在前提未满足时访问缓冲。

AArch64 不等于支持 SVE；需要 SVE2 的对象不能仅靠 SVE 检查保护。根据实际指令和编译参数检测准确的 CPU/系统能力，在任何可选指令前完成判断，获取向量长度的辅助函数同样需要保护。

全局编译参数可能使分派与回退代码也使用可选指令。特定机器专用构建可以存在，但要明确部署要求，不能据内部回退分支宣称整个程序可移植。

输入不适用可以提前走 Rust；候选已执行后报错，必须保留失败和原有错误语义。若为了构造一致错误再次调用 Rust，而 Rust 对同一输入成功，应报告候选存在问题，不能静默返回成功并把它计为候选正确命中。

### 7. 完成正确性与边界验证

使用确定性数据和固定随机种子，逐值比较结果，检查长度与原有错误。直接内核与真实 RleDecompressor 入口分别测试，不能漏掉分派、子缓冲准备或封装问题。

```text
测试类别      覆盖要求
值与次数      u32/u64分别验证，U8适用，其他次数宽度验证回退
重复段        短段、长段、混合长度、U8次数255、允许的零次数
向量边界      少于/等于/多于一及多个向量，最后不足一向量
输出数量      合法零输出、刚好写满、不足、超出及尾段截断
入口语义      严格模式和clamp模式分别验证
异常输入      子缓冲长度不匹配、非法run、算术或分配边界
初始化协议    首段错误、部分写入后错误、未知状态、前缀不足或超限
子缓冲        Flat与压缩子缓冲分别核对，未测布局单列
平台分派      候选关闭、不支持指令集、其他不适用条件和正常候选执行
```

条件允许时覆盖多个合法 SVE 长度，并确认执行线程的实际长度。只在一个长度测过，就只报告该长度；其他长度和非 SVE 回退平台没有执行过，必须标为未测。

完成源代码修改后，运行当前目录规范要求的针对性测试和检查；准备提交时执行规定的格式及 lint，不以文档检查代替代码验收。

### 8. 独立审计真实SVE执行

在正式计时之外记录完整 RLE 入口、原版、实际 u32/u64 原生调用次数、展开值数和回退原因。计数放在能确认真实实现执行的位置。

确认关闭候选时不进入 SVE，打开且输入适用时进入对应内核；两侧请求、处理值数和输出一致。开关、外层入口或汇编中的 SVE 指令不能代替执行证据。

正式性能采集关闭审计，核对源码和构建身份没有变化。算法模式、审计和阶段计时分别控制。

### 9. 定义展开、完整解码和批次计时

根据实际计时器说明包含什么，不根据名称随意缩小范围：

```text
原生展开内核    Rust/C内核内部的重复值写入，以实际边界为准
RLE展开入口     展开函数中的检查、分配、Rust/SVE展开、返回检查及封装
RLE完整解码     RleDecompressor入口、子缓冲处理、展开和结果构造
完整批次解码    decode_batch的调度、页面初始化、解码、数据拼接及Arrow结果
完整业务查询    SQL规划、扫描、解码、SQL算子和全部结果取回
```

直接调用 MiniBlockDecompressor 的 RLE 实现、使用准备好的 Flat 子缓冲，测到的是该入口调用总时间；还可能包含调用端引用准备和结果释放。不能因此称为纯 SVE 内核或完整业务时间。

只计时完整 RLE 而没有单独围绕展开计时，就只报告完整 RLE 加速比，不能将同一数字再次填为展开加速比。

### 10. 核查官方用例与自建用例

扫描固定提交下的 benchmark 注册、辅助生成器和计时闭包，保存实际完整用例名。不能只检查一个文件就断言整个仓库不存在相关测试。

在提交 123245f2085a164b1e70751eb784aa77046dab46 的已核查源码中：

```text
源码      rust/lance-encoding/benches/scheme_comparison.rs
target    scheme_comparison
group     scheme_comparison_decode
case      i64_runs/rle/<encoded_bytes>B
输入      8192个int64，每值重复32次
计时      完整decode_batch，不是单独的RLE完整入口
```

字节数后缀由准备阶段生成，不能对所有版本固定写成 2344B。新用例适配到旧源码时，分别记录用例来源、实现基线和补丁，不能称为最新主分支实现的测试。

确认当前提交确实注册了 scheme_comparison target 后，可以从仓库根目录使用下列入口列出及执行用例。候选编译特性和运行开关按第 3、6、8 步核对；仅运行该命令不能证明 SVE 已启用。

```sh
cargo bench --locked -p lance-encoding --bench scheme_comparison --profile release-with-debug -- 'scheme_comparison_decode/i64_runs/rle/' --list
cargo bench --locked -p lance-encoding --bench scheme_comparison --profile release-with-debug -- 'scheme_comparison_decode/i64_runs/rle/'
```

列出的用例必须非空，完整名字以实际输出为准。若旧基线没有该 target，先明确本轮是适配官方用例还是自建测试，不直接添加后再称为旧版本原有 benchmark。

该提交的 take.rs 还有 primitive_take 的 scan/take i64_runs 场景，但编码自动选择，必须先查实际 RLE 命中。换了提交重新核查，历史发现不是永久结论。

自行增加直接入口、全位宽、百万值或 mixed 用例时，明确标为自建或扩展，不改称官方现成用例。

### 11. 设计固定入口的对照矩阵

根据问题只改变需要研究的因素。例如固定 u64、U8 次数、Flat、同一 RLE 入口及模式，分别改变输出数量和次数分布：

```text
输出数量      固定重复32次    mixed重复次数
4096          测试            测试
1000000       测试            测试
```

定义 mixed 规则，例如次数 1～255、末段按目标数量截断。值与次数使用独立固定随机流，两侧使用逐字节相同输入；数据生成和独立逐值校验放在计时范围外。

使用用户确认的 CPU/NUMA、线程、缓存和频率，先查资源空闲和拓扑。采用仓库规定的 release-with-debug；尽量同构建切换原版/候选，不同构建需保存差异。

事前确定预热、采样、轮次和先后顺序。同轮同场景配对比较，交替或平衡顺序，保存失败尝试、离群值与全部原始样本。Criterion 样本和内部调用次数分别报告。

大批量不保证更快，mixed 也不保证更快。每个组合独立报告，不用整体均值掩盖固定重复场景的退化。

### 12. 汇总并解释局部与整体收益

检查正确性、实际命中、工作量和样本完整，再计算原版耗时除以候选耗时。保留前后耗时及每轮比值，跨轮采用约定的几何平均等方法，给出波动和退化。

```text
观察结果                    后续检查
没有进入SVE                 查构建、加载库、值/次数类型及指令检测
有的分布变快、有的变慢      查run数量、长度、尾谓词和原版生成代码
展开变快、完整RLE变化小     查子缓冲、检查、分配、分派和封装
RLE变快、decode_batch不明显 查调度器初始化、任务提交、内存管理和数据复制
完整解码变快、SQL变化小     查阶段占比，独立测完整查询
```

局部占比较低可能限制整体收益，但没有同次运行的分段证据，不能认定全部差异来自某个外层阶段。不同输入或不同入口的时间不能直接相减，并命名为精确分配或调度开销。

需要火焰图时保持原用例和实现身份独立采样。图宽是采样占比，父子栈不能相加，CPU 占比不等于精确墙钟分段。采样用于定位，性能成绩使用约定的非采样运行。

## 输出

- 源码基线、候选补丁、Rust/C 工具链、编译特性和实际程序/库身份。
- 调用链、具体优化点、值/次数支持范围、严格/clamp 规则及回退条件。
- 动态向量长度、谓词尾段写入、内存边界和初始化前缀协议的说明。
- 分类型、入口、布局、异常、向量长度和平台条件的正确性记录及未测项。
- 独立命中审计，分别给出实际 u32/u64 SVE 次数、处理值数和回退原因。
- 官方或自建用例身份、输入生成、计时边界、环境协议和原始样本。
- 各场景前后耗时、加速比、波动及退化，不同计时层次分别给结论。
- 若测完整批次或 SQL，另列对应成绩；没有实测时不宣称业务已加速。

表前说明时间单位、汇总方法和计时范围，使用空格对齐：

```text
输出类型  输出数量  重复分布  计时范围  原版耗时  候选耗时  加速比  正确性状态
```

不能执行目标验证时，交付已有证据和待办，标记 awaiting_target_evidence。文档、编译、代理场景或本地分析器通过，都不能写成 SVE 实机通过。

## 约束

- 保持现有文件格式、值顺序、返回结果和错误语义，不删除检查或修改输入换取成绩。
- u32/u64、U8与其他次数宽度、严格与clamp、Flat与压缩布局分别界定和验证。
- Flat 场景不声称实质子解压，也不能据此推断 BP 加快了 RLE 子解压。
- 准确检测所需指令集后才执行 SVE/SVE2，包括向量长度辅助函数。
- 不把历史向量长度、特定机器全局编译参数或旧加速比当作普遍条件。
- 输出成功且长度验证通过之前不暴露；错误和部分写入保持合法所有权与前缀协议。
- 超限前缀、未知状态和原生实现失败不能通过截断计数或成功重试掩盖。
- C 写入边界必须真实成立，Rust 返回后检查不能修复已发生的越界。
- 直接 RLE、自建测试、官方批次和 SQL 分别命名，不能共用一个收益结论。
- 未独立计时的展开或内核不填写独立加速比，未采集不代表零耗时。
- BP/RLE 父子累计时间先去重，联合模式用实测而不是独立倍数相乘。
- 保留退化、失败和统计不确定性，不预设大批量或 mixed 一定获益。
- 只要求源码或现有结果分析时，不自行启动远端压测或发布修改。
- 正文包含完整流程；evals/evals.json 的场景定义不等于 ARM 内核、回退和业务已经验收。
