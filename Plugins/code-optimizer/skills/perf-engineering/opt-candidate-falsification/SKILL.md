# 候选生成 + 证伪优先（阶段 3）

## 何时使用

- 瓶颈已定位，需要从多个方向里挑出性价比最高的。
- 有一个"听起来很对"的优化假设，想在动手前先验证真假。
- 想避免把昂贵重编译/全量对比浪费在注定无效的方向上。

## 核心原则

1. **证伪优先（disprove first）是整个项目性价比最高的动作。** 先找反证、再信假设。
2. **便宜证据阶梯**：能在前四步排除的，绝不上第五步。
3. **证伪不是"什么都不做"**：它关掉无效方向的同时，要把有效方向照亮。
4. **候选先求全，再排序；排序看四维，不只看占比。**

## 步骤

### 1. 候选六字段

每个候选统一写清：

| 字段 | 说明 |
|---|---|
| 目标组件 | 改哪个组件/路径 |
| 量化依据 | 来自瓶颈分析的占比/分配量/调用次数 |
| 预期增益 | **给区间不给点值** |
| 成本 | 轻 / 中 / 重（是否重编译、是否动数据接口） |
| 风险 | 低/中/高 + 一句话 |
| 优先级理由 | 为什么排这个位置 |

### 2. 排序四维 + 去重

- **绝对占比** + **剩余空间** + **性价比（收益/成本）** + **正交性（能否叠加、不互相抵消）**。
- 生成候选时先和"已做过 / 已过期"清单交叉去重。

### 3. 便宜证据阶梯（从便宜到昂贵）

```
① 在已有采样文本里 grep          （零成本）
② 读源码控制流 / 调用点           （零成本）
③ 算术量级推算                    （零成本）
④ 注入环境变量 + 单轮计时          （低成本）
⑤ 重编译 + 完整对比               （高成本）
```

### 4. 三个最有价值的量级判据

- **零触发（先说"采样未观察到"）**：`grep -c` 计数 = 0 → 只能记为"**采样未观察到**该路径执行"，不能直接判"从未触发"——
  短调用可能落在相邻两次采样之间被漏掉。要确认零触发，需升级到：**调用计数**（插桩/日志计数 = 0）、
  **完整请求轨迹**（trace 里无该调用），或**可证明分支不可达的控制流**（读源码证明入口条件恒假）。
- **带宽受限**：`GFLOP/s ÷ 核 ≈ 峰值 20% 上下` **不能单独判**——指令依赖/访存延迟也能造成 ~20% 吞吐；
  需补**实测内存带宽 vs 平台可持续带宽**，实测贴近可持续带宽才判带宽受限。
- **从未触发**：资源峰值远低于阈值 → 该项不是瓶颈，**但口径要用"运行时管理总内存"而非只堆 live**（见下）。

### 5. 用环境变量做证据前，先验证注入真的生效

`docker inspect` / 观测确实产生了输出（如 gctrace 有行），否则对比无效。

### 6. 证伪收尾

- 留痕（写进结论）+ **还原环境**（源码/入口/配置回到保留态）。
- 明确指出"正确的方向是什么"，哪怕它超出本次范围。

## 门禁

- [ ] 每个候选都有六字段，预期增益是区间
- [ ] 排序用了四维，且做过与历史候选的去重
- [ ] 每个高成本候选都先过一遍便宜证据阶梯
- [ ] grep 零命中只记为"采样未观察到"，零触发另有调用计数/完整轨迹/不可达控制流支撑
- [ ] 带宽受限用了实测带宽 vs 可持续带宽对照（否则标待验证）
- [ ] GOMEMLIMIT 触发判断用 /memory/classes 总内存口径，结论限定"本次限额实验"
- [ ] 环境变量类证据已确认注入生效
- [ ] 证伪结论留痕 + 环境已还原 + 有效方向已指出

## 产物

- 候选清单（六字段 + 排序）
- 证伪记录：假设 / 便宜证据 / 结论 / 省掉了什么 / 正确方向
