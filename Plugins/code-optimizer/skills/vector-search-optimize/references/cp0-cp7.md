# 向量检索通用优化流程

Faiss 和 DiskANN 专项工作流采用下列阶段，在各自的工作流中约定角色、构建入口、验证项和状态结构。其他引擎由当前主 Agent 在独立 `run_dir` 中记录阶段、状态和可复现产物。专项接管后使用既有状态及校验器，恢复前核对已完成阶段的实际文件。

| 阶段 | 执行内容 | 完成证据 |
| --- | --- | --- |
| CP0 定义范围 | 确定目标、优化层级、版本、负载、可修改范围、资源、交互模式和停止条件。先区分实现优化、参数调优和诊断。 | 任务、实验目录和阶段记录 |
| CP1 环境与源码取证 | 从查询入口沿调用链确认实际执行的索引、距离、量化和后端。服务任务区分客户端、网络、调度、分片与索引内核。核对可用构建、测试、采样工具和平台。 | 入口到热点路径的证据、环境记录和限制 |
| CP2 冻结基线 | 通过正确性冒烟并运行可复现的基线。记录版本、构建、数据、ground truth、索引、查询与资源。先声明质量门槛、测量指标、预热、缓存、重复次数、漂移和异常规则。 | 冻结 manifest、基线原始样本和质量门槛 |
| CP3 采样与候选 | 在已声明的负载上采样，将热点映射到实际源码或服务组件。候选给出单一主要机制、收益上限、风险、证伪实验和回滚条件。按交互模式选择候选。 | 采样报告、归因、候选计划和选择理由 |
| CP4 实现 | 按计划做最小改动，保留原路径。代码优化提供默认关闭的特性开关或可审计的回退路径。参数实验单独记录唯一变更量。 | 补丁或配置变更、有效开关及自检记录 |
| CP5 构建与正确性 | 核对基线和候选产物身份。验证开关双向、边界、并发、失败回退和实际查询语义。配置变更验证生效与回滚。 | 构建日志、可用的 UT/ST 或集成报告、原始结果差异 |
| CP6 平衡性能对照 | 先确认冻结条件和质量门槛，再按 A1–B1–B2–A2 或预声明的等价序列运行。记录全部有效样本、离散程度、漂移及被排除样本的依据。 | 每次命令和输出、逐负载比较、异常与漂移说明 |
| CP7 验收与交付 | 由独立角色复核改动、正确性、实验矩阵和结论。记录接受、拒绝或证据不足。需要返工时注明返回阶段和重做条件。 | 结论、复现命令、证据路径和授权范围内的交付 |

## 冻结条件与阶段门槛

- 在 CP2 和 CP6 使用 [测量契约](../../vector-experiment-methodology/references/measurement-contract.md)。纯查询实现优化优先复用相同索引。构建实验单独记录训练和索引生成。服务实验补齐并发、到达率、分片、副本、过滤条件、资源限制和缓存策略。变化的条件单独立项。
- 在 CP5 使用 [测试契约](../../vector-ut-st-validation/references/test-contract.md)。按任务选择结果 ID、距离、Recall@K、过滤语义和实际工作量的比较。遇到并列距离或近似数值差异，使用预声明的判定规则。证据缺失时标明适用范围与未执行项。
- 未冻结基线时先补 CP2，正确性未通过时返回 CP4 或 CP5。信号落在噪声范围时记录证据不足。只对预声明且可比的工作负载矩阵汇总收益，保存逐负载结论和原始证据。
- 缺少源码、部署权限或可控负载时，交付可执行范围内的诊断与基线。独立复核无法完成时记录验收缺口。阶段状态由当前主 Agent 维护，用户授权决定源码修改和外部交付范围。
