# TurboQuant 候选规划

## 输入与选择

读取当前源码、[热点检查项](turboquant-performance-hotspots.md)、冻结 manifest 和可用实验记录。按可移除成本、实现范围、数值/平台风险及验证成本排序，选择一个主要机制。

| 方向 | 适用证据 | 验证重点 |
| --- | --- | --- |
| 查表与地址生成 | 测得 decode/gather 依赖或重复地址开销 | 表范围、布局、alias 及浮点顺序 |
| 查询状态复用 | 投影/因子可在既定生命周期复用 | query 切换、metric、并发与内存占用 |
| SIMD/归约重组 | 实际 VL 与成本模型支持局部改写 | FMA、归约次数、尾段和 fallback |
| 可选索引缓存 | 重复位提取开销可被缓存摊销 | 存储增量、编码/解码、序列化与质量 |

## 每个候选需要说明

1. 目标调用链、文件/符号、实测占比及机制假设。
2. guard、默认关闭的特性宏、fallback 和最小改动范围。
3. 是否改变布局、距离、候选集合、比较顺序或精排；纯实现优化保留既定语义。
4. 基于占比的理论上限和额外成本。上限不是收益预测。
5. 实际路径的 UT/ST、开关与边界矩阵、冻结性能对照及停止条件。
6. 已有记录的来源与适用差异；缺少资料时说明依据，不虚构已验证/已否定状态。

## 结果

结论来自本次证据，记录到 `run_dir/candidates/<id>/VERDICT.md`。不把某个数据集、处理器或单次候选的结果改写为通用技能的固定推荐或禁令。
