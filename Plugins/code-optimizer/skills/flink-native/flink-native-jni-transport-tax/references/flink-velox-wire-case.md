# 案例实录：Flink×velox 栈传输四税的定位与消除

本文按经验类六要素组织（现场特征 / 判断依据 / 处置动作 / 实测效果 / 复验方法 /
适用边界）。数字均为**自测口径**：nexmark 类负载、固定事件规模、并行度 4、
blackhole sink、双端（向量化栈 vs 原生 Flink）同日锚定。换负载与环境必须重测。

## 现场特征

有状态算子（Top-N/去重族）按原生流程重写并对齐后，端到端仍差约 4.5 倍；继续
优化算子逻辑差距不动。重负载查询在原生栈需要数倍 TaskManager 堆（对照端随后
在同一 TM 堆与 JVM 参数下同口径重跑，异堆配置轮次不进双端比值——见基准协议
flink-native-bench-protocol 的"双端同口径重跑规则"）。现象指向"差距不在计算"。

## 判断依据

三层拆账（算子/传输/内存）把残余差距归属到传输层，证据链：

1. 算子层已按原生函数族逐段对照对齐（语义对照矩阵通过，行为冻结一致）；
2. 内存层问题此前已单独修复（状态形态审计，见姊妹 skill
   `flink-native-stateful-operator-tuning`——那条线与本案例互补）；
3. 剩余差距随 wire 字节数同步变化——账单指向数据桥。

税种定位：

- **税①**：分区输出走"引用切片"（StreamPartition 算子与 KeyGroupPartitionFunction，引用切片的字典包裹在 wrapForPartition）——切片只是
  引用视图，真实序列化时逐元素从各缓冲 gather 取货（BaseVector::copy 类的通用
  copy 语义）。生产点零成本 = 欠账进消费点。
- **税②**：wire 走 Base64 编码的字节流。
- **税③**：byte[] → String → 再转 byte[] 的中转链——实测一条记录九次拷贝。
- **税④**：桥上批行数 1（逐条过桥），固定开销占比接近 100%。

## 处置动作

分三阶段、每阶段独立门禁（编译部署 → 三指标复测 → 行为冻结核验）：

1. **阶段一（税①）**：分区内显式实体化——切片后逐行取货物化成连续内存结构，
   gather 欠账变成生产点显式成本；
2. **阶段二（税②③）**：wire 改字节流直传（去 Base64 层），byte[] 直通消除
   String 中转链；
3. **阶段三（税④）**：输出攒批 + 扫参定缺省批行数 2048（扫描矩阵收敛；本阶段
   出现过一次门禁 fail——缺省拍脑袋设小了，复测不达标后扫参收敛，fail 过程
   保留为"攒批缺省必须扫参"的反例教材）。

## 实测效果

分阶段边际贡献（自测口径，同日锚定八跑证据）：

| 阶段 | 消除的税 | 差距缩量 | 备注 |
|---|---|---|---|
| 一 | 税①实体化欠账 | **约 87%** | 单阶段吃掉绝大部分差距 |
| 二 | 税②编码 + 税③拷贝链 | 次之 | wire 字节数同步下降 |
| 三 | 税④小批固定开销 | 再次之 | duration 收益需专项复核（攒批只压固定开销占比） |

行为冻结：全部用例 changelog/Discard 输出与优化前基线**精确一致**（12 用例 MATCH
+ key 分组 IDENTICAL）——性能提升零语义代价。内存（RSS 峰值）同口径复核无回退。

### 证据状态

- 本案例的量化数字（分阶段收益、拷贝次数、行为冻结计数）为**自测口径**，测量条件
  见文件头；判断依据中的机制锚点（类名）可在上游开源分支 grep 定位复核；
- 原始 benchmark 证据（逐轮 duration/wire/RSS 明细）存于提交者工作区，**随三仓
  上游 PR（gluten / velox / velox4j 的 rank-operator 系列）合入后可公开复核，
  届时回填本文件的证据索引**；
- 在证据公开前，第三方按下方"复验方法"在自有环境重建结论——本案例的结论
  结构（税种归属、消除顺序、行为冻结算放行）不依赖原始证据文件即可复现。

## 复验方法

1. 双端同日锚定跑基线（任一端内存不足时按基准协议"双端同口径重跑规则"处理：
   放大堆的端与对照端在同一 TM 堆、同一 JVM 参数下重跑，双端比值仅用同配置
   轮次；无法对齐时该组作参考结论、不入比值汇总；不可跨日比较）；
2. 逐阶段单独编译部署、三指标（duration / wire bytes / RSS）复测，单阶段归因；
3. 每阶段 changelog 折叠对比（+I/-U/+U/-D 还原终态精确一致）+ key 分组一致性；
4. 攒批缺省值以扫参矩阵收敛为准，不继承本案例数字。

## 适用边界

- 本案例税①的形态是"分区切片引用未实体化"——其他栈的实体化欠账可能出现在
  视图/惰性列/跨段引用等别的形态，**按账单特征（消费点爆发）识别，不按形态
  名称套用**；
- "阶段一吃 87%"是本案例的税种权重，非普适比例——四税的占比由各栈的账单决定；
- 攒批有语义边界（延迟与内存上限），对延迟敏感场景缺省值须重新扫参；
- 实体化是"把欠账变显账"，对本来就连续存储的 wire 结构不适用（无欠账可还）。
