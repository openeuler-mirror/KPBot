# binary-compile-forensics — 二进制编译参数产物取证

构建系统（cmake/make/blade…）的配置继承链可以被任何一层覆盖污染——产物本身才是
"实际用了什么参数"的权威答案。本 skill 用三条独立证据链从产物反推：**.comment 段**
（编译器版本，不需要 -g）、**DW_AT_producer**（完整编译参数指纹，需要 -g 构建）、
**SIMD 指令采样**（无 -g 时的兜底）。

## 工作流程

```
拿到待取证文件（.o / .a / .so / 可执行文件）
  → 三链取证（每文件独立，单项失败不中止全局；完成=至少一条链产出结论）
  → 交叉判读：参数指纹 vs 采样兜底 vs 预期参数
  → 结论：构建基线确认 / 发现偏差 / 证据不足（如实降级）
```

## 可执行入口

```bash
# 单文件取证
bash scripts/inspect_build_flags.sh /path/to/libfoo.a

# 多文件（产物与依赖库一起对照）
bash scripts/inspect_build_flags.sh /path/to/app.bin /path/to/libbar.so

# 静态库逐成员全查（定位混链构建的污染成员）
bash scripts/inspect_build_flags.sh -a /path/to/libfoo.a
```

## 检测内容（三条证据链）

| 链 | 依赖 | 能拿到什么 | 拿不到时 |
|---|---|---|---|
| 1. 编译器版本 | 无（裸 readelf） | .comment 段的 GCC/clang 版本串 | .comment 数据缺失（部分 strip 流程会裁剪；以实测为准）→ 该链标"无证据" |
| 2. 参数指纹 | -g 构建 | DW_AT_producer 完整参数（-O/-march/-mcpu/-g/-f…），**不受构建系统任何覆盖欺骗**；注意 -gno-record-gcc-switches 时存在但不记录待核验开关；分离 debuginfo 时先按 build ID 查找匹配的 debuginfo 包 | 无 debug info → 降级到链 3 |
| 3. SIMD 兜底 | objdump 可反汇编 | SVE z 寄存器 / NEON v 寄存器指令计数（采样前 30 万行）——**零命中只说明"样本中未见"，不证伪编译时启用了 SVE** | 交叉架构对象 → 该链跳过 |

## 参数速查

| 参数 | 说明 |
|---|---|
| 文件路径（1..n） | .o/.a/.so/可执行文件；.a 自动抽首个成员 |
| `-a` | 静态库**逐成员全查**并标出成员名（默认只查首成员，大库耗时） |

## 输出契约

- **stdout**：每个文件（或 -a 模式下每个成员）一节——`[编译器版本]`（分号分隔多
  版本=混链构建！）、`[实际编译参数]`（DW_AT_producer 逐条 + 解析出的优化等级/
  目标架构/其他开关；注明"仅前 5 个编译单元，未覆盖单元的参数为未知"）、
  `[SIMD 兜底探测]`（SVE/NEON 计数与判定；零命中标"样本中未见"）；
  结尾结论行——`完成取证文件数/总文件数` + `取得指纹文件数` 两个独立计数
- **stderr**：单项失败诊断（文件不存在、无法反汇编、静态库成员读取失败、
  三条链均无结论的"非 ELF"文件）
- **退出码**：`0` 全部文件完成取证（含部分链降级；完成=至少一条链产出结论）；
  `4` 部分文件完成（部分失败，stderr 有各文件失败原因）；
  `1` 没有任何文件完成取证（三条链均无结论——路径错、架构不符、格式不支持）；
  `2` 用法错误（无参数）；`3` 依赖工具缺失（readelf/objdump/ar 不可用）

## 成功、失败与 blocked

- 成功 = 每文件**至少一条链产出结论**（.comment 非空 / DW_AT_producer 非空 / SIMD
  有效计数）；三条链全空 = 该文件未完成取证（不计入 OK_FILES）
- 失败（exit 1）= 所有文件的三条链均无结论（全部路径错/架构不符/格式不支持）
- blocked（exit 3）= 宿主机没有 binutils 工具——这是环境前置问题，不是取证失败

## 约束

- 只读操作：不修改被检文件、不执行被检文件、不联网
- 静态库默认抽首成员（`-a` 逐成员全查并标出成员名）——大库全查可能耗时数分钟，
  采样反汇编有 60s 超时
- 参数指纹的完整性取决于 -g 构建；release 产物常见无 debug info 或 debuginfo 分离，
  此时**先按 build ID 查找分离的 debuginfo 包**——找不到才降级到 SIMD 兜底。
  **如实降级不冒充**（不会把 SIMD 采样说成参数证据）
- DW_AT_producer 只抽前 5 个编译单元去重——未覆盖单元的参数标为未知，结论
  限定于实际抽到的编译单元和其中明确记录的参数

## 和同类 skill 的分界

- 源码树构建配置审计（CMakeLists 继承链核对）不在本 skill——本 skill 只看产物，
  配置链的权威在构建系统侧
- 热点库版本差距核对（`hot-library-version-gap`）：那个回答"跑的是哪个版本"，
  本 skill 回答"这个版本是怎么编的"；两者在库归因场景天然衔接
- 火焰图/profiling 类（`flamegraph-libopt`、`go-pprof-analysis`）：回答"哪里热"；
  本 skill 在优化归因前固定构建基线，防止把构建差异误归因为代码差异
- patch 使能验证（符号级 nm/strings 三探针）：那个验证"我的 patch 生效没有"，
  本 skill 验证"整份产物的构建参数"——粒度互补

## 错误处理

| 现象 | 原因与处理 |
|------|-----------|
| `[编译器版本]` 空 | .comment 被 strip 或非 ELF——换链 2/3，或确认文件格式 |
| `DW_AT_producer` 无输出 | 构建未带 -g **或 debuginfo 已分离**——先按 build ID 查找分离的 debuginfo 包；找不到才降级用 SIMD 采样兜底；需要权威指纹让上游带 `-g` 重编 |
| SIMD 零命中 | **样本中未见**（不证伪启用）——目标函数可能在采样范围之外；如需判定编译开关另取参数记录 |
| `[静态库] 无法读取成员` | ar 归档损坏或非标准 .a——用 `ar t` 手工核对成员表 |
| 多版本编译器串同时出现 | 混链构建（部分 .o 来自不同工具链）——用 `-a` 逐成员定位污染成员 |
| 三条链均无结论 | 非 ELF 或文件损坏——该文件计入"未完成取证"；全部文件如此则 exit 1 |
| `-a` 耗时过长 | 大库逐成员全查有 60s/成员的 SIMD 采样保护——先用默认首成员模式排查 |
