# RLE 计时范围与矩阵补充

## 计时层次

```text
完整查询
  +-- Lance扫描
  |   +-- RLE完整入口
  |       +-- 子缓冲准备或子解压
  |       +-- 展开入口中的检查、分配、Rust/SVE展开和封装
  +-- SQL算子和完整结果取回
```

展开入口若包含检查、分配，不能命名为纯 C/SVE 内核。直接 RLE 入口不等于 decode_batch，更不等于 SQL。明确调用端引用准备和返回后释放是否计时。

## 官方与自建

在已核查提交 123245f2085a164b1e70751eb784aa77046dab46 中，scheme_comparison.rs 的 scheme_comparison_decode/i64_runs/rle/<encoded_bytes>B 使用 8192 个 int64、固定重复 32 次，测完整 decode_batch。

同版本 take.rs 的 primitive_take/scan/i64_runs/<encoded_bytes>B 及 take 的 cold/warm 用例采用自动编码选择，必须核对元数据与实际分派。字节数后缀在准备时生成，不能固定写成某个历史值。

新基准文件适配到旧实现时，分别记录用例来源与实现基线。对其他版本重新核查，不能从一个文件或旧结论推出官方永远没有独立入口基准。

## 固定入口矩阵

固定 u64、次数宽度、Flat 子缓冲、同一入口和模式，交叉改变 4096/1000000 输出与 fixed32/mixed1..255。末段按目标数截断，值与次数采用独立随机流，同一组原版/候选使用相同字节。

历史上出现过小 fixed32 变快、大 fixed32 变慢、大 mixed 变快，因此规模或分布本身不是收益保证。这只是反例，不是新机器的成绩或验收阈值。
