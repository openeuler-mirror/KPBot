# 绘图前的数据整理

## 先判断结构，再 reshape

Agent 接收到文件、文件列表或目录时，先盘点每个相关文件的表头、分隔符、样本粒度与单位。目录可能混有旧结果、图片、日志，不能直接将全部文件当作样本合并。文件名中的版本、机器或重复编号仅作为待确认线索，必要时询问用户。

根据实际结构选择最少必要的转换：

- 同构表：可配置 inputs 直接拼接，附版本/机器等文件级 dimensions。
- 不同列名：建立字段映射，如 latency_us 与 duration_ms 经确认单位后统一；转换后记录公式。
- 每轮一列：转为 run_id、case、metric、value 等逐观测记录。
- 一个文件一个指标：按明确实验 ID/配置键连接，不按行号假定配对；连接前核对键唯一性和缺失。
- 含多级表头、注释、混合文字的 TXT/日志：Agent 解析所需记录到 CSV/JSON，保留文件及原行号；不需要修改绘图引擎。
- 已有 min/max/median：可保持宽表分别映射指标，或转成长表并保留 statistic 列；不能还原不存在的原始样本。

## 数据保护和核对

原文件只读，整理结果另存（如 prepared/）。保留实验来源、运行 ID、分组条件、原始单位、状态与来源行。不要因为多个文件都含 run_id=1 就把它们误当同一次实验；先确认语义，再建立跨文件唯一标识。

记录整理前后行数、丢弃/过滤原因、合并键和未匹配记录。缺失值不填零；重复行需确认是真实重复运行还是重复导出，不能默认去重。先确认独立运行与运行内采样的区别，再选择聚合层级。

交给绘图程序前检查：每个指标值可解析、单位统一、分组维度完整、每个图的实验编号不冲突。已有统计值标为 summary。多次独立实验应保留逐轮值及可用离散程度，不在 reshape 时只剩一个平均数。

## Agent 无读图能力时

仍执行文本层面的数据/配置/文件检查。交付时明确图片未经 Agent 视觉审核，提供文件路径并请用户检查长标签全称映射、图例、坐标范围、波动是否清楚。用户反馈通过自然语言进入下一次参数修改。
