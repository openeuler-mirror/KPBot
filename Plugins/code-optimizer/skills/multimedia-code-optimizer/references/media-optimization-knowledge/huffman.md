# Huffman 与位流

## 码表与前瞻解码

频率生成码长；限长用 package-merge 等构造。Canonical code 令 count[0]=0、code=0，逐长度 l 更新 `code=(code+count[l-1])<<1`，同长度按格式符号序递增。以 left=1 起逐层 `left=2*left-count[l]`，负值为超额订阅；不完整树按格式判断，JPEG 禁止全 1 码字。

MSB-first k 位主表把长度 l≤k、码字 c 展开到 `[c<<(k-l),((c+1)<<(k-l))-1]`，保存符号及码长；长码进次级表。增大 k 减少次级查询，但主表占 `2^k*entry_size`，按码长分布、缓存容量和换表频率选择，固定码表复用。尾部补零查表仅接受码长≤有效位数的项。低位端取位格式使用对应索引排列。

### 表项融合长度与距离解释

解码表项同时保存基值、码长、码长加附加位数的总消费量，以及字面量／次级表／结束标志。长度或距离命中后，保存旧位缓冲，一次消费全部位数，再从旧值提取附加位并加上表内基值。省去“解出符号→查基值表→查附加位数→再次更新位缓冲”的串行链。

把字面量放在易测试的标志位，把次级表和结束项归入同一异常标志，常见路径只检查一次类型。字段位置围绕移位、位提取和测试指令安排，而不是机械照搬符号结构；快速循环的 refill 预算覆盖表项的总消费量。

### 单表项预解双符号

构建 K 位 Huffman 表时，对首符号是字面量的表项，检查索引在首码之后剩余的位数。若这些位已包含第二个完整码字，就把第二符号及其码长放进表项空闲高位。

运行时一次查表同时取得两个连续符号，第二符号不再依赖“消费首码→生成新索引→再次加载”的串行链。表项数量和前瞻位数不变；只有能容纳第二码的条目带双符号结果，其余仍返回一个符号。短码占比高、同表处理大量数据时，建表阶段的额外解析能换掉大量运行时查表。

## 幅值与批编码

幅值先扩宽取绝对值，非零类别为 `word_bits-CLZ(a)`，零类别为 0。负数附加位为幅值反码的格式用 `(c-(c<0))&((1<<nbits)-1)`；零无附加位。

预存码字与长度，批内码长前缀和决定拼接位置；跨目标字宽拆分，再转义。批内共享位缓冲、游标、预测器及码表，批末一起提交。容量按批内最大码长＋附加位＋已有缓冲＋结束标记并计入转义膨胀；入口预留成功后省逐符号容量判断，否则缩批。批止于重置/换表/提交点，可重试批从原状态重算。

## 位缓冲与独立流

无符号寄存器保存有效位，移位小于字宽；宽装载受可读字节数限制，padding 不增加有效位。JPEG 熵数据 0xFF 后填 0x00，refill 分开处理填充、标记与尾部；restart 恢复规定预测器和熵状态。并行解码采用独立流或起点、码表、状态明确的重启段。

### 位缓冲计数的置位更新

64 位位缓冲将可消费位数上限定为 63。以旧计数 b 为基准，宽装载并合入缓冲后，输入地址前进 `7-((b>>3)&7)` 字节，计数更新为 `b|56`。上限的二进制全一形态把“剩余容量减法、字节对齐、加回计数”化成一次 OR；地址先加 7、再减位域，还能缩短地址更新依赖链。

若只要求计数低字节有效，且解码表项低字节就是消费位数，可直接从计数减整个表项，省去先取低字节的指令。比较按低字节、移位按有效移位位数解释。此表示用于有整字读取余量的快速循环；装入但未计数的前瞻位留给预解，不能提前消费。
