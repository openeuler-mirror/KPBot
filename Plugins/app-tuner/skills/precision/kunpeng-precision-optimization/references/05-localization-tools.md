# 定位手法：把「哪一项」找出来

原则：从最便宜的手段开始，每一步都要能给出「排除了什么」的证据。

## G-1 选项逐项加回法（首选）

前提：两平台**不加任何优化选项**时结果一致。若存在库差异，先用同一开源数学库屏蔽。

步骤：
1. 两侧清空全部可选项，确认一致（建立「零选项基线」）。
2. 按顺序逐个加回选项，每加一个跑一次。
3. **第一次出现差异的那一项就是嫌疑项**。
4. 屏蔽该项（或找它的精度等价替代），继续加剩余选项，确认没有第二个源。

成本优化：选项多时用二分——加一半看是否出现差异，逐步缩小到单项。

实例（WRF 3.4.1 形态）：零选项一致 → 加 `-w` 仍一致 → 加 `-ftz` 出现差异 → 锁定 FTZ 语义。

## G-2 未初始化内存对齐

- 现象：同一代码两平台结果不同，但所有显式数值路径都相同。
- 判据：加 `-finit-zero` / `-finit-array`（x86：`-init=zero -init=arrays`）后差异消失 ⇒ 原差异来自未初始化内存，不是数值实现。
- 处置：要么统一初始化选项，要么修代码把变量显式初始化（后者更根本）。

## G-3 插桩定位（最贵，最后用）

原理：假定两平台函数**输入一致**，若函数内部计算不产生差异，则输出必一致；输出不一致 ⇒ 差异在该函数内部。

步骤：
1. 定主计算路径，把路径上所有函数列为候选。
2. 在对照侧调用前插桩，把**输入参数写入文件**（如 `CALL write_args(grid, ids, ide, jds, jde, ips, ipe, jps, jpe)`）。
3. 把参数文件搬到目标侧，在相同位置插桩读入同一组输入（`CALL read_args(...)`）。
4. 两侧调用后打印输出的**摘要**（MD5 最实用：大数组直接比数值不直观，摘要可判等）。
5. 下钻：摘要不一致的最内层函数就是差异点。

纪律：
- 摘要算法、字节序、打印格式两侧必须一致，否则比的是格式不是数值。
- 只对「可疑路径」插桩，全量插桩会让程序慢到跑不完。

## G-4 数学库接口扫描

- 手段：随库提供的接口扫描脚本（如 `math-filter.sh <binary>`），在二进制目录执行，列出程序实际引用的数学库符号。
- 判据：差异落在「目标库未覆盖的接口」上 ⇒ 不是选项能解决的，别在编译选项上兜圈。
- 处置：向库方补接口 / 换等价实现 / 改写算法。

## G-5 接口一致清单的用法

库方通常提供一份「与对侧库精度一致」的函数清单（基础数学、复数、以及带后缀的变体）。
用法：扫描结果命中清单内 → 判定「库层已对齐」，进下一层；命中清单外 → 进入 L1/L3 排查。
不要凭记忆背诵清单，以随库发布的版本为准（版本间会变）。

## G-6 定位顺序总表

| 序 | 手段 | 成本 | 能排除 |
|---|---|---|---|
| 1 | 选项逐项加回 | 低 | L2 编译器层 |
| 2 | 未初始化对齐 | 低 | 伪差异 |
| 3 | 接口扫描 | 中 | L3 库层 |
| 4 | 插桩 | 高 | 函数内具体语句 |

## 反模式

- 一上来就插桩：通常花两天找到一个「其实改个选项就好」的问题。
- 插桩时两侧打印格式不同，把格式差异当成数值差异。
- 用未对齐版本的接口清单下结论。
