# 复用多级聚合中的计算

追踪一批输入进入多个汇总层级的过程，找到重复算金额、重复计算分组哈希、重复定位分组和更新聚合值的位置。按热点选择需要优化的步骤。

## 输入

| 输入 | 核对内容 |
| --- | --- |
| SQL 与物理计划 | ROLLUP 或 GROUPING SETS、分组字段顺序、分组标识、局部和最终聚合 |
| 聚合表达式 | 参数类型、确定性、NULL、过滤和错误语义 |
| 批次与分组 | 批次标识、列向量及字典映射、活跃行、哈希种子及合并规则 |
| 定点聚合 | 输入与累加器宽度、状态布局、精度、尺度及溢出行为 |
| 现有证据 | 原版执行路径、分组或表达式计数、候选开关和完整查询样本 |

## 执行步骤

### 1. 确认每个层级实际执行了什么

从查询入口追到展开、表达式计算、哈希分组和聚合更新。记录每个处置阶段的输入和输出，以及不同层级是否引用同一批输入。以 Velox 为例，可从 Expand、FilterProject、HashAggregation、GroupingSet、HashTable 追到定点 SUM 的更新入口。

```text
原版每层  展开分组字段 → 计算金额 → 算分组哈希 → 定位 → 更新该层小计
候选可共享  基于同批输入的金额、已核对的哈希前缀、整批同组时的定位
```

同一笔 (2 × 10) 得出的 20 元可以分别计入可乐小计、饮料小计和总计。复用计算以后仍应在三个层级各更新一次。

### 2. 确定表达式缓存的身份和有效期

选择引擎可安全复用的确定性表达式。候选需要相同的表达式、参数值、相关类型和行映射。若存在条件执行、异常或延迟加载，确认每个层级原本会计算哪些行以及错误应在何时出现。

从同一批次的对应行消费已有金额。固定缓存的生命周期和所属执行实例。新批次、行选择或字典映射变化时，重新验证或使该部分缓存失效。相同向量对象可能共享底层存储，仍需确认值的视图和选行规则。

### 3. 找到可以续算的分组前缀

列出每个层级的真实哈希输入顺序、种子、NULL 混合规则和分组标识放在哪一步。保存公共边界的中间值，后续层级在确认前缀列和行映射一致后，从该边界继续处理剩余字段和分组标识。

```text
可乐层  公共前缀「饮料」 → 处理「可乐」及本层分组标识
饮料层  公共前缀「饮料」 → 处理饮料层分组标识
```

先逐行对照完整哈希与续算哈希。哈希相同只能用来找候选，是否同组仍按引擎的键相等规则判断。真实 NULL 与汇总层补出的 NULL 可能投影相同，分组标识继续区分它们。

区分 SQL `GROUPING`/`GROUPING_ID` 的位掩码和计划中分组集实例的身份；位掩码只说明哪些字段被汇总，不能唯一识别重复实例。对 `GROUP BY ALL GROUPING SETS ((a), (a))`，一笔金额 10 的输入必须产生两行金额 10，不能合成一行金额 20。保留计划中的实例标识，或证明原有独立累加与重复输出机制仍完整保留；金额和哈希计算可以复用，不等于可合并累加状态。

### 4. 验证整批同组后复用定位

只在能证明活跃行属于同一完整分组且同一分组集实例时共享位置。核对键、分组掩码、实例身份、NULL、表的当前状态和分区。若引擎已经折叠实例，保留其原有重复输出机制，不能重复累加金额。缓存引用按表生命周期失效。

定位一次后继续按原规则遍历聚合输入。过滤掩码、DISTINCT、逐行值、空值及溢出仍由原聚合语义处理。组状态不再可共享时回到正常定位。

### 5. 缩短可证明安全的定点累加

先读累加器和合并状态的实际布局。写清有符号输入范围、当前和的范围、溢出如何记录以及最终输出尺度。证明快路径更新与常规路径的数值和状态都一致，再就地更新；适用条件不成立或状态不明确时走原逻辑。

Q67 记录的候选用「64 位输入、128 位累加器的高 64 位全零或全一」筛选一类安全状态。迁移时需重新证明目标实现的有符号算术、状态布局和最终精度规则。

### 6. 建立正确性矩阵

| 场景 | 核对内容 |
| --- | --- |
| 跨层重复计算 | 金额及每个层级的更新次数正确，实际计算次数下降 |
| 前缀相同和前缀不同 | 续算哈希等同完整计算，不适用时回退 |
| 一列空值、多列空值、展开补 NULL | 保持原分组标识和结果行重数 |
| 同组和混合组、字典重排、选行变化 | 定位、缓存命中和失效行为正确 |
| 正负交替、空输入、累加边界及部分聚合合并 | 定点值、状态和最终错误行为一致 |

对 Q67 的 `SUM(COALESCE(price * quantity, 0))`，任一乘数为 NULL 的输入行贡献 0。若过滤后整张输入为空，ROLLUP 的空分组集仍输出一行总计，SUM 值为 NULL，明细和非空分组集不产生行。跨批次复用时，空批次不能提前生成总计；应在全部输入处理完成后核对这条输出。

验证应从正常 SQL 入口触发。精确比较各个层级的分组键和金额。

### 7. 记录工作量与完整查询收益

分别记录表达式执行、哈希字段混合、表定位和聚合更新次数，以及临时缓存分配。用工作量解释该段减少了什么。对端到端时间使用固定数据、资源和计时口径的配对样本。缓存占用的空间与内存净变化分别记录。

## 输出

- 物理调用顺序、重复工作所在阶段、改动的模块和启用条件。
- 表达式缓存身份、哈希可复用前缀、同组证明及失效和回退方式。
- 分组及定点正确性矩阵、命中计数、缓存用量和完整查询对照。
- 逐项收益能支持到哪一层，并列出仍需验证的边界。

```text
模式 | 分组层级 | 金额计算次数 | 哈希/定位次数 | SUM 回退次数 | 缓存大小 | 查询耗时
```

## 约束

- 保持分组层级、分组掩码、分组集实例身份、重复输出，以及真实 NULL 与合成 NULL 的语义。
- 缓存必须关联正确的输入批次、行映射和执行状态。跨批次或跨线程的复用需要额外证明。
- 哈希前缀复用必须得到与完整计算相同的哈希；分组相等仍由键比较确认。
- 定点快路径保留运算精度、空聚合和溢出行为。候选失败时能够回到已有路径。
- 分开报告表达式、哈希、定位和累加的工作量。完整候选的累计时间按实测明示。

## 实施与验收细节

按金额、前缀、定位、SUM 四项分别实施和消融，读取[复用与定点契约](references/implementation-validation.md)。合成用例覆盖金额、前缀和简化整数模型；同组定位、真实累加器状态和合并仍须引擎验证。

## 本地用例

在 `cases/rollup-contract/` 中执行 `python3 run.py`。用例检查批内金额复用、哈希续算、NULL 与分组层级、有符号累加，以及同一可变向量跨批次、版本、选行和字典映射变化时的缓存失效。重复分组集案例按多重集检查两行各 10 的结果，金额求值可复用为一次，累加状态仍按实例区分。结果写入用例目录的 `results/result.json`。模型评估规格在 `evals/evals.json`，Velox 源码位置及历史验证见 [Q67 案例](references/velox-q67.md)。
