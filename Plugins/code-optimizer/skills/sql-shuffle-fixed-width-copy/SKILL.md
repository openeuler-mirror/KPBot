# Shuffle 写端短串固定宽度拷贝

## 说明与范围

聚焦已取得有效字符串字节视图后的序列化搬运。宽度 W=16 且 16≤n≤32 时，头尾各复制 16 字节；20 字节的两次范围分别为 1–16 和 5–20。内联布局和读端构造不在此处改动。

## 输入

| 输入 | 核对内容 |
| --- | --- |
| 热点与入口 | native Shuffle writer 的字符串写入循环、原拷贝调用及长度直方图 |
| 地址与容量 | 源实际可读范围、目标可写容量、偏移、长度、整数宽度及别名 |
| 契约 | 序列化布局、有效字节、邻接数据、原路径重叠处理及错误行为 |
| 基线 | 代表性缓冲、每长度分支命中次数、写端局部及完整查询计时 |

## 实施步骤

### 1. 确认写入热点

从 Exchange 的实际序列化入口定位变长 memcpy。区分输入文件的 codec 与 Shuffle 写入，记录真实加载库及可优化长度比例。

### 2. 证明范围与算术

先检查 source_offset、target_offset、length 及两端容量，防止 offset+length 溢出。n≥16 才能使用末尾减 16 的公式；长度 13–15 走原分支或另有完整证明的短拷贝。

### 3. 实现头尾两次拷贝

对 16≤n≤32 写入 `[dst,dst+16)` 与 `[dst+n-16,dst+n)`。两次目标写入可能重叠，但对应相同源字节。n=16 完全重合也必须保持正确；n=32 恰好衔接。

### 4. 隔离源目标别名

目标内的头尾重叠不代表允许源目标任意重叠。若有别名，沿用原 memmove 语义或安全通用分支；不能仅因为两次固定写最终范围正确就忽略先写破坏后读。

### 5. 对照容量与邻区

迁移原 0–64 长度扫描及 88 组偏移/容量矩阵；覆盖容量恰好够用、源目标非零偏移和 13/15/16/17/20/31/32/33。核对有效字节、目标前后区、源不变及拒绝越界后无写入。

### 6. 记录实际命中和退化

按长度与别名分支统计命中，先跑目标原生边界/内存检查，再比较同样输入的写端耗时与查询耗时。16–32 字节比例过低时提交无收益结论。

## 约束与回退

- 源/目标地址与容量必须真实可访问；声明字符串长度和分配器通常有填充都不能代替证明。
- 固定拷贝保持原序列化布局和逐字节输出，别名不明、长度或容量不满足时回退。
- Python memoryview 有界行为只验证几何关系，不证明原生指令加载或指针安全。

## 交付与验收

交付范围推导、快路径/回退分支、逐字节对照及原生边界证据。记录 `长度分布 | 固定拷贝次数 | 别名回退 | 有效字节/邻区一致 | 写端耗时 | 查询秒数`。

实现与证据细节见 [实施参考](references/implementation.md)。

## 本地用例与验证边界

从 Skill 根目录运行 `python3 cases/fixed-copy-contract/run.py`，按 `cases/fixed-copy-contract/case.yaml` 校验结果。使用 `python3 -O cases/fixed-copy-contract/run.py` 或 `PYTHONOPTIMIZE=1` 重跑，结果应一致。用例通过普通布尔检查决定 `success` 和非零失败退出码。
