# DSH 首版验证记录

## 环境与边界

验证使用 DSH 0.2.2-rc.3、Node.js 24.18.0，以及独立 CANNBOT `deepseek-v4.1-flash` 会话。模型的单次输出在隔离配置中限制为网关允许的 4096 token；未修改主 DSH profile。模型验收工作目录、DSH_HOME、会话、候选和报告均隔离，凭据不写入提交内容。

本地机器为 x86_64 WSL2；本记录不证明 ARM/Kunpeng 性能收益。可复现目标和固定工具见 `tests/fixtures/dsh-optimizer/`。

## 离线与发布形态

- DSH 测试覆盖包移动/拆分、名称与路径冲突、只覆盖指令的两种加载一致性、安装所有权、重装和安全卸载、旧工具的同名 `dsh` 路径兼容，以及真实 DSH Registry/Filesystem 的独立容器加载与注销。
- C 夹具的 11 项正确性检查通过，故意错误实现被拒绝；固定比较执行器先检查正确性再做两组 ABBA，失败时仅保留命令证据，不生成成功测量结果。
- 旧 Claude Code/OpenCode 安装回归通过；shell 语法和差异空白检查通过。
- 实际 npm tarball 在独立消费项目安装后，按包 exports 导入原生 Provider，并在独立 DSH Registry 中加载技能；打包后的项目安装/卸载通过。发布文件不含私密运行目录、凭据或个人实验资料。

执行入口：

```bash
npm ci --ignore-scripts
npm run test:dsh
npm run test:install
npm pack --dry-run
```

未安装 DSH 或 GCC 的环境会明确跳过对应可选测试，不应把跳过描述为通过。

## 真实模型验收：已经验证的行为

入口加载与共享资源读取探针通过。普通异步子代理实际完成热点分析、实验执行检查、对抗审核、隔离候选实施和独立验证；模型生成了循环融合候选，基线与候选均通过固定夹具 11 项正确性检查。父源码、Git HEAD 和固定验收工具保持不变。

本次最终状态是 **blocked，未采纳候选**，原因与处理为：

- 模型生成的诊断 shell 包装脚本在 brace group 中执行 `exit`，导致基线构建后提前结束，未产生诊断测量。唯一 reservation 已消费，未重置或重跑预算。
- 后续候选实施/验证只作为组件覆盖，不冒充诊断支持证据。局部性能波动较大，噪声门控未过，收益及系统验收均为 inconclusive。
- 初版报告误把“验收命令成功执行”当作系统判据通过，与旧 status 形成矛盾；共享 CLI 拒绝放行。按原始证据另存新版报告后，CLI 校验成功并路由 ValidateExperiment，但预算已耗尽，未执行该路由。
- 原始失败记录及旧报告保留，候选未晋升、未集成、未提交，缺失的 perf/PMU 指标未编造。

根据这些观察，DSH 运行说明明确了“完整验收判据”与“命令退出成功”的区别；夹具增加固定配对执行器，避免临时 shell 控制流干扰工具接入验证。

## 尚未证明

本次证明了真实模型的加载、子代理分发、资源访问、候选编译/正确性与阻塞保护，**尚未证明一条完整成功收敛并采纳候选的端到端路径**，也未验证鲲鹏硬件专项、app-tuner、旧 workflow、批量驱动或图形界面外观。PR 不应将本记录表述为全部优化场景或系统性能验收通过。
