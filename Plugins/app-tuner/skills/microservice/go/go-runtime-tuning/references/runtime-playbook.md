# Go 运行时参数与容器适配

## 1. 并行度（GOMAXPROCS）

| 版本 | 行为 | 建议 |
|---|---|---|
| 旧版本 | 默认取宿主逻辑核数，不感知容器配额 | 显式设置或引入自动适配库 |
| 新版本 | 默认感知容器 CPU 配额 | 仍要打印确认实际取值 |

检查：

```bash
cat /sys/fs/cgroup/cpu.max            # quota period（cgroup v2）
cat /sys/fs/cgroup/cpuset.cpus.effective
nproc
grep -E 'nr_throttled|throttled_usec' /sys/fs/cgroup/cpu.stat
```

判定：

- 配额换算出的核数 < 实际并行度 → 并行度偏大。
- `nr_throttled` 持续增长 → 时间片被打断，需要下调并行度或提高配额。
- 并行度明显低于配额 → 算力未用满，需要上调。

## 2. GC 参数

| 参数 | 作用 | 代价 |
|---|---|---|
| GC 百分比 | 控制下一次 GC 的堆增长比例 | 越高越省 CPU，内存占用越高 |
| 内存上限（软限制） | 接近上限时自动收紧 GC | 设置过低会导致 GC 频繁 |
| 动态调节 | 按内存使用率在上下限之间调整 | 需要稳定的内存画像 |

建议组合：内存上限（预留 20%~30% 余量）+ 适度放宽 GC；不要关闭 GC。

## 3. 记录项

每轮记录：QPS、P50、P99、进程 CPU、RSS、GC 次数、GC 停顿、分配速率。四项指标（吞吐、延迟、CPU、内存）必须同时呈现，避免用内存换吞吐却不声明。

## 4. 判定路径

1. 先确认并行度与配额是否匹配（看 `nr_throttled`）。
2. 再看 GC 次数与堆大小，判断是"阈值太紧"还是"分配太多"。
3. 分配太多 → 移交组件专题；阈值太紧 → 调整 GC 参数。
4. 调整后必须有同口径对照，且保留回退配置。

## 5. 回退

| 动作 | 回退 |
|---|---|
| 并行度设置 | 移除环境变量或自动适配库 |
| GC 百分比 | 恢复原环境变量 |
| 内存上限 | 去掉或调高，观察 RSS |
| 动态调节 | 关闭并恢复原参数 |
