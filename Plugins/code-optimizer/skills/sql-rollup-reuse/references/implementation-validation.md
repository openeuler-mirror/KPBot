# ROLLUP 复用实施与验证

## 1. 金额缓存

在同一输入批次上计算确定性金额，把表达式身份、输入类型、批次代次、行选择/字典映射和相关执行配置绑定到缓存。记录哪些行已经计算；新增选行只补算未计算且原本需要计算的行。新批次、复用可变向量、表达式或映射变化时失效。不得因提前求值触发原条件分支不会发生的异常。

以每输入行的实际金额求值次数核对节省；各 ROLLUP 层级仍分别更新聚合。缓存保存数值和 NULL 状态，受执行实例拥有；报告空间与释放点。

跨调用保留缓存的测试使用同一个可变向量对象，分别改变内容版本、批次代次、选行和字典索引。不能仅以对象地址作为 key；缓存持有向量引用并绑定这些元数据。内容改变需由拥有方发布新版本或显式失效；没有可靠代次/不可变性证明时放弃跨批次缓存，不能假定它会自动发现内存变化。

## 2. 哈希前缀

固定字段顺序、种子、NULL 规则及 grouping id 的混入位置，缓存可续算的中间状态。不能把已经 finalize 的哈希当作前缀，除非算法明确支持。按相同键向量身份、行映射和批次范围判断复用；逐行与从头计算的完整哈希相等。

## 3. 同组定位

证明活跃行的全部分组键、NULL 语义、分组掩码及分组集实例身份相等后，只定位一次。SQL `GROUPING_ID` 位掩码不等于实例身份；同一分组键列表可在计划中出现多次。保留每个实例的独立聚合状态，或证明已有折叠状态加重复输出的机制不变。哈希值相等不足以证明同组。缓存表位置不得跨表代次、spill、rehash 或分区切换；状态变化按引擎保证刷新或回退。继续逐行处理聚合掩码、DISTINCT 和参数，不能把定位复用变成少累加。

例如 `GROUP BY ALL GROUPING SETS ((a), (a))`，输入 `(a=7, amount=10)` 应输出两行 `(7, 10)`；不能只按键和掩码共用累加状态，得到一行 `(7, 20)`。若原计划依靠输出复制保留重复实例，也不能先重复累加为 20 再复制。用结果多重集核对金额与重数，金额表达式仍可只求值一次。分组集重复语义可对照 [PostgreSQL SELECT 的 GROUP BY ALL/DISTINCT 说明](https://www.postgresql.org/docs/15/sql-select.html)，目标引擎还须核对实际计划及实现。

## 4. 定点 SUM

先固定输入为有符号 64 位、累加数值为有符号 128 位的候选范围。高字全零或全一表示当前数值位于 [-2^64, 2^64-1]，加一个有符号 64 位数不会溢出有符号 128 位；这只是数值范围证明。还须保持累计溢出标志、空组状态、精度/尺度以及 partial/final 合并契约。无符号输入、128 位 partial 值、已有异常状态均不由这个证明覆盖。

先检查 guard 和状态，再做无未定义行为的算术及更新。未通过时调用原检查路径；不能先写状态、检测失败后重复累加。最终 decimal 精度限制独立检查，128 位未溢出不等于 decimal 输出合法。

## 验证与消融

逐项记录金额求值、哈希字段混合、表定位、聚合更新、SUM 快路径/回退和缓存字节；分母明确为输入行、展开行还是非 NULL 更新。四项分别切换，再测联合候选，不将累计成绩分配给单项。

覆盖真实/合成 NULL、混组、选行重排、缓存失效、空组、全 NULL、正负交替、64/128 位边界、溢出状态和 partial/final 合并。结果按分组键、grouping id、金额及重数精确比较。无目标执行记录时标记 `awaiting_target_evidence`。
