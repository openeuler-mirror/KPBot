# LZ4 候选哈希与真实兼容矩阵

## 源码定位

`lz4/lz4` 的 `v1.9.4`：[`lib/lz4.c`](https://github.com/lz4/lz4/blob/v1.9.4/lib/lz4.c)，搜索 `LZ4_hashPosition` 及实际表类型分支。这是原 skill 检视时核对过的定位参考，不代表历史优化补丁已在该版本，也不替代目标工程锁定库。原 SQL67 合并跑分包含多个算子改动，不能为本项单独分配收益。

## 边界和真实匹配

读取 `n` 个字节参与哈希与发出 `m` 字节加载是两个问题。使用目标编译器反汇编核对 m，保证最后一次加载仍在输入边界内。记录 byU16/byU32 等表模式和架构分派；未覆盖分支保留原逻辑。

哈希索引相同仍需比较匹配字节，索引不同也不要求压缩流与原版相同。压缩格式和解码结果保持兼容；窗口、offset 和最小匹配长度校验由原编码器负责。

调用实际使用的 API 或 Frame 工具。Block API 与 Frame 格式的结果分别报告，不能用 CLI Frame 往返冒充裸 Block 或字典验证。每组保存固定输入、构建选项、随机种子、块数、输出长度及失败样本。双边 Sanitizer 失败先定位，未解决时状态不能标为通过。
