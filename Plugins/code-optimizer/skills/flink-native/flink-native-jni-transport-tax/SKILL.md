# 跨语言数据桥传输税诊断与消除

当混合引擎的优化在算子层收敛后差距仍未消除时，用本 skill 把嫌疑从"计算"转到
"搬运"。核心判断：**跨语言桥上的开销是四类可枚举的税，每类都有独立账单与消除
手法**；先定位税种，再逐税消除，最后行为冻结收口。

## When to use

满足以下任一条件时进入：

1. **残余差距**：算子/内核逻辑已对齐参照实现，端到端仍差数倍且不收敛；
2. **逐行开销异常**：每行过桥成本远超行数据本身的处理成本（放大镜下桥占比过高）；
3. **批形态异常**：桥上流动的是 1 行批或小批（固定开销占比接近 100%）；
4. **新增数据桥**：设计期需要避坑（四类税全部有设计期规避手法）。

不适用：无跨语言边界的纯 JVM/native 热点；单纯的网络传输带宽问题（若序列化后
字节数正常、耗时在网卡/网线，属网络采集技能范围）。

## Core findings

1. **税①实体化欠账（最隐蔽）。** 跨语言传引用结构（列式向量/对象图）时，若下游
   只拿到"指针族"而字节内容散在多个缓冲，任何一次真实消费都会触发全量 gather
   （通用 copy 语义：逐元素从各缓冲取货并物化成连续内存）。账单在**消费点**而非
   生产点爆发——生产端账单看着是零，实际是欠账。识别特征：数据结构"过桥零拷贝"
   但下游序列化/落盘时耗时爆炸。

2. **税②编码税。** 桥或 wire 格式引入非必要编码层（Base64 类）：字节量膨胀
   ~33% 之外，还引入编解码两端的整流循环与临时缓冲。识别特征：wire 字节数与
   原始数据量之比明显超过结构差异能解释的范围。

3. **税③拷贝链。** 跨语言边界前后出现多重中间形态（byte[] → String → 再编码
   → byte[] 一类的链），一条记录的拷贝次数逐环累计（实测案例：一条记录九次
   拷贝）。识别特征：profile 上边界方法内部出现多个临时分配与数组拷贝帧。

4. **税④小批固定开销。** 桥的每批固定成本（队列入队出队、批头构造、JNI 调用
   簿记）在 1 行批时占比接近 100%。批行数是**放大倍率的倒数**——攒批是最便宜的
   收益，但攒批参数有语义边界（延迟与内存上限），须扫参定缺省而非拍脑袋。

5. **四税独立可消除，消除顺序按账单。** 先账单后动手：单批 wire 字节数、单行
   摊薄拷贝次数、每批固定开销三张账决定先杀哪税。经验排序（自测案例）：税①
   常吃掉大头（单阶段消除约 87% 差距的案例存在），税③④次之，税②看格式选型。

6. **消除必须行为冻结护航。** wire 格式与批参数改动会触碰序列化契约与行序语义：
   每阶段消除后，changelog/输出与基线精确一致才允许计收益（多行、少行、字段
   不一致任一出现即回滚性能结论）。

## Methodology

1. **账单基线。** 取代表性一批（含正常批与最坏小批），数：批行数、原始数据
   字节数、桥上 wire 字节数、单行摊薄拷贝次数（从生产端到最终消费点全程）、
   每批固定开销（空批过桥成本）。产物：三张账单表。
2. **税种归因。** 对照四税特征逐项判：wire/原始比异常→税②嫌疑；消费点耗时
   爆炸而生产点零→税①嫌疑；边界方法内部多临时分配→税③；批行数中位数≈1→
   税④。产物：税种归属表（每税给"能解释多少差距"的估计）。
3. **逐税消除（每税独立门禁）。** 税①：消费点前显式实体化（把 gather 欠账变成
   生产点显式成本，按需拷贝——只拷被消费的列/行）；税②：wire 改字节流直传
   （去编码层，格式走紧凑二进制）；税③：砍中间形态（byte[] 直通，消除 String
   中转）；税④：攒批 + 扫参定缺省（延迟上限内取收益最大批行数，记录扫描矩阵）。
   产物：每税改动清单 + 单税复测账单。
4. **行为冻结核验。** 每税消除后跑 changelog 折叠对比（+I/-U/+U/-D 还原终态，
   精确一致）+ key 分组一致性。产物：每税一致性证据。
5. **分阶段收口。** 三指标（duration / wire bytes / RSS）逐阶段全表；残余差距
   给归属与后续清单。产物：终态对照表。

## 检查清单

- [ ] 桥上流动的是引用结构还是连续字节？消费点有没有隐式 gather？
- [ ] wire 格式是否含非必要编码层（Base64 类）？wire/原始比是否可解释？
- [ ] 从生产到消费点数过拷贝次数吗（含临时 String/byte[] 中转）？
- [ ] 批行数中位数是多少？固定开销占比算过吗？攒批缺省是扫参定的吗？
- [ ] 每次税改后的 changelog 一致性证据在吗？
