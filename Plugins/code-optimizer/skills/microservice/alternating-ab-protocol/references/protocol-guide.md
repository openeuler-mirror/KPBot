# 交替协议的设计原理与实测案例

## 为什么必须交替而非分组

共享机器存在**慢漂移**：温漂（CPU 降频）、邻居负载（其他进程周期性活跃）、
页缓存冷热——这些因素在分钟级时间尺度上系统性偏移。

分组执行（先跑完 A 全部轮次，再跑 B 全部轮次）时，后半段的 B 处于与
前半段 A 不同的环境状态——漂移伪装成优化效果。

交替执行（A→B→A→B...）让每对相邻轮共享同一环境窗口，漂移被比值序列
消去。

## 实测案例（protobuf 5-patch 系列验证）

在 .19（384 核 aarch64，taskset -c 288-295）上验证 5-patch 优化：

- 分组模式（先 base 后 opt）：+2.1%（被漂移失真的低估读数——后半段邻居负载升高，
  opt 阶段环境比 base 阶段更差，读数比真值低 5.3pp）
- 交替模式：+7.4%（真实值——N/N 同向，无单调漂移）
- **差值 5.3pp 完全来自环境漂移**

另一个方向：folly allocator 对照中 jemalloc 实测**耗时 +69.5%**
（性能约 -41%），5/5 轮同向——真负收益，与社区 "jemalloc 更快" 的直觉
相反（负载形态前提：小对象高频构造）。

## 三级健康度

| 级别 | 检查 | 为什么 |
|---|---|---|
| 跨轮离散度 CV ≤5% | base 各轮值之间的变异系数 | CV 大说明环境噪声已淹没信号，比值不可信（安静微基准典型 1~3%） |
| 逐轮比值无单调漂移 | opt[i]/base[i] 序列 | 持续单调上升/下降 = 环境在变（不是代码效果） |
| 方向一致性 N/N | 全部轮次同向（加快/变慢/无差异均可判） | 混向 = 噪声区 |

**方向一致性替代统计显著性**：在各轮独立同分布、且**预先指定**比较方向
（"opt 是否比 base 快"）的前提下，5 轮 5/5 同向的单尾概率为
(1/2)^5 = 0.03125（1/32）；若测完数据后才选择加快或变慢方向来"确认"，
应使用两尾概率 0.0625（1/16）。混向则无论绝对差多大都不可信。

## fail-closed 设计

任一侧命令异常退出、或输出无可解析的正时间值（含负值与非法表示法）时：
- 打印该侧原始输出尾部（诊断线索）
- 立即 exit 1
- **绝不把缺失测量当作 0ns 计入方向统计**（防止假 N/N 一致）

这与 "空结果不静默成功" 的社区纪律一致。
