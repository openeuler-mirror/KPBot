# BP 接入与验收记录

## 将分派写成可核对的表

按输出类型、压缩位宽和入口记录：原版函数、候选函数、构建条件、CPU 条件、物理输入字节、物理输出元素及失败状态。不能用“u32/u64 支持”代替具体位宽集合。零宽、满宽、不支持类型和候选关闭的路径单列。

原生函数的长度单位写在签名说明旁。对固定物理块内核，先验证完整压缩块可读且完整输出空间可写，再处理逻辑截断；损坏输入不得借“不适用”吞掉错误。若候选可能部分写入，返回协议必须与无写入回退区分。

## 分开记录四类证据

| 层次 | 验收证据 | 不能替代的检查 |
| --- | --- | --- |
| 布局与值 | 独立压缩字节参照、逐值比对、位置可辨输入 | 真实分派 |
| 内存与错误 | 尾块、容量、截断、哨兵或目标内存检查 | 吞吐率 |
| 命中 | 正常入口处的候选及回退计数、实际处理值数 | 汇编中存在向量指令 |
| 性能 | 同包装配对样本、完整解码与查询各自计时 | 上述正确性证据 |

审计模式下分别按类型和位宽记录入口、NEON、原版、错误和处理值数；明确错误是否与调用计数重叠。同一有效请求的工作量应一致。正式计时停用计数，保留算法分派条件。

导入的 `evals/evals.json` 是审查场景，不执行 ARM 解码。没有目标机器时，将内核正确性、内存检查、平台回退和性能分别标为待验证，不合并为“验证通过”。
