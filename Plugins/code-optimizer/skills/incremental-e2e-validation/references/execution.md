# 执行与续跑

## 1. 确定业务问题

先记录用户希望改善的业务指标。
为查询明确结果完全读取的时点。
为服务明确请求完成、错误率及测量窗口。
为批处理明确输入条数、处理完成和输出校验。
异步任务的提交耗时和实际完成耗时各有边界，采用用户指定的业务边界。

多个请求类型、数据规模或并发档位形成独立场景。
每个场景运行同一优化清单和适用的比较。
某项只支持部分输入时记录适用范围及回退路径。
总体业务汇总采用用户给定的权重和指标定义。

## 2. 清点优化点

每项记录名称、目标、改动位置、启停方式和已有证据。
补丁类记录父版本及补丁摘要。
运行配置类记录变量、取值及进程继承方式。
编译选项类记录实际编译命令与输出产物。
依赖关系应包含隐含依赖，例如共享布局、接口变更或公共预处理。

互斥项各自可以保留独立对照。
用户要求比较互斥路线时，各路线分别给出全组合行。
优化项存在多个实现版本时先固定本次版本。
候选修复后更新身份，重新验证受影响的配置。

## 3. 编排比较

先运行矩阵工具并检查每个配置的 active 与 reasons。
数组顺序代表叠加顺序。
某项依赖尚未出现时，该前缀配置带有缺依赖原因。
与用户给定顺序核对后再形成可执行路径。

比较序号在一个矩阵内稳定。
候选清单或顺序变更时生成新的矩阵与实验标识。
首项独立、增量及累计可引用同一比较。
最终累计与全部组合可引用同一比较。

将每对比较映射到正确性测试和性能采集任务。
估算时间时分别考虑切换、预热、验证、采样和恢复。
预算不足时先说明哪些格可能缺测，再执行已有授权内的任务。

## 4. 构造配置

推荐从已知原版构造每个单项及前缀组合。
可使用现有构建目录、隔离工作区或显式开关。
工作区中已有用户改动时保存其身份并避免覆盖。
补丁应用失败或冲突时保存错误并定位依赖。

编译成功后记录实际输出文件摘要。
运行前确认测试入口加载的是该产物。
动态库、插件或远程部署尤其需要确认实际加载位置。
运行时变量应随每次启动显式应用。
记录最终有效值，以识别默认配置或服务重启导致的丢失。

目标是让独立比较只改变当前项。
累计比较的差异应等于对应前缀集合。
若额外修复也进入候选，应更新候选定义和基线关系。

## 5. 验证正确性

执行用户指定的框架和完整命令。
记录用例集、数据、容差、退出码和日志。
各配置使用同一正确性判据。
组合可能改变路径与边界，因此组合也要验证。

如测试框架允许测试子集，沿用用户选定的子集。
记录覆盖范围，使后续读者知道结论适用范围。
失败时保留失败输入和对应产物身份。
性能数据可作为诊断附件，正式收益表标明正确性未通过。

命中审计检查启用候选、关闭候选以及不适用输入的行为。
检查全开配置中各项是否真实启用。
若一个优化导致另一个路径不再执行，记录这一交互。
该组合的实际业务收益仍有意义，但被绕过项的独立贡献需谨慎解释。

## 6. 采集一个比较块

按计划确定 AB、BA、ABBA 或 BAAB 的顺序。
A 表示本对照的控制配置，B 表示候选配置。
控制配置可能是原版，也可能是前序组合。

每次运行执行下列动作。

1. 核对环境条件和实际配置。
2. 按既定规则恢复输入、缓存与服务状态。
3. 执行同等预热。
4. 执行性能命令并等待完整业务结束。
5. 保存退出状态、实际工作量、主指标和原始日志。
6. 记录环境观测与影响本次采样的事件。

ABBA 中两次 A 和两次 B 按预声明规则形成块内双方代表值。
若框架直接输出块统计，保留框架的聚合定义。
正式汇总逐块计算相对变化。
不同对照之间复用块数据时保留共同来源，避免误称为独立重复。

## 7. 异常与复测

超时、非零退出、请求遗漏、环境偏离分别记录。
识别到后台任务未完成时，先确认终止或完成再启动下一项。
复测使用新的运行标识。
保留失败记录、排除原因和替代采样位置。
按预声明规则处理异常，避免根据收益大小决定保留样本。

仅一个比较受影响时补测该比较。
共享的配置产物发生变化时，重查所有引用该产物的比较。
原版或输入变更时重新建立实验条件。
当前预算耗尽时保存已完成结果和剩余矩阵。

## 8. 中断后恢复

恢复时先读取矩阵、已完成记录和最后有效配置。
检查目标机及产物是否仍与实验身份一致。
确认临时开关、进程、服务和数据是否处于预期状态。
从完整且有效的比较块之后继续。
中断的半个块保留为不完整记录。

跨时间窗口继续采样时重新核对原版表现。
若产生明显漂移，将新窗口作为新的采样批次。
不同批次分别报告或按事先约定的配对设计分析。

## 9. 收尾

汇总全部配置的正确性状态。
生成结果表并核对各引用。
补充工具无法自动确认的真实命中和日志结论。
恢复约定配置并检查服务或业务入口。
记录当前有效优化集合及仍需用户决策的事项。
