# 生成器中的语义分支应落在生成期 — 方法细节

> 来源与适用范围：本文整理自原始工程实践记录（`SKILLS_ALL.md` 汇编稿），未提供可公开引用的上游文档，也未经独立复现。文中阈值、收益倍数与机器相关数据绑定当时的生成器版本、硬件与配置，迁移到其他环境前必须重新测量。置信度：中；未覆盖范围与平台差异见正文。

## 适用背景

目标场景是配置驱动的代码生成器：调用方给出形状与一组配置项，生成器发出汇编与 C++，编译成动态库后由运行时调用。生成的时机与分析的对象之间因此存在一条分界：一部分量在生成期就已知，例如分块尺寸、展开因子、精度、布局、是否累加；另一部分量只有在调用时才拿到，例如缩放系数与累加系数这类标量。

本文讨论的问题是，当某个语义分支取决于后者时，这段判断应当出现在生成物里，还是应当由生成器在生成期分成两套代码。

## 1. 语义与指令序列的分离

BLAS 的接口约定规定，累加系数为零时输出缓冲区不被引用。这条约定属于语义层，而指令序列并不会因为系数为零自动跳过读取。若生成器不感知这条约定，仍照常发出“读取原输出、乘累加系数、加上乘加结果、写回”的序列，那么系数为零时它仍在计算“零乘以原输出”。

按 IEEE 754，零乘以 NaN 仍得 NaN，零乘以无穷仍得 NaN。浮点乘加指令不会因为一个操作数为零而对另一个操作数做检查。因此，当调用方提供的是未初始化的输出缓冲区，且其中恰好含有 NaN 位型时，这部分污染会沿累加链扩散到整块输出。

这类缺陷有三个共同特征：进程不崩溃、不报错；结果取决于调用方缓冲区的历史状态；同一命令重复执行的结果不一致。三个特征叠加，使它很难通过复现来定位，也很容易被误判为并发缺陷或工具链缺陷。

## 2. 分支层次的判断

判断一段语义分支该放在哪一层，依据三条。

第一条看该量在生成期是否已知。若累加系数是生成期的常量，直接在生成期选择序列即可，生成物中不含任何判断。

第二条看判断发生的频度。若判断位于每个输出元素上，代价可以接受；若位于每个展开步上，代价按乘加次数放大，还会打断展开与软件流水。把逐元素的条件放进 K 方向的循环，是这类改动最常见的错误。

第三条看能否由入口自然区分。若纯运算与累加本就是两种使用方式，最干净的做法是提供两个入口，每个入口生成各自的序列，调用方按需选择。

按这三条，运行期标量控制的语义分支应当落在入口划分上，而不是落在生成物的循环里。这条结论的理由不止于性能：分支一旦进入生成物，生成器就必须假设运行期的一切组合都可能出现，而它原本可以把这类不确定性在生成期消掉。生成器的职责正是把决策提前，把判断从运行期搬到生成期属于它的本分。

## 3. 去掉读取之后的初始化责任

不读取原输出，并不等于累加器已经为零。

ZA 累加器是硬件状态，其内容不保证在入口处为零，也不保证在两次调用之间被清零。生成器去掉“读取原输出并乘系数”这段序列之后，若没有显式清零累加器，结果就是未初始化的寄存器内容参与运算。

这会导致一个容易被忽略的转折：缺陷的表现形式从确定变为另一种确定。原先是在输出中看到 NaN，容易识别；改动之后是在输出中看到数量级异常的大数，且可能只在优化版本中出现，因为调试构建可能恰好把相关寄存器置零。因此在同一处改动中，清零责任必须与去掉读取同时落实。

实现上两种写法都可以：在序列起始处显式清零累加器；或让第一次乘加采用初始化形式而非累加形式。前者更直观，后者少一条指令。

## 4. 生成侧开关的表达

生成器内部表达这类分支时，宜采用生成期的布尔量，由它决定发出哪一套序列，而不是把运行期标量作为开关。

三条约束需要同时满足。

开关不得改变既有默认行为的产物。默认值不写入序列化配置，否则未启用新形态的配置会得到不同的内核标识，历史记录随之失去可比性。

开关必须与入口绑定。若某入口声明为纯运算，而生成出的序列仍含读取原输出的指令，说明开关与入口的对应关系没有建立，这种不一致应当在生成期暴露，而不是留到数值出错时才发现。

不支持的组合应当直接报错。生成器在接受无法生成的配置时报错并指出冲突项，比静默降级到另一条序列安全，因为后者产生的产物与配置声明不符。

## 5. 验证分支确实生效

判断一条测试是否合格，有一个简单标准：把被测分支的保证去掉，这条测试是否会失败。会失败，说明它测到了那件事；不会失败，说明它测的是别的。

按此标准，验证纯运算入口不读原输出，应当把输出缓冲区预先填成 NaN，然后断言结果等于乘加结果且不含 NaN。这里必须用 NaN 而不能用零：零乘以零不产生可观测差异，用零填充等于关闭检测。

同一套用例不能原样用于累加入口。累加系数非零时原输出本就参与结果，NaN 传播属预期行为，此时断言“不含 NaN”会得到假通过。两个入口需要各自独立的用例。

缩放系数为零属于同一类情形。零乘以输入中出现的 NaN 或无穷，同样会把异常值带入结果，判据与累加系数为零完全一致，修复时不应只覆盖一半。

此外还有两类相邻但不同的检测，容易与上述混淆。检测越界读取，应当在输入的行尾填可识别的有限值并按带填充的步长分配，使填充区真实存在；检测越界写入，应当在输出缓冲区的有效范围之外放置围栏值并在调用后检查其未被改写。这三类检测分别对应读取依赖、读越界、写越界，不能互相替代。只填充输入一侧时需注意，另一侧若恰为零，越界读带来的影响会被乘积抵消，测试仍会通过。

## 6. 约束

实现范围是 FP32、NT 布局、单线程、流式向量长度为 512 位。以下情形未经验证：多线程下各工作区累加器的清零责任划分；双精度；其他布局；非 512 位的流式向量长度。

上述范围之外，清零责任与开关绑定关系需要单独确认，不能直接沿用本文的结论。
