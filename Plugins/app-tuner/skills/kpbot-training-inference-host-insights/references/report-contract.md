# 报告内容与验收约定

## 正文结构

默认标题：《训推社区 Host 洞察：推理框架、缓存存储与 DeepSeek / GLM / Kimi Agent 生态》。续接既有系列时可保留旧标题，文件名与目录保持归档连续性。

1. 生成日期、正式覆盖起止、检索时间、时区与信息截止。
2. 目录和执行摘要：0–5 项有证据的发现、部署/研发重点、最关键限制。
3. 范围/方法：六社区来源覆盖、页数/时间边界、标签解释和缺口。
4. 项目动态表：时间、项目/版本/PR、状态、变化、条件、影响与直接链接。
5. 厂商贡献表：NVIDIA/Intel/AMD，作者/组织证据、状态、影响、链接；待验证归属不硬分类。
6. 模型支持矩阵：GLM/DeepSeek/Kimi × 实际检查的框架/后端；区分新模型、已有模型新组合、量化/并行/长上下文/MoE/推测解码/工具调用修复。
7. Mooncake/3FS专题：组件与集成关系、Host/存储/网络机制、容量/性能/一致性/恢复边界。
8. 三家模型与Agent专题：三家×五类检查结果、事件表及跨层影响；无增量/缺口可用紧凑矩阵，避免15段重复套话。
9. 优化部署方案：机制、场景、软硬件前提、步骤、预期收益、原始基准条件、风险、限制和回退。
10. Host/CPU机会优先级表：类型、价值、复杂度、依赖、风险、最小实验和验收指标。
11. 未决问题、结论与按项目分组参考资料。

章节可合并以改善阅读，但完整周期任务的检查范围不能省略。无可推荐机会时在第 9、10 项说明原因即可。无更新时缩短分析，保留覆盖与无增量证据。

## 标签与证据层次

- **事实**：一手来源支持；“作者报告X”可为事实，X本身不因此成为独立验证结果。
- **经验**：工程实践判断，解释与本次事件的关系。
- **假设**：推演机会，明确依赖与可证伪实验。
- **待验证**：证据不足或冲突，不通过措辞掩盖。

将源码已合入、release可用、作者跑通、独立复现、生产部署分别写清。时间无时区/时分时不补造。关键代码引用尽量固定SHA或具体PR，不只链接浮动主页。

## Markdown与HTML

报告YAML建议含 title、type、status、created、generated_at、coverage_start/end、retrieved_from/to、timezone、tags、关联HTML/证据文件。按当前项目规范调整。

HTML为UTF-8单文件；样式内嵌，无外部JavaScript、字体/CDN依赖。要求：

- 目录锚点、清楚层级、显著日期/覆盖窗。
- 桌面/手机可读；宽表容器内部滚动，长URL换行。
- 用 `prefers-color-scheme` 适配浅/深色。
- 外链 `target="_blank" rel="noopener noreferrer"`；引用紧邻事实，不只放文末。
- 正文内容、数字、状态、链接、限制与Markdown一致；不在HTML单独修事实。

可使用可用的Markdown渲染库；不要求特定工具或为单次任务另建复杂框架。若编写复用脚本，则实际运行并验证它。

## 交付检查

检查YAML可解析、文件存在、stem冲突避让、MD/HTML关键事实一致；目录与外链属性有效；索引链接解析；历史文件保留；没有模板占位符、未核的官方采用结论或无条件倍数。

在真实浏览器查看桌面与约390px窄屏、浅深色、正文表格；检查页面横向溢出、裁切和对比度。只做静态检查时说明限制，不宣称已渲染。

最终回复简洁列出产物绝对路径、覆盖窗、主要检索来源、0–5 项有证据的发现、有依据时列最高优先级 Host 机会，否则写“本期暂无可推荐的 Host 机会”、Mooncake/3FS与三家模型生态重要变化及缺口。不要把待验证基准称为实测，也不让用户从进度消息拼凑结果。
