# L7 检索配方层

## 三个可调点

1. **候选倍数**（本例 `2×limit`）与返回字段：先量化"每行字节 × 候选行数"再决定砍哪一项；
   砍候选数会改变 recall，必须跑结果指纹对拍。
2. **多路召回**（全文 + 向量）本来就并发：测拆分时取**区间并集**，串行化会平白多一倍时间。
3. **rerank**：确认它是否真的被调用、命中缓存比例多少；未命中时会成为新的长尾。

## 纪律

- 配方改动属于"改语义边界"，必须与正确性门禁一起跑（见 `agent-memory-bench-gate`）；
- 先量化再改：`每行字节 × 候选行数 × 查询数` 是理论上限，对照实测占比判断值不值得做；
- 与 L1 载荷瘦身叠加时，注意两者都在减字节，收益会重叠，不要线性相加。

## 输出

- 配方变更前后的结果指纹与 recall 对比
- 单次查询的字节数变化与耗时变化
