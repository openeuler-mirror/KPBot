# Proxy 采集能力检查

## 操作流程

1. 核对用户指定的节点、容器、源码路径与实际运行入口。路径、挂载或启动配置无法确认时，列出缺项；仓库中有采集模块不能证明当前实例已加载它。
2. 从实际入口检查是否接通 worker 启停、请求读取、响应跟踪和异常收尾。普通转发与 P/D 分离分别核对；只有用户需要 golden 或日志关联时，再单独判断对应钩子与后端能力。
3. 已识别本技能的控制器且知道配置路径时，可在同一容器或 PID 命名空间使用 proxy 的 Python 解释器查询状态：

```bash
$PY "$S/scripts/capturectl.py" --config "$CFG" status --json
```

`$S` 为安装后的父 skill 目录，`$CFG` 为容器内配置绝对路径。核对 worker 数、配置版本和有效开关。没有 worker 回报或返回码为 4 时，说明状态未确认；有效开关关闭仍可表示已接入。其他兼容实现使用其已知的只读状态接口。

## 输出

给出“已支持”“未接入或接入不完整”或“无法确认”，引用实际入口、钩子位置和状态证据，另列采集开关与未验证能力。无法读取指定运行环境时，不把源码检查结果当作运行验证。检查不发送测试请求，不改配置、不重启，也不自动开启采集。
