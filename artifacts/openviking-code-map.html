01 / 总体结构

调用与公共层后端与服务配置与环境

入口与OpenViking服务分属不同进程；公共层和适配器在同一个CLI进程内。窄屏可以横向查看，点击模块可跳转文件索引。

recall：跨项目查找相关记忆

  1. KPBot提供线索

    query与features表达当前问题，project_ids指定希望查询的项目。

  2. 公共层核定范围

    从可信user_id与允许项目生成sources；拒绝伪造身份和include_shared=true。

  3. 原生查询

    适配器固定拼接query/features，每个项目调用find，target_uri覆盖所选kind目录。

  4. 合并并补读

    按原生score去重排序，download完整资源，验证URI、摘要、owner、项目、kind与private。

  5. 返回结果

    items标为original，最多limit条；部分补读失败报告partial，全失败报告READ_FAILED。

03 / 保存与检索的数据流

保存：内容从KPBot进入后端

{
  "kind": "experience",
  "project_id": "project-a",
  "task_id": "task-101",
  "content": {
    "summary": "示例经验：减少循环中的重复搬移",
    "evidence": [
      "由KPBot提供的完整证据"
    ]
  }
}
  1. 公共层

    检查项目与用户，补入owner_id和private。content保持原值。

  2. 适配器

    生成唯一source_id，封装record和SHA256摘要。审核经验与任务过程使用同一保存机制。

  3. OpenViking

    content/write创建resource，执行本地向量索引；download确认原文字节一致。

remember的ok=true表示完整输入已经保存；processing再说明索引/处理是否ready、pending、failed或unknown。

04 / 数据存在哪里，边界在哪里

逻辑资源位置

viking://user/{provider_user}/resources/kpbot/
  {sha256(KPBot owner_id)}/
    {sha256(project_id)}/
      experience/{uuid}.json
      task_process/{uuid}.json

记录包包含schema_version、source_id、record、record_sha256。project_id、owner_id、task_id及原content一同保存在OpenViking中。

每次提交使用新UUID，重启后直接从后端恢复定位和原文。

本机运行环境

.runtime/openviking/
  venv/                 uv创建的Python环境
  models/               已校验的本地BGE模型
  data/                 OpenViking管理的数据与索引
  ov.conf               私有服务配置
  config-user-*.json     私有业务配置
  credentials/          管理与普通用户凭证

上述配置目录与文件受权限保护，运行数据、凭证及模型均被Git忽略；本页不包含任何凭证值。

KPBot私有项目范围由公共层确定；普通USER key对应OpenViking用户。ROOT/ADMIN只用于部署管理。

适配器负责封装与核验，OpenViking负责持久化。当前embedding输入窗口有限，长过程原文完整保存不等于全篇检索质量已经证明。

06 / 当前实现与验证范围

  • 两类输入完整、可逆保存
  • 同用户多项目检索与kind筛选
  • 普通后端用户认证及私有范围核验
  • 补读、哈希检查、partial与错误返回
  • 整次调用时限、取消与WRITE_UNKNOWN
  • 客户端关闭、资源保留和重启检索
当前部署：vectors_only、本地中文BGE、vlm={}。未启用VLM提炼、自动完整过程采集、跨用户共享；北向未增加get/list/delete。读取与列目录只在适配器内部按需调用。

当前测试套件覆盖 backend CLI、公共层契约、OpenViking 适配器与可选真实服务验证，提交前全部通过；此前另验证过服务进程重启后的检索。真实服务测试代码中的restart用例是客户端重建，服务进程重启是另行执行的检查。本页生成过程没有重新运行测试，也不表示服务实时健康或优化收益。

插件的记忆入口只有 OpenViking：backend 命名空间每次调用创建并释放一个客户端。现有开发说明未被修改，本页用于查看实现结构。
