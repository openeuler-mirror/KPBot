# Kitex 框架热路径静态分析

本 skill 只做**只读分析**：给出请求链路的成本地图和候选改造清单。真正的代码改造由 `code-optimizer` 承接，且必须先有可编译 POC 与单变量验证。

## 何时触发

- 配置层（传输、连接、GC、协议）已调过，收益见顶。
- 证据显示结构性开销（锁、分配、派发）无法通过参数消除。
- 需要判断"改框架是否值得"，或评估上游版本已修复了哪些点。

## 范围

- 覆盖：框架链路的成本地图、结构性瓶颈识别、改造候选与优先级。
- 不覆盖：代码修改、补丁、收益验收。

## 出处

- 链路结构：目标版本的传输、派发、编解码与连接池实现；netpoll 的事件循环实现。
- 结论必须标注对应版本，不引用其他环境的数据。

## 命中验证与越界验证

- 命中：问"配置都调过了还能怎么快"，应答候选改造清单与验证方案，而不是补丁。
- 越界：问"帮我把连接池改成无锁"，应答本 skill 只输出候选，落地交 `code-optimizer`。

## 分析步骤

1. **画链路**：从连接建立到响应写回，逐段列出：事件循环 → 派发 → 解码 → 业务 → 编码 → 写回 → 回收。
2. **标成本**：每段标注成本类型（系统调用 / 调度 / 锁 / 分配 / 拷贝）与证据来源（本轮 profile，不引用外部数字）。
3. **找结构点**：识别无法通过参数消除的结构，例如全局锁、共享计数器、每请求必经的构造与拷贝。
4. **对照上游**：确认该结构在新版本是否已改；已改的优先升级而不是自己改。
5. **排序候选**：按"影响面 × 改造成本 × 风险"排序，标注是否需要改协议或语义。
6. **给验证方案**：每个候选取一组证据、验证指标与回退方式。

## 候选改造方向（未验证，仅作分析假设）

| 方向 | 结构性原因 | 风险 |
|---|---|---|
| 连接池分片化 | 独占连接池用单一锁保护空闲列表，高并发下所有请求争用同一临界区 | 连接生命周期与回收语义变化 |
| 负载均衡选择器无锁化 | 每次选择都要读锁保护的可变结构 | 权重更新与一致性 |
| 元信息解析池化 | 每请求构造键值容器并拷贝字符串 | 生命周期与复用安全 |
| 请求派发快路径 | 每请求经过派发池与埋点包装 | 与 trace 上下文传递冲突 |

> 以上方向来自源码静态分析与公开资料，**尚未在本轮环境验证**。落地前必须先在 `code-optimizer` 侧做 POC，并单独一轮 A/B。

## 输出

```text
链路成本地图（段 → 成本类型 → 证据来源）
结构点清单（位置 → 为什么参数无法消除 → 是否上游已修）
候选改造（编号 → 机制 → 预期 → 风险 → 回退 → 验证指标）
优先级与建议（先升级 / 先改哪一段 / 不建议改）
```

## 与相邻技能的边界

- 不改代码、不产出补丁、不给具体实现代码。
- 不把未验证的候选写成"推荐动作"，只能标"候选假设"。
- 不替代 `kitex-profiling`（证据）与 `microservice-ab-testing`（验证）。
- 与上游版本相关的结论必须注明版本；不引用其他环境或他人的性能数字。
- 本 skill 可独立调用，不依赖 `WORKFLOW.md` 的中间产物。
