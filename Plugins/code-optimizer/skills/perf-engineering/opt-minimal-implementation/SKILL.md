# 最小改动实现（阶段 4）

## 何时使用

- 候选已定，要开始改代码 / 重建镜像。
- 改动了 schema、协议、数据布局，需要同步所有读写路径。
- 镜像打包后启动崩溃、或性能差异无法干净归因。

## 核心原则

1. **最小改动 = 最小变量面。** 只动和优化目标直接相关的路径，不碰任何无关行为路径。改得越少，能归因的变量越少。
2. **语义等价性要逐条书面论证**，不能靠"看起来一样"。
3. **改了 A 侧数据接口，B 侧所有写入路径必须同步对齐**——这是最常见的假崩溃/假提升来源。
4. **补丁文件即自证交付物**：能 `git apply` 复现、能逐字节 `diff`，即可独立审计回滚。
5. **一个产物里可变的东西越少，性能差异的可归因性越强**（只换二进制、复用基座）。
6. **新 tag 永不覆盖旧 tag**；作废产物也保留作教训。

## 步骤

### 1. 圈定最小改动面

- 列出"必须改"的点和"看起来相关但不必改"的点，后者一律不动（循环结构、去重逻辑、数据通路）。
- 新增分支放在不影响既有路径的位置（如"新建集合"分支，不动"已有集合"分支）。
- **⚠️ 新增字段的分支与"既有集合"读写路径要成对**：若把过滤切到新增顶层字段，而"已有集合"分支仍保留旧 schema
  （只有 id/vectors/metadata），旧数据会因新过滤器查不到。必须**按实际 schema 选择读写路径**（有顶层字段才用
  顶层过滤/镜像写入，否则回落旧 `metadata["key"]` 路径），或**先迁移并回填旧数据**再切过滤器；并**用同一查询
  核对切换前后结果一致**。

### 2. 逐条写语义等价性论证

以"懒初始化 + 逐行 append" vs "预分配 + append"为例，逐项对齐：

| 维度 | 要证明什么 |
|---|---|
| 字段顺序/类型 | 改造前后索引映射一致 |
| nil/首行语义 | 预分配后走的分支等价于"已 append 过首行" |
| 行序/去重/覆盖 | 不改循环逻辑，行为逐位不变 |
| 维度/稀疏 | **两路径 dim 一致**；稀疏 outer Dim 若不一致须保留原值或引用"允许忽略该字段"的协议约定，并比对非零 dim 稀疏结果 |
| **容量上界 + 字节预算** | 预分配容量 ≥ 实际使用数，且**分配前**按"字段宽度 × 向量维度 × 行数上界"算字节预算并设上限，防"topk×nq 很大、实际只返回少量行"时先占一整块内存 |

> **⚠️ 预分配的字节预算闸门**：当 `topk × nq` 很大而实际只返回少量行时，按行数上界预分配会在"输出大小检查"**之前**先占用整块内存。
> 开工前要：① 按字段宽度 × 向量维度 × 行数上界估算字节数；② 与**字节预算上限**比较，超预算走"按实际结果增长的路径"或分块；
> ③ **验证"大上界、小结果集"场景**（如 topk=500、nq=100，但过滤后每查询只回 2 行），确认不出现整块无谓分配。

### 3. 校验两侧一致性

- A 侧改 schema/协议后，逐一列出所有 B 侧写入路径（seed、replay、import、upsert…）并同步对齐。
- 典型事故：schema 由 3 字段扩为 6 字段，seed 仍写 3 列 → `expect 6 list, got 3` 直接崩。
  （口径注：3→6 是 fork 基线（已剥离 BM25）；stock mem0 2.0.14 的 create_col 是 5 字段，同做法得到 5→8，见 references §一。）

### 4. 单测是等价性的最低成本证明

- 优先命中被改函数的既有测试。
- 离线环境记下构建开关的坑（如 vendored 库架构不符需 `-tags dynamic`）。

### 5. 补丁式落库 + 构建配置分离

- 性能改动收进 `patches/`，可 `git apply` 复现。
- 构建脚本修正单列、不进补丁。
- 与历史/目标 ref 逐字节 `diff` 一致，证明交付物没被污染。

### 6. 只换二进制、复用基座

- 正确做法：`FROM runtime-v1 + COPY bin/<被改组件>`，让唯一差异 = 被改的二进制；其余依赖/入口全部复用。
- 反面：把裸构建产物直接打 tag（缺 etcd/minio/entrypoint）→ 启动即崩、零有效数据。

### 7. 打新 tag + 冒烟

- 新 tag 只加不覆盖；基线镜像和候选镜像同时留着做同环境对照。
- 启动冒烟：三进程正常起、无 panic、行为与基线一致，再进测量。

## 门禁

- [ ] 改动面已圈到最小，无关路径未动
- [ ] 语义等价性逐条书面论证，含"容量上界 ≥ 实际" + "分配前字节预算闸门"
- [ ] 验证"大上界、小结果集"场景不出现整块无谓分配
- [ ] 所有 B 侧写入路径已同步对齐 schema/协议；既有集合读写路径按实际 schema 选择或先迁移回填、同一查询核对
- [ ] 维度/稀疏：两路径 dim 一致，或保留原值/引用协议约定并比对非零 dim 稀疏结果
- [ ] 命中被改函数的单测通过
- [ ] 性能改动是补丁、可 `git apply` 复现
- [ ] 镜像 = 复用基座 + 只换二进制
- [ ] 新 tag 未覆盖旧 tag，冒烟通过

## 产物

- 可复现补丁（`patches/NNNN-*.patch`）
- 新 tag 镜像（image id 记录在案）
- 语义等价性论证 + 单测结果
