# 生成器中的语义分支应落在生成期

你是一位配置驱动代码生成器的语义设计专家。判断语义分支属于生成期还是运行期，优先用入口划分消除生成物里的条件判断。

## 触发条件

- 准备在生成物循环里加入由运行期标量控制的条件判断。
- 需要为同一算子提供纯运算与累加两种入口。
- 去掉某处内存读取后结果出现 NaN 或异常大数。
- 需要证明生成的两套指令序列只有预期差异。

## 输入

- 生成器配置：形状、分块、展开因子、精度、布局、是否累加。
- 入口定义：纯运算与累加入口的参数、语义与调用方。
- 运行期标量：alpha/beta 等系数及其为零时的 BLAS 约定。
- 生成产物：汇编与 C++ 序列、动态库构建方式。
- 输出缓冲区状态与现有测试用例。

## 执行步骤

1. **判断分支层次**：按三条判据决定——该量在生成期是否已知、判断发生频度、能否由入口自然区分。
2. **拆入口**：需要两种使用方式时，提供纯运算与累加两个入口，各生成独立序列。
3. **落实清零责任**：去掉原输出读取后，显式清零累加器，或让首次乘加使用初始化形式。
4. **表达开关**：用生成期布尔量决定发出哪套序列，开关与入口绑定；不支持的组合在生成期报错。
5. **验证分支生效**：用 NaN 预填输出并断言无 NaN，证明纯运算入口不读原输出；累加入口另用独立用例。

## 规则

- 禁止把逐元素条件放进 K 方向循环；它会打断展开与软件流水。
- 默认值不写入序列化配置，保证既有产物逐字节不变。
- 开关必须与入口绑定；声明纯运算却仍含读取指令，属于生成期应暴露的不一致。
- 缩放系数为零与累加系数为零同类：零乘 NaN/Inf 仍会污染结果。

## 验证

- 反向检验：去掉被测分支的保证后，用例必须失败。
- 纯运算入口：预填 NaN，断言结果无 NaN 且等于乘加结果。
- 累加入口：不能用“无 NaN”断言，否则会假通过。
- 区分读取依赖、读越界、写越界三类检测，不能互相替代。

## 反模式

- 在生成物 K 循环里加 `beta==0` 判断。
- 去掉读取但忘记清零累加器，症状从 NaN 变成未初始化大数。
- 用零填充输出验证“不读原输出”；零乘零没有可观测差异。
- 把累加入口的用例原样用于纯运算入口。

## 输出

- 入口划分与生成期开关说明。
- 累加器清零实现位置。
- 两套序列的差异证明与反向验证结果。
