# Fastokens/BPE 类分阶段预取调查

本参考用于调查批处理哈希查表中的 harvest→probe 流程。符号名可作为搜索线索，不能据此断言某个 Fastokens 版本具有相同实现。架构分支、长度阈值、批容量和提前量都从本次实际源码求证。随包的 [源码调查用例](../cases/source-only/prompt.md) 提供独立输入，可用于练习这类分析。

## 从阶段追到具体地址

```text
实际入口 → 收集片段/索引 → 计算目标地址 → 预取封装
          → 查表循环 → 近期 look-ahead → 消费目标数据
```

| 调查项 | 从当前源码求证的内容 |
|---|---|
| 入口 | 从实际调用者追到收集和查表函数；不要凭函数名认定所有 encode 路径都经过它们 |
| 条件 | 短/长片段的实际长度表达式和单位、缓存开关、miss 条件、架构或 feature 分支；空实现仍是 noop |
| 批容量 | 定位 `SPAN_CHUNK` 或对应配置及满批/尾批控制流；容量表示一次处理规模，不是固定预取距离 |
| 跨阶段提前量 | 确认预取在 harvest、消费在 probe；若中间工作量可变，记录 `kind=phase,value=null`，不从批容量推导字节数或周期数 |
| 循环提前量 | 定位 `PROBE_AHEAD`、`PEEK_AHEAD` 或实际索引表达式，分别记录单位、触发条件和消费点；同时检查启动预热、短输入、尾部及填充条目 |
| 目标地址 | 展开 `slots[hash & mask]` 等公式，区分缓存槽、原始字符串、token IDs、keys/ids 数组；同一 hash 不保证对应同一地址 |
| 表身份 | 检查慢路径的扩容、换表、基址与 mask 刷新；两阶段是否预取/消费同一物理槽位，取决于中途表身份是否保持 |
| 分支目标 | 长片段缓存、预测 miss 的 FoldTable、merge bucket 等可能各有独立提示；按对象和条件分别列策略，不能合并成一个距离 |

先判定封装在目标架构上是否实际执行预取，再填距离。若分支为空，按 [输出契约](output-contract.md) 记录不适用距离；封装位于 harvest 阶段不代表该架构发出了跨阶段预取。

## 入口与产物核对

- 完整输入缓存、segment cache 或其他复用机制可能绕过查表，也可能在 miss 时选择另一实现。核对实际配置及分派，不把专用测量入口等同于完整 Python encode。runner 若重置环境变量，以实际运行配置为准。
- commit 或版本号可能只标识补丁基线。结合工作区差异、源码摘要、工具链和构建配置确定来源；查看项目配置文件是否在构建工作目录下生效。
- 检查验证脚本是否使用 mock 工具或假产物。元数据测试只能支持元数据一致性；真实机器指令需要相应产物或有出处的反汇编。
- Python/FFI 入口应定位实际加载的扩展库。新 Rust 可执行文件不能证明现有 wheel 已更新，需分别核对 `.so/.pyd` 的身份与目标函数。
- 历史记录明确标为外部证据并注明验证范围；功能测试通过、发现预取指令或短窗口计数，都不能独立支持稳定加速结论。

最终报告按“源码已确认的阶段、地址和提示 → 产物是否对应 → 运行路径是否观察到 → 仍缺什么”组织。性能比较另需可比输入、各自构建身份和测量窗口；不把提示层级或回填计数直接解释为收益。
