# 干净归因：识别混杂因素

## 何时使用

- 一轮表观改善（如 p50 -19.8%）看着漂亮，但多轮对比发现是运行间方差。
- 二进制体积或 `.text` 段对不上，怀疑"除了我改的这点，还有别的东西跟着变了"。
- 需要判断一条"无增益"结论能否干净归到改动本身，还是要降级放弃。

## 核心原则

1. **单轮对比是危险的**：必须拿多轮分布看噪声范围，一轮离群不代表真改善。
2. **二进制体积 / `.text` 段对不上是"有混杂因素"的强烈信号**：先查再下结论。
3. **无法干净归因就诚实降级**：别硬下"改了没用"，也别硬下"改了有效"。
4. **负结果不是白做**：它把"L2 距离带宽受限"这类判断又确认一遍，同样沉淀进结论。

## 步骤速览

混杂因素清单、判据与坑点**只在 `references/clean-attribution.md` 一处维护**，本节给步骤名与去向：

1. **先问"能不能干净归因"**——按序排查混杂因素（构建路径差异 / 单轮方差 / 外部负载漂移）→ references §2。
2. **用多轮分布戳穿单轮幻觉**——交替复测（基线/候选交错）、比两组分布；改善方向按指标定义（吞吐越高越好 /
   时延越低越好）→ references §3。
3. **体积 / .text 对不上 → 立即停**——无法干净归因就诚实降级；"带宽受限"等派生结论保留为假设而非已确认
   → references §1/§3。

## 门禁

- [ ] 单轮改善经多轮分布复核（交替复测，非先跑完一边再跑另一边）
- [ ] 改善方向按指标定义判定（吞吐越高越好 / 时延越低越好），未把稳定退化误判为增益
- [ ] 二进制体积 / .text 段与基线一致（或差异被解释）
- [ ] 增益或无增益可归到改动本身
- [ ] 无法归因时结论已降级并说明；"带宽受限"等派生结论保留为假设而非已确认

## 结果（标定案例形态）

TOP1(b) faiss L2 展开/预取：1 轮 p50 表观 -19.8% 实为方差（优化轮 120.21ms 与 top2 首轮 120.93ms 几乎相同），
且 `libknowhere.so` 206→314MB、`.text` +45% → 无增益且无法干净归因，放弃。细节与基线口径见
`references/clean-attribution.md` §1。
