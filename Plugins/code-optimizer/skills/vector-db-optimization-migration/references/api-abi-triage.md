# API/ABI 变更分诊

跨版本迁移最容易把“编译通过”误当成“迁移完成”。本文件给出公共头、类布局、虚函数、模板与序列化的通用分诊路径；具体类名与高风险位置按引擎 adapter 加载。

## 1. 先判断是否触碰 ABI

只要命中以下任一条件，就视为 ABI 变更，必须做全项目一致性检查：

- 公共头中的类新增/删除数据成员；
- 新增/删除/改变虚函数（包括顺序）；
- 改变基类层次、模板参数、`enum` 底层类型；
- 改变序列化字段、读写版本常量；
- 改变内联函数使用的宏或 `-march`，导致不同 TU 生成不同布局/实现。

> `strings <目标引擎动态库>` 不能证明宏已启用；必须看 `compile_commands.json` 或等价构建记录与运行时行为。

## 2. 分诊决策树

```text
源码改动是否只在本 .cpp / 匿名命名空间？
├── 是 → 无 ABI 风险，直接按 G0/G1 验证
└── 否 → 是否修改公共头？
    ├── 否 → 是否改变模板/宏影响的头文件展开？
    │   ├── 否 → 低风险，仍要全量重建
    │   └── 是 → 按 ABI 变更处理
    └── 是 → 新增了什么？
        ├── 数据成员 → 所有 TU 必须看到同一头文件与宏；检查 copy/move/序列化
        ├── 虚函数 → 检查 vtable 与所有派生类；避免在公共头条件编译
        ├── 基类/层次 → 目标版本可能已重构，优先 ADAPT/REPLACE 而非硬贴
        ├── 模板参数/分发 → 确认所有实例化点与显式实例化列表
        └── 序列化字段 → 覆盖 save→load 与旧索引 load
```

## 3. 引擎专属高风险位置

先按下表确定通用风险类别，再打开对应 adapter 获取该类别的具体类名、文件与字段：

| 风险类别 | 通用关注点 | Faiss 示例 | DiskANN 示例 |
| --- | --- | --- | --- |
| 公共索引类/元数据 | 新增成员导致布局与 vtable 变化；版本号与字段顺序 | `Index*` 系列 | `GraphHeader` / 索引元数据 |
| 距离/量化接口 | 新增虚函数或改变签名；派生类与调用点 | `DistanceComputer`、`ProductQuantizer` | PQ pivots/codes/LUT |
| 扫描/结果处理 | 模板分发、快慢路径、结果顺序契约 | `ResultHandler`、`InvertedListScanner` | 候选缓冲区 / scratch |
| 访问/缓存结构 | 布局、阈值、版本号、初始化语义 | `VisitedTable` | `visited` HashSet/bitmap、cache |
| 磁盘/序列化布局 | 记录大小、对齐、sector/分页、兼容分支 | `index_read.cpp` / `index_write.cpp` | 节点记录、sector 装箱、load 路径 |

Faiss 的完整风险表见 `engines/faiss.md`，DiskANN 见 `engines/diskann.md`。不得把某个引擎的具体类名写入另一引擎的迁移结论。

## 4. 验证动作

1. **全量干净重建**：不只构建目标文件；记录构建目录、编译器版本、flags。
2. **编译一致性**：`scripts/check_compile_flags.py` 检查相关 TU 的 `-D`、`-march`、`-flto`；按参数顺序解析（`-U` 取消的宏算缺失，含空格形态 `-D NAME`/`-U NAME`），`-march val` 与 `-march=val` 等价识别，`-fno-lto` 等负向 flag 记为显式关闭，uniform flag 缺失也算分裂，默认缺失或分裂即退出 1。
3. **链接检查**：确认没有意外符号缺失或重复；必要时检查 SONAME。
4. **运行时探针**：`gdb`/breakpoint 或 `LD_DEBUG=libs` 确认实际加载库。
5. **序列化往返**：目标库 save → 目标库 load；旧索引 → 目标库 load。
6. **ASAN/valgrind**：覆盖拷贝、移动、析构、`reconstruct()`。
7. **G2/G3**：位级探针与端到端 top-k dump，确认不是“能跑但结果错”。

## 5. 处理原则

- 优先 `ADAPT` 到目标版本的新 API/类层次，而不是把旧结构硬贴回去。
- 能放 `.cpp` 私有实现就不要放公共头；能不改虚函数就不改。
- 必须改公共头时，用 CMake public define 全项目传播，禁止逐文件局部开宏。
- 量化、重排、布局改变默认 `OPT_IN`，并提供 feature-off 逐位一致路径。
- 序列化变更必须显式声明兼容范围；不能验证旧索引时，不得承诺兼容。
- 任何 ABI 变更都要在追溯矩阵中单列，并绑定 G1/G2/G3 证据。
