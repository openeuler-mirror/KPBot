# cluster_registry：集群节点清单

采集前按集群名在此查节点列表。登记新集群时按下方模板添加；**不要在 skill 的脚本里内置真实节点列表**（节点列表一律通过 urls.txt 传入）。

| 集群名 | 池/角色 | 节点列表（ip:port） | collector 建议采集机 | 备注 |
|--------|---------|--------------------|--------------------|------|
| （示例，替换后删除本行）cluster-a | D（decode） | 10.x.x.1:8000, 10.x.x.1:8001, 10.x.x.2:8000, 10.x.x.2:8001 | 10.x.x.1（集群内任一节点均可访问全部 metrics 端口） | 4 引擎 × 2 主机；urls.txt 逐行写 http://10.x.x.1:8000/metrics |
| （示例，替换后删除本行）cluster-a | P（prefill） | 10.x.x.9:8000, 10.x.x.10:8000 | 同上 | PD 双池采集时 P/D 各建一个 urls 文件 |

## 登记约定

- **节点列表**：写 `ip:port`（metrics 端口）；生成 urls.txt 时每行展开为 `http://<ip>:<port>/metrics`，`#` 开头为注释
- **collector 建议**：填一台能访问该集群全部 metrics 端口的 SSH 机器；没有建议就留空，采集时与用户确认
- **主机归属**：多引擎同主机时 ip 相同、端口不同——报告的主机内端口级失衡分析依赖这一映射，清单里的 ip 必须是真实主机 IP（不要写 VIP/代理地址）
- **信息更新**：集群扩缩容、端口变更后同步更新本表；采集发现某节点持续 -1 时先回这里核对清单是否过期
