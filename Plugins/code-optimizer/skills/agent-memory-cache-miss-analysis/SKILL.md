# 缓存缺失率（数据侧 + 指令侧）

## 口径

- 数据侧：每级 `REFILL / ACCESS` 相除得缺失率；DRAM 归因用 `L3D_REFILL / L1D_REFILL`
  （L1 每个 fill 追到最终来源）。
- 指令侧：单独算 **L1I / L2I**，并用"每千条指令的 miss 数"归一化，不要只看百分比。

## 平台差异（不要混用）

| 平台 | 口径 |
|---|---|
| AArch64（有分级 refill/access） | `REFILL / ACCESS`；DRAM = `L3D_REFILL / L1D_REFILL` |
| x86_64（分级不齐） | L1D 用 `L1-dcache-load-misses / loads`；L2 用 `l2_request_g1.*` / 访问计数比；L3 不一定可测；DRAM 用 uncore 内存控制器 |

## 两种典型信号

1. **数据侧上移**：检索 L2D 14.2% → 26.0%、DRAM 归因 13.6% → 30.5%。载荷变小后空间局部性变差，
   属正常迁移，**不要据此回滚**。
2. **指令侧变密**：客户端优化后 L1I miss 密度涨 2~4 倍（代码足迹相对变大），是"下一步该把热路径
   进一步下沉"的信号。编译型客户端通常看不到这条，改看分支预测失败与前端停顿。

## 不要做

- 不要跨架构比较绝对值（x86_64 L1I 每千指令 9.2 vs AArch64 2.0），只比趋势；
- 平台缺少分级事件时不要宣称该级数字，写"不可测"并降级到上一级归因。
