# 重复测量与波动报告契约

适用于 prepare-project 建立基线和 verify-optimization 对比候选。复用项目已有测试命令；本契约不提供通用 benchmark 执行器，不替代领域内更严格的测试协议。

## 测试前：先声明计划

把 `measurement_plan` 放在 `baseline` 中，随完整 prepareProject 传递；无基线计划时 Verify 应在看到候选测量结果前补齐。计划可保存在独立 JSON 并记录引用，至少包含：

| 字段 | 内容 |
|------|------|
| scope / groups | 系统或局部；父版本、候选版本身份与路径，允许多个候选 |
| workloads / metrics | 测试命令、输入规模/线程等分组维度；指标、单位、方向、主指标、每轮提取方式、最终中心统计量 |
| independent_unit | 每次新进程，或明确重置状态的服务试验；注明不能重置的状态和相关性风险 |
| warmup / reset | 每轮预热、缓存冷/热、随机种子、服务状态恢复；预热不计入样本 |
| repetitions / order | 每组计划独立次数；AB/BA 交替或预先固定种子的随机区组顺序 |
| budget / stopping | 总运行次数、总耗时上限、单命令超时、停止/追加规则及预算来源 |
| validity / acceptance | 失败、缺失、异常环境的处理；业务验收线、漂移/噪声判据及依据 |

用户未指定次数时，对可负担的短测试采用每组 5 次独立测量作为初始默认计划，先估计整体成本并记录；这不是统计充分性的保证。昂贵测试按已有预算降低次数并说明限制，用户明确要求一次时执行一次但只报告探索性结果。不要为补齐字段反复询问用户，也不能擅自扩大用户时间/资源预算。不能确认可负担性时先采用有界试跑估计成本；试跑是否进入正式统计需事先声明。

独立重复不同于 benchmark 内循环、同一进程的请求样本、多个输入尺寸或多轮修改代码。每个独立单元先按计划提取一个值，再对独立单元统计。每轮 p99 的平均值应称“各轮 p99 的均值”，不能称合并请求的 p99。进程重启只是实现独立性的手段，不证明外部环境独立。

诊断预算与验收测量预算分别记录，不把 5 次重复假称为 5 个优化假设，也不借重复绕过既有预算。诊断流程中每次实际执行继续受原预算预留机制约束；重复计划必须能在有效次数和总超时内完成，不能后台无界重试。

## 执行中：保留所有尝试

- 在安全隔离的父状态和候选副本上运行，不通过 checkout/stash 覆盖用户工作区。测试同一机器/输入/编译配置/并发/绑核及观测条件；不并发运行争抢资源的性能任务。
- 基线阶段先采集独立基线；候选就绪后优先在同一时段重新交错测量基线与候选，以发现漂移。前期基线与本轮基线分别保存，不能混合扩大 n。多候选采用区组轮转或随机顺序，每个区组含所有比较组。
- 每次尝试记录组、独立 run_id、区组 pair_id（确有配对时）、时间/顺序、命令、源码/二进制/机器身份、退出码、raw 文件及提取位置。多个 CSV/TXT/JSON 可由 agent 先解析为下述长表，不能捏造缺失数据或把汇总行展开成重复样本。
- 失败、超时、无效值和环境异常均保留；不能因数据“不好看”删除慢样本。替补或排除必须符合事先规则并保留原因和原始数据。正确性失败沿用失败路由，不能仅排除后继续宣布通过。
- 耗时或次数预算耗尽、原进程未退出、无法恢复状态时停止，保留实际完成数。追加只能按预先规则，或新建计划版本并解释原因；禁止测到正收益便停止。

## 输出与结论

每个 workload × 配置 × 指标 × 组输出 n、mean、样本标准差（分母 n−1）、median、min/max、未缩放 MAD；非零均值可辅助报告 CV=SD/abs(mean)。n=1 的 SD/MAD 波动估计不可用，不填 0；单次观测也不能支持可靠提升或退化。不同单位、输入规模和统计层次不能混合。

向用户展示“均值 ± 样本标准差”，同时给 n 和 [min,max]，偏态/离群明显时补 median/MAD。±SD 不是置信区间、不是极值范围，也不保证后续结果落在其中。零 SD 可能来自取整或计时分辨率，不能据此证明无噪声。

沿用预先声明的 mean 或 median 计算 speedup：higher 为 candidate/baseline；lower 为 baseline/candidate。任意有意义的有限零/负指标可描述统计，但比值仅对正数计算；零/负指标改用有单位的差值且不得套用旧 speedup 验收线。主指标和硬阈值事先固定，不挑最好的指标/尺寸报告。

`measurement_quality` 记录 sufficient/inconclusive、理由、实际/计划次数、可比性、漂移检查和证据路径。以下情况不得通过性能验收：单次、计划未完成且没有预声明停止规则、不可比、缺失/失败未解决、明显漂移、或现有证据无法区分收益与噪声。未知按 inconclusive；次数达标不自动 sufficient。统计工具只输出描述性结果，不给 sufficient/passed。

业务收益阈值（例如既有 1.1x）不等于噪声判据；CV 小、误差条不重叠或若干轮同方向都不能单独当作显著性检验。需要小收益的统计推断时预先选择适合独立/配对设计的方法、假设、置信水平及多重比较处理，报告方法和区间；未实施推断时明确只是描述统计。高噪声先检查竞争负载、温度/频率、NUMA、缓存、构建及随时间趋势，预算不足则未决，不强行得出收益。

## 标准库统计工具

从已安装的 verify-optimization skill 目录定位 `scripts/summarize_repeats.py`；不得假定当前目录为插件根。prepare-project 独立安装且工具不可用时，按本契约计算并保留计算过程，不因此跳过重复测量。

输入支持多个 CSV（UTF-8，可 BOM）、TSV、JSON 记录数组；自由格式 TXT/宽表先由 agent reshape。必需列为 `group,run_id,metric,unit,value`；自定义维度列通过 `--dimensions` 指定。每个分组/指标内 run_id 唯一，内循环必须先归约，不能自动去重。混合运行批次应把 batch 纳入维度。失败记录保存在尝试清单，勿把空值当零交给统计器。

自定义维度不能与必需列或输出字段 `statistics`、`observations` 重名；如原始数据使用这些名称，reshape 时重命名。CSV/TSV 每行列数必须与表头一致，错误引号或多余列将报错，不静默忽略。

```bash
python3 <skill_dir>/scripts/summarize_repeats.py baseline.csv candidate.tsv \
  --dimensions workload,threads --output repeats-summary.json
```

工具输出源文件与 SHA256、各组的描述统计及逐样本位置；不执行 benchmark、不自动删异常值、不计算显著性、不判断正确性。将摘要嵌入 `baseline.measurement_summary` 或 `performance.measurement_summary`，完整 raw/计划/尝试清单在 evidence_refs 中引用。绘图可交给已安装的 benchmark-visualization，传独立样本和分组定义，展示散点/误差条；无绘图技能仍须提供文字波动报告。
