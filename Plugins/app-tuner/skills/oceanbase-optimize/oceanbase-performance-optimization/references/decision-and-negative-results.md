# 决策矩阵、负结果与停止条件

## 1. 决策矩阵（扩展版）

| 证据 | 首选 | 次选 | 不做 |
| --- | --- | --- | --- |
| `T<tenant>_ApplySrv` 单线程持续 ≥90% 单核（`pidstat -t -p <pid> 1` 线程级采样，≥3 次）、insert 低且加 worker TPS 不涨 | ApplySrv 自适应线程 | 多队列叠加；减少跨 P | 加 worker |
| 128U 整机 CPU 未满、`sql_nio` 单线程持续 ≥90% 单核且请求队列（Recv-Q）增长（`pidstat -t` + `ss -lntp`） | `net_thread_count` | 网卡队列/中断 | 加租户 CPU |

| 只写 CPU 占用高且 IO 等 | 换盘/分盘 | 冻结错峰 | 只加 CPU |
| 全机整体低 | uncore turbo/grub/nf_conntrack | 64K 页 | 不验证叠加 |

## 2. 负结果台账（实测）

| 尝试 | 结果 | 原因 | 是否可再用 |
| --- | --- | --- | --- |
| jemalloc/tcmalloc | 无收益 | 无 malloc 热点 | 换版本可重试 |
| CRC32 硬件指令 | 无收益 | 无 CRC 热点 | 否 |
| KAE | 只写场景收益未量化（需实测） | 仅转储压缩 | 只写场景可评估 |
| `-mtune=neoverse-n2` | -2.5%（Go1） | 热点在访存/等待 | 否 |
| `-mtune=tsv110` | -1%~-3.2% | 同上 | 否 |
| third-party `-O3` | 无显著收益 | — | 否 |
| 全量第三方升级 | 读路径≈0 | 收益来自 OB 补丁 | 谨慎 |
| `numa_balance=on`（920B） | 只写 -2.6%，只读 +0.7% | 迁移抖动 | 逐场景 |
| 5.10 内核（920B） | -7%~-8% | idle 更高 | 否 |
| 锁微调 | 无收益 | 锁占比需实测 | 否 |
| false sharing 对齐 | 无收益 | 热点占比小 | 先 `perf c2c` |
| 数据预取（serialize） | 无收益 | 随机访问 | 否 |
| `idx=0` 实验 | insert +14% | 牺牲正确性 | **禁止** |
| 去掉 obproxy | 平台相关（+58%/-6%） | 口径变化 | 仅诊断 |
| 全局 proxy 编译优化 | 约 1.7% | 火焰图变但收益小 | 谨慎 |
| 内核 PGO+LTO | 无收益 | — | 否 |
| 64K 页 | 约 +5% | 需重编内核 | 客户接受时 |

## 3. 反模式

1. 多变量同改（绑核+参数+编译+补丁）→ 无法归因。
2. 用诊断实验（去 obproxy、去排序）当交付收益。
3. 用单场景提升掩盖其他场景回退。
4. 没有基线就换编译器/第三方。
5. 把客户端瓶颈当服务端瓶颈。
6. 把 query-mix 变化包装成配置收益。
7. 交易类临时参数不恢复。
8. 跨机型/跨版本直接横比百分比。

## 4. 停止条件

出现任一情况，停止当前优化并回到归因：

- 功能/计数/事务回读失败。
- 错误率显著上升且非预期冲突。
- 收益 <5% 且多轮不稳定。
- 负收益无法解释/无法回滚。
- 环境身份不明（二进制/配置/数据不可确认）。
- 需要高风险变更（内核/副本/数据格式）但未获授权。

```

- 瓶颈证据：<线程/函数/占比/场景>

- 备注：<风险/副作用/后续>
```

## 6. 经验法则

- 结构性问题（跨 P、线程单点、队列）优先于参数微调。
- 参数收益通常小于绑核/NUMA/线程；编译收益是整体抬升。
- OB 热点分散，单点指令优化收益有限。
- 任何“巨大收益”先怀疑口径变化（去 proxy、去排序、换数据）。
- 没有回滚方案的变更不做。
