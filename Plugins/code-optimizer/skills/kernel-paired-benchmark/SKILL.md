# 短内核的同进程配对测试

把原版和候选放进同一个进程，在相同输入和输出地址上交替运行。先用同实现的自对照检查测量偏差，再判断原版与候选之间的差异。

## 输入

开始前，从项目和用户已有材料中确认以下内容。

```text
实现         原版、候选的入口，源码版本，构建和特性开关
工作负载     类型、位宽、长度、对齐、分布等参数矩阵
正确性       参照实现、输出规则、数值容差、候选适用与回退条件
运行环境     目标机器、工具链、CPU/NUMA、线程和缓存策略
测量计划     计时范围、预热、组数、进程数、顺序和无效轮条件
已有数据     原始四段计时、实验身份、命令和退出码
```

用户只要求设计方案时，输出计划和待确认条件。用户要求复算时，使用已有数据并说明缺口。执行测量时沿用项目工具链和已授权的运行范围。

## 执行步骤

### 1. 找到真实入口，确定计时范围

核对两种实现做的是同一件事，包括输入解释、实际处理值数、输出布局和错误语义。记录正常入口怎样进入候选，以及哪些参数会回退。

逐项说明分配、头部解析、数据准备、复位、分派和结果释放是否计时。例如测 BP 解包时，压缩输入和输出缓冲区可以提前准备，循环内只保留解包、必要入口检查和调用开销。测完整解码则按实际操作计入分配、解析和结果构造。

两种实现需要能在同一个程序中共存。依赖进程隔离、启动成本或一次性状态的任务，继续使用项目的进程级测试。

确认编译器没有把重复计算移出循环或删除。沿用当前语言或基准框架的防消除手段，让每次调用实际执行且输出可被观察；需要时核对反汇编。两侧使用一致的调用封装，记录函数指针、内联或分派差异。

### 2. 冻结条件，列出完整矩阵

记录源码、二进制和输入摘要，编译器、优化选项、目标 ISA、链接方式、核与内存绑定、频率策略及竞争负载。条件变化后使用新的实验身份。

在看结果前确定参数矩阵、缓存策略、预热、组数、独立进程数、自对照门槛和重试预算。零位宽、满位宽、不适用类型等回退点也要进入对应矩阵。

热缓冲区反复访问与大于缓存容量的流式访问分别建负载。流式方案使用输入池时，两种实现遍历相同索引序列，并记录池大小及复用周期。

### 3. 准备缓冲区，处理状态复位

对于只读输入、覆盖写输出的内核，每个参数点准备一份输入和一块输出，A、B 复用相同地址。

对于原地修改或有状态内核，要保证每次逻辑操作都有可比的起点。一段执行 N 次时，只在第 1 次前复位不够。可采用以下方式。

- 每次恢复输入或内部状态，记录恢复成本是否计时。
- 提前准备输入池，让两侧使用相同地址序列，整段后统一恢复。
- 测完整操作时，把业务确实需要的恢复成本纳入计时。

预热和正确性校验也可能改变状态，正式计时前恢复起点。先校验单次调用，再校验整段重复调用后的输出。检查候选及实际回退，正确性失败时先处理实现问题。

### 4. 校准每段的迭代次数

每个参数点选择共同的 N，让两侧批次时长足以覆盖时钟分辨率和调用开销。以原版校准时，候选可能快很多，需要检查候选批次仍有足够长度。

AA、BB、AB 使用同一 N。需要调整时重新设定该参数点两侧共同的 N，不能只增加其中一侧。预热和校验放在声明的计时范围之外，计时循环内避免日志和文件写入。

BP 历史实例可作为起步参考，参数按当前任务调整。

```text
每类实验组数        21
独立进程数          3
原版批次校准时长    约10ms
每段未计时预热      64次调用
```

CPU 编号和 NUMA 节点从当前机器拓扑选择，不能照搬历史机器的编号。

### 5. 分别执行 AA、BB、AB

A、B 首先是计时位置标签，实际调用由实验类型决定。

```text
实验    A标签调用    B标签调用    目的
AA      原版         原版         检查原版的测量偏差
BB      候选         候选         检查候选的测量偏差
AB      原版         候选         估计两种实现的差异
```

每组四段独立计时，使用下列顺序并交替。

```text
顺序    第1段    第2段    第3段    第4段
ABBA    A        B        B        A
BAAB    B        A        A        B
```

组数为奇数时，两种顺序相差一组，可以在下一独立进程交换起始顺序。每段执行同样的预热策略，保存实际调用的入口和原始耗时。

候选入口与优化内核命中分别记录。例如 BP W0、W32 进入候选入口后仍可能回退原版：记录中的 `implementation` 表示调用 original 还是 candidate 入口，实际内核路径及回退原因另存，不能把 candidate 标签当作 NEON 命中证据。

如果采用每类 21 组，一个参数点、一个进程共执行 63 组、252 段计时。内层 N 次循环是批次工作量，不算 N 个独立样本。

### 6. 先判断自对照，再解释 AB

AA、BB 按与 AB 相同的标签位置计算比值，预期接近 1。门槛在采集前声明，BP 历史实例使用以下设置。

```text
比值中位数    0.97至1.03
P10           至少0.95
P90           至多1.05
```

这些是实例门槛，不代表所有平台都保证相同误差。控制组失败时保留全部数据，检查后台竞争、频率、顺序、预热、校准及状态复位。AB 数字可以保存，可靠收益判断标为证据不足。按预先预算复测，并保留失败尝试及原因。

控制组通过也不能直接证明一个很小的 AB 收益显著，仍需看分布和独立进程之间的变化。

### 7. 扫完矩阵，做独立进程重复

逐参数点完成声明的实验，保留候选未命中、回退、失败和无效点。不要只留下最快的位宽或输入长度。

不同独立进程可以采用升序、降序和固定种子乱序，记录实际顺序。采前核对机器负载，采中记录实际亲和性和频率。performance 策略本身不能证明每个时刻都锁定同一频率。

### 8. 按组内配对公式复算

四段原始耗时为 t1 到 t4，每段均执行 N 次。

```text
ABBA
    A每次耗时 = (t1 + t4) / (2N)
    B每次耗时 = (t2 + t3) / (2N)
    配对加速比 = (t1 + t4) / (t2 + t3)

BAAB
    A每次耗时 = (t2 + t3) / (2N)
    B每次耗时 = (t1 + t4) / (2N)
    配对加速比 = (t2 + t3) / (t1 + t4)
```

每个参数点、每个独立进程取组内比值的中位数。21 组取排序后的第 11 个，偶数组数取中间两项平均。两组耗时各取中位数再相除，会产生另一种统计量，不能替代上述结果。

例如合成数据 ABBA 为 10、8、8、14，BAAB 为 9、12、12、9，两组比值为 1.5 和 4/3，比值中位数约 1.416667。按组平均耗时分别汇总再相除则约 1.411765。

P10/P90 使用预先记录的分位数算法，配套工具采用线性插值。跨进程保留逐轮值，按预声明方式汇总。跨不同负载汇总比值时写明矩阵和权重，不混合不同工作量的原始延迟。

### 9. 校验记录并生成结果

每份工具输入对应一个实验身份、参数点和独立进程。记录需要能关联到组、顺序、段编号、标签、实际实现、N 和整数纳秒耗时，完整字段见 [数据格式](references/protocol.md)。

由项目测试程序生成 measurement.json，再从本 skill 目录运行以下命令。复算脚本只依赖 Python 标准库，配套用例要求 Python 3.9 或更高版本。

```sh
python3 scripts/analyze_pairs.py measurement.json > comparison.json
python3 cases/protocol-contract/run.py
```

工具检查四段完整性、重复编号、标签与入口、身份冲突、共同 N、数值有效性、声明组数及两种顺序的组数平衡。新采集应在顶层声明 `expected_blocks`，例如 AA、BB、AB 各 21 组。

```text
measurement_status=controls_passed    已有记录的自对照统计和顺序组数平衡均通过
measurement_status=inconclusive      自对照或顺序组数平衡未通过，AB比值仍保留
completeness_status=complete          记录数与声明组数一致
completeness_status=not_declared      未声明组数，需要核对原计划
```

格式或数据非法时工具退出码为 2。成功完成复算时退出码为 0，包括输出 inconclusive 的情况，读取结论时还要检查 JSON 状态。

`inconclusive_reasons` 给出 `self_controls_failed` 或 `unbalanced_orders`，各类结果还保留 `order_counts`。偶数组数应各占一半，奇数组数只能相差一组。这个检查不证明实际执行时确实交替，仍需核对采集器及原始运行顺序。

## 输出

- 实验条件、计时边界、输入复位方式和正确性结果。
- 逐参数点、逐进程的自对照统计、候选命中、配对加速比及离散程度。
- 原始四段记录、复算 JSON、失败尝试及无效点原因。
- 收益判断、输入和缓存适用范围，以及仍缺少的证据。

原始数据与汇总结果分开保留。报告小幅变化时同时展示各轮和分布，说明是否足以支持收益方向及幅度。

## 约束

- 条件变化后使用新实验身份，不用另一个构建或负载的历史值拼接当前配对。
- 不因结果较慢删段、删轮或放宽门槛。正确性失败不由性能提升覆盖。
- 自对照检查测量偏差，不会消除两种实现之间全部缓存、频率和代码布局差异。
- P10/P90 是样本分位数，不能称为置信区间；循环次数不能当作独立实验数。
- 热缓冲区收益限定在对应负载，业务、分配及流式访问收益需要相应测量。
- 工具无法从标签证明实际复位、候选命中或机器码正确，相关判断需要采集证据。
