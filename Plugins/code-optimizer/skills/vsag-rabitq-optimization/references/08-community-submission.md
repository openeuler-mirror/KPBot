# 阶段 8：社区提交准备

只有阶段 6 性能验证和阶段 7 覆盖率验收均通过后才进入。准备材料不等于获得提交、push 或签署权限。

## 提交前检查

- 差异中无 KDNN/私有后端名称、代码、路径、环境变量和链接依赖。
- 使用项目配置的 OpenBLAS/CBLAS，batching 的默认值、opt-in 行为和 feature guard 清晰。
- 说明索引兼容性、正确性/recall、风险、回退方式和环境变量覆盖。
- 标注 ARM64 SVE/SVE2 本地验证范围；x86、无 SVE ARM、TSAN 未运行时明确交由 CI 或后续验证。
- benchmark 数据与阶段 1、6 的配置一致，不引用不可复现的历史峰值。

## 材料清单

1. 中文设计/使用文档；
2. 英文设计/使用文档；
3. issue 草稿：背景、瓶颈证据、方案、兼容性和验收标准；
4. PR 草稿：变更摘要、实现、测试、性能、风险和回退；
5. review checklist：并发、异常、fallback、数值、线程和平台检查；
6. benchmark YAML：commit、数据集/索引、硬件、NUMA/绑核、查询参数、线程矩阵、batch 参数、重复方式及结果；
7. ARM/SVE 范围声明与未验证配置；
8. 回退方案和默认关闭/环境变量控制说明。

issue 编号、PR 链接等未知内容保留清晰占位符。只有用户明确授权后才替换为外部对象、执行 push、创建 issue/PR 或添加人工 DCO sign-off。
