# 减少哈希连接探测与键比较

按实际热点选择同键批次共享探测、短键直接判等，或分别验证两项。批次优化减少访问同一张哈希表的次数，短键优化减少每次等值比较的工作。

## 输入

| 输入 | 核对内容 |
| --- | --- |
| 连接入口 | 物理计划、探测和构建入口、连接类型、输出及额外过滤 |
| 批次 | 活跃行、解码后的键、键长度、编码、批次大小和键分布 |
| 哈希表 | 构建侧唯一性、匹配多重性、分区状态、引用有效期 |
| 键比较 | 等值或字典序接口、排序规则、哈希规则、短键存储布局 |
| 验证环境 | 原版与候选切换方式、真实输入及完整结果校验 |

## 执行步骤

### 1. 定位下游真正执行的探测与比较

从连接输入沿解码、哈希表探测、候选键比较和结果输出追踪。在实际探测批次统计活跃行数、同键批次比例和表探测次数。对于短键，确认热点调用只消耗相等或不等的结论。静态文件看起来有序，还要核对它在当前执行计划中经过分区和选行之后的形态。

### 2. 列出可共享探测的条件

从单键普通内连接开始。确认当前构建表已完成且可用，活跃行的键有效且相等，构建侧键唯一，连接没有额外依赖探测行的条件。唯一性优先使用构建阶段已知的信息，避免每批遍历整张表。

对字典、常量、扁平向量或存在选行的输入，读取引擎实际比较的值。不同字典位置可能表示相同值；物理表示相同也要具备正确的逻辑类型和空值语义。发现无法确认的条件，退回正常探测。

### 3. 保持每条输入对应的输出

快路径确定共同键后，对当前哈希表探测一次。匹配成功时给每个活跃探测行复用匹配引用，同时保留该行自己的字段。未找到时按内连接语义处理整批活跃行，遵守已存在的批次输出和计数接口。

```text
同一张日期哈希表有 101 → 5 月 1 日
原版  100 笔各自查 101，共查 100 次，输出 100 笔
候选  符合条件时查 101 一次，复用给 100 笔，输出仍是 100 笔
```

引用只在有效的表状态及批次范围内复用。遇到分区切换、spill 或重建时遵循引擎已有生命周期，避免跨状态缓存。

### 4. 将直接判等放在正确的比较接口

先剥离需要排序结果的调用。在专门的等值路径里检查类型和排序规则能否按有效字节比较、哈希和相等的规则是否一致、短键是否实际内联。仅当满足条件时走长度和内容比较，处理空值后再读字节。

例如 `A12` 在字节序相等的例子里有 3 个字节，十六进制为 `41 31 32`。长度相同后直接比有效字节。指定大小写、重音、正规化或填充相关规则时，保留该规则。长键通过已有实现处理。

### 5. 验证快路径、边界与回退

| 场景 | 确认点 |
| --- | --- |
| 同键命中、同键未命中 | 候选探测次数符合预期，输出行重数一致 |
| 混合键、空值、构建侧重复、额外过滤 | 条件不成立时走原路径，保持逐行语义 |
| 阈值前后、不同向量编码或选行 | 候选只用于已正确识别的活跃行 |
| 空串、前缀相同但长度不同、内嵌零、多字节字符 | 判等与原规则一致 |
| 内联边界、长键及特殊排序规则 | 适用输入命中，其他输入回退 |

用正常入口核对完整行值及重数。跟踪探测发生的位置，别把携带同一匹配行的输出次数记成哈希表探测次数。

同时区分实际提交查找的有效键数与批量查找函数调用数。原版可在一次批量调用中提交 100 个键，共享路径也调用一次但只提交 1 个键；示例的 100→1 指键查找工作量，不能用同为 1 的函数调用数证明。普通路径按参与查找的键数累加，共享路径按实际查找的一个键累加，NULL 或未选中的行不计入。

### 6. 确定触发阈值和收益

对比不同批大小、同键比例与键分布下的检查成本和探测节省。阈值基于当前负载。Q67 候选中的 64 行属于该实现的参数；如果扫描活跃行本身昂贵，阈值和识别方法也会影响收益。

两项独立时，分别比较原版、只开同键探测、只开短键和同时开启。记录候选命中、探测次数、比较次数和完整查询耗时。单次的表访问减少能说明做了更少工作，实际时延和内存按测量报告。

## 输出

- 热点调用点及选择的优化分支。
- 批次准入、构建侧不变量、缓存有效期、比较布局和回退条件。
- 完整连接结果、候选命中、探测和比较次数。
- 各模式的真实负载配对结果、阈值依据及尚待验证的输入。

```text
模式 | 活跃行 | 同键候选命中 | 查找键数 | 批量查找调用数 | 短键等值次数 | 完整查询耗时
```

## 约束

- 保持连接类型、输出字段、行重数和额外谓词语义。
- 构建侧重复匹配及其他未证明的情况使用正常路径。
- 哈希表引用遵守拥有方的生命周期，不跨代次、重建和 spill 状态复用。
- 直接字节比较仅用于规则相符的等值调用。只读有效内容或按布局已初始化的字节。
- 批次识别成本纳入对照。多个优化的收益独立取证。

## 本地用例

用例将普通探测和共享探测的输出分别与逐行枚举的内连接结果核对，覆盖重复匹配的行重数与逐行过滤。执行 `python3 -O run.py` 时同样校验完整结果、查找计数和短键判等，失败会返回非零退出码。

在 `cases/join-contract/` 中执行 `python3 run.py`。用例检查阈值前后、重复构建键、附加谓词、空值、未命中和字节比较边界，含同长度、同前四字节但后半段不同的 `abcdX`/`abcdY`。单独断言原版/共享路径的查找键数为 100/1，而批量函数调用数均为 1。输出在用例目录的 `results/result.json`。模型评估规格在 `evals/evals.json`，Velox 源码位置及历史验证见 [Q67 案例](references/velox-q67.md)。
