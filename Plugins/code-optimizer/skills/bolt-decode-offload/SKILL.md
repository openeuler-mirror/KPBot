# L2 解码下沉（解释型客户端专用）

## 前置条件

- 客户端火焰图里驱动层反序列化 ≥ 40%（实测某案例 86.5% 自耗时）；
- 官方/社区已有**同版本**编译实现，不要自己写。

## 做法

```bash
pip install neo4j-rust-ext==<驱动版本>.0    # 例：neo4j==6.2.0 -> 6.2.0.0
python -c "import neo4j._rust as r; print(r.__file__)"   # 真实判据
```

- 扩展版本规则：**`<驱动版本>.0`**，且不是每个补丁版本都有对应扩展；
- 该包会顺带把驱动钉在声明版本，注意别把项目的 5.x 顶成 6.x。

**已知坑**：wheel 把 `_rust*.so` 装进 `lib64` 站点目录而驱动在 `lib` 时，驱动看不见扩展
（表现为 `RUST_AVAILABLE=False`）。把 `.so` 复制进驱动包目录即可，重装后需复查。

## 实测（标定案例）

| 阶段 | x86_64 | 鲲鹏 |
|---|---|---|
| 检索 | 21.86 → 9.80 s（−55%） | 24.97 → 11.31 s（−55%） |
| 写入 | 15.65 → 6.37 s（−59%） | 16.33 → 6.87 s（−58%） |

## 风险

- 版本错配会**静默回退**纯 Python，必须用导入路径自证；
- 不同架构 wheel 不可混用；Python ≥ 3.10。

## 不适用于

客户端已是 C++/Go/Rust——除非它当前走通用反射/动态序列化，否则"再换一门编译语言"收益接近 0。
判据：驱动/反序列化在火焰图里 < 15%。此时预算转到载荷、检索配方与服务端。
