# 测试与指标口径

先把业务用例、测试记录和指标的统计对象对应起来。一个功能用例可以证明超时后保留候选顺序；线上回退比例要从覆盖该人群的请求计数中计算。现有材料只有测试设计时，写明输入和预期，执行结果标为“未见记录”。

## 怎样描述已有测试

| 材料 | 报告应说明什么 |
|---|---|
| 功能、边界与异常用例 | 关联的业务用例、前置状态、输入或故障注入点、预期输出、实际断言及通过情况。涉及重试时，同时核对调用方结果和下游写入次数 |
| 离线评估、回放或 A/B 对照 | 数据来源、样本选择、标签或基准结果、版本和对照条件。线上试验还需说明分流单位、观察窗口及影响判断的差异 |
| 压测、容量或稳定性测试 | 环境与拓扑、请求组合与规模、开放到达率或固定并发、预热与稳态窗口、超时和重试策略。说明计数端点与监控范围；单个负载点只代表该工况 |

## 业务指标怎样选

从用户目标选择能回答当前问题的指标，名称沿用项目口径。例如：

- **搜索**：空结果率可用“返回空列表的有效查询数 / 成功完成的有效查询数”；注明失败请求是否单列。评价排序质量可用 NDCG@K（前 K 位归一化折损累计增益），需要相关性标注、K 值及查询集合。
- **推荐**：召回率 Recall@K 应说明相关条目的定义与集合。点击率应注明按有效曝光事件还是按用户统计，同时给出点击与曝光的关联规则和窗口。
- **广告**：按用例选择填充率、可归因转化率或重复扣费率。明确分母是符合资格的广告请求、有效点击还是可计费操作；服务端返回、客户端曝光、扣费完成是不同端点。

## 系统性能怎样读

| 指标 | 计算与解读 |
|---|---|
| 吞吐 | 在同一稳态窗口，压测端分别按发出事件、终态事件和成功事件计数，各除以窗口秒数，单位为请求/秒（QPS）。终态包括成功、客户端超时及其他最终失败。服务端到达率按服务端接收事件另算。说明重试按逻辑请求还是按尝试计数，配置的目标 QPS 单列。 |
| 各级时延 | 端到端取调用方发出至收包，服务端取接收至写出，排队取入队至开始执行，业务阶段取该阶段开始至结束，下游调用取发起至收到结果或超时。对每项分布注明字段、筛选条件和有效样本数，按成对起止记录或直方图观测数核实。分位数用毫秒表示，单笔只报耗时。各阶段 P99 不能相加得到端到端 P99，跨实例汇总应使用原始样本或可合并的直方图。[分位数与直方图](https://prometheus.io/docs/practices/histograms/) |
| CPU 利用率 | 服务进程或容器的平均用核数 = 窗口内累计 CPU 时间增量 / 墙钟时间。折算占比时，注明同窗有效核数或容器配额的来源。例如 60 秒消耗 180 核秒，平均占用 3 核。容器同期的 `cpu.max` 为 `400000 100000` 时，配额为 4 核，占配额 75%。缺少分母时可报告平均用核数。整机忙碌率另标主机范围。[Linux cgroup v2 的 CPU 统计与配额](https://docs.kernel.org/admin-guide/cgroup-v2.html) |
| DDR 带宽与利用率 | 先报内存控制器读、写带宽（GB/s）及其通道、插槽或 NUMA 范围。若从计数器换算，按该平台事件定义将增量换为字节，再除以采样时长。带宽利用率 = 实测总读写带宽 / 同范围的参考带宽 × 100%。注明分母是理论峰值还是同硬件、同读写模式下实测的可持续带宽；没有可比分母时只报 GB/s。共享控制器的数据反映该范围的总流量，不能直接归因给单个进程。[鲲鹏相关内存控制器计数器说明](https://docs.kernel.org/admin-guide/perf/hisi-pmu.html) |

“DDR 利用率”也可能指控制器忙周期占比。此时沿用原始计数器的事件定义，并与带宽占比区分。已用内存占容量的百分比反映内存容量占用，应单独命名。
