# 其他应用的复用条件与设计门禁

本文件是 **次级** 参考：本 skill 的首要目标是 libco。只有当其他栈式协程应用
具备共享栈、用户态切换、AArch64 等匹配特征时，才使用本文件做接口映射。
不记录参考实现的性能数字；接口、阈值、块大小和验收指标必须按目标应用重新映射。

## 1. 迁移原则

- **方法优先**：拿走判断依据、验证协议和设计反例，不复制某一版代码。
- **先画像**：确认目标应用是否有共享栈、用户态切换、AArch64、两方向复用；
  条件不满足就跳过对应方法。
- **能不改就不改**：目标应用若已被 libc/编译器覆盖，先建立基线，不要为套方法而重构。
- **阈值不是常量**：128B/384B、tier 档位、重复轮次都是参考值；按目标尺寸分布和噪声重定。
- **目标指标优先**：协程库看 ns/switch，业务应用看端到端延迟/吞吐；direct copy 只作解释。
- **不固化结果**：参考实现的数据不写进 skill；是否采用由目标应用实测决定。

## 2. 方法迁移矩阵

| 目标应用特征 | 可复用方法 | 跳过/降级条件 |
|---|---|---|
| AArch64 用户态上下文切换 | 整数/SP 保存、d8-d15、16B 对齐 | 切换由 OS/线程库完成时，只做 ABI 检查 |
| copy-stack / 共享栈 | save/swap、对齐、分块、余数、tier、验证 | 非共享栈或只有单向拷贝时，不拆 save/swap |
| 大块连续内存拷贝 | 对齐、分块、余数、tier、验证 | 小消息为主时先与 libc 对照 |
| 只有单向生产者→消费者 | 对齐、分块、余数、tier | 没有“写后立即读”的 swap 方向，不套 `ldnp+stp` |
| 非 AArch64 平台 | 验证协议、tier 方法、设计门禁 | 不使用 NEON/`stnp`/`ldnp`，使用 libc |
| async/await 状态机 | 仅性能测量与验证思路 | 没有栈切换，不使用上下文/栈拷贝方法 |
| 内核/OS 调度、信号栈 | 仅 ABI 与对齐检查 | 不直接改内核切换路径，不套用户态共享栈方案 |

## 3. 先识别语义

- 是否存在两个方向：**保存/换出**（写后不立即读）与**恢复/换入**（写后立即读）。
- 是否共享栈/copy-stack；每次切换实际拷贝多少字节；栈使用深度分布。
- 是否 AArch64；是否使用 NEON/SVE；是否手写汇编。
- 协程数、栈大小、切换频率、save_buffer 生命周期；调度/分配是否可能成为主瓶颈。
- 是否有 GC/栈扫描、栈增长、信号栈等会移动或复用栈的机制。

## 4. 上下文切换

- 保存 x19-x29、SP、返回地址；16B 栈对齐。
- **保存 d8-d15**；不要默认保存 q8-q15 上半。
- 若 NEON 内核使用 q8-q15，必须显式保存或在切换中恢复；否则改用 q0-q7/q16-q31。
- 用汇编级 d8-d15 测试 + 编译器 `-S` 检查。
- 目标应用的上下文结构、入口参数、首次启动路径必须单独核对，不能只替换汇编符号。

## 5. 拷贝路径

- 存在两个复用方向时，拆 save/swap 两个入口；只有一个方向时不要强拆。
- save：`ldp` + `stnp`；swap：`ldnp` + `stp`。
- 目标 64B 对齐；处理前缀；块内核覆盖完整块。
- 余数：32/64/96B 内联；1–127B 用首尾重叠，避免逐字节循环。
- 块大小：把 128B/384B 当起点，先扫描目标尺寸分布；历史多档不作为默认。
- 非 AArch64 平台使用 libc `memcpy`。

## 6. 验证

- 长度矩阵：0/1/小值/各 tier 临界 ±1/大长度。
- 对齐矩阵：dst/src 偏移 0/1/3/7/15/31/63。
- 哨兵：前后各 16B；逐字节比对；返回值 == dst。
- 性能：固定绑核与编译器；5 轮 ABBA；记录原始数据；小尺寸单独看。
- 先正确性后性能；baseline 不正确时禁止比较吞吐。
- 目标应用若有业务语义（消息边界、序列化、校验和），增加端到端一致性检查。

## 7. 迁移后验收

| 目标应用 | 主指标 | 必须同时通过 |
|---|---|---|
| 协程库/用户态调度器 | ns/switch、切换吞吐 | 多协程寄存器/栈/共享栈逐字节 |
| 网络/服务框架 | p50/p99 延迟、QPS | 请求/响应内容逐字节、错误率 |
| 语言 runtime | 协程创建/切换延迟、暂停时间 | 栈扫描/GC/异常路径回归 |
| 通用大块拷贝库 | 目标尺寸分布加权吞吐 | 全尺寸/对齐逐字节、哨兵 |

报告至少包含：机器型号、CPU/NUMA 绑核、编译器与 flags、协程数/栈深/尺寸分布、
重复次数、中位数与尾部分位数。只报最好点不算验收。

## 8. 常见设计错误

- 只看一个尺寸调块大小，或把 direct copy 的几何平均当业务收益。
- 把 save 的 temporal hint 用到 swap。
- 在 NEON 内联汇编里使用 q8-q15 而不保存。
- 把所有 >=128B 统一成 384B，或删除 64B 对齐前缀而不做对照。
- 把 libco 的阈值、结构体布局、函数名直接复制到目标应用。
- 给 async/await 状态机强套栈切换或 save/swap。
- 在 baseline 不正确时比较吞吐，或把 harness/客户端开销算进库收益。
