# 阶段 2：后端迁移

用于区分内部 KDNN 路径与开源 VSAG 路径，并将社区实现迁移到项目配置的 CBLAS/OpenBLAS。

## 迁移规则

- 先确认目标是内部实验还是社区提交；不得把内部实现直接复制到开源树。
- 社区路径只调用项目构建系统配置的 CBLAS/OpenBLAS 接口，使用 row-major SGEMM 完成稠密 ROM 变换。
- 保持无 OpenBLAS、功能关闭或不适合 batching 时的原有路径可用。
- 迁移不得改变索引序列化布局、距离语义、query 生命周期或 benchmark 口径。
- 内部 KDNN 工作保留用户指定的后端和计时约束，不得修改工具路径来掩盖环境问题。

## 私有依赖清理

检查代码、构建文件、脚本、文档和提交差异，确认不存在：

- KDNN 或其他私有库的头文件、符号和链接依赖；
- 私有源码路径、工具路径和环境变量；
- 内部 benchmark 名称、机器标识、凭据或未脱敏结果；
- 绕过项目 BLAS 配置的硬编码库路径。

## 阶段出口

产出后端映射、修改文件、fallback、构建依赖和残留扫描结果。残留未清零时不得进入社区提交；迁移代码必须进入阶段 5 验证。
