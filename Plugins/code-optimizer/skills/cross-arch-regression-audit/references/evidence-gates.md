# 证据门控：双门槛判定与报告契约

> 配套 SKILL.md 第 3、4 步。一个架构差异要成为候选优化点，必须**同时**通过两道门槛；
> 只过一道的不报，两道都过但未实测的收益不承诺。

## 门槛一：考古不出引入理由

### 考古路径（按优先级）

1. `git log -L <start>,<end>:<file>` 直接追差异行历史；
2. `git log --grep=<关键词>` 找引入 commit，读 message 全文与关联 issue/PR 讨论；
3. 读差异处注释、`README`/docs 中对应架构章节；
4. 上游搜索：其他发行版/fork 对同一差异是否有过讨论或修复（公开 PR 是最强证据）。

### 结论口径

| 考古结果 | 结论 |
|---|---|
| commit/注释明确说明理由，且理由针对的现状仍存在 | 合理差异（D 类），归档 |
| commit/注释说明理由，但针对的硬件/版本/前提已不存在 | 理由过时，进候选池并记录过时依据 |
| 找不到任何说明（"随手带进来"） | 无理由差异，进候选池 |
| 差异在两架构间随机漂移（两侧各错各的） | 报告并建议上游统一重构，不作为单侧对齐候选 |

**纪律：考古不到理由就如实记录"无理由"，不替原开发者编造合理化解释。**

## 门槛二：热点路径可数成本

### 热点路径证明

候选差异必须落在下列之一的**已证明热点**上：

- 业务负载路径（压测/生产流量经过的代码）；
- 启动/恢复路径（延迟直接计入用户可感指标）；
- 同步请求路径（请求-应答串行链路上的每一环）。

冷路径（低频管理操作、错误处理、诊断输出）上的差异一律降级为观察项。

### 可数证据清单

| 证据类型 | 采集方式 | 用法 |
|---|---|---|
| MMIO/PIO exit 计数 | `perf kvm stat`、KVM debugfs（`mmio_exit_user`/`mmio_exit_kernel`） | 每字节 N 次 exit × 热点字节数 = 成本下界 |
| trace 事件计数 | trace 点计数、`kprobe`/`perf probe` | 事件次数 × 单次耗时 |
| 单实例延迟分解 | 分阶段计时（分解到毫秒级步骤） | 差异所在步骤的耗时占比 |
| 宽限期/锁等待 | `/proc/<pid>/task/*/stat`、锁持有计数 | 每次等待的绝对耗时 |
| 微基准 A/B | 同负载下开/关差异点 | 直接差值（仅辅助，结论须覆盖真实负载） |

### 量化口径

- 计数必须**归因到差异点本身**：不能拿整链路延迟冒充差异成本；
- 对照测量固定其余变量，单变量切换；小收益（<5%）用交错顺序复测防噪声；
- 实测锚点（公开案例）：guest console 差异在单实例 create 的量化——模拟串口路径
  `mmio_exit_user` 1811 次 / 每字节 2 次寄存器 exit / vCPU 线程写 1651 次，切换
  半虚拟化 console 后 exit 计数 2 次——数量级差异一目了然。

## 误报清单（出现即拦截）

1. **有明确注释理由的差异**被当作"无理由"——考古没做完整；
2. **正确性必需的差异**（页大小、ABI、指令集专属语义）被当作性能问题；
3. **冷路径差异**带不出可数成本却进了候选——门槛二失效；
4. **把对齐收益归因错**：同时改了布局/绑核和机制，收益算给机制——单变量纪律失效；
5. **拿"配置已改"当"优化已生效"**：缺重启后运行时核对；
6. **编造能力**：成熟侧机制在移植侧实际不存在（缺驱动/缺内核配置/缺硬件支持），
   未核实就宣称可对齐——必须先核对两侧运行时生效证据；
7. **负样本意识缺失**：死参数、无害差异（如仅影响启动日志的 earlyprintk 泄漏项）被
   报成优化点——冷路径/零成本差异只进观察项。

## 候选优化点报告模板

每个过双门槛的候选点按此模板记录：

```markdown
### 候选：<一句话标题>

- 差异位置：<文件:行号>；成熟侧=<取值/机制>，移植侧=<取值/机制>
- 分类：A/B/C；考古结论：<无理由 | 理由过时：原理由 X 针对的 Y 已不存在>
- 热点路径：<哪条路径>；可数成本：<exit 计数 / 事件数 / 耗时>（采集方式附命令）
- 对齐方案：<向成熟机制对齐的具体改法>；前置核对：<移植侧能力/配置/依赖核实项>
- 回退方案：<恢复步骤>
- 验证计划：<固定变量清单 + A/B 载荷 + 观测指标>
- 收益：gain_pct=null（未实测）| <实测值 ± 区间>（附原始数据路径）
```

## 结果状态机

| 状态 | 含义 |
|---|---|
| `archived-D` | 合理差异归档，不再跟踪 |
| `observed` | 未过门槛二（无数出成本 / 冷路径），观察项 |
| `candidate` | 双门槛通过，待验证 |
| `verified` | A/B 实测完成，收益/退化已有数据 |
| `blocked` | 缺权限/缺硬件/缺补丁，验证被阻塞（记录缺失项） |
