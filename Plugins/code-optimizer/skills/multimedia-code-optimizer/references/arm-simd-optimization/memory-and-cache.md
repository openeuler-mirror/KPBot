# AArch64 访存指令手段

分块、打包与融合见[减少数据搬运](../media-optimization-knowledge/core.md#减少数据搬运)。

## 访存指令选择

| 访问模式 | 指令手段 | 实现要点 |
|---|---|---|
| 基址加元素索引 | LDR/STR 的 scaled-register offset | 让索引保持元素编号，利用寻址模式完成按元素宽度缩放；32 位索引可用 UXTW/SXTW 扩展后寻址 |
| 连续指针递增 | LDR/STR 前/后索引写回 | 将访存与指针更新合并；下一次地址依赖写回，独立基址加偏移有时更利于并发加载 |
| 两个相邻寄存器连续读写 | LDP/STP | 减少地址与访存指令数量；比较成对访存和独立加载的调度，尾部必须容纳两份数据 |
| 交错字段拆合 | NEON/SVE 的 LD2/3/4、ST2/3/4 | 一次访存完成解交错/交错；寄存器内重排用 ZIP/UZP/TRN，避免为布局转换落内存 |
| 已知后续地址需提前装入 | PRFM；SVE 用带谓词的预取形式 | 预取距离可从 `访存延迟/每轮周期` 估算迭代数；硬件预取不足且地址能提前生成时采用，过远会挤占缓存。`__builtin_prefetch(p,0,locality)` 的 locality 为 0–3 常量，不指定精确缓存层 |
| 单次流式访问挤占热数据 | SVE LDNT1/STNT1，或成对非临时访存 LDNP/STNP | 以 non-temporal 提示表达低复用；提示不保证绕过缓存，近期要再读的数据保留普通访存 |
| 大块清零/复制 | 采用具备 DC ZVA / MOPS 分派的平台内存函数 | DC ZVA 仅用于清零，块大小由 DCZID_EL0 描述，地址会定位到整个清零块；首尾仍需精确处理。MOPS 复制/设置路径按能力分派 |
| 短尾部只能访问少量有效元素 | SVE 谓词 load/store | 以实际元素宽度构造谓词；NEON 的 select 不抑制访存，固定宽度路径需窄加载或局部缓冲 |
