# SQL51 销售日聚合前移

## 说明与范围

Web 和门店销售各自按商品与日期汇总日销售额，再进入累计求和窗口。本 Skill 检查在数据交换前是否能合并重复组、缩窄传输列，或在满足维表条件时调整日期连接前后的聚合位置。分析分别覆盖 `web_sales` 和 `store_sales` 的执行分支。

| 金额契约 | 输入/中间/输出类型、精度与尺度、NULL、溢出和舍入规则 |
| 工作量 | 每分支输入行、局部状态数、日组数、交换字节、峰值内存与 spill |
| 修改范围 | 允许手工改 SQL，还是仅修改实际命中的引擎规则或执行实现 |

## 实施步骤

### 1. 区分日聚合和累计窗口

模板 `sum(sum(ws_sales_price)) over (...)` 的内层是按日 SUM，外层是累计窗口；门店对应 `ss_sales_price`。按真实节点记录两层的类型和输入，不能把累计 SUM 当作可任意交换的日聚合。

```text
Web   日期连接/过滤 → 日 partial → Exchange → 日 final → 累计 SUM
门店  日期连接/过滤 → 日 partial → Exchange → 日 final → 累计 SUM
```

Exchange 的实际位置以最终计划为准，两条分支分别取证。

### 2. 用真实输入量和状态大小选择候选

确认交换的是销售原行、partial 状态还是日结果。记录 partial 输入 N、实际输出状态记录 G、状态宽度与交换字节。多个 task 可对同一业务组分别产生状态，不能把全局 distinct 组数当作 G。

N/G 只说明行数压缩潜力。状态更宽、热点组 spill 或原版已经高效局部聚合时，以字节和时间决定是否继续，不能由组数直接宣称加速。

### 3. 在现有连接边界内前移 partial

优先保留日期连接和过滤位置，在 Exchange 前合并可合法归并的状态。传输 `(item_sk,d_date)`、SUM 中间状态及后续必需字段，不用窄化的最终金额替代引擎定义的状态。

确认 final 仍合并同一商品和日历日期，累计窗口读到完整日结果。NULL 标志、聚合 FILTER、精度和异常状态属于状态契约；未证明时保留原 partial/final 边界。

### 4. 允许重写时再评估连接前预聚合

采用保守准入：维键唯一、连接与过滤位置正确、没有未处理的逐销售行条件，且金额状态允许重组。先按 `(item_sk,sold_date_sk)` 聚合，再连接维表；未知关系或错误行为未证明时沿用原顺序。

两个代理键可对应同一日历日期。例如键 10/11 分别汇总 10/8，连接后必须再按 `(item_sk,d_date)` 合并成一行 18，而不是两行 10 和 8。下游逐行累计窗口不能替代这一步。

### 5. 验证 NULL、精度和错误行为

全 NULL 日组仍为 NULL，不补成 0，也不能删除这条日记录。覆盖负金额、空分支、月份边界、未匹配日期和商品过滤。

改变求和括号、位宽或 CAST 位置可能改变溢出/舍入。SQLite 整数分只验证逻辑结构，不证明真实 decimal 状态等价；在目标引擎对照正常值、类型和异常，不能证明时关闭该项改写。

### 6. 从正常入口确认命中和工作量

分别记录规则是否启用、输入行、局部输出状态数、final 日组数、交换列与字节。看到 HashAggregate 不代表目标前移已生效，要核对其阶段、键和位置。

诊断与性能采集分开。正式计时关闭额外计数，保留必要准入；记录 task 峰值和 spill，避免总量下降掩盖长尾退化。

### 7. 对照完整查询

固定 SQL、数据布局、资源、缓存和全部结果取回边界，交错运行原版/候选。先比较日结果、累计结果及完整结果的值、NULL、类型和重数，再报告时间。

两条分支的 Shuffle 和局部耗时独立列出。保留原始配对样本、失败及退化；局部字节减少不能代替端到端实测。

## 约束

- 保留月份过滤、日期连接重数、商品非空条件及按日分组。维表关系或聚合状态合并语义未证实时保留原边界。
- 保留全 NULL 组、负金额、decimal 精度和溢出行为。核对原运行模式下的正常值与错误。
- 单项结果分别报告两条分支的 Shuffle 和耗时，完整查询收益使用配对比值中位数。已有高压缩率 partial 时先确认继续调位有收益空间。
