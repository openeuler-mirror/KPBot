# Flink Native 栈 vs 原生栈性能对比基准协议

为 Flink native 向量化栈的性能工作提供可信测量：**同一查询集、同一事件规模、
同一并行度、双端同日锚定**下的 duration / wire / RSS 三指标，以及"性能结论必须
行为冻结护航"的判定纪律。没有可信的测量与一致的行为，任何优化结论都是空中
楼阁。

## 场景与口径

### 查询集与负载

- **查询集**：nexmark 类流查询（无窗 Top-N、去重、窗口聚合、双流关联等形态
  覆盖），每查询一个 SQL 文件、固定输入数据；
- **事件规模**：固定事件总数（如 1 亿事件量级），事件生成参数写进口径记录；
- **并行度**：固定（如 P=4），单 TaskManager 部署形态记录进环境指纹；
- **sink**：blackhole sink 吞输出（性能口径下不观测输出的场景）；**changelog
  观测载体**是同形态 print sink 用例（Top-N 类查询用小规模对照用例观测
  changelog，与性能用例仅 sink 与规模不同、计划/算子同构）。

### 双端内存口径对齐（关键）

原生栈与向量化栈的 TaskManager 内存需求不同——**重负载查询（如 Top-N 族）在
原生栈可能需要数倍堆**（8GB 堆下原生重负载查询堆耗尽 FAILED 的实测先例）：

1. 任一端 OOM/FAILED 即**口径不成立**，不得用该轮数字出结论；
2. **双端同口径重跑规则**：一旦需要给失败端放大 TM 堆（如 64GB），对照端必须在
   **同一 TM 堆、同一 JVM 参数**下重跑，双端比值只用同配置轮次计算——堆大小直接
   改变 GC 行为与常驻内存，异配置轮次的 duration/RSS 比值被口径差异污染，不能
   归因给执行栈本身；
3. **无法双端对齐时**（如只有单端集群、无法给对照端放大堆）：该组只能作为
   **"带口径差异的参考结论"归档**，单列呈现并标注差异，**不得进入双端比值
   汇总**；
4. **禁止**用"一端跑不动"直接判负——那是资源口径问题，不是性能结论。

### 同日锚定纪律（纪元纪律）

- 双端数据**同一天跑**；跨日数字不可比（环境漂移：宿主负载、JIT、页缓存）；
- 每轮记录：日期、两端 commit/构建标识、环境指纹（内存配置、JVM 参数、native
  库加载自检——压缩/序列化库 native 加载失败回退 Java 实现会污染一切结论，
  启动自检必做）；
- 多跑取证据（如八跑），报告给分布（中位数/分位），不给单轮。

## 指标采集

| 指标 | 定义 | 采集要点 |
|---|---|---|
| duration | 作业提交到 FINISHED 的时长 | 作业必须到 FINISHED 才算成功；FAILED/CANCELLED 一律废轮 |
| wire bytes | 网络边序列化传输字节量 | 反映数据桥与序列化格式税（归因传输层用） |
| RSS 峰值 | 单 TM 进程常驻内存峰值 | **采样窗口限定为本轮**（作业提交至 FINISHED）：记录 TM 进程 PID 与采样间隔；多轮复用同一 TM 时取窗口内采样序列的峰值，**禁用进程生命周期高点（VmHWM）**——早先重查询的峰值会污染后续轻查询；或为每轮启动独立进程后再读高水位 |

三指标**每轮同采**——只报 duration 不报 wire/RSS 的轮次不可用于归因（"只报吞吐
不报资源"是判定废轮的口径）。

## 行为冻结核验（放行条件）

性能结论的放行前提是**行为零变化**：

1. **按用例承诺分级核验**——观测用例分两类，放行前各自满足：
   - **终态承诺用例**（只承诺最终结果集）：changelog 折叠对比——输出按 +I/-U/+U/-D
     折叠回最终结果集后**精确一致**（多行、少行、字段不一致任一出现，性能数字
     全部作废）；
   - **逐条 changelog 承诺用例**（下游按序消费、审计回溯等场景）：折叠终态一致
     之外，还须**按 key 逐条核对每条记录的 RowKind、字段与顺序**——注意同一 key
     先 +I(a) 后 -D(a) 与两条都未发，折叠后终态同为空，但 print sink 序列可观察
     到差异：折叠一致不等于 changelog 序列一致；
2. **key 分组一致性**：按分区键分组折叠逐 key 对比（IDENTICAL 判定）；
3. **多并行与续跑**：代表性用例覆盖多并行度（如 P=4、多 key 基数）与 savepoint
   续跑——批参数与序列化改动最容易在这里露馅；
4. 性能提升必须以零语义代价为前提——性能与行为两条证据链分开归档，缺一不放行。

## 通过 / 不可比条件

**通过**：双端同日锚定、口径记录完整、三指标多跑、观测用例行为冻结全部一致、
作业全部 FINISHED。

**不可比（出现任一即废轮或需补跑）**：

- 跨日比较；**两端 TM 堆配置不一致（无条件不可比，不因补跑而豁免）**——须按
  "双端同口径重跑规则"对齐后重跑再比；
- 一端 OOM/FAILED 用另一端数字出结论；
- 双端 TM 堆配置不一致的轮次进入双端比值汇总（此类只能作参考结论归档）；
- native 库回退未检出（压缩/序列化库加载自检缺失）；
- 查询集/事件规模/并行度任一不对齐；
- 行为冻结未做或未过。

## 结果组织

每轮证据按"查询 → 端 → 轮"归档原始输出；汇总表给：三指标中位数与分位、
**双端比值（倍数，仅同 TM 堆配置轮次）**、带口径差异的参考结论（单列并标注
差异，不计入比值）、内存口径记录、行为冻结结论（MATCH/IDENTICAL 清单）、
废轮原因。验收报告引用汇总表路径，不复制数字——数字只在一处维护。

## 与其它技能的边界

- **环境前置**：双端跑基线前的构建工具/集群健康检查走本域 `flink-velox-env` 子域、
  安装部署走 `flink-velox-install` 子域（只扫不改/装好复核），本协议假设环境已就绪；
- **双端安装**：native 栈与原生栈的安装部署差异由 flink-velox 家族裁决，本协议
  只消费其结果（两端就绪的集群），不重复覆盖环境判定；
- 改码优化（算子/数据桥）走 code-optimizer 侧 `flink-native-stateful-operator-tuning`，
  本协议是其 Methodology 第 1 步的展开；
- 集群参数与资源配置建议（TM 内存公式、并行度推荐）走本域 bigdata-playbook；
- 本协议只管"怎么测可信"，不管"怎么调"。
