# TLBI 离线负载、快照与线性度验证

本指南用于准备和比较当前项目的测试，不预设机器地址、日期、资源规格、CPU 列表、
并发上限或收益。Host/Guest 操作分开记录，只管理本轮确认归属的资源。

## 选择自动化或手动路径

优先审查部署环境中的 `make_ub_image.sh`、`ub_bench.sh` 或同类脚本：

- 核对实际版本、帮助、参数解析、基础镜像、资源规格、默认快照和绑定算法。
- 检查是否修改 Host 时钟/网络/启动项，是否复用共享状态或批量清理不属于本轮的沙箱。
- 脚本写死的规格、CPU 编号或并发上限不作为平台通用约束；需要适配时用受控副本，
  并将适配后的内容固定用于所有对照组。
- 显式传入同一个快照名并核对快照 ID，不依赖脚本默认值；名字中的不同字符也可能
  指向另一份快照。

对确实采用以下接口的脚本，参数化调用方式为：

```bash
bash "$MAKE_UB_IMAGE_SCRIPT" "$UB_PACKAGE" "$SNAPSHOT_NAME"
bash "$UB_BENCH_SCRIPT" "$SANDBOX_COUNT" "$SNAPSHOT_NAME"
bash "$UB_BENCH_SCRIPT" "$SANDBOX_COUNT" "$SNAPSHOT_NAME" --no-pin
```

变量取自已确认的路径与方案，执行前核实接口。绑定/不绑定是布局对照，
`--no-pin` 不是 TLBI 禁用开关。

## 离线材料与 ABI 前提

1. 从包清单或用户输入取得预期 SHA-256 和版本，校验材料包，检查归档路径、
   链接和文件类型；不接受越界路径或在 Host 根目录直接解包。
2. 确认预编译 ELF 的架构、解释器与版本化库依赖。aarch64 二进制不能直接用于
   x86_64；基础镜像的 glibc/Perl ABI 必须满足本批材料要求，不按镜像名称猜测。
3. 核对所带 Perl、libperl 和其他动态库的完整性及实际加载路径。
   不同发行版可能使用不同库目录；只检查 spawn 不能证明 Perl 的依赖也完整。
4. 如果材料带 `make` shim 绕过构建检查，说明它只适用于已验证的预编译产物，
   不能把返回成功当成重新编译成功。更换基础镜像、架构或材料版本后重新自检。
5. 沙箱无外网不自动视为异常。材料已自包含时不运行 apt 联网补依赖；
   缺库、GLIBC 符号版本或 ELF 不兼容时先修复材料/镜像匹配关系。

## 制作可复用快照

1. 按当前项目确定基础镜像、vCPU/内存和测试身份，核对实际 `aenv` CLI 语法。
2. 后台创建测试沙箱，取得并验证真实 ID，再上传材料；不要先占住交互终端，
   或把其他沙箱的 ID 当作本轮目标。优先用已核实的非交互执行接口完成后续步骤。
3. 只在本轮可丢弃的 Guest 内按审核后的归档清单安装。核查有效 CPU 数、
   实际 Perl 路径/版本、Perl 与 spawn 的动态库，并执行真实目标用例自检。
   不对整个目录递归设置可执行位来掩盖权限问题。
4. 自检通过、负载退出且文件写入完成后，使用项目支持的快照接口创建持久快照，
   记录名称/ID、材料哈希、工具版本、基础镜像和 Guest 内核/VMM 身份。
5. 从快照新启动一次验证工具和文件确实保留，确认后才用于正式对照。
   Host 功能切换若不影响兼容性，保持同一快照；涉及 Guest 内核、启动状态或设备 ABI
   变化时按实现要求重建匹配快照，不能跨版本强行恢复。

## 运行 Process Creation

在已确认的 Guest 工作目录中，目标命令为：

```bash
cd "$UNIXBENCH_DIR"
./Run -c "$PARALLEL_COPIES" spawn
```

`-c` 是工作负载并行副本数，不是配置 vCPU 的接口。该值、沙箱规格、并发沙箱数、
预热和外层重复次数由当前实验确定并保持一致。
spawn、Execl 和全量 UnixBench 是不同范围，不得混用结果。

- 检查实际输出包含完整 Process Creation 行、lps、对应 INDEX 和完成状态，
  不能只看退出码、make shim 返回值或日志文件存在。
- 保存每沙箱输出、内部采样说明和外层轮次。UnixBench 自带的内部 samples
  不替代独立实验重复；跳过、失败、OOM 或超时保留记录，不选择性丢弃。
- 同时启动并发任务并核对共同运行窗口；CPU 分配错开不代表负载同时执行，
  负载依次完成更不能称为并发线性度测试。
- 结合当前可用内存、Host/daemon/页缓存预留、CPU 和存储压力控制并发；
  不能只按虚机标称内存之和判断资源足够。

## 控制变量与生效证据

- 比较功能开关时，固定源代码/补丁、其他内核配置、Guest、快照、CPU 映射、
  并发/工作量及背景负载；布局与位图策略变更另外对照。
- 绑核时记录 vCPU TID→逻辑 pCPU→物理核/cluster 映射，检查 SMT 和有效 cpuset。
  恢复后重新识别 TID，使用 `taskset -pc "$VCPU_TID"` 查询，而不是传 pCPU 编号。
- Host 重启后校验实际启动项、机制状态及可信时间。不要把教程时间写回单板，
  也不要在测量中途校时；耗时采用单调时钟。
- 通过所用实现的日志、跟踪或位图观测确认范围机制，不以 cmdline、绑核或
  Process Creation 成绩变化单独证明广播范围已经缩小。

## 指标与线性度

- `lps` 是每秒循环数，越高越好。INDEX 是所用 UnixBench 版本按照内置基准值
  对 lps 归一化的派生指标；读取当前 Run 的规则，不写死归一化常数。
- 固定版本时，lps 与 INDEX 的等比例变化不是两项独立性能证据。
  输出表的 BASELINE 列是归一化参考，不是本轮关闭组的实测结果。
- 只测 spawn 时报告 Process Creation 子项；不能把 Partial Only 总分与
  全量 System Benchmarks Index Score 直接比较。
- 开启收益使用 `(X_on - X_off) / X_off * 100%`。关闭相对开启的下降使用另一个
  分母，不能把该下降比例改称开启收益。
- 每个功能状态分别建立匹配布局/规格的单沙箱基线 `X1`。
  同质并发沙箱的均值为 `mean(Xn)` 时，单沙箱性能保留率为 `mean(Xn) / X1`。
  只有存在共同稳定窗口时，才将同期 `sum(Xn)` 作为聚合吞吐估计，
  并计算扩展倍数 `sum(Xn) / X1` 与效率 `sum(Xn) / (N * X1)`。
- 同时报每沙箱值、资源映射、离散程度和各轮结果，不仅给出一个均值。
  不把并发沙箱间分数的分位数称为请求延迟 P95。

最后区分：布局是否正确、范围机制是否生效、正确性是否通过、该负载是否有收益。
本指南不承诺固定提升，UnixBench 结果也不能直接当作沙箱恢复或真实业务收益。
