# HNSW 候选评估检查项

## visited状态

先确认实现采用位集、字节/整数 epoch 表还是其他表示，再计算真实容量、对齐和每 worker 足迹。省去一次清理可能增加存储或管理成本；应一起测量。复用必须覆盖首次使用、重新借出、容量变化、epoch 回绕和并发隔离。

## 候选容器

统计 push/clear/pop/threshold 等操作的调用比例与 self 成本。摘要、分段或索引加速可能减少读取而增加每次写入的维护开销；根据实际读写比例评价整体效果。

## 预取与局部改写

预取、内联和循环展开可能改变代码布局、流水线与寄存器压力。使用同条件交错对照，区分真实增益与噪声；不以消除调用或某一条指令的采样权重直接估算收益。

## 图实例与结果

查询对照优先加载同一个保存图。若结果变化，依次检查索引哈希、参数、并发、storage 与候选/visited 语义，不预先断言差异只能来自构图。构建优化另行报告图实例方差。

## 证据

路径开关需要实际分派/汇编证明。校验和可辅助定位一致性问题，但不能替代逐结果 ID/距离比较。行号应绑定 commit 与 diff，避免依赖人为固定的源码锚。

## 实验结论

基线漂移超过预声明范围时调查或复测，并保留所有结果；不能以更早的绝对基线覆盖当前漂移。最终记录适用工作负载、限制和 verdict，具体经验留在实验目录。
