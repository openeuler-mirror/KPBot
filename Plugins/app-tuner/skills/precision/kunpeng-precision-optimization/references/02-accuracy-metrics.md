# 精度量化评估

目标：把「结果差得多不多」变成可复现的数字与可签字的验收。

## 两条路线（Q-1）

| 路线 | 做法 | 适用 |
|---|---|---|
| 量化 | 在固定区域、按固定要素算 4 个指标 | 下结论、写验收 |
| 图形 | 画要素分布/差异图（NCL 一类工具） | 定位异常区域、向客户展示 |

先图形后量化：图形告诉你「哪里差」，量化告诉你「差多少、能不能收」。

## 四个指标（Q-2 ~ Q-5）

| 指标 | 含义 | 判定 |
|---|---|---|
| RMSE | 两组数据的均方根偏差 | 越小越接近；0 = 完全一致 |
| ME | 平均误差（带符号） | 越接近 0 越好；反映系统性偏置 |
| MAE | 平均绝对误差 | 越小越好；0 = 一致 |
| Pearson / SCC | 线性相关与空间相关系数 | +1 完全正相关，-1 完全负相关，0 不相关 |

三个组合判据（Q-6）：
- **ME≈0 而 MAE 大** ⇒ 误差正负抵消，不代表精度好。
- **相关系数高而 RMSE 大** ⇒ 形态对、幅值偏，往往是单位/缩放/常数表问题。
- **RMSE 小但最大值差很多** ⇒ 看极值区（降水强度、边界层），均值指标会掩盖局部失效。

## 评估口径（必须写进验收单）

- 区域范围、要素清单、时间步/时刻、对照数据来源与版本。
- 任何一个变化都要重跑基线，否则历史数字不可比。
- 阈值按要素分别设：同一阈值套所有要素必然得出错误结论。

## 脚本形态

一段可直接跑的评估骨架（`netCDF4` + `numpy`/`scipy.stats`）：

```python
from netCDF4 import Dataset
import numpy as np
from scipy import stats

def metrics(a, b):
    # 先统一升到 float64 再相减：整型相减后平方会回绕
    # （int16 下 [256,512] vs [0,256] 差值 256，256**2 溢出为 0，RMSE 会把真实的 256 报成 0）
    a = a.astype(np.float64)
    b = b.astype(np.float64)
    d = a - b
    return dict(rmse=float(np.sqrt((d**2).mean())),
                me=float(d.mean()),
                mae=float(np.abs(d).mean()),
                pearson=float(stats.pearsonr(a.ravel(), b.ravel())[0]))
```

两条纪律：
0. **先做类型提升**：输入若是整型（int16/int32）或混精度，先转成同一个浮点类型再相减。
   整型的差、平方都可能在原类型里回绕，指标会算出「完美一致」这种反向错误结论。
1. 读写同一区域、同一插值口径后再算指标（这类数据常见为 NetCDF/GRIB，需先做保持一致的水平/垂直插值）。
2. 指标算完与运行日志一起归档，形成「版本-指标」对照表。

## 反模式

- 只报相关系数不报 RMSE——形态一致但量级错了看不出来。
- 换了对照数据版本还拿来比历史数字。
- 用单点最大值当全局结论（极值区噪声大，需多时次平均）。
