# P/D 环境采集

## 工作流程

1. 确认每个容器所在节点、容器名和角色（`P` 或 `D`）。只采用户指定的对象；
   角色不明确时先确认，不按容器名猜。跨机器时各自在容器所在的宿主机执行。
2. 在父 skill 目录运行 `bash scripts/discover.sh` 检查环境。给每个容器一个空的或
   尚不存在的输出目录，每次只传入一个容器。若容器名与本地已有目录同名，先换
   工作目录，并用父 skill 的绝对路径调用采集脚本，避免被识别为采集包。
3. 按用户指定的角色执行对应命令。

```bash
bash scripts/collect.sh <P容器名> --role P --out <P输出目录>
bash scripts/collect.sh <D容器名> --role D --out <D输出目录>
```

`--role` 只写整包标签，所以同一台机器上的 P、D 也要分两次采。用户提供容器内的
Python 路径时，可以加 `--python`；解释器画像是否完整以采集结果为准。

## 输出

- 每侧分别记录节点、容器名、角色、采集时间和实际产物路径。可交给后续流程的
  快照是 `采集/` 目录或 `采集.tar.gz`；`采集/环境报告.html` 用于快速查看。
- 检查 `采集/collection_meta.json` 的 `targets`、`role`，并读
  `采集/SUMMARY.txt` 区分成功、跳过和失败。退出码为 0 不代表所有项都采齐。
- 失败或中断时，列出原因、已保留的产物及其完整性。

采集沿用父 skill 的只读约束。采集包可能包含完整环境变量和启动参数，答复只引用
受限产物路径。
