# mem0/milvus 基准统计设计（组内/组间 CV + 方案 C）

## 何时使用

- 要判断"某组快了 7% 是真快还是执行机外部负载漂移"。
- 要多组多轮对比，且每轮底库必须一致。
- 要设计一个"存档轮不计分、clone 轮作数据点"的可复现统计口径。

## 核心原则

1. **数据池一致性优先**：先让多轮底库逐字节一致，再谈噪声分解；否则"快"可能来自少干活。
2. **组内 CV 看测量紧致、组间 CV 看系统性效应**：一起报，缺一个都会误判。
3. **存档轮不计分**：每组第 1 轮 build+seal 只固化底库，3 个 clone 复用轮才是数据点。
4. **组间隔离**：每组独立黄金前缀，避免 clone 卷串组。

## 步骤

### 1. 方案 C 轮结构

```
每组 4 轮：
  轮1 = build + seal 存档轮（不计分）
  轮2..4 = 3 个黄金卷 clone 复用轮（数据点）
组间独立黄金前缀：blg*_g{1..3}
```

9 个数据点数据池完全一致（起点/终点行数实证），组间 CV 不被数据池漂移污染。

### 2. 组内 CV 与组间 CV 分解

对每指标（吞吐 / 分位时延 / elapsed）报告三列：

| 指标 | 组内均值 | 组内 CV%（区间） | 组间 CV% |
|---|---|---|---|
| qa.retrieval 吞吐 | 80.46 / 80.23 / 74.65 | 0.38-0.67 | **4.19** |

判读：组内 CV <1.5% 且 g1/g2 均值几乎重合、g3 系统性偏慢（吞吐/elapsed 类 ~7%、p50 类 ~15%），呈"组内离散度低 + 组间台阶"形态。
这只支持**描述性观察**——"g3 均值相对 g1/g2 存在约 7%（吞吐/elapsed 类）~15%（p50 类）组级偏移"；偏移是外部负载还是被测回归、
是否与被测改动相关，属 **inconclusive（原因待定）**（标定案例里时段与组别一起变化，跨 66min 窗口，
CV 无法区分这两类组级差异，需交错组序重测或对齐主机负载记录后才能下结论）。g3 贡献了组间 CV 绝大部分。

### 3. 读懂偏移来源

- **组内紧致 + 组间偏移**：同一数据池内多轮高度一致，但组间有台阶 → 描述为"组级偏移"，不直接归因外部漂移；
  要判 inbound/outbound 漂移按 `verify-optimization/references/repeated-measurement.md`（既有真源，仓库已存在）规则另行判定。
- **组内松散**：单轮本身不稳定 → 先修 seed/相位稳定性（`benchmark-seed-stability`，独立 PR 待合入）再谈对比。
- **组间偏移该不该追**：把 1.5%（组内）与 3%（组间）当作**观察阈值/复测触发线**，不是验收门禁——超过只说明
  "值得复测"，要么独占机器重测，要么把外围负载窗口纳入记录，要么交错组序排除时段混淆；结论仍停留在
  "偏移不可归因"，不是"可归因到被测改动"。

## 验收清单（描述性，非放行门禁）

- [ ] 数据池一致性经起点/终点行数实证（内容层另加数据摘要，见 references §1）
- [ ] 存档轮不计分、clone 轮作数据点
- [ ] 组内 CV 与组间 CV 并报，且写明 std 用样本分母（n−1）
- [ ] 组间独立前缀（不串组 clone）
- [ ] 偏移表述为描述性观察（组内离散度 / 组间台阶），显式标注 inconclusive，未下因果结论

## 结果（标定案例形态）

- 分组压测组内 CV 0.20–1.46%、组间 CV 4.07–4.24%（吞吐/elapsed 类）、p50 8.38%（样本标准差分母）；
  g3 相对 g1/g2 系统性慢——吞吐/elapsed 类 ~7%、p50 类 ~15%；且时段与组别一起变化（跨 66min 窗口），偏移
  **不可归因**（inconclusive）——这是"组内离散度低 + 组间台阶 → 描述性观察、不下因果定论"的典型场景，
  不是"组级效应 vs 噪声"的二分判定。
