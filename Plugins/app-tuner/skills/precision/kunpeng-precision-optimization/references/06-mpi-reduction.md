# 并行归约：求和顺序导致的差异

## 机理（P-0）

浮点加法不满足结合律：`(a+b)+c ≠ a+(b+c)`（末位不同）。归约树形状一变，结果就变。
两个独立变量都会改树形：
1. **归约算法**（实现内部选择，常随报文大小、节点数、环境变量而变）。
2. **进程数/线程数**（改变切分与参与集合）。

判据：结果随规模变化而变化，且单进程下可对齐 ⇒ 差异在 L4，不是编译器或库的问题。

## 两条处置路线（P-1 / P-2）

### P-1 统一归约算法（首选，不改代码）

让两侧按**同一顺序**归约（典型是「按 rank 的 recursive doubling」）。

| 库 | 参数形态 |
|---|---|
| Hyper MPI | `UCX_BUILTIN_ALLREDUCE_ALGORITHM=1` |
| Intel MPI | `-genv I_MPI_ADJUST_ALLREDUCE=1` |

判据：两侧都设成 1 后差异消失 ⇒ 差异纯来自归约算法；仍不一致 ⇒ 进 P-2 或回上层排查。
参数名与取值是实现相关的，换 MPI 实现必须重查（不要跨实现搬运）。

### P-2 重写归约（要改代码）

**先纠正一个常见误解：本地排序不能保证跨树可复现。**

反例：三个 rank 各持一个 double 值 `1e16`、`-1e16`、`1`。本地排序不改变任何输入（各进程只有一个元素），
于是归约结果完全取决于树的形状：`(1e16 + (-1e16)) + 1 = 1`，而 `(1e16 + 1) + (-1e16) = 0`。
两种树都给不出同一个答案，排序对此无效。

排序只能消除「同一集合的输入顺序不同」这一类差异；它**消除不了结合顺序**（树形）本身。
要承诺「跨进程数、跨算法可复现」，必须让**加数的全局累加顺序固定**，两条现实路线：

| 路线 | 做法 | 代价 |
|---|---|---|
| 固定全局顺序 | 按全局索引（而非 rank）顺序累加：收集到单点顺序加，或按固定分段做确定性部分和再按固定顺序合并 | 通信量/串行度上升，扩展性变差；适合小向量、低频调用 |
| 可复现累加器 | 每个进程用可复现求和（Neumaier/Kahan 变体，或 reproducible summation 算法），合并时也保持同一确定性规则 | 每元素多几次浮点运算；需验证算法本身对树形不敏感 |
| 定点/整数化 | 把浮点按共同指数缩放成定点整数求和 | 受动态范围限制，需处理溢出与精度损失 |

因此：

- 适用（排序路线）：值的集合由数据决定、进程数固定、且组内元素数 > 1 的重排场景——把「输入顺序不同」抹平。
- 不适用：单值/小向量归约、进程数或算法会变的场景——这类必须走「固定全局顺序」或「可复现累加器」。
- 无论哪条路线，验收都要写清：进程数、算法、累加器类型，并在 32/64/128 进程上重跑确认。

## 算法选型（P-3 ~ P-5）

主流 MPI 实现提供多种 Allreduce 算法，按**节点内/节点间**分别选择，常见类型：

| 类型 | 节点内 | 节点间 | 特点 |
|---|---|---|---|
| Recursive doubling | RD | RD | 顺序最「确定」，适合对齐验收 |
| 混合树（Binomial / K-nomial） | 树 | RD | 性能好，顺序随树形变 |
| Ring | 环 | 环 | 中大包才启用（常见阈值 16384 字节/进程） |
| 节点/socket 感知变体 | 按拓扑选 | RD | 拓扑感知，顺序最不稳定 |

- P-3：算法选型同时影响**精度（顺序）**与**性能（树高/环长）**，换算法必须重测四指标。
- P-4：小包走树类、中大包走环类，是实现的默认策略；阈值是实现相关的，需实测确认。
- P-5：拓扑感知算法在大规模下性能最好，但顺序最难复现——要 L2 就关掉感知变体。

## 落地纪律（P-6）

1. 先固定进程数与网格切分，再谈算法差异（不要两个变量一起动）。
2. 用 P-1 做最小改动验证：一致 ⇒ 结论成立；不一致 ⇒ 差异不在归约顺序。
3. 只有 P-1 不够时才上 P-2；上线前四指标 + 性能回归一起验收。
4. 线程归约同理：OpenMP reduction 的合并顺序也随线程数变，线程层建议固定线程数或做确定性归约。

## 反模式

- 只改 MPI 参数就宣布「精度问题已解决」，却没重跑多规模（32/64/128 进程）确认。
- 用「本地排序」当可复现方案却没做单值反例测试（`1e16`、`-1e16`、`1` 三进程必现 1 与 0 两种结果）。
- 把「进程数变了结果变了」当 bug 追，忽略网格切分这个正常变量。
- 在验收单里不写清进程数/线程数，导致数字无法复现。
