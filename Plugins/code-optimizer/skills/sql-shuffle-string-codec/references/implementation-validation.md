# 字符串内存与 LZ4 兼容性验收

## 所有权与固定拷贝

沿输入、输出向量、序列化缓冲和解压缓冲画出拥有方及销毁点。视图只复制指针时，目标必须持有原缓冲；目标独立持有长串时，分配空间、复制有效字节后再发布视图。用输入释放或复用后的读取检查发现悬空引用。

对 W=16、16<=n<=32，头尾两次加载和存储均在各自 n 字节区域内。头尾目标重叠不代表允许任意源目标重叠；若范围别名，证明加载/存储顺序安全或使用原有 memmove 语义。13–15 字节回退或采用另外已证明有界的实现，不能读取指针前的字节。

## 读端

使用所属缓冲区的实际边界检查一次加载宽度，检查 offset、length、offset+length 的溢出与合法性，再构建引用。可读 16 字节只是候选的一个条件；仍需正确的布局、字节序、对齐/非对齐规则、ISA 分派及活跃缓冲寿命。无填充、边界不足、跨块或损坏输入按原契约处理。

## LZ4 双向兼容矩阵

固定同一批原始序列化字节，使用真实原版/候选库执行四组：原压原解、原压候解、候压原解、候压候解。每组检查解码状态、解码长度及逐字节相等，再经 reader 重建并比较行值/NULL/顺序。压缩字节可以改变，只有传输协议要求确定性时才要求压缩流也相同。

分别覆盖实际使用的 Block/Frame、字典模式、块大小、不可压/高重复输入、短输入和尾部。Frame 覆盖头、块链接、校验和及截断处理；目标未使用的模式标为未测。候选定位哈希改变不得破坏 offset、匹配验证和尾部加载界限，五字节参与哈希不证明只加载五字节。

记录两库版本、构建选项、加载路径、固定随机种子、每组块数、失败输入及错误。Sanitizer 同种子双边失败需要定位并记录未解决项，不能凭“双边均失败”记为通过；已有历史案例不替代本轮运行。

## 工作量与性能

审计写端/读端快路径命中与各回退原因，记录压缩/解压调用、输入输出字节及结果校验。正式测量关闭额外审计，分别比较拷贝、重建、压缩、解压、压缩率、峰值内存和完整查询，不仅汇报压缩速度。无真实编解码器证据时标记 `awaiting_target_evidence`。
