# 跨架构计算精度优化（一致性判定与调优）

HPC 程序换架构、换编译器、换并行规模后结果对不上，是迁移期的头号阻塞项：单点末位差异会在长迭代里
被放大成根本不可比的输出。本技能提供一套**分层隔离 + 量化验收**的判定方法：先证明差异在哪一层，
再决定用编译选项、库替换、并行参数还是改代码兜住。

只做判定与口径：不执行编译、不跑压测、不改用户代码；给结论时必须能追到「哪一层、什么证据、怎么复现」。

## When to Use（何时使用）

- 迁移到鲲鹏/ARM 后结果与 x86 不一致，或换编译器/换选项后结果变了
- 要决定开不开 `-fp-model fast` / `-ffp-contract` / `-ffast-math` / `-finit-array`
- Allreduce 后结果差最后几位，怀疑归约顺序
- 只改进程数/线程数结果就变，要判定是缺陷还是正常差异
- 要给「精度达标」下一个可验收的定义（RMSE/ME/MAE/相关系数）
- 要一套能回滚、能交接的调优流程

## 心智模型：四层误差栈

| 层 | 差异来源 | 典型证据 | 兜住手段 |
|---|---|---|---|
| L1 代码语义 | 数组/值域越界、未初始化内存、未定义行为 | `-O0` 与 `-O3` 结果不同；换编译器才暴露 | 修代码、加边界断言 |
| L2 编译器变换 | 优化级别、浮点模型、向量化、循环重结合、FMA 收缩 | 选项逐项加回能锁定单个 flag | 选项集 / 单文件降级编译 |
| L3 库实现 | 数学库近似实现、x86 40/80 位扩展精度路径 | 符号级比对、接口清单 | 换库 / 软浮点补偿 / 多精度模拟 |
| L4 求和顺序 | MPI 归约算法、线程内归约、网格切分 | 进程数或线程数一变就变 | 固定归约算法 / 固定全局累加顺序 |

**排查顺序固定为 L2 → L3 → L4 → L1**：前三层改配置就能验证，成本低；L1 要读码改码，最贵放最后。

## 验收等级（本技能约定）

| 等级 | 含义 | 何时用 |
|---|---|---|
| L0 | 单线程、同机、同配置可重复 | 调优期间的回归基线 |
| L1 | 同平台多进程结果一致 | 排除并行引入的差异 |
| L2 | 跨平台、同配置结果一致 | 客户要求「结果一致」时的目标 |
| L3 | 跨平台、跨规模统计等价（四指标在阈值内） | 现实生产目标；L2 不是总能拿到 |

先问客户要哪一级：要 L2 就必须连编译器版本、库版本、优化级别一起锁死；要 L3 才允许用统计口径验收。
不要把「完全一致」当默认目标——代价指数上升，且常常物理上不可达（例如 x86 的 80 位扩展精度路径）。

## 快速判定表

| 现象 | 先判 | 处置 |
|---|---|---|
| 换编译器后结果变 | L2 | 选项逐项加回（05 章 G-1） |
| 只有极小值区不同 | L3 | FTZ/DAZ 顺序差异，接受或算法层归一化（03 章 D-3） |
| `-fp-model precise -O3` 与 `-O0/-O1` 不同 | L2 | ICC 循环重结合缺陷，受影响文件降 `-O1`（04 章 F-8） |
| r2c/c2r 数值对不上、`pow` 类差末位 | L3 | 80 位扩展精度路径，多精度库或改算法（03 章 D-2） |
| 归约后差末位、随进程数变 | L4 | 统一归约算法；要跨规模可复现则固定全局累加顺序（06 章） |
| 一关优化差异就消失 | L1 | 未定义行为，修代码（07 章） |

## 流程

1. **定等级与基线**：确认 L0–L3 目标；固定硬件、编译器版本、库版本、算例，记录对照结果（01 章）。
2. **过一致性 CheckList**：代码与算例指纹、编译器版本、O0–O1 对照、单线程一致、选项集显式（01 章）。
3. **分层隔离**：按 L2 → L3 → L4 → L1，每层给出「有证据的排除」而非猜测（03 章决策树）。
4. **实施调优**：编译器与库（04 章）→ 并行归约（06 章）→ 应用代码（07 章）；每步先写回滚动作。
5. **量化验收**：四指标 + 图形法；达标归档，未达标回第 3 步（02 章）。

## 反模式

- 目标定成「完全一致」：后期成本指数上升，且部分差异物理不可消除。
- 一上手就改代码：先查编译选项与库，这两类最常被跳过。
- 变量一起动：编译器、库、进程数同时改，结论不可归因。
- 单次测量下结论：不写进程数/线程数/版本的精度数字无法复现。
- 把「进程数变了结果变了」当缺陷追：网格切分变化是正常差异源。
