# 五章报告骨架模板

以 CubeSandbox CubeMaster create-path 优化报告为实证蓝本（该报告对标参照报告的
水准并补齐其成本模型、争用放大、故障屏障三个质量维度）。章节名按项目语境改写，
骨架不变。

## 标题与摘要

- 标题：`<系统> <组件> <路径>性能分析与优化报告`
- 开篇 3-5 行结论摘要：做了什么、收益多少（权威口径数字）、证据在哪。

## 一、底座与关键路径解剖

| 小节 | 内容 | 模板 |
|---|---|---|
| 1.1 底座构建与实验身份 | 双臂构建、sha256、版本注入、工具链、patch 校验 | 表格：臂 × {sha256, 版本串, patch 符号数} |
| 1.2 执行链路图 | 请求从入口到落库的完整路径（文字链 or mermaid） | `client → API → Master(handler→service→db) → Cubelet → …` |
| 1.3 负载与调用模型 | 负载形态（并发/轮次/对象）、单请求调用序列 | 调用序列列表 + 每步预期的读写 |

要点：读者看完第一章必须能回答"测的是什么系统、哪条路径、负载长什么样"。

## 二、观测口径与标定

| 小节 | 内容 | 模板 |
|---|---|---|
| 2.1 采集口径 | pprof 端点与窗口、语句普查方法（如 performance_schema 的 events_statements_history_long，注意 prepared statement 在 digest 表不可见的坑）、窗口对齐方式 | 方法描述 + 采集命令 |
| 2.2 负载期热点函数 | 负载窗口内 cum 排名 | 表：函数 × base cum / patched cum / 变化 |
| 2.3 逐轮延迟分布 | 每轮 min/avg/p50/max + 语句增量逐轮表 | 轮次 × {total_time, SELECT+, INSERT+} |

要点：**口径先于数字**。窗口要与负载时长匹配（实证：30s pprof 窗口配 7.5s 负载，
后 22s 是空闲 GC 噪声，稀释了信号——条件允许应缩窗重采，条件不允许就如实披露）。

## 三、方案与验证

| 小节 | 内容 | 模板 |
|---|---|---|
| 3.1 瓶颈定位 | base 组证据：热点 + 语句普查数字（如 SELECT ~315/轮，其中重复读占 X%） | 普查表 + 引用 2.2 热点 |
| 3.2 优化手段 | patch 内容分层描述：缓存什么、何时失效、异步化什么、失败路径 | 改动文件列表 + 机制图 |
| 3.3 运行时效果 | 热点消失/迁移对照（如 QueryContext -93%、同步 UPSERT → 后台 worker） | 前后对照表 + 火焰图引用 |
| 3.4 成本模型与争用放大 | 直接节省 = 消除的调用数 × 单次成本；实测节省 ≠ 直接节省时归因（锁/连接池/GC 争用放大） | 两栏对比 + 放大倍数 + 归因 |
| 3.5 验证屏障 | 故障注入矩阵：注入什么故障 × 期望行为 × 结果（如 34 个 Go fault 用例：缓存损坏/持久化失败/并发竞争） | 用例组 × PASS/FAIL |

要点：3.4 和 3.5 是与普通报告拉开差距的两个维度——前者解释"为什么收益比纸面大
（或小）"，后者证明"安全机制不是纸面的"。

## 四、独立发现与改进建议

实验途中撞见、与本方案无直接因果但有价值的观察。实证案例：

- 无索引全表扫描（lifetime 2600 万次查询的路径）
- 后台清理器的僵尸记录 kill-retry 循环
- GOMAXPROCS 未设上限导致 GC 放大

每条给：现象 → 证据 → 建议动作。标注"未在本方案中处理"。

## 五、证据与复现资产清单

```
docs/<报告目录>/
├── <系统>_<组件>_<路径>_优化报告.md   # 本文
├── experiment_summary.txt            # 实验总账（人机两读）
├── <方案标识>.patch                   # SHA256 钉死
├── flamegraphs/  base/patched/diff .svg
├── reports/      逐轮 bench ×2臂 + 普查 ×2臂 + 生命周期门禁 ×2 + 环境指纹
└── scripts/      采集/清理/折叠/门禁脚本
```

每个文件一句话说明。清单即复现手册——按 scripts/ 的顺序应能重跑出 reports/ 的
数字。

## 数字呈现规范

1. 每个性能数字带三要素：**轮数 + 清理协议 + 统计量**（"5 轮均值（轮间全量清理）"）；
2. 对照收益两种写法并用：绝对值（133.6→128.1ms）+ 相对值（-4.1%）；
3. 权威口径与本次标定并列时，注明各自协议差异（哪次是历史 CI、哪次是本次标定）；
4. 语句/热点类计数给倍率（÷52）比给差值（-309）直观。
