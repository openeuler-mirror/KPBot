# Kitex 传输与连接参数对照

## 1. 事件循环线程数（poller）

| 项 | 内容 |
|---|---|
| 默认值 | `runtime.GOMAXPROCS(0)/20 + 1` |
| 位置 | netpoll 全局配置，Kitex 本身不设置 |
| 生效时机 | 必须在建立任何连接之前 |
| 建议起点 | `max(NUMA 节点数, GOMAXPROCS/16)`，在 8/16/32 上对比 |
| 风险 | 线程过多带来空闲开销与上下文切换；过少导致事件处理串行 |

判定方法：先看系统调用在 CPU profile 中的占比与事件循环线程的负载分布，再看增加线程数后吞吐是否随之上升。线程数不足时，曲线会先升后平；到达平台期即说明瓶颈已转移。

## 2. 连接形态

| 形态 | 适用 | 代价 |
|---|---|---|
| 独占连接池 | 低并发、需要连接级隔离、语义要求简单 | 并发度受连接数限制；每请求要获取/归还连接，存在锁竞争 |
| 复用连接（mux） | 高并发、连接数受限、下游实例少 | 引入分片映射锁与乱序响应；长尾可能变差；超时与重试语义需回归 |

判定方法：观察 fd 随并发增长的速度、连接获取锁等待、以及切换复用后 P99 的变化。若吞吐上升但 P99 明显恶化，需要权衡是否可以接受。

## 3. 连接池参数（非复用）

| 参数 | 默认 | 调整原则 |
|---|---|---|
| 单地址最大空闲连接 | 10 | 与并发度匹配；过小会把锁竞争转成 dial |
| 全局最大空闲连接 | 100 | 与下游实例数 × 每实例空闲数匹配 |
| 最大空闲时间 | 1 分钟 | 过短会频繁重建连接，过长占用 fd |

验证时同时看：fd 数量、dial 次数、连接获取锁等待、P99。

## 4. NUMA 与中断

- 事件循环线程与接收网卡中断尽量同节点；跨节点会放大 P99。
- 判定方法：对比服务端与压测端/上游同节点、跨节点两种部署的同口径结果，确认差距后再决定布局。
- 绑核、IRQ 亲和、sysctl 由系统层技能执行，本 skill 只输出"应放在哪个节点"的结论。

## 5. 命令速查

```bash
# 当前 fd 与连接
ls /proc/<pid>/fd | wc -l
ss -s
ss -tn state established '( sport = :8888 )' | wc -l

# 锁与阻塞（需在服务里显式开启采样）
curl -s -o mutex.prof "http://127.0.0.1:6060/debug/pprof/mutex"
go tool pprof -top -nodecount=15 bin/server mutex.prof

# 系统调用分布（定性）
timeout 5 strace -c -f -p <pid>
```

## 6. 回退

| 动作 | 回退 |
|---|---|
| 设置事件循环线程数 | 删除该配置调用并重编译 |
| 切换复用连接 | 移除复用选项，恢复独占连接池与默认参数 |
| 调整池参数 | 恢复原空闲连接数与超时 |
