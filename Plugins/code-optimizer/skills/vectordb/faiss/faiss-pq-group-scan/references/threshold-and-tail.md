# 阈值与尾部

## 启用阈值

分组核的可摊销固定成本（scratch 栈帧、循环序言）与列表长度无关；转置按完整 tile 发生、随码数增长，属于每码成本而非固定成本：

- 测量方法：固定 M 与查询形态，扫列表长度（如 2 的幂及中间点），报告每码总成本（含转置摊到每码的部分）与逐码路径的比值；交叉点即阈值，取整后加安全余量。
- 若每码转置成本已超过每码计算节省（比值曲线不随列表长度下降、无交叉点），维持原逐码路径，并在结论中显式记录"无适用区间"。
- 阈值以上用分组核，以下直接走原路径；验收规则与技能正文一致——未声明容差时逐 ID/距离精确一致；声明容差时 Top-K ID 仍按基线结果与原并列规则精确校验，数值容差只作用于对应距离；若实验允许 Top-K 成员变化，单列质量门槛与验证方式。
- 阈值依赖 M、lane 数与平台；换条件重测，不沿用旧值。记录"低于阈值回退"为显式 guard，不隐藏在运行时试探里。

## 组宽选择

- 剩余码数决定 R 档位（如 ≥16 组用 R=16，≥8 用 R=8 …）；每次调用返回实际处理的码数，外层循环推进。
- 尾组不满时降档而非填充假码：填充会引入假距离，破坏统计与结果语义。
- 档位集合以寄存器与代码体积为上限；收益曲线平顶即收敛。

## 尾段

- 剩余码数 < L 时回退四码/单码原路径；该路径本身也要覆盖（非 4 倍数余数）。
- M 非 tile 倍数：tile 内残维用标量填充转置；表行寻址按 m0+t 计，不越界。
- 过滤路径：带 IDSelector 时分组核不适用（跳过逻辑破坏 lane 对齐），整段回退原路径；无过滤是启用前提之一，须在 guard 中一并判断。

## 验证

- 阈值两侧、每个 R 档位、尾段各形态与基线一致（声明容差时 Top-K ID 按基线与原并列规则精确校验，容差只作用于距离）。
- 工作量计数（扫描数）一致；Recall 与 ID/距离比对通过后再进入性能对照。
