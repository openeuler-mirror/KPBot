# 优化字符串搬运与 Shuffle 压缩

从实际使用的列和缓冲区出发，分别诊断输出字符串、序列化、压缩和接收端重建。保持读写的行值、有效字节、缓冲区所有权及编码契约。

## 输入

| 输入 | 核对内容 |
| --- | --- |
| 业务入口与物理计划 | SQL、列类型、哪次 Exchange 使用 native Shuffle、读取文件的编解码器 |
| 写入与读取入口 | 连接输出、序列化、打包、压缩、解压、字符串视图重建的实际调用 |
| 字符串输入 | 字节长度分布、空值、内联边界、跨块和缓冲区尾部的占比 |
| 缓冲区与构建 | 所有权、实际可读和可写范围、别名、CPU 特性、字节序、加载库与编解码模式 |
| 验证材料 | 真实或代表性的 Shuffle 缓冲区、原版与候选库、完整结果和既定性能指标 |

## 执行步骤

### 1. 区分文件读取和 Shuffle 数据交换

从实际计划和加载的库追踪两条路径。输入是 Snappy Parquet 时，LZ4 的耗时仍可能来自 native Shuffle。先确定目标究竟是输出字符串、序列化拷贝、压缩、解压还是字符串视图重建。

```text
读文件 → 算子输出列 → Shuffle 写入 → 压缩并传输 → 解压 → 重建输出列
```

分别核对写入数据的分区、长度分布、压缩表模式和实际 CPU。对于循环里的短串或 SIMD 候选，确认其在真实输入中有足够调用量。

### 2. 梳理连接输出的所有权

区分已经存进字符串视图的短串和通过指针引用的长串。短串可在布局一致时直接写入目标槽位。需要独立持有的长串先分配目标空间，再逐块复制并建立引用。处理空值、空串、跨块及字典索引，验证输入缓冲区释放后输出仍可读取。

### 3. 定义固定宽度拷贝的适用范围

用字节数检查源地址和目标地址的真实范围。对宽度 16、长度 16–32 字节的数据，可在允许的别名条件下，把头尾各 16 字节复制到对应位置。

```text
20 字节例子
第一次  第 1–16 字节 → 目标的第 1–16 字节
第二次  第 5–20 字节 → 目标的第 5–20 字节
重叠的第 5–16 字节写入相同内容，最终 20 字节完整
```

在代码中用范围或容量检查确定是否进入候选。13–15 字节不能直接用「尾端回退 16 字节」的公式；须证明另外的短分支安全，或交回原实现。偏移、整数算术、容量、源目标别名和每次实际写入范围都要核对。

### 4. 对读端设置实际可读边界

进入向量化重建前检查该 ISA 已构建且运行时可用，并确认字节序、对齐或允许的非对齐访问及指令实际读取宽度。字符串声明长度不能证明缓冲区有足够字节。尾部不足、无填充、数据跨块或布局不符时走原构造路径。输出引用应由能活到读取结束的缓冲区持有。

### 5. 将哈希改动限定在候选定位

确认当前搜索的表模式、哈希输入宽度和实际加载宽度。LZ4 的「取五字节参与哈希」不必然意味着机器只读五字节。要核对最后一次加载的位置、边界与回退分支。

以 `ABCDX` 与 `ABCDY` 为例，前四字节相同，第五字节可用于改变候选索引。找到候选后仍核对实际匹配，保留既定格式、编码规则和合法的解码结果。测试时分开比较压缩流、解压字节与序列化结果。

### 6. 用样本和跨版本读写验证

| 场景 | 检查点 |
| --- | --- |
| 0、内联边界、13–15、16、20、32、33 字节 | 分支、拷贝范围、尾部及相邻数据 |
| 空值、空串、长串、跨块、输入释放 | 值、顺序、引用有效期和目标字节 |
| 缓冲区末端、无填充、对齐变化 | 实际加载宽度和回退 |
| 原版与候选交叉解码 | 原压候解、候压原解，以及各自的往返校验 |
| 格式完整性与结果一致性 | 正确性、帧兼容及完整查询结果；如覆盖无效输入，保持原错误语义 |

序列化链路在契约要求时逐字节对比。压缩候选变化时，用解码结果和格式兼容性判定功能正确，并单独记录压缩流是否变化。

### 7. 分别测局部和完整查询

原版与候选回放同一批代表性输入。先确认候选实际执行，再分开记录拷贝、重建、压缩和解压的时间、输入与输出字节和内存。完整查询使用相同资源、输入布局和计时边界。需要归因到单个改动时，只切换该项；多项合并成绩按合并候选报告。

## 输出

- 文件与 Shuffle 调用链、实际加载的库、优化分支及回退原因。
- 适用字节范围、源和目标容量、别名及引用寿命约定。
- 局部样本和结果对照、交叉解码、边界命中及完整查询校验。
- 压缩前后字节数、各阶段耗时、峰值内存与完整查询配对结果。

```text
模式 | 字符串长度分布 | 写/读候选命中 | 压缩前后字节数 | 解码耗时 | 精确结果 | 查询耗时
```

## 约束

- 以字节而非字符作为内联、拷贝和读取宽度的单位。
- 各次读写须落在已证明可访问的区域，且符合容量、别名和编解码器对尾部的约定。
- 输出或引用不能悬空。保持空值、空串、长度和有效字节语义。
- 字符串处理候选不改变已有传输布局。压缩器改动保留约定格式和双向解码兼容。
- 独立对比压缩大小、局部耗时和整条查询表现，记录尚未覆盖的架构或分支。

## 实施与验收细节

修改拷贝、读端和压缩器时，读取[内存与兼容性验收](references/implementation-validation.md)。Python 合成用例只检查拷贝几何和简化读端分派，所有权、ISA、原生内存安全及真实 LZ4 交叉兼容另外验证。

## 本地用例

在 `cases/shuffle-contract/` 中执行 `python3 run.py`。除原有长度、越界写拒绝和读端分派外，用例增加 88 组源/目标偏移与边界组合，含 44 组目标容量恰好够用、22 组源和目标偏移都非零，逐字节检查目标区域、区域外哨兵及源缓冲区不变。结果写入用例目录的 `results/result.json`，`case.yaml` 还要求失败数为 0、失败明细为空。

用例使用普通控制流决定成功和退出码，`python3 -O run.py` 或 `PYTHONOPTIMIZE=1` 下仍须检测错误实现。Python 用例只验证拷贝几何，不验证原生指针越界、别名、所有权或 ISA；LZ4 兼容性仍需真实编解码器。模型评估规格在 `evals/evals.json`，Velox、Gluten 和 LZ4 的仓库、相对路径、固定源码参考与历史验证边界见 [Q67 案例](references/velox-q67.md)。
