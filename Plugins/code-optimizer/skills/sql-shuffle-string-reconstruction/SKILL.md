# Shuffle 读端字符串视图重建

## 说明与范围

从解压后缓冲区重建字符串输出列，单独处理实际可读范围、内联布局、ISA 分派及输出引用寿命。序列化写入和 LZ4 压缩算法保持现有契约。

## 与总入口及其他技能的分工

本 skill 是 [sql-shuffle-string-codec 总入口](../sql-shuffle-string-codec/SKILL.md) 登记的接收端实施单元，只处理解压后字符串视图重建及所引用缓冲的寿命。总入口选择优化阶段并组织组合验收。[写端固定拷贝](../sql-shuffle-fixed-width-copy/SKILL.md) 的可写容量证明不能代替 reader 的实际可读范围；[LZ4 候选查找](../lz4-hash-candidate-optimization/SKILL.md) 负责压缩器内部改动和真实编解码兼容矩阵。

## 输入

| 输入 | 核对内容 |
| --- | --- |
| 读端入口 | Shuffle reader 重建循环、长度/偏移来源、解压缓冲所有权及消费时机 |
| 内存与布局 | 实际缓冲大小、字符串范围、内联阈值、槽位布局、字节序及对齐约定 |
| 目标能力 | 构建时 ISA、运行时 CPU 特性、允许的非对齐访问和安全标量回退 |
| 验证 | 无填充尾部、跨块/损坏输入、输入释放与输出消费用例及读端基线 |

## 实施步骤

### 1. 定位解压后的构造成本

区分解压耗时与逐条 StringView 重建。记录真实 reader、输出列和内联字符串比例；确认目标热点需要宽加载而非修正 codec。

### 2. 先校验逻辑值范围

用所属缓冲大小验证 offset 与 length，防止整数溢出。损坏、负偏移、跨块及声明长度超出边界时保持原错误处理；不能用宽加载分支掩盖无效数据。

### 3. 建立宽加载准入

除内联布局匹配外，还要确认一次实际加载宽度可读、ISA 已构建且 CPU 可用、字节序一致、对齐或非对齐规则合法。例：12 字节字符串紧贴无填充缓冲末端，不能凭长度执行 16 字节读取。

### 4. 保留标量构造与拥有方

尾部可读不足、空串、非内联串或能力不符时沿原构造。非内联 StringView 指向解压缓冲时，输出应持有缓冲；如果 reader 会提前复用，复制到输出拥有空间。

### 5. 验证边界和重建值

覆盖内联阈值前后、0/15/16 字节剩余空间、非零偏移、无填充、非对齐、缺 ISA、NULL/空串及长串。对照值、NULL、长度、顺序及缓冲寿命，不能只比较是否进入快路径。

### 6. 分别衡量构造与查询

在相同已解压输入上测宽路径与回退成本、实际命中及输出内存。再做同资源查询配对；保留原压缩器，避免把压缩率变化当成重建收益。

## 约束与回退

- 可读 16 字节只是准入条件之一；字符串声明长度不能证明实际缓冲可读范围。
- NULL 位图、字符串布局和输出顺序沿用原协议；不符合布局或能力条件时保留通用构造。
- 输出对长串的引用必须持有缓冲或独立复制，不能因成功构造视图就认为生命周期已解决。

## 交付与验收

交付 reader 调用链、布局/ISA/范围准入表、输出所有权和反例。记录 `内联比例 | 宽路径次数 | 尾部/ISA/布局回退 | 值与寿命校验 | 重建耗时 | 查询秒数`。

实现与证据细节见 [实施参考](references/implementation.md)。

## 本地用例与验证边界

从 Skill 根目录运行 `python3 cases/reconstruction-contract/run.py`，按 `cases/reconstruction-contract/case.yaml` 校验结果。使用 `python3 -O cases/reconstruction-contract/run.py` 或 `PYTHONOPTIMIZE=1` 重跑，结果应一致。用例通过普通布尔检查决定 `success` 和非零失败退出码。

用例验证分派、值范围和拥有方模型，未执行 NEON、真实 StringView 布局或原生 reader；NULL 位图和损坏输入错误语义还需引擎验证。 未完成的目标端证据标为 `awaiting_target_evidence`。触发与边界评估规格见 [evals/evals.json](evals/evals.json)，规格不等于已执行模型评测。
