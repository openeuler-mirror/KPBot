## 2. 混杂因素清单

| 混杂因素 | 检测信号 | 后果 | 处置 |
|---|---|---|---|
| 构建路径差异 | 二进制体积 / `.text` 段对不上 | 增益或损失都归不到改动 | 降级结论，放弃或重构建 |
| 单轮方差 | 优化轮 ≈ 基线某轮 | 表观改善是噪声 | 多轮分布复核 |
| 外部负载漂移 | 组间 CV 大、组内紧致 | 组级效应而非被测改动 | 记录窗口 / 独占重测 |
| 版本静默回退 | 转发变量丢失 | 测的是旧基线 | 运行容器确认实际 tag |
| 数据池漂移 | 起点/终点行数对不上 | 快来自少干活 | 黄金卷固化：固定输入数据快照（如 Milvus 底库卷 seal + 行数/哈希校验），复用轮逐字节比对 |

## 3. 判据：单轮 vs 多轮

- 单轮 p50 -19.8% 是幻觉的典型形态：优化轮与基线**某一轮**几乎相同。
- **单轮 = 证据不足**：一对 p50 接近 ≠ 两组整体中位相同，两组分布的中位仍可能明显不同。
  要判定须在**相同条件下交替复测**（基线/候选交错），比较**两组分布**，再判断差异是否落在噪声范围。
- **改善方向按指标**：吞吐越高越好（"多轮高于基线中位"）；**时延越低越好**（"多轮**低于**基线中位"）。
  若基线 100ms、候选每轮 110ms，"全部高于基线中位"会把稳定退化误判为增益——写判据前先确认指标方向。
- 负结果也沉淀：TOP1(b) 的观察**与**"L2 距离带宽受限"一致（~2.7 GFLOP/s/核 ≈ 理论峰 ~8%），
  但**只能记为假设**：~8% 利用率可能由指令依赖/访存延迟造成，且本轮同时换了构建路径，展开/预取无法单独
  归因。要坐实需相同构建条件下的实测带宽 + 对照实验。

## 4. 与防假提速 / 溯源的分工

- 防假提速（`opt-anti-fake-speedup`，独立 PR 待合入）：排除"少干活"（量 + 质）。
- 干净归因（本 skill）：排除"混杂因素"（体积/.text/路径/方差）。
- 溯源记账（`opt-traceability-and-reverify`，独立 PR 待合入）：把"无增益 + confound"结构化进负结果表。

## 5. 坑点

- **只看表观改善就拍板**：单轮 p50 改善是方差陷阱。
- **改善方向写反**：时延指标（p50/p95/p99）越低越好，误用"全部高于基线中位"会把稳定退化判成增益。
- **一对 p50 接近就下"无差异"结论**：两组分布的中位仍可能明显不同，要交替复测比分布。
- **忽略 .text 段体积**：构建路径混淆最隐蔽，体积对不上是强烈信号。
- **把"带宽受限"从假设当结论**：~8% 利用率 + 换构建路径下无法单独归因，只能留作假设。
- **硬下"改了没用"**：无法归因时，结论应降级为"无增益且无法归因"，而非"证明无用"。
