# 指标语义与比较规则

## 三类百分比

| 名称 | 分子/分母解释 | 不可替代的指标 |
|---|---|---|
| Bad Speculation | 依当前平台 Top-down 模型解释 | 分支失败率 |
| branch-misses / branches | 同范围事件计数之比 | 流水线损失占比 |
| Hotspot 事件占比 | 该报告内函数/地址事件份额 | 占全部流水线的份额 |

热点与 Top-down 独立运行时，可以建立待验证的来源假设。
不能从 Top-down 13.03% 中减去 hotspot 的 5.89%。
即使同一次运行，分母不同也不能直接相减。
热点 shares 变化时，检查总事件数是否也变化。

## L1 与层级

先确认 CPU、工具版本及模型定义。
只有确认四项构成完整 L1 分区，才检查和接近 100%。
现有仓库测试使用 99～101，可作为候选容差，不是物理定律。
脚本要求显式 tolerance_pp，避免默默套用阈值。
所有子树不能统一要求“子项和等于父项”。
重叠指标、归一化基准和显示舍入必须按模型解释。
没有公式或原始事件时，不反算私有模型。

## 基础计数

IPC 复算需要相同范围、窗口、缩放与聚合方式。
不能将多个 CPU 的平均 IPC 与总 instructions/cycles 直接判等。
cycles 为零时不计算比值。
字段精度决定显示容差；两位小数可按其舍入规则选取容差并注明。
计数不同步、缩放不同或浮点大整数精度损失时，先保留原文。
脚本使用 JavaScript Number，非安全整数计数标记 unsafe_count 并停止数值判断。
需要逐计数精度时另用整数处理并记录方法。

## PMU 可调度性

time_enabled 与 time_running 必须来自相关会话并使用同单位。
存在多个事件时，不能用某一事件的良好比例替代所有事件。
记录最差事件或逐事件表，并在 evidence 中指出策略。
有效运行比例低时可考虑减少事件、拆分层级或改变采集方案。
事件分批后必须确认负载阶段可重复。
不要把不同批次的波动计数直接拼成同步模型。
比例高也不能证明选对了进程、阶段或事件。
工具不暴露时报告 unknown，不根据退出码伪造比例。

## 固定工作量与固定窗口

固定工作量：比较同一批工作，保留完成时间。
固定窗口：两组处理量可能不同，记录窗口内实际完成量。
每帧 cycles 的分母必须是计数窗口内的帧数。
只有总任务帧数时，不能除以窗口内计数。
如果目标是 API，进程级计数不能直接命名为 API 计数。

## 重复性

保存每次原始值、运行顺序、时间和环境。
报告中位数、范围及样本数；必要时给离散程度。
不要把连续子报告当作独立实验次数。
异常样本可以有原因标签，不能静默删除。
延长窗口可改善部分噪声，但不能修正范围偏差。
少量样本不输出无依据的置信区间或准确率。

## A/B 人工准入

逐组审核有效性，再检查：

1. 相同业务问题和工作单位。
2. 输入、配置、CPU、阶段与预热可比。
3. 构建差异明确且是预期变量。
4. 事件定义、执行级别和聚合方式一致。
5. 固定工作量或固定窗口的比较口径明确。
6. 独立重复与交替顺序足以评估漂移。
7. 正确性和业务指标没有被省略。

可比较部分必须逐项说明，不能用单个总状态替代。
IPC 降低但业务更快可能源于剩余工作构成变化。
Top-down 占比改善并不自动等于端到端收益。
优化建议写成机制假设及实验，而不是确定收益预测。
