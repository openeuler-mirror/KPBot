# IVFPQ 候选规划

## 输入与选择

读取当前源码、[热点检查项](ivfpq-performance-hotspots.md)、冻结 manifest 和可用实验记录。按可移除成本、实现范围、数值/平台风险及验证成本排序，选择一个主要机制。

| 方向 | 适用证据 | 验证重点 |
| --- | --- | --- |
| 固定形状查表/循环组织 | decoder 和 M/nbits 组合稳定、扫描占比显著 | FP 累加、非特化形状、selector/metric 和尾段 |
| LUT 准备复用 | query/list setup 可识别重复计算 | 预计算模式、偏置、缓存足迹与生命周期 |
| 候选容器与调用边界 | 测得比较/维护成本及接受比例 | fresh 阈值、tie、更新顺序、代码体积 |
| 访存/预取 | 实际倒排或精排访问延迟可复现 | 有效地址、带宽、ahead 与其他负载回退 |

## 每个候选需要说明

1. 目标调用链、文件/符号、实测占比及机制假设。
2. guard、默认关闭的特性宏、fallback 和最小改动范围。
3. 是否改变布局、距离、候选集合、比较顺序或精排；纯实现优化保留既定语义。
4. 基于占比的理论上限和额外成本。上限不是收益预测。
5. 实际路径的 UT/ST、开关与边界矩阵、冻结性能对照及停止条件。
6. 已有记录的来源与适用差异；缺少资料时说明依据，不虚构已验证/已否定状态。

## 结果

结论来自本次证据，记录到 `run_dir/candidates/<id>/VERDICT.md`。不把某个数据集、处理器或单次候选的结果改写为通用技能的固定推荐或禁令。
