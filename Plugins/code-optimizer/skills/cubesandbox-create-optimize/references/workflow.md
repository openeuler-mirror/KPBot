# 三方案组合实施、消融与交付手册

## 1. 工作边界与输入

本包可单独复制到技能目录，所有方案的文档、patch、采集计划与分析器都在本包内。使用时不读取同级技能，也不依赖个人环境中的 `rsi-*` 包。本入口用于完整创建路径归因和多机制组合验收；1、2、3 单项是组合实验中的对照臂。单一症状的专项诊断不进入本流程。

从任务和目标环境取得以下输入，已有信息不重复询问：

| 输入 | 应记录的事实 | 缺失时可先做的事 |
|---|---|---|
| 源码/版本 | CubeMaster、Cubelet、CubeShim、cubecow、VMM 和 bench 的 commit/diff | 静态映射本包 patch 到当前源码 |
| 目标环境 | CPU、内核、存储、DB、服务单元、单/多 Master | 阅读原理、准备构建与测试计划 |
| 模板/负载 | READY 模板身份与版本、c100/n100、create-only、warmup | 检查 bench 参数与输出 schema |
| 正确性契约 | 成功应答、spec 可丢失窗口、rootfs 持久化、取消/重试 | 给出需要保持的状态与失败路径 |
| 历史结果 | 原版本、最终 patch、创建总时间和测量口径 | 按来源记录；不将缺报告说成方案未验证 |
| 任务产物 | 本次独立 RUN_DIR、授权服务与实例范围 | 生成仅写本地产物的实验计划 |

## 2. 一条请求的阶段模型

按目标版本确认实际调用图，以下是定位用模型，不是声称所有阶段完全串行：

```text
API create
  → Master：模板/恢复源判断 → locality → 副本选择/bind → 创建调度
  → Cubelet：rootfs 准备 → PodSandbox / shim 启动
  → Shim/VMM：快照恢复 → agent 连接 → Guest 必需初始化
  → 创建应答
  ↘ spec 写入：原版在应答前等待，候选按契约移入后台
  ↘ pool fill/flush：候选后台准备及合并持久化
```

用 request ID/sandbox ID 和同一单调时钟窗口关联阶段；跨进程日志只能在时钟已校准或有显式因果关系时拼接。父阶段包含子阶段时不能将二者相加；并行支路总时长取汇合关键路径，不将省下的所有局部毫秒直接当总时间下降。

先按 timestamp 截取单轮新增日志，保留原日志起止偏移，避免把历史请求混入。至少观察 Master resolve/spec、Cubelet derive/锁/fsync、Shim restore/connect/monitor/runtime。正式测量的日志等级两臂一致，细粒度 profiling 可放独立诊断轮。

## 3. 版本识别与三种处理方式

在源码根目录保存 `git rev-parse HEAD`、`git diff --binary` 和现有产物哈希。分别运行三个本地 patch 的 `git apply --stat` 与 `git apply --check`，不要直接一条命令批量应用。

- 目标与历史布局一致：逐方案审查后应用，记录实际 diff。
- 接口漂移：按本地三个原理章节中的函数语义迁移，生成新 patch；保留版本与变更记录。本包 S1 参考补丁已包含 JoinSet 生命周期修复，原始版本可从 Git 历史追溯，不再要求使用存在已知缺口的旧实现。
- 已含相同机制：记录 `already_present` 及现有代码证据；判断需不需要调整参数，不重复增加并行任务/缓存/池。

同一机制可能存在多个历史补丁。它们即使具有相同 basename、目标路径或 `index` 前像，也不构成可依次叠加的增量；用补丁 SHA256 和最终源码行为识别版本。若目标已有另一实现，先比较其生命周期、缓存失效和写入顺序语义，再保留或迁移成一个最终实现。本包 S1 的 `JoinSet` 所有权、失败 shutdown/drain、结果绑定后汇合和有界退避应一并保留，不能由只做裸 `tokio::spawn` 的历史变体覆盖。`git apply --check` 只判断文本上下文，不能证明这些性质。

本包独立携带实现与工具，版本记录也按本包维护：在 manifest 中保存 skill commit、三个补丁和分析脚本的 SHA256。包内某项发生修订时重新执行其用例及受影响的组合验证，不能因为其他来源存在同名文件就推定内容或验证结果同步。

三个历史补丁修改不同文件，这降低文本冲突，但不消除共享 CPU/DB/存储和生命周期交互。组合必须核对整体资源与持久化契约。

## 4. 按依赖实施与发布

推荐顺序为 Master → 存储池 → Shim，方便逐项看到变化。任务已有部署计划时可调整，仍应保持每次只改变一个可识别实验变量。

| 方案 | 本地操作手册 | 必需构建产物 | 发布后的就绪条件 |
|---|---|---|---|
| S1 Guest | [agent-runbook.md](agent-runbook.md) | 含正确 VMM 的新 shim | 新建实例确实运行新哈希，agent/health 正常 |
| S2 Master | [master-runbook.md](master-runbook.md) | 新 Master | 新进程哈希、心跳、模板 READY、DB 可用 |
| S3 存储池 | [pool-runbook.md](pool-runbook.md) | Rust 静态库+头文件+匹配的 cgo Cubelet | 新 Cubelet 哈希、准备调用完成、池水位到达实验目标 |

每步先做自己的故障测试与正常生命周期；失败则只回退该步并记录原因，不能继续叠加掩盖失败。组合验证要检查：缓存不会选到已不可用模板、清池不与 Guest/实例清理冲突、异步 spec 不复活已删除行、预连接失败不会遗留后台任务。

## 5. 实验臂与开关

`0/1` 表示该机制未启用/启用，保留统一源码基线与编译配置。没有运行时开关的机制用可追溯的独立构建，不能编造环境变量当开关。

| 实验臂 | S1 | S2 | S3 | 用途 |
|---|---:|---:|---:|---|
| base | 0 | 0 | 0 | 相同环境下重新取得的基线 |
| 1 | 1 | 0 | 0 | Guest 单项 |
| 2 | 0 | 1 | 0 | Master 单项；内部再分 cache-only/async-only |
| 3 | 0 | 0 | 1 | 影子池单项 |
| 12 | 1 | 1 | 0 | Guest 与 Master 交互 |
| 13 | 1 | 0 | 1 | Guest 与存储交互 |
| 23 | 0 | 1 | 1 | Master 与存储交互 |
| 123 | 1 | 1 | 1 | 三合一最终结果 |

最小交付为 base/1/2/3/123，解释组合交互需完整矩阵。每条 `base vs candidate` 单独按 [reproduction.md](reproduction.md) 做 ABBA，不把所有 base 样本汇总后分配给不同候选。每个 block 的部署、等待、warmup、清理和池准备过程也记录。

S3 增加“候选二进制关池”的消融：确认收益是否来自池，历史实现应 unset DISABLE 表示开池，设 `1` 表示禁用。S1 和 S2 原 patch 没有统一运行时开关，用拆分 patch/构建执行消融。123 不是三个单项百分比之和；瓶颈迁移和资源争用可放大或抵消收益，只报告实际测得的组合总时间下降。

## 6. 每次测量的操作单元

1. 确认当前臂的运行哈希、模板 READY、实例和 TAP 清理状态。
2. 若是满池实验，恢复声明的水位；若测冷池或持续负载，不混入满池结果。
3. 按冻结命令执行一次独立 c100/n100 create-only，保留 JSON 与 stdout/stderr。
4. 检查 100 次成功、0 错误和 total_time 单位；错误样本保留并停止本条确认性比较，定位原因，不挑删后继续宣称通过。
5. 清理本次实例，核对 spec 删除和 worker drain，等待下一轮准备条件满足。
6. 将该次报告路径填到预生成 plan 对应位置，保留时间戳、实际臂与环境记录。

`scripts/plan_comparison.py` 生成 12 个 ABBA block、每位置 5 次调用的采集清单；`scripts/compare_create_time.py` 检查数据和计算下降率。命令和输入字段全部在本地 reproduction.md 中，不依赖其他技能格式。

## 7. 归因、验收与回退

报告同时给主指标与机制证据：

| 机制 | 解释用证据 | 不能据此单独宣称 |
|---|---|---|
| S1 | 握手重叠、monitor 建连数、runtime 构造数 | 全部 Guest RPC 都被隐藏 |
| S2 | resolve 阶段、同键 SELECT、队列、最终 spec 状态 | 入队成功等于持久化完成 |
| S3 | 领养/回退、FICLONE/fsync、补池速率/成本 | 满池突发结果代表无限持续性能 |
| 123 | 整批 total_time、正确性、完整消融 | 单项数字相加即为组合收益 |

先按正确性契约验收，再读每条统计 verdict。用户已验证的组合创建时间下降 15–20% 保留为历史经验；本次迁移结果按对应版本与环境单独记录。没有目标机时可以交付完整技能和计划，不能填造本次运行结果。

回退按当前实际发布顺序逆序执行。先停止本次测试创建，处理异步写/flush，再恢复匹配的二进制和必要库；逐服务核对运行哈希、心跳和 c1 健康。保留历史备份，不以 `git reset --hard` 或全盘清存储替代回退。

```text
回退：备份身份、步骤、执行状态与恢复健康记录
历史经验与本次复现分别列示
```
