# 归档溯源 + 复验（阶段 6）

## 何时使用

- 一个优化点走完量化决策，要落定论、登记溯源表。
- 要记录一个放弃项（证伪 / 无增益）。
- 做了目录重组、submodule 化、构建链路迁移等等价重构，要证明没退化。

## 核心原则

1. **把"可复现"建模成一张闭表**：产物 tag ↔ image id ↔ 基线 ↔ 补丁 ↔ 结果文档 ↔ 状态（保留/废弃）。
2. **双锚定**：tag + 内容寻址 id（image id / commit），防止 tag 被覆盖后失去指认能力。
3. **覆盖全部产物**，包括废弃的和历史中间版——负结果和正结果同等重要。
4. **任何"应该等价"的重构，都得实跑复验**；请求计数等硬指标就是防假提速的锚。
5. **单一事实源 + 契约化**：横切常量收敛一处，JSON Schema 固化接口，静默回退比报错更危险。

## 步骤速览

溯源表六列结构、kept 清单、负结果四列范例与复验口径**只在 `references/traceability.md` 一处维护**，
本节给步骤名与去向：

1. **登记溯源表（六列）**——`镜像 tag | image id | 基线 | 补丁/改动 | 结果文档 | 状态`，tag + image id 双锚定，
   覆盖废镜像/中间版 → references §1。
2. **kept 清单按实际参与组件登记**（四角色仅本案例示例，不套死）→ references §2。
3. **归档分层**——docs 定论层 / opt-trace 按优化点编号 / BOARD 进度源 → references §3。
4. **负结果记账（四列）**——做了什么/结果/放弃原因（证伪 vs 无增益）/正确方向；结论限定到"本次配置/本轮观察"→ references §4。
5. **等价重构实跑复验**——硬指标 + 运行容器镜像 ID + 采集器退出状态 + 相位产物可解析，三项齐备才判修复 → references §5。
6. **单一事实源 + 契约化**——横切常量收敛 manifest/config/contracts，版本转发显式校验 → references §6。
7. **子 agent 协作纪律（若并行）**——边界无交集、共享事实显式化、开工前读"勿重造" → references §7。

## 门禁

- [ ] 溯源表六列齐全（含 image id 列），tag + image id 双锚
- [ ] 覆盖废弃/历史中间版产物
- [ ] kept 清单按实际参与组件逐一登记（含 tag + 产物标识），四角色仅作本案例示例，不套死
- [ ] 负结果四列记账，且环境已还原；结论限定到"本次配置/本轮观察"（如 GC 结论不越到"非瓶颈"）
- [ ] 等价重构已实跑复验：硬指标逐位一致 + 运行容器镜像 ID + 采集器退出状态 + 相位产物可解析，三项齐备
- [ ] 横切常量收敛单一事实源，版本转发有校验
- [ ] 结论已落唯一活事实源，副本已标注来源
