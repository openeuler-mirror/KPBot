### 1.1 资源与公平性

| NUMA / CPU | node1（48-95） | node3（144-191） |

- 两份任务书除 skill 引导段外逐字相同（diff 验证）；skill 副本净化检查零泄漏（无 hmv/KDNN/ANNC 等专名、无消融报告链接）
- 验收协议：batch 59 × 并发 1/2/4/8/16/32 × 交替 ≥5 轮（轮间换序）× 每轮 3 warmup × 2000ms 窗口 × 中位数
- 双侧均遭遇环境扰动并如实处置：skill2 侧外部 llama-server 短暂闯入 CPU 段（污染轮作废重测 + mpstat 门禁）；noskill2 侧外部编译风暴（gatekeeper 延迟启动 + 6 轮中位数）；两个 agent 均因本机 API 代理故障中断 1.5h 后恢复
- 三方终态对比（round-5）：server NUMA2 / client NUMA1（node0 被外部实验占用），3 轮 × 三侧轮内交错（轮间换起始侧），同口径全梯度

### 1.2 人工版对照配置（round-3/4 修正后的逐模型最优）

cvr = ANNC+CF2+FM+prepack+NEON；hmv = ANNC+CF2+**FM=0**+prepack+NEON；adx = ANNC+CF2+FM+**Eigen**（不进 KDNN）；presort = 同 cvr + **线程 16/16**（本轮新增修正——skill2 发现 8/12 协议的 1/1 线程配置使 presort 只用 1 核，人工版 16/16 实测 = 1/1 的 4.5×，三方公平起见对齐到 16/16）

## 4. 分析

### 4.1 三方各赢一块，无全面胜者——但每块的成因都清晰

- **人工赢高并发 cvr/hmv**：与第一轮结论一致（prepack 删每次调用冗余 → 吞吐域收益随并发放大）。且人工 hmv 终态在本轮修正了 FM=0（规避 kdnnFusedGemm 缺陷）与 adx 走 Eigen，这两个 round-3/4 的教训直接体现在本轮配置里。
- **skill2 赢 presort 全档**：三件事叠加——16/16 线程修正（+488% 单项，**skill v2「线程对齐」章节的直接命中**）+ SVE JIT + cap4。值得注意的是它**击败了人工版的 prepack+NEON**（−26%）：presort 的 shape 下 SVE JIT 的单核效率优势（256-bit）超过 prepack 省打包的收益——**KDNN NEON prepack 并非本机 presort 的最优内核路线**，这是对 8 月冲刺路线的一个重要反馈。
- **noskill2 赢 adx 高并发**：自适应并发门控（按 step_id 统计在飞请求数动态路由）是本轮唯一的"发明型"优化，在同一份验收标准（全梯度不回退）下，它用工程手段拿到了 skill2 因保守而放弃的 +18%。**门控本身是 per-request 动态的，这是"逐模型路由"向"逐并发路由"的进化**——正好是并发域框架（skill v2 §4.3）描述的交叉点问题的运行时解法。
- **noskill2 赢 cvr 低并发**：其 ANNC only 配置（无 SVE）在 c1-c4 优于 skill2 的 SVE+ANNC 与人工的全开——SVE 路由在小图低并发下有逐 op 开销（与第一轮 KDNN 低并发劣势结论一致）。

### 4.2 hmv 的 ANNC 分歧（skill2 判 -18% vs noskill2 判 +22%）——三方数据未能裁决

round-5 中 noskill2 hmv（SVE+ANNC）与 skill2 hmv（SVE only）互有胜负（c4 skill2 还高 4.4%，c1/c8/c16/c32 noskill2 高 5-10%）——**但两侧二进制不同树**（skill2 有 BN 折叠修复、noskill2 有自适应门控代码），无法干净归因。结论：hmv×ANNC×SVE 的交互是真实的未决问题，双侧的 A/B 都可能各自为真（不同副配置下的不同结果）。这本身是「图层开关 × 内核路由联合调优」反号现象的又一例证。

### 4.3 skill v2 的实效评估

| skill v2 改进 | 本轮命中证据 |
|---|---|
| 线程对齐（L3 原则） | ✅ **presort 1→16 修正 = skill2 独有发现**，贡献其最大胜利（noskill2 未质疑标准配置） |
| 冻结图折叠三坑（graph_opt §4.1） | ✅ skill2 修了全部三处（含 loader 死代码断链），noskill2 完全没碰 BN 折叠 |
| 惰性命中取证 | ✅ 双侧都做了（noskill2 自发现；任务书也有提示，该项部分归因任务书） |
| 并发域框架（benchmarking §4.3） | 部分——skill2 交付了按并发域的配置矩阵（adx 高并发备选）；但它对 adx 的"全梯度不回退"处理选择了保守放弃而非 noskill2 的运行时自适应——**skill 给了描述框架，没给"动态路由"这个解法** |
| 交付配置矩阵（SKILL §4） | ✅ skill2 报告 §7 是标准配置矩阵；noskill2 也有等价物（逐模型配置节） |

**净结论**：skill v2 在本轮的价值集中在**线程对齐**与**折叠三坑**两个可清单化的知识点上（各值一个数量级/一个模型档的差距）；而在需要发明的场景（adx 自适应路由）与需要判断的模糊地带（hmv ANNC 分歧），skill 既没帮上也没添乱——noskill2 靠自身工程能力赢下了这两块。**skill 的价值形态是" checklist 命中即大胜、未覆盖处归零"，不是全面放大。**

### 4.4 资源与纪律

- token：skill2 233.6k vs noskill2 213.3k（skill +9.6%，与第一轮 +12% 一致——通读 skill 文本的固定开销）
- 双侧验证纪律均严格（命中证据、正确性对拍、污染轮作废），skill2 的报告结构与 skill 模板高度吻合（分层归因、配置矩阵、负结果卡片含适用范围——skill v2 的负结果格式被直接采用）
- 效度威胁：① 双侧测量时段外部负载不同（skill2 早段安静、noskill2 晚段编译风暴）——但各自 vs 自己的基线（同 binary 同环境交替）抵消；② API 代理故障中断 1.5h（双侧同时）；③ 三方对比中 hmv 人工侧 c2 存疑、presort c32 noskill2 缺测（配置容量上限，非测量失败）；④ 外部会话实验（tf_ablation_clean）全程占用 node0 并间歇占用 28500 端口——已通过端口迁移 + 数据核查确认无污染

## 5. 与第一轮的对照结论

| 维度 | 第一轮（skill v1，单点并发 4） | 第二轮（skill v2，全并发梯度） |
|---|---|---|
| skill vs noskill 提升（几何平均） | skill +17.9% vs +15.4% | 分模型分裂：skill2 赢 presort（+730% vs +41%），noskill2 赢 hmv/adx 高并发（+30%/+18% vs +14%/+3.7%） |
| skill 的差异化贡献 | 稀疏融合先发、线程对齐（cvr） | 线程对齐（presort）、BN 折叠三坑修复 |
| noskill 的差异化贡献 | KDNN 线程上限 | **自适应并发路由**（发明型）、kdnn_num_threads bug 修复 |
| skill 的先验误导 | presort KDNN 负结果过度泛化（−6pp） | 无明显误导；但保守取向使其放弃 adx SVE（少 +18%） |
| agent vs 人工 | agent 终态 4/4 超人工 full（当时人工"够不着"ANNC） | **三方各赢一块**：人工赢 cvr/hmv 高并发（prepack），skill2 赢 presort，noskill2 赢 adx 高并发 |

**总结论**：

1. **口径升级改变了游戏**：第一轮单点并发 4 下 agent 全面领先人工版；全并发梯度口径下三方各赢一块——因为"最优"本身按并发域分裂了，任何单点口径的结论都是片面的。
2. **skill v2 的清单化改进被验证有效**（线程对齐、折叠三坑），但**上限受制于知识覆盖**：本轮两个 agent 的最大创新（自适应路由、hmv ANNC 判断）都不在 skill 里。skill 的正确预期是"防止已知的坑 + 命中已知的富矿"，不是替代工程创造力。
3. **三方最优仍是并集**：presort = skill2 配置；adx 高并发 = noskill2 自适应门控；cvr/hmv 高并发 = 人工 prepack 路线（但 presort 上 SVE>prepack 的发现提示人工的 NEON prepack 路线在部分 shape 下应让位于 SVE）。把三方互补项合到一棵树上，是比任何单一版本都大的提升空间——预估相对基线：presort 8×、adx 高并发 +18%、cvr 高并发 +19%、hmv 高并发 +18% 的组合全部可得。
4. **对 8 月冲刺的具体反馈**：① presort 的 1/1 线程生产配置应重审（16/16 = 4.5×）；② KDNN NEON prepack 在 presort shape 上劣于 SVE JIT（−26%），prepack 的适用面需要按 shape 重新标定；③ loader BN 折叠死代码（skill2 修复的三坑）应回流主线——与 round-2/3 结论一致，本轮第二次独立发现。
