# L6 运行配置

| 配置 | 结论 | 代价 |
|---|---|---|
| 服务端全线程绑核 | 只绑主线程等于没绑；JVM 用 `taskset -a -pc` | 需按核预算规划 |
| 连接池 | **不要缩**（本例 96/192）；缩到 8/32 时排队 → 判饥饿 → 连接重置 → 重试雪崩（冷对冷慢 1.65×，重试 34×） | 内存 |
| JVM/JDK | 新版与旧版性能相当（~2%），但重试显著更少；重启会回退系统 JDK，需显式 `JAVA_HOME` | 升级风险 |
| 预热 | 重启后 **2 轮完整负载**才进稳态（首轮慢 40~80%），基准必须丢这两轮 | 时间 |

## 使用纪律

- 配置项只用来"消除误判与长尾"，不要当主收益报；
- 改配置必须与代码改动分开做 A/B，否则归因混乱；
- 非 JVM 服务端按等价项替换（线程池、GC、缓冲、预热）。

## 判据

绑核是否生效：看进程实际 CPU 亲和性（`taskset -a -pc <pid>` 逐线程打印，或 `ps -o psr -L <pid>` 抽查线程亲和性）。**不带 `-a/--all-tasks` 的 `taskset -pc` 只作用于主线程**，会漏掉工作线程漫游。
连接池是否够：看重试次数与排队时间，而不是 CPU。
