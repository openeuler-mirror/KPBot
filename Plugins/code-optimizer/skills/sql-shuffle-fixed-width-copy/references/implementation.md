# 固定宽度拷贝的实现与验收

## 源码参考

`apache/gluten` 的 `v1.3.0`：[`cpp/velox/shuffle/VeloxHashShuffleWriter.cc`](https://github.com/apache/gluten/blob/v1.3.0/cpp/velox/shuffle/VeloxHashShuffleWriter.cc)。这些固定链接来自原 skill 最新检视修订时核对过的源码参考，用于定位模块；不代表 SQL67 历史跑分的真实基线，也不组成经验证的依赖版本。目标实施应记录工程锁定提交、补丁及实际加载库。

## 几何与别名

W≤n≤2W 时，头部为 `[0,W)`，尾部为 `[n-W,n)`，并集覆盖 `[0,n)`；交集中的每个目标字节都来自同一逻辑源位置。这个证明要求两次源读取未被目标写入改变。跨源目标重叠需要原 memmove 路径或单独顺序证明。

本地用例保留原 skill 的 65 个长度、17 个固定分支长度及 2 次非法目标偏移拒绝。边界矩阵为 11 个长度 × 2 个源偏移 × 2 个目标偏移 × 2 个尾容量，共 88 组，其中 44 组精确容量，22 组源目标偏移同时非零。另覆盖双向源目标别名回退。

## 原生验证

将相同字节和偏移迁入 C++ 用例，用 guard page 或内存检查器验证无填充、地址末端和算术溢出。即使 Python 用例全绿，目标端仍应核查编译器实际加载宽度与合法的未对齐访问。

只对写入链路逐字节相等作结论；压缩流变化与读端重建属于独立优化点。局部性能须记录每长度比例、吞吐、复制字节及无命中时的分派成本。
