# 决策树、负结果与停止条件

## 1. 决策树（从证据到动作）

```
性能不达标
  ├─ 正确性失败？ → 停止性能测试，修正确性
  ├─ 客户端/网络先瓶颈？ → 加压测机/网络，不调 MySQL
  ├─ 目标 cpuset/业务核未满？
  │    ├─ IRQ 核满/IRQ 抢核 → mysql-os-optimization
  │    ├─ iowait 高 → 刷脏/盘/durability
  │    └─ 锁等待/长事务 → SQL/索引/事务
  ├─ 业务核满？
  │    ├─ ut_delay/latch → 自旋/争用/实例/绑核
  │    ├─ B+Tree/记录比较 → fast-tuple/rec_get_offsets
  │    ├─ Read View/trx_sys → Read View version
  │    ├─ 排序/collation → SQL/索引 + NEON collation
  │    ├─ redo/binlog fsync → durability/组提交/preallocate
  │    └─ 内存分配/拷贝 → 结构优化
  └─ 达标：保留并记录
```

## 2. 杠杆优先级

1. **正确性/数据模型**：索引、SQL、事务边界、隔离级别。
2. **部署/系统**：规格、绑核、IRQ、NUMA、大页、文件系统。
3. **配置**：Buffer Pool、redo/binlog、IO、刷脏、线程、AHI。
4. **编译**：`-O3`、LSE/CRC、LTO、原子写。
5. **源码**：结构/比较/锁/拷贝。

原因：越靠前影响面越大、风险越可控；源码优化在错误归因上会浪费大量时间。

## 3. 已证伪/反模式

| 尝试 | 结果/风险 | 原因 |
| --- | --- | --- |
| Buffer Pool 命中率接近 95%（>99% 几乎无增益）仍继续加大 | 收益递减/内存浪费 | 工作集已覆盖 |
| 高 CPU 读多仍开 AHI | 可能负收益 | latch/维护成本 |
| 只加 `innodb_buffer_pool_instances` | 小 pool 反而慢 | 管理开销/碎片 |
| 超过盘能力的 `innodb_io_capacity` | IO 竞争、尾延迟 | 队列积压 |
| 只看 avg 不看 P95/P99 | 掩盖长尾 | 分布偏斜 |
| 把线程数提高当优化 | 锁/IRQ 瓶颈时更差 | 运行点变化 |
| 把 query-mix 变化当服务器收益 | 口径错误 | workload 变化 |
| 任一表空间路径未确认原子写就关 doublewrite | 数据损坏 | 只验数据目录不足；独立/undo/临时表空间可能无整页原子写保证 |
| 未验证 `-march`/LTO | 崩溃/无收益 | 平台/工具链 |
| 只改 collation 实现不改 SQL | 收益有限 | 数据分布/语义 |
| 同时改多个参数 | 无法归因 | 变量混淆 |

## 4. 停止条件

出现任一，停止当前轮并回到证据：

- 正确性失败（MTR/冒烟/对账/回读）。
- 错误率上升、P99 明显恶化且无法解释。
- 目标场景收益 <5% 且波动 >5%（视为噪声）。
- 出现 OOM/崩溃/数据风险。
- 变更无法回滚或回滚未验证。
- 归因证据不足（只有“感觉”）。

## 5. 台账模板

```
日期/环境：
场景/数据集/线程：
基线：TPS/QPS/P95/CPU（轮次、波动）
候选：同上
变更：文件/参数/函数，改前→改后
归因证据：perf/off-CPU/等待/状态
正确性：MTR/冒烟/对账
判定：有效/无效/劣化；保留/回滚
负结果：原因、是否可复用
回滚命令：
```

## 6. 组合变更的处理

- 组合变更（如实例数 + worker 数）必须标注“组合收益”，不能单独归因。
- 需要单独归因时，补一组只改一个变量的对照。
- 多场景（Point/RO/RW/WO）分别判定；不能用一个场景代表全部。
- 跨部署形态（物理机/容器/虚机）不可直接横比，需注明。

## 7. 风险分级

| 级别 | 例子 | 要求 |
| --- | --- | --- |
| 低 | 动态参数、查询提示 | 基线 + A/B + 回滚 |
| 中 | 需重启参数、绑核/IRQ | 维护窗口 + 备份 + 复验 |
| 高 | durability、原子写、数据格式、补丁 | 用户确认 + 全量备份 + 回滚演练 |
| 极高 | 删数据/重建 datadir | 明确确认 + 备份校验 + 二次确认 |

## 8. 交付前检查

- 每个变更都有证据、预期、验证、回滚
- 正确性门禁通过
- 四场景分列，轮次/波动/口径完整
- 二进制/参数/数据集身份可追溯
- 负结果已记录
- 报告脱敏（无 IP/账号/个人路径）
