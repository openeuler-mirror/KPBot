# 性能优化报告写作协议

把优化实战变成**可信、可复现、可评审**的报告。核心信条：报告的每一个数字都要有
仓内证据文件背书；每一个结论都要能回答"怎么测的、和谁比、为什么不是噪声"。

## 流水线位置

本 skill 是优化工作的**收尾段**：对照实验、profiling、验证用例都已完成之后才进入。
上游是各类优化工作流与专项优化 skill 的产出——双臂对照数据、火焰图、验证结论，
作为本 skill 的输入交接（Go 服务的采样与火焰图素材可由 `go-pprof-analysis` 采集）。
实验没做完就写报告是本末倒置。

## 总流程（六步）

```
1 证据盘点 → 2 对标参照 → 3 五章成稿 → 4 证据入仓 → 5 评审迭代 → 6 确认后提交
```

### 第 1 步：证据盘点

写之前先列**证据清单**，缺什么补什么（报告不能开天窗）：

| 证据类别 | 内容 | 实证案例（CubeSandbox create-path 优化报告） |
|---|---|---|
| 变更本体 | patch 文件（SHA256 钉死）+ 改动范围统计 | 模板解析缓存 patch（6 文件 +628/-35） |
| 构建身份 | 双臂二进制 sha256、注入的版本串、工具链 | 两臂同 go1.25.7、同版本注入，sha256 各异 |
| 功能门禁 | 生命周期冒烟（create→list→delete ×N） | 21/21 × 双臂 |
| 性能口径 | ≥5 轮对照 + 轮间完整清理 + 每轮指标增量 | total_time 133.6→128.1ms（100 并发 create 负载、5 轮均值、轮间全量清理） |
| 深挖证据 | 语句普查（statement census）、热点前后对比 | SELECT ~315→~6/轮（÷52） |
| profiling | 负载窗口 pprof + 折叠火焰图 | base 500ms / patched 220ms create 路径 |
| 安全屏障 | 故障注入证明防护机制真实生效 | 34 个 Go fault 用例全过 |
| 环境指纹 | 版本/负载/已知噪声源快照 | experiment_summary.txt 头部整节 |

**同一目录落一份 experiment_summary.txt**（人机两读的实验总账），报告所有数字从
这里对账。

### 第 2 步：对标参照报告

用户说"按 XX 报告的水准写"时：

1. 通读参照报告，拆出它的**章节骨架 + 证据目录布局**（文件数、目录结构、是否含
   脚本/火焰图）；
2. 逐项对比自己手上有什么，**列出缺口清单**（实证：参照有成本模型、争用放大、
   故障屏障三个章节而初稿没有——补齐后才算对齐）；
3. 证据资产**镜像参照的目录布局**，但按自己实验的实情裁剪（实证：参照 ~29 个
   证据文件 → 本报告裁到 40 个并重排五类资产；裁掉 pprof 中间产物与废协议轮次，
   保留 patch + summary + 火焰图 + 报告 + 脚本五类）。

### 第 3 步：五章成稿

骨架与逐章模板见 [report-template.md](references/report-template.md)。要点：

1. **一、底座与关键路径解剖**——构建身份 + 执行链路图 + 负载模型。读者先知道
   "测的是什么系统里的哪条路径"；
2. **二、观测口径与标定**——先讲"显微镜"（怎么采 pprof / 怎么普查语句 / 怎么
   定窗口），再给热点排名和逐轮延迟分布。**口径先于数字**，否则数字无法解释；
3. **三、方案与验证**——瓶颈定位 → 手段 → 运行时效果 → **成本模型**（直接节省
   vs 实测节省，差值要给归因）→ **故障屏障**（注入故障证明安全机制不是纸面的）；
4. **四、独立发现**——实验途中撞见的、与本方案无关但有价值的问题（体现实验的
   完整性和后续线索）；
5. **五、证据与复现资产清单**——仓内相对路径列表 + 每个文件一句话说明。

### 第 4 步：证据入仓

- 报告只引**仓内相对路径**，绝不出现机器本地路径（家目录、盘符绝对路径等）——
  报告要能被任何 clone 的人读懂；
- 证据五类入仓：patch / experiment_summary / flamegraphs/ / reports/ / scripts/
  （采集与分析脚本必须入仓，否则复现链条断掉）；
- 裁剪纪律：**中间产物不入仓**（pprof 原始 .pb.gz、折叠中间态、废协议轮次数据），
  入仓的是"能支撑报告数字的最小充分集合"。

### 第 5 步：评审迭代

- **每次提交前必须用户确认**——先给用户看 diff/预览，得到明确"提交吧"才动手；
- 用户反馈逐条改，改完复述改动点再求确认（实证：火焰图迭代了四轮才收敛）；
- 远程/本地同步用 **base64 往返校验内容**，不信行数（行数相同内容可能已毁）。

### 第 6 步：提交纪律

- 证据资产与报告**同批或紧邻提交**，commit message 描述证据范围（不是一句
  "更新文档"）；
- 尾注遵循所在仓库政策（如仓库要求 AI 辅助标注则带 Assisted-by，DCO 由提交人
  签署）；
- 推送后核对远端 blob hash = 本地（web 预览有 CDN 缓存，**别用预览判断推送成败**，
  用 API raw 读或 blob hash 判）。

## 写作纪律（7 条硬规则）

| # | 规则 | 反例 → 正例 |
|---|---|---|
| 1 | **去内部黑话** | "方案二"→"模板解析缓存方案"；"臂"→"base 组/patched 组"；"自测"→"本地验证" |
| 2 | **无机器本地路径** | "家目录下的 …/report.md"→"reports/base_clean_bench1.txt" |
| 3 | **数字口径三要素** | 轮数+清理协议+统计量（均值/中位）必须随数字出现，不裸报单值 |
| 4 | **权威数字优先** | 历史权威口径（如 CI 的 +4.30% CI[3.30,5.50]）为主量级，本次标定（-4.1%）作为收敛证据并列呈现，不用单次新测量推翻口径更老的成体系数据 |
| 5 | **废协议如实披露** | 被否决的测量协议（如无清理轮间串扰）写明否决原因——这是可信度而非污点 |
| 6 | **成本模型必做** | 直接节省 ~1.3ms/req（单次调用消解成本估算）≠ 实测节省 ~14ms/req（100 并发 create 负载下 5 轮均值，争用放大下全链路收益——按规则 6 需归因为争用放大）时，差值必须给出解释，不能假装没看见 |
| 7 | **中文文档编码** | 中文 .md 只用 edit 工具 / `python -X utf8` / `cmd /c` 改；PowerShell 5.1 裸 Get-Content/Set-Content 会双重编码毁文档（实证事故：整份报告变乱码，靠 git 恢复） |

## 火焰图管线（Go pprof 场景）

详细管线与校验门见 [flamegraph-pipeline.md](references/flamegraph-pipeline.md)。
核心三条：

1. **用 `go tool pprof -traces` 折叠，不用 `-raw`**——raw 的位置列是数字
   location ID 不是符号名，解析它必出垃圾图（实证事故：第一批 SVG 全废）；
2. **折叠后必须校验**：collapsed 总权重 ≈ pprof 头部 Total samples；top 帧与
   `-top` 对得上；预期消失/保留的函数在各视图里逐一确认；
3. **视图口径与报告文字一致**：差分图蓝=被消除的路径、红=新增路径，报告表格
   措辞与图例严格对应；切割范围选 handler 路径全帧视图，不过度过滤（实证：
   全滤 runtime.* 后图丢了上下文被判不合格）。

## Anti-patterns（12 条）

| # | 反模式 | 正确做法 |
|---|--------|---------|
| 1 | 拿到数据直接开写 | 先盘点证据清单，缺口补齐再动笔 |
| 2 | 无参照自嗨 | 有参照报告就对标：骨架+质量维度+证据布局三对齐 |
| 3 | 报告留本地路径 | 证据入仓，只引仓内相对路径 |
| 4 | 黑话满篇 | 描述性命名，第三方读者无上下文也能懂 |
| 5 | 裸报单轮/最好轮数字 | ≥5 轮 + 轮间清理 + 均值/中位 + 逐轮列出 |
| 6 | 单次新测量当权威 | 权威口径为主，新数据作收敛/佐证 |
| 7 | 直接节省=实测节省的差值不解释 | 成本模型 + 争用放大归因 |
| 8 | 防护机制只写"已实现" | 故障注入用例证明屏障真实生效 |
| 9 | 解析 pprof -raw 折叠 | `-traces` + fold_traces.py + 权重校验 |
| 10 | 未经确认就 commit/push | 每次提交先给用户过目 |
| 11 | 用 web 预览判断推送成败 | API raw / blob hash 判，预览有 CDN 缓存 |
| 12 | 证据只留在实验机 | 最小充分集入仓（五类：patch/summary/火焰图/报告/脚本） |
