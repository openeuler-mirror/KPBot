# L5 服务端读路径补丁

## 前置条件

- 服务端火焰图里"每行必走"的解码/相似度例程合计 ≥ 5%；
- 客户端已优化到位（否则测不出）；
- 服务端可重建（源码 + 构建命令可用）。

## 做法

按火焰图逐个打，每项单独成版本，累积保留（`v0_orig → v1 → v2 → …`），每版记录产物 md5。
本例四项：

| 版本 | 补丁 | 目标 |
|---|---|---|
| v1 | 数组位桶解码快路径 | 属性数组解码按常见位宽走直线 |
| v2 | 属性存储浮点快路径 | float 数组解码免通用路径 |
| v3 | 向量查询记忆化 | 同一查询内重复的向量转换/校验只做一次 |
| v4 | 向量相似度单遍就地 | 省一趟扫描 + 一份拷贝 |

## 实测（在最优客户端之上累积）

| 版本 | x86_64 | 鲲鹏 |
|---|---|---|
| v1 | 5.54 → 3.86（−30%） | 6.01 → 4.60（−24%） |
| v2 | → 3.32（−14%） | → 4.15（−10%） |
| v3 | → 3.15（−5%） | → 3.81（−4%） |
| v4 | → 3.22（持平） | → 3.81（0） |

服务端累计 −42% / −37%；**写入 ±0.1 s（结构性无收益，符合预期）**。

## 风险

- 收益强烈依赖并发度与架构：同一套补丁在 5 副本 x86_64 上让检索 15.59 → 8.12 s（−48%），
  在鲲鹏只有 2~4%；
- 只改读路径就断言"整体提升"是错的，写路径占比高的场景会被稀释；
- 版本管理与回滚必须扎实，否则"优化后不知道基线是哪份二进制"。

## 不适用于

服务端封闭二进制；或客户端尚未优化到位（结论须标"待客户端优化后复测"）。
优先选读路径热点，写路径通常无收益。
