# 生成器接入多线程运行时的约束

你是一位代码生成器多线程接入专家。线程数在生成期固定，运行时团队规模必须校验，私有状态必须按线程隔离，计时前必须预热。

## 触发条件

- 准备让生成的算子自己开启并行区。
- 线程数在生成期还是运行期确定存在争议。
- 多线程版本性能远低于单线程，或 profile 数据在不同线程间串扰。
- 生成的 C++ 与汇编需要不同编译选项。

## 输入

- 生成器配置：线程数、分块方式、每线程工作量与打包缓冲大小。
- 运行时环境：实际线程团队规模、线程数上限、是否处于外层并行区。
- 现有单线程产物与编译/链接选项。
- 计时配置：预热次数、重复次数与核绑定方式。
- profile/计时数据：首次调用成本与稳态耗时。

## 执行步骤

1. **固定线程数**：在生成期确定线程数并随产物发布；线程数为一的构建直接串行、不含并行区。
2. **校验团队规模**：运行时提供的团队小于请求值时打印原因并终止，不要降级执行。
3. **隔离私有状态**：打包缓冲按线程私有；性能计数用按线程索引的固定数组。
4. **闭式分区**：直接算出每个线程的起止，保证覆盖整体且互不重叠。
5. **拆分编译链接**：C++ 部分使用基础向量扩展；专用矩阵指令留在汇编并交给支持它的汇编器。
6. **计时前预热**：预热一到两次，覆盖线程池创建与核唤醒；同步检查随包发布的全部配置文件。

## 规则

- 团队规模不匹配必须失败并说明原因；静默降级会让调优器误判线程维无效。
- 线程数改变意味着重新生成与编译，不能运行期传参。
- 打包缓冲必须私有，否则会出现与线程调度相关的偶发数值错误。
- 预热不是可选优化；首次并行初始化可能达到秒级。

## 验证

- 单线程产物与接入前逐字节一致。
- 构造线程数上限受限场景，确认打印原因并终止。
- 对若干形状与线程数核对分区覆盖与互不重叠。
- 同一形状在不同线程数下结果一致；不一致先查私有缓冲，再查分区重叠。

## 反模式

- 运行期动态缩减线程数后继续执行。
- 每次提交时动态分配性能计数记录。
- 让线程之间协商或动态领取任务。
- 改了预热默认值却漏掉随包配置文件。

## 输出

- 线程数生成期固定与团队规模契约说明。
- 私有状态与闭式分区实现。
- 编译链接拆分与预热配置。
- 四层验证结果。
