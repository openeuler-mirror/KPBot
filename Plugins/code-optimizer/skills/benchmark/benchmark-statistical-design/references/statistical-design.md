# 基准统计设计全量（标定案例）

## 1. 方案 C（数据池一致性优先）

多组多轮对比里，若每组重 seed，数据池会漂移，组间差异就无法归因。方案 C 用黄金卷解决：

```
每组 4 轮：
  轮1 = build + seal 存档轮（不计分）
  轮2..4 = 3 个黄金卷 clone 复用轮（数据点）
组间独立黄金前缀：<prefix>_g{1..3}
```

- build+seal 轮固化底库（`benchmark-golden-volume-replay`，独立 PR 待合入），存档不计分。
- 3 个 clone 复用轮为数据点，底库与 build 轮逐字节一致。
- 9 个数据点数据池完全一致：起点 81592 行 → 终点 82480 行（`milvus-storage.json` 实证）。

> **行数一致 ≠ 内容一致**：三组各自 build 黄金卷时，clone 只保证**组内**来源相同；不同组即便起止行数相同，
> 仍可能包含不同向量或租户分布。要排除数据池漂移，还需二选一：(a) 让各组从**同一已校验快照**派生；
> (b) 无法派生时，比较各组的**稳定数据摘要**（行数 + 租户数分布 + 向量/行内容校验和），摘要一致才认为
> 数据池无漂移。标定案例的行数实证只覆盖"行数层"，内容层摘要需一并记录才构成完整的一致性证据。

## 2. 指标口径

对每指标报告三列：组内均值（3 组）、组内 CV%（区间）、组间 CV%。

14 指标 = 3 个相位的 3 类口径：`qa`（retrieval 吞吐 / retrieval p50 / p95 / p99 / extraction 吞吐 /
elapsed）、`ingestion`（memory_write 吞吐 / retrieval 吞吐 / elapsed）、`overall`（elapsed / retrieval 吞吐 /
retrieval p50 / p99 / extraction 吞吐）。本 reference 只内联 5 个关键指标的三组完整值（下表），
完整 14 指标原始值报告结构（每指标原始值 / 组内 mean·std·CV / 组间 CV）随标定项目内部存档，
不入本 skill 包——如需复算，用下表的完整三组值即可核验 CV 公式与阈值判定。

关键指标形态：

| 指标 | g1 / g2 / g3 组内均值 | 组内 CV%（区间） | 组间 CV% |
|---|---|---|---|
| qa.elapsed_seconds | 114.83 / 115.23 / 123.69 s | 0.36-0.84 | 4.24 |
| qa.retrieval 吞吐 | 80.46 / 80.23 / 74.65 req/s | 0.38-0.67 | 4.19 |
| qa.retrieval p50 | 55.67 / 56.00 / 64.35 ms | 0.63-1.46 | 8.38 |
| qa.extraction 吞吐 | 13.92 / 13.87 / 12.92 req/s | 0.38-0.83 | 4.15 |
| overall.elapsed_seconds | 121.10 / 121.45 / 130.02 s | 0.20-0.84 | 4.07 |

> 汇总范围说明：上表「组内 CV%（区间）」只覆盖这 5 个指标各自的组内 CV 分布；`qa.retrieval p50`
> 的组间 CV 8.38% 与 `overall.elapsed_seconds` 组内 CV 下界 0.20% 是这两个指标各自的极值，
> 不代表其它指标的 CV 也落在同一区间。判读阈值见 §3，不把单一指标的 CV 外推到全部 14 指标。

## 3. CV 分解判读（描述性，非因果定论）

- 组内 CV（0.20–1.46%）：同一数据池内多轮高度紧致，只能说明**测量本身稳**，不推论任何显著性。
- 组间 CV（吞吐/elapsed 类 4.07–4.24%、p50 8.38%）：g1/g2 均值几乎重合，g3 系统性偏慢
  （吞吐/elapsed 类 ~7%、p50 类 ~15%）且组内紧致（CV<1.5%），呈"组内离散度低 + 组间台阶"形态。

**判读口径（与仓库既有统计纪律对齐，不擅自下因果结论）**：

- 上面这种形态只支持**描述性观察**："三组多轮测量紧致，但 g3 均值相对 g1/g2 存在约 7%（吞吐/elapsed 类）~ 15%（p50 类）的组级偏移"。
- 该偏移**是否与被测改动相关、是外部负载还是真实回归，属 inconclusive（原因待定）**：本标定案例里
  运行时段与组别一起变化（g3 在窗口最末段跑，跨 66min），无法用 CV 区分"外部负载漂移"与"其它组级差异"。
  要下结论需对齐主机负载记录，或把组序交错重测（g1/g2/g3 打乱时间顺序各跑一轮）。
- 判定"明显漂移 / 收益 vs 噪声"的规范动作见既有真源
  `verify-optimization/references/repeated-measurement.md`（统计工具只输出描述性结果，不给 passed；
  误差条不重叠或若干轮同方向都不能单独当作显著性检验）与
  `benchmark-visualization/references/statistics-rules.md`（不用波动范围自动判断显著性）。
  本 skill 只产出 CV 分解这张"描述性温度计"，不做验收放行。

## 4. 公式（std 分母口径）

- 组内 CV = std(该组数据点) / mean(该组数据点) × 100%
- 组间 CV = std(各组均值) / mean(各组均值) × 100%

**std 一律用样本标准差（分母 n−1，即 numpy `ddof=1` / pandas `DataFrame.std()` 默认）**。

- 组内 CV：每组 3 个 clone 数据点，n=3，分母 n−1=2。
- 组间 CV：3 组均值，n=3，分母 n−1=2。用表中 qa.retrieval 吞吐三组均值 [80.46, 80.23, 74.65] 复算：
  样本标准差口径组间 CV ≈ **4.19%**（本表报告即此口径）；若换总体标准差（分母 n）则 ≈ 3.42%。
- 差异来源：n=3 时样本标准差 = 总体标准差 × √(3/2) ≈ 1.225 倍。**CV 接近观察线时必须写明用哪个分母**，
  否则同一组数会给出 4.19% vs 3.42% 两个结论，直接改变是否触发复测。

两个 CV 一起报：只有组间 CV 不知道是"组内抖动大"还是"系统性台阶"；只有组内 CV 不知道组间效应。

## 6. 坑点

- **不隔离复制池**：组间复用同一前缀会导致 clone 卷串组，9 个数据点不再独立。
- **存档轮计分**：build+seal 轮的 elapsed 含固化成本，若计入数据点会系统性偏慢。
- **只报组间 CV**：看不到"g3 组内紧致"这个判据，无法排除"单轮离群"。
- **共享执行机**：跨窗口负载漂移不可归因到被测改动；超过观察线只说明"值得复测"，需独占机器、
  记录负载窗口、或交错组序排除时段混淆，结论仍停留 inconclusive。
