# 服务端火焰图

## 工具选择

| 服务端运行时 | 工具 |
|---|---|
| JVM | async-profiler / JFR |
| Go | `pprof` |
| C++ | `perf record` |
| Python 服务 | `py-spy` |

## 要区分的三类（占比决定补丁顺序）

| 类别 | 典型符号（以某 JVM 属性图库为例） | 实测占比变化 |
|---|---|---|
| 属性/数组解码 | `PropertyStore.readArrayFromBuffer` | 7.4~10.0% → 4.7~4.9% |
| 向量合法性/拷贝 | `VectorSimilarityFunctions$*.maybeToValidVector` | 8.0~10.3%（补丁目标） |
| 查询执行/规划 | 查询规划与执行层 | 大但不可改（框架成本） |

## 判读

- 单行解码类函数 ≥ 5% 且"每行必走" → 值得改（快路径 / 批量 / 去临时对象）。
- 相似度类 → 先看是否多次遍历或多次拷贝，单遍就地通常能省一趟扫描 + 一份拷贝。
- **写路径不看这些函数**：服务端读路径补丁对写入实测 ±0.1 s，属结构性无收益。

## 前置

- 客户端必须已优化到位，否则服务端耗时被客户端噪声淹没，测不出真实收益；
- 机器空闲度 ≥ 98%，采样窗口在稳态（缓存已热、JVM 已预热）。

## 输出

- 三类占比（优化前/后）
- 候选补丁清单与目标对照（交给 `graph-store-readpath-patch`）
