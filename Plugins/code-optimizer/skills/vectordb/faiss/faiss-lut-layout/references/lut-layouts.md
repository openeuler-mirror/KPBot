# LUT 布局对比

## 连续打包缓冲

- 形态：每列表把 nc 个查询的表行按消费者顺序拷进连续缓冲（nc × dim12），不足位以填充值补齐；消费者在内核里顺序推进 LUT 指针。
- 优点：消费者访问完全顺序；与 qbs 打包形态天然耦合；对窄寄存器层友好。
- 成本：每列表一次 memset（填充）+ 全量拷贝；nc 小或列表短时 setup 占比失控。

## 行指针直寻址

- 形态：仅准备每查询的行指针数组（指向原始表区），消费者按 `rows[q] + 子量化器偏移` 直接取行；无拷贝、无 memset。
- 优点：setup 降为指针计算；布局与 qbs 形态解耦，各层可用自己的分组映射；表区共享只读。
- 成本：消费者每次取行多一次间接寻址；原始表区布局必须与消费者期望一致（子量化器 ×16 字节组织），否则仍需重排。

## 切片与分片

- 8-bit 浮点表（M 行 × ksub）通常远超 L1：按子量化器组切片（如每 4 个子量化器一片），让一片在处理一批码期间驻留 L1，码循环按片推进。
- 布局与访问顺序共同决定驻留：只改布局不改访问顺序拿不到收益，须一起设计并测量。
- 表压缩（更窄元素、偏置缩放）改变数值契约，属于质量权衡，另立实验。

## 选择依据

| 条件 | 倾向 |
| --- | --- |
| nc 大、列表长（拷贝可摊销） | 打包或行指针均可，测每元素成本定 |
| nc 小或列表短 | 行指针（消除每列表固定拷贝） |
| 表足迹超 L1 | 切片/分片，与访问顺序联合设计 |
| 各层需差异化 qbs 映射 | 行指针（解耦布局与分组） |

## 接口两侧

布局切换要求生产者与消费者成对扩展：新增行式入口时，扫描器接口补对应方法并保留打包入口为默认；未覆写的实现回落旧路径。两侧接口都要进测试矩阵，防止只改一侧造成的静默错位。
