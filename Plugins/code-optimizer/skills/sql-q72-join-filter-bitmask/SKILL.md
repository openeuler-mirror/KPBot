# SQL72 连接过滤结果的位图压缩

## 说明与范围

`HashProbe` 完成商品键探测、候选配对和剩余谓词求值后，还要从候选数组取出通过的配对。对满足条件的内连接，直接按序枚举布尔位图中的真位，并同步压缩建表行指针和探测侧行号。例如 `[false, true, false, true]` 只需要搬运下标 `1` 和 `3` 对应的两组映射。压缩接在真实过滤求值之后，原谓词的求值范围保持不变。[实施细节](references/implementation.md)

## 与相邻技能的分工

本 skill 位于候选配对及剩余条件求值之后，只压缩通过位对应的两组行映射。[数量上界预筛](../sql-q72-join-quantity-pruning/SKILL.md) 位于哈希探测之前，负责减少探测行和候选配对。两者分别统计输入行、候选配对及通过配对，不能把压缩收益记成减少哈希查表。

若压缩后的输出仍有字符串物化热点，由 [连接字符串物化](../sql-join-string-materialization/SKILL.md) 处理列提取及拥有方；本 skill 保留原映射和谓词求值范围，不负责搬运字符串字节。

## 输入

| 输入 | 核对内容 |
| --- | --- |
| 查询与物理计划 | 内连接节点、剩余谓词来源、实际 build/probe 方向和链路中使用的算子 |
| 过滤结果视图 | 候选数 `numRows`、布尔元素布局、解码映射、NULL 保证、活动行范围 |
| 输出结构 | `outputTableRows`、`rawOutputProbeRowMapping`、相关行数及原地写入约定 |
| 回退契约 | 外连接、半连接、反连接、缺失匹配检测和通用 `filterPassed` 分支 |
| 验证环境 | 目标源码版本、可运行样本、选择密度、位图边界、局部与完整查询基线 |

## 实施步骤

### 1. 把配对生成、条件求值和输出压缩分开定位

```text
哈希探测 → 枚举候选配对 → 对配对求值 → 布尔位图 → 压缩两组行映射 → 列投影
```

在 `HashProbe::evalFilter` 找到读取已解码布尔结果并压缩输出的分支。记录热点究竟出现在谓词计算、候选生成，还是检查通过标记。后两种输入计数分开记录。

### 2. 核实布尔位图能直接按候选行号访问

准入须为内连接、`numRows > 0`、过滤输入全部选中、解码结果为 identity mapping 且明确无 NULL。确认引擎提供的布尔数据访问器返回相应位图，并且候选两组映射长度覆盖 `numRows`。字典/常量映射或可能有 NULL 时保留通用读取。

### 3. 保留特殊分支与未匹配行检测

在原有特殊连接语义分支之后放置位图路径。确认当前代码版本是否先处理缺失匹配、外连接填充等逻辑。条件不符时执行原生的 `filterPassed` 或原特殊分支，保证为 NULL 的条件仍按原规则处理。

### 4. 按正序枚举真位并同步移动两组映射

用引擎现有按真位遍历器把扫描限制在 `[0, numRows)`。从最低真位向上枚举，每命中一个消耗一个输出槽，同步写入建表行指针和探测行号。正序下已写数量不超过当前源下标，可以保持原地压缩安全以及重复配对的相对顺序。

### 5. 核对返回计数、尾位和后续投影

返回真实通过行数。全假结果应为零，全真应保留完整顺序。最后一个位图字中候选域外的填充位不能生成输出。验证后续列提取使用压缩后的行映射和同一个计数，避免把商品、日期或数量取自不对应的原行。

### 6. 同时验证有效路径和回退路径

覆盖空批、全假、全真、稀疏、多个重复配对、`63/64/65` 行、脏尾位、NULL、字典、常量映射、部分选中以及非内连接。对照两组映射、输出行数、顺序和重数。只比行数会漏掉映射串位。

### 7. 分开测压缩开销和完整查询

对不同命中密度测每候选配对、每通过配对的压缩耗时，记录候选行与通过行、快路径次数和回退原因。保持候选配对与原条件相同，再用同环境交错复测端到端耗时。稀疏命中通常更容易观察到收益，稠密输入也应提交退化数据。

## 约束

- 保留原谓词计算和 SQL NULL 行为。只有已证明 identity 且无 NULL 的布尔位图可直接使用。
- 原地写入需按真位正序，成对移动两组映射并保持重复配对的重数。边界只使用有效候选范围。
- 空批、部分选中、非内连接、间接映射和可能有 NULL 时按原语义执行。外连接未命中处理不得被旁路。
- 位图压缩节省的是过滤后的选择与搬运。单独记录比较、配对生成与压缩的工作量，避免合并归因。

## 交付与验收

交付执行边界、位图与映射的准入证据、对照结果、每种密度的局部数据及完整查询复测。至少输出以下字段。

```text
模式 | 候选配对 | 通过配对 | 位图路径批次 | 回退原因 | 双映射一致性 | 压缩耗时 | 查询秒数
```

从目录根运行 `python3 cases/join-bitmask-contract/run.py`。契约在 `cases/join-bitmask-contract/case.yaml`，结果写入同级 `results/result.json`。`bitmask_route_positive` 验证确实选择位图并按原顺序搬运两组映射。`python3 -O cases/join-bitmask-contract/run.py` 与 `PYTHONOPTIMIZE=1` 模式应一致。始终回退或读出有效范围之外的位时，用例应以非零退出。

模型评估规格在 `evals/evals.json`。本地位图用例验证路径和映射契约，真实 `HashProbe` 分派及性能需要目标端验证。缺失的证据标为 `awaiting_target_evidence`。
