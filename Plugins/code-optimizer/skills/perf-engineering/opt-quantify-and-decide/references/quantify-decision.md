- 其它锚（每对 = 两个相位的同名计数，或 events/items 两列，见下方标注）：

  - 1140/4140：**ingestion** 相位的 memory_write events / items 两列
  - 8700/12000：**qa** 相位的 memory_write events / items 两列

### 质
- 顶层 `user_id == "trace-user-001"` 计数 = **10000**、空值 = **0** → **底库**确实有该用户 10000 条预热数据。
  **但这不证明每次检索真命中**：错误过滤条件可能让每次检索返回空集、请求数却照样一致。还需**对齐回放查询**，
  核对每请求实际响应的**命中数**与**结果 ID**——候选与基线命中数一致、结果 ID 对齐（近似检索约定召回率容差
  如 `|候选∩基线| / k ≥ 0.9`）。

## 5. 噪声判定
- TOP2 三轮 80.6/78.2/80.3 全部高于基线中位 → 但这**不是充分判据**：若基线是 70/75/85、候选 78/79/80，
  三轮高于中位、中位 +3% 却仍全落在基线波动范围 [70,85] 内。**用交替复测的逐轮差值估计不确定性区间**，
  差异系统性超出噪声范围才算增益；证据不足则保留"待定"。
- GOMEMLIMIT 单轮 -5.16%，方向为负且落在 flatidx 轮间波动内 → 判为噪声、放弃（单轮证据，标"本轮未检出收益"）。
  **注意**：qa retrieval 的 flatidx 三轮原始值本记录未留存（见 §2 注），"落在轮间波动内"无法在本文件内复算，
  此处沿用标定项目内部存档的结论，复验时需回补 flatidx qa retrieval 三轮原始值。

## 6. 代价量化与决策
- TOP2 代价：预分配按上界容量，对小结果集过度分配 → p99 +6.77%（~+30ms）。
