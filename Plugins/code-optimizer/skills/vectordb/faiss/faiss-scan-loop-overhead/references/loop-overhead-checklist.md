# 扫描循环开销检查表

| 开销 | 观测方式 | 改写 | 必测项 |
| --- | --- | --- | --- |
| selector/过滤分支 | 分支占比、误预测率；调用方是否恒为空 selector | 模板布尔编译期特化，无过滤实例删分支 | 两实例分别对照同条件基线逐结果一致（含 selector 排除原 Top-1 的场景）；二进制体积；有过滤路径不退化 |
| 共享统计写 | 每迭代写共享计数器；跨线程伪共享 | 局部累加 + 出口单点 flush | 计数语义与原口径一致；异常路径也 flush；并发汇总 |
| 间接索引（saved_j/ids[j]） | 暂存-回读模式；寻址指令占比 | 连续分组直取（如 4 码一组按 j 直接寻址） | 非 4 倍数尾段；过滤路径仍用暂存 |
| heap/结果容器 | 更新次数 / 接受比例 | 按比例决定：预判阈值、容器改写或维持 | tie 与替换顺序；更新语义 |
| 入口校验 | O(n) 逐项断言耗时 | 并行化或合并校验 | 失败条件与异常类型不变；并行下无数据竞争 |
| 指针表空判 | 每 scan 前置判断 | 提前抛错或编译期消除 | 空表路径的报错契约 |

## 判读规则

- 调用次数多不等于单次开销高：先算每调用成本再决定优化对象。
- 读点加速（直取、预取）可能增加写点维护成本，读写比例一起看。
- 分支消除的收益依赖误预测率与流水线深度，以对照为准，不以指令数下降为准。
- 特化实例的冷热分离（无过滤热、有过滤冷）可能改善 I-cache；同样以对照确认。
