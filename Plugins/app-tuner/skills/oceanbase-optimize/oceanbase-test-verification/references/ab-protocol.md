# A/B 协议、噪声与报告

## 1. 什么算有效对比

有效 A/B 必须同时满足：

1. 同一数据快照（重置或恢复）。
2. 同一 OB 版本；二进制身份按被测变量区分：
   - **测运行参数**：两腿必须使用同一二进制，md5/commit 摘要一致（否则无法归因于参数）。
   - **测编译选项或源码补丁**：两腿本就是不同二进制，分别记录各自 md5/commit 与
     编译参数，并固定其他条件（数据快照、配置、Unit、`primary_zone`、绑核、
     连接方式、并发/时长、预热、轮数）；不要求摘要相同，否则会排除有效实验。
3. 除被测变量外，配置一致（Unit、冻结/限流、线程、绑核、obproxy）。
4. 同一连接方式（直连/obproxy）、同一并发/时长、同一预热。
5. 每腿 ≥3 轮；取中位数或均值，并给出波动范围。
6. 单变量：一次只改一个参数/编译选项/补丁。

## 2. 噪声判定

| 指标 | 噪声阈值（经验） | 处理 |
| --- | --- | --- |
| TPS/QPS | 轮间波动 >5% | 重测；检查数据/冻结/其他负载 |
| avg 延迟 | 波动 >5% | 重测 |
| P95/P99 | 波动 >10% | 重测；长尾对冻结/合并敏感 |
| CPU | 波动 >3% | 检查是否跨 NUMA/其他进程 |

收益 <5% 一般视为噪声；除非多轮稳定且业务指标同步改善。负收益必须回滚并记录。

## 3. 常见“假收益”

| 现象 | 原因 | 纠正 |
| --- | --- | --- |
| 改参数后 TPS +20% | 同时改了绑核/租户/obproxy | 回到单变量，固定其他条件 |
| 只读提升但写下降 | 场景不同，用读场景掩盖写回退 | 分场景列结果，不合并 |
| 去掉 obproxy 后大涨 | 口径变化（少一跳） | 明确标注为诊断实验，不作为优化收益 |
| 换盘/换内存盘后提升 | 瓶颈在 IO，不是配置 | 先判断 IO 是否主瓶颈 |
| 关审计后提升 | 审计本身是开销 | 记录副作用与合规影响 |
| 忽略错误码后成功率高 | 错误被跳过 | 报告忽略码与比例 |

## 5. 停止条件

出现以下任一情况，停止性能对比：

- 功能冒烟/计数/事务回读失败。
- 节点/租户/副本状态异常。
- 错误率显著上升且不是预期冲突。
- 数据未重置或环境有其他负载。
- 二进制/配置身份无法确认。

## 6. 归档

每次 A/B 归档：

1. 原始 sysbench 日志（含每轮）。
2. 参数快照（`SHOW PARAMETERS`）。
3. 节点/租户/Unit 快照。
4. 二进制 md5/编译参数；压测工具链须另记 sysbench/LuaJIT 归档 sha256、LuaJIT
   固定 tag（`v2.1.0-beta3`）及冻结 commit、解压后版本串、编译出的 luajit 二进制 md5
   （安装步骤见 `benchmark-harness.md` §1）。摘要缺失或两腿不一致时，本轮标为不可比。
5. observer/obproxy/sysbench 的 pidstat/mpstat（如有）。
6. 结论与回滚命令。

## 8. 常见失效模式（完整表）

| 现象 | 可能原因 | 处置 |
| --- | --- | --- |
| TPS 锁死，sysbench CPU 打满 | 客户端先瓶颈（Lua/结果解码） | 加客户端/减结果集/换场景 |
| 只读 QPS 低但 observer CPU 不满 | 租户 CPU 配额小、worker 少、跨 P | 查 Unit、worker、绑核 |
| 写入 CPU 明显低于读场景但 TPS 不升 | 等 IO / ApplySrv / 冻结 | off-CPU、线程 CPU、磁盘延迟 |
| 多实例性能差 10%+ | 网卡中断跨 NUMA、实例互相抢 | VF/中断隔离、每实例独立 NUMA |
| 成功率下降 | 唯一键冲突、超时、副本异常 | 先查错误码与日志，不只看吞吐 |
| 两轮差异大 | 数据未重置、冻结/合并、其他负载 | 重置数据、预热、固定核、记录环境 |
| 128U 跑不满 | `net_thread_count` 不足（sql_nio 瓶颈） | 加 net 线程；确认租户 CPU |
| 新二进制结果不同 | 语义回归/数据格式不兼容 | 立即停性能测试，跑功能冒烟 |
