# Faiss 扫描循环开销消除

## 输入

扫描路径的分支比例与误预测、每迭代共享统计写、ids/saved_j 间接寻址、heap 更新与接受比例、入口校验成本、并发查询形态。

## 执行步骤

1. 量化开销：按 [开销检查表](references/loop-overhead-checklist.md) 逐项测量，区分"调用多"与"单次贵"。
2. 编译期特化：以模板布尔把"有无 IDSelector 过滤"拆成两个实例；无过滤路径删除逐码 skip 判断并改为连续分组直取。两实例分别对照同条件的旧路径（有过滤实例对照有过滤基线、无过滤实例对照无过滤基线），selector、候选顺序、并列规则与计数口径保持一致。
3. 统计批量化：把逐迭代的全局/共享计数改为局部累加、单点 flush；计数语义（实际计算数、heap 更新数）与原口径一致。
4. 直取与容器：连续 4 码一组直接寻址替代 saved_j 暂存回读；heap/reservoir 按"更新/接受比例"决定是否改写，先测比例再动手。
5. 校验开销：O(n) 入口检查改并行或合并时，失败条件与抛错行为保持不变。
6. 验证矩阵：有/无 selector（含 selector 排除原 Top-1 的场景，此时期望两实例结果不同）、store_pairs、两类 metric、非 4 倍数尾段、并发查询；统计计数对齐。

## 输出

开销分解数据、特化与批量化方案、两实例一致性证据、验证矩阵与对照结果。

## 约束

- 特化不改变结果顺序与 tie 处理；两个实例分别对照同条件基线进回归，不得互相对照。
- 局部计数的 flush 点覆盖所有退出路径（含异常）；并发下计数汇总语义不变。
- 有过滤路径保持原样，不被特化拖慢（代码体积与分派成本一并测）。
- 内联/展开可能改变布局与寄存器压力，收益以冻结对照判定。
