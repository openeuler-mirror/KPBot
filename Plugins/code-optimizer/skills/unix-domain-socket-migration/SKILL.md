# Unix Domain Socket 迁移

你负责判断一条同机进程间通信链路是否值得从 loopback TCP 换成 AF_UNIX（UDS），并在允许时完成迁移。输出必须回答四个问题：**能不能、怎么做、有没有收益、代价是什么**。四个问题按顺序回答，前一个不成立就不进入下一个。

这是一条传输链路级别的工程决策，不追求「换了就一定更快」。客户不允许改环境、不允许反复压测时，给出可行性判定、收益上界、改动清单和回退方案，本身就是完整交付。

本 skill 属经验/方法类：按「现场特征 → 判断依据 → 处置动作 → 实测效果 → 复验方法 → 适用边界」组织；验证部分同时遵循方法与验证类的基线、通过条件和不可比条件约定。

## 先确认换的是哪条链路

同一条通信链路上可能同时存在两类 socket：

| 链路 | 例子 | 迁移影响 |
|---|---|---|
| 对外监听 | 客户端连接服务端的端口、Redis/HTTP 监听 | 客户端也要改；监控、防火墙、服务发现受影响 |
| 内部进程间 RPC | proxy→datanode、app→agent、sidecar→backend | 两端都在自己控制内；影响面小，通常是首选 |

先定位要换的链路，不要把对外监听的 UDS（例如服务自身提供的 `unixsocket` 配置项）和内部 RPC 传输混为一谈，两者的配置位置、客户端改造和回退方式都不同。

## 输入

开始前从代码、配置和用户处收集：

```text
链路           客户端进程 → 服务端进程，承载什么协议，请求形态（小消息/大消息、QPS、连接数）
拓扑           是否同 host，是否同容器，路径在两端是否可见，是否有共享卷
两端可控性     能否改配置、能否重启、能否接受灰度，是否有混合版本窗口
传输实现       框架/库/自研，是否原生支持 AF_UNIX 监听与连接，连接类型（短连接/长连接/连接池）
观测手段       是否有 perf、strace、ss 权限，能否采集 syscall 与内核路径占比
验证授权       只读评估 / 一次性验证 / 允许交替 A/B
约束           客户禁止改现网、禁止压测、禁止重启等
```

## 第一问：能不能

逐项过门禁表。任何一项不满足，先给 `not_applicable`、`needs_prerequisite` 或 `blocked`（缺证据时），不要继续做收益对比。

| # | 检查项 | 怎么查 | 不满足时的结论 |
|---|---|---|---|
| 1 | 地址类型与可见性 | 先区分 pathname 与 abstract：pathname 检查两端共享文件系统/挂载可见性；abstract 检查是否在同一 network namespace、框架是否支持、对端身份策略 | pathname 不可见判不适用；abstract 不依赖共享目录，不能因路径不可见直接判不适用 |
| 2 | 框架原生支持 UDS | 查文档/源码：监听地址能否写成 `unix:`/`unix://`/路径形式；客户端连接地址是否同样支持；版本是否覆盖目标版本 | 评估代码改造量（见「怎么做」），改造大或框架不可改时判不适用 |
| 3 | 路径长度与目录 | Linux `sockaddr_un.sun_path` 只有约 108 字节；路径尽量短（如 `/run/<svc>/<name>.sock`）；目录存在且可写 | 换短路径或改用 abstract namespace（若框架支持）；否则不适用 |
| 4 | 权限模型可接受 | pathname socket 的访问控制来自文件系统权限；连接方需要对端 socket 文件有写权限、对目录有进入权限；跨用户场景确认 chmod/chgrp 与 umask | 权限无法对齐时不适用；可用 `SO_PEERCRED` 做对端身份校验 |
| 5 | 生命周期可管理 | 框架停止时是否自动删除 socket 文件；崩溃（SIGKILL/掉电）后是否残留；启动前清理策略是否安全 | 无法管理残留时不适用（残留会导致下次 bind 失败） |
| 6 | 观测与探活可替代 | 健康检查、服务发现、监控、防火墙、负载均衡是否依赖 TCP 端口/端口探测 | 列出替代方案（客户端带超时 connect、最小协议请求、进程指标）；替代不了时先不动 |
| 7 | 部署形态允许 | 只读文件系统、受限容器、跨 pod 无共享卷、SELinux/AppArmor 限制 | 按具体限制判不适用或先补挂载/策略 |
| 8 | 多实例路径唯一 | 同机是否有多个副本；路径是否按实例/租户区分 | 设计唯一路径；一个路径只能有一个 listener |
| 9 | 发布方式允许 | 两端能否同时切换；能否灰度单实例；混合版本是否能兼容 | 不能灰度且不能停服时，先做配置可切换的改造 |
| 10 | 收益空间存在 | 小消息、高频、每请求往返；瓶颈证据指向内核网络路径或每请求系统调用 | 瓶颈在存储/业务/锁/大消息带宽时，换 UDS 的收益会被淹没 |

## 第二问：怎么做

### 原则：一个 listener，一条配置

把传输方式做成一个 endpoint 字符串，让 TCP 和 UDS 走同一条代码路径。不要新增第二个 listener、第二个 server 或第二套连接分支——历史案例里最初的实现就是加了一个并行 UDS server，随后反复回退，最终全部删除、改为纯配置驱动。双 listener 会带来清理、就绪判定、监控和回退的双份复杂度，收益却相同。

### 配置优先

优先使用框架已有的 endpoint 配置，不改业务代码：

```text
# 服务端（监听）
bind  unix:/run/<svc>/<name>.sock

# 客户端（连接）
backend-addrs  unix:/run/<svc>/<name>.sock
```

两端按各自框架的地址语法解析同一个 socket：pathname socket 通过文件系统可见性关联，同一共享卷可以在两端挂到不同路径（如服务端 `/run/backend`、客户端 `/mnt/backend`），因此不要求配置字符串逐字节相同；照抄服务端路径可能反而连不上。改完后从客户端实际 `connect`，验证连到的是预期服务。

### 生命周期

```text
启动前：若框架不清理残留 → 确认没有 live listener 后删除残留文件
启动中：先起服务端，客户端等待/重试；就绪判定用客户端带超时的 connect，`ss -xl` 只用于人工确认监听者
运行中：不要删除 socket 文件；不要重复 bind 同一路径
停止后：确认进程退出后再清理；框架已自动清理时不要重复删除
```

清理前必须先确认没有监听者。直接 `rm` 一个仍被使用的 socket 文件会让在途连接行为不可预期。

路径使用绝对路径：相对路径按各自进程的工作目录解析，两端 cwd 不一致时会连到不同路径。

### 权限与身份

```text
目录：0750 或更严；属主/属组按服务账号设置
socket 文件：由 umask 或启动后 chmod 控制；跨用户访问时显式 chmod/chgrp
身份：需要校验对端时用 SO_PEERCRED（uid/gid/pid），不要依赖路径本身
多租户：同机不同租户共用 UDS 时需要目录级隔离，文件系统权限就是安全边界
```

### 框架不支持时的代码改造

只在确认框架没有 UDS 能力、且改造可控时执行。改造范围应限制在传输适配层：

```text
1. endpoint 解析：识别 unix: 前缀，构造 sockaddr_un（注意 sun_path 长度与终止符）
2. 监听：socket(AF_UNIX, SOCK_STREAM, 0) → bind → listen；路径冲突时给出明确错误
3. 连接：connect 前处理 ENOENT/EACCES/ECONNREFUSED；支持重试与超时
4. 清理：进程正常退出时 unlink；异常退出后由下次启动的残留清理兜底
5. 测试：等价性（同一组请求/响应）、错误路径（路径不存在、权限不足、残留文件）、并发与重启
6. 不要引入第二套事件循环或协议栈；TCP 与 UDS 共用同一读/写/超时逻辑
```

### 监控、探活与回退

- 端口探活改成客户端带超时的 `connect`；`ss -xl` 只用于人工确认监听者，不能替代 connect。需要判断业务就绪时，在 connect 之后再发最小协议请求。
- 依赖 TCP 端口的服务发现、防火墙、负载均衡规则要同步调整，避免留下「端口没了起来了但没人用」的盲区。
- 保留 TCP 配置作为回退：切换 UDS 前确认回退步骤可执行，回退时两端一起改回并清理 socket 文件。
- 灰度优先单实例/单分片，观察错误率、连接数与延迟后再全量。

## 第三问：有没有收益

### 机制与上限

AF_UNIX 跳过 TCP/IP 协议栈（IP 分片重组、TCP 拥塞控制与状态机、校验和、路由、skb 处理），因此能消掉这部分内核开销。但它仍然经过 socket 层、epoll、系统调用和数据拷贝，收益上限是链路中内核网络路径的占比，不是「零开销」。

标定案例里，perf 中 `tcp_transmit_skb`、`ip_finish_output2`、`enqueue_to_backlog` 等 TCP/IP 栈函数是主要可消除开销；具体占比未随包披露，收益上限按目标环境实测确定。后续 profile 也确认 TCP 前端和 UDS 后端都仍会经过 socket/epoll，因此继续压收益要靠减少调用频率，而不是继续换传输。

### 成立条件

| 条件 | 说明 |
|---|---|
| 同机高频小消息 | 每请求都有一次往返，且消息小到 TCP/IP 栈开销占比可见 |
| 连接已复用 | 若每条请求都新建连接，收益主要来自建连成本，波动大且容易误判 |
| 瓶颈证据指向内核路径 | perf 中 tcp/ip/skb 路径占比高，或 `strace -c` 显示每请求系统调用多 |
| sys% 有下降空间 | 内核态占比高、用户态逻辑并不重 |
| 对端可控 | 两端都能改配置或代码；只有单侧可改时先评估是否仍值得 |

不成立：大消息或带宽主导、低 QPS、长连接上请求稀疏、瓶颈在存储/业务/锁/GC、跨机或路径不可见。

### 不能实测时的估算

允许只读评估时，用下面三类证据给出保守上界，并明确标注 `upper_bound` 与 `verified=false`：

```text
1. perf/SPE 火焰图：TCP/IP 栈函数在总 on-CPU 中的占比
2. `timeout -s INT 10s strace -c -f -p <pid>`：每请求 syscall 数与类别（send/recv/epoll/writev）；`-s INT` 让 strace 在中断时打印汇总
3. 在目标进程所在 netns 用 `ss -ntp state established`（TCP）或 `ss -xp state established`（UDS）核对连接两端地址与进程归属；`ss -x` / `ss -ltn` 只列本机 socket，不能证明目标连接走了 loopback
```

上界 = 可消除的内核路径占比 × 该路径在总时间中的权重，不要直接外推成端到端提升；如果采不到数据，只给「条件成立时的方向与量级」，不给数字。

### 实测方式

```text
同负载、同机器、同连接数、同数据、同绑核；
一次前后对比：TCP 基线 → 切 UDS → 同负载再跑一次；记录吞吐、p50/p99、CPU usr/sys、错误数；
允许交替时：TCP → UDS → TCP（可多轮），用中位数与波动带判断，收益低于波动带不采纳；
结论标注 measured / single_run / upper_bound，并记录环境与命令。
```

不承诺固定百分比。不同负载、不同连接模式、不同内核版本上的幅度差异很大。

## 第四问：代价是什么

| 代价 | 具体表现 | 处理 |
|---|---|---|
| socket 生命周期 | 崩溃/被杀后残留文件，下次 bind 报 `EADDRINUSE` | 启动前安全清理；框架停止路径确认会 unlink；停止后确认无监听再删 |
| 容器与挂载 | 跨容器需要共享卷；只读文件系统不可写 socket 路径；跨 pod 无共享卷不可行 | 部署前确认挂载；路径放在可写共享目录 |
| 监控与探活 | TCP 端口消失，端口探活、服务发现、防火墙、LB 规则失效 | 改用带超时 connect/最小协议请求/进程指标；同步调整依赖端口的配置 |
| 安全边界 | 无网络边界，访问控制退化为文件系统权限；同机其他用户可能可连 | 目录权限收紧；必要时 `SO_PEERCRED` 校验；多租户分目录 |
| 排障方式 | tcpdump 抓不到；工具链换成 `ss -xl`、`strace`、应用日志 | 提前准备排障命令；保留连接计数与错误指标 |
| 发布与回滚 | 两端需同时切换；混合版本可能不兼容；回退要同时改回 | 先做可配置切换；灰度单实例；保留 TCP 配置与回滚步骤 |
| 多实例 | 一个路径只能一个 listener；同机多副本路径冲突 | 路径包含实例标识；或由外层代理分发 |
| 性能边界 | 大消息/带宽主导时可能更差；仍受 socket buffer、backlog、拷贝限制 | 用实测判断；不要在大消息链路默认切换 |
| 复杂度 | 多一套路径/权限/清理要维护 | 只在收益与代价都明确时采纳 |

## 安全与授权

- **授权跟随动作**：只读评估不需要变更授权；改配置、重启进程、删除 socket 文件前，确认目标、范围和有效窗口，未授权就停在只读档。
- **路径先校验再操作**：只处理本次链路的绝对路径；确认目录与文件属主、类型；拒绝系统目录、越界路径、指向外部的符号链接和非 socket 文件；删除前确认没有 live listener。
- **凭据与数据**：不打印令牌、环境变量或完整配置；日志、抓包和报告只保留必要字段，外发前脱敏。
- **资源与恢复**：测量、重试和并发设上限；改配置前记录原值和恢复动作，失败或结束后恢复并做健康检查，确认实际生效值。
- **安全验收**：用临时路径和合成数据覆盖 live listener 不误删、非 socket 文件拒绝、权限不足报错、回退后健康；核对返回状态与实际副作用，不能只看命令退出码。

## 分级验证

按用户授权程度选择一档，默认只读。三档都自包含，不依赖其他流程。

### 档 1：只读评估（默认）

不改环境、不改代码、不压测。交付：门禁逐项结果、链路定位、收益上界与依据、改动清单、代价清单、回退方案、未验证项。结论可以是「不适用」或「维持 TCP」。

### 档 2：一次性验证

在测试环境或单实例上改配置/代码，做一次功能回归和一次前后对比。功能回归至少覆盖：请求成功、错误路径、重启后恢复、socket 文件清理、并发连接。性能对比记录单次结果并标注 `single_run`，不把它当作稳定收益。

### 档 3：受控 A/B

允许交替测量时执行：固定负载、机器、连接数、绑核与数据；按 TCP→UDS→TCP 交替，每档至少两轮；用中位数、极差或样本波动判断收益是否超出噪声；低于噪声带就回退并记录负结果。若客户不允许反复测量，停在档 1 或档 2。

### 基线与指标

基线固定为同机、同负载、同连接数的 TCP 运行；指标至少包含吞吐、p50/p95/p99 和错误数，主指标在看结果前确定。链路级与端到端分别设基线，不混用。

### 通过条件与不可比条件

通过条件：正确性零错误、收益超出噪声带、代价可接受；三者缺一不采纳，标 `inconclusive` 并保留原始数字。

以下情况不可比，不能计算收益比：负载、连接数或消息大小不同；机器、内核或绑核/NUMA 不同；进程或容器拓扑不同；测量窗口内存在其它负载；一次用单次对比、另一次用交替测量。只保留各自原始数字和原因。

## 受阻与交回

以下情况不要猜测或硬做，交回已完成的部分：

| 受阻情形 | 交回 |
|---|---|
| 读不到部署拓扑或路径可见性 | `blocked` + 缺项；已完成的门禁项与 `unknown` 项 |
| 没有改配置、重启或删除文件的授权 | 只读结论 + 改动清单 + 收益上界 + 回退方案；不执行变更 |
| 没有测量窗口或不允许压测 | 只读档结论；收益标 `upper_bound` 或 `unknown` |
| 只有一端可控 | `needs_prerequisite` + 另一端需要的改动或证据 |
| 运行时出现未知错误 | 保留原始错误、命令、时间与路径；不反复重试扩大影响 |

交回时至少包含：缺什么、已确认什么、下一步需要谁提供什么。受阻时 `verdict` 取 `blocked`，`blocked_reason` 写明缺项；不要用「应该可以」代替未验证项。

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 加一个并行 UDS listener/server | 清理、就绪、监控、回退双份复杂度，收益不变 | 单 listener + 配置驱动 |
| 只改服务端或只改客户端 | 连不上，或误判为「UDS 没收益」 | 两端按各自语法解析地址，并从客户端验证 connect 到预期服务 |
| 启动前不清理残留、或运行中误删 | `EADDRINUSE` 或破坏在途连接 | 先确认无 live listener 再删；框架清理路径确认 |
| 健康检查仍探 TCP 端口 | 服务已就绪但被判不健康 | 改用带超时 connect/最小协议请求；文件存在不算就绪 |
| 以为「同机」就够了 | 框架不支持、路径超长、权限不对、容器挂载缺失 | 先过门禁表，逐项取证 |
| 大消息/低 QPS 也切 UDS | 收益落在噪声里，甚至变差 | 先确认收益空间；不成立就维持 TCP |
| 用 tcpdump 排障 UDS | 抓不到包，误判为「没流量」 | `ss -xl`、`strace`、应用日志 |
| 把 UDS 当零开销 | 忽略 socket/epoll/拷贝仍在，收益预期过高 | 以内核路径占比为上界 |
