# 顾问模式工作流（硬件+场景 → 分层配置建议）

输入：硬件 + 场景 + 目标指标。产出：分层配置建议表 + 调优顺序 + 验证计划。

## 第 0 步 · 输入补齐

必须拿到（缺则问，不猜）：
1. CPU 型号与架构（x86 / aarch64-Kunpeng）、socket 数、核数、SMT 是否开。
2. 内存：每通道 DIMM 数、频率、大页现状。
3. 网卡：型号、PCI 拓扑（哪些口在哪个 socket）、驱动与固件版本。
4. 场景：业务模型（L2/L3/隧道/查表密度）、包长分布、流数规模。
5. 目标：吞吐（Mpps/Gbps）还是时延（均值/尾部）还是功耗——冲突项让用户拍板。
6. 约束：能否重启（GRUB/BIOS 才能改的东西要明示）、能否改代码、多进程共存等。

## 第 1 步 · 分层建议表（输出模板）

每项：**推荐值 | 理由 | 出处（官方 URL 或目标仓本地 doc 路径）| 验证方法**。

| 层 | 内容 | 参考模块 |
|----|------|----------|
| BIOS | 性能策略/Turbo/C-states/IOMMU | M1 |
| 内核 GRUB | 大页/isolcpus/nohz_full/irqaffinity/iommu | M2 |
| 运行时 OS | governor、irqbalance、挂载、ulimit | M2 |
| EAL | -l/--lcores 映射、--numa-mem、-a、iova-mode、simd 位宽 | M3 |
| 内存 | 每 socket 池、cache、mbuf 尺寸 | M4 |
| PMD | rxq/worker 映射、rxd/txd、burst、offload 裁剪、vector | M5 |
| 应用 | worker 模型、批处理、热路径纪律检查 | M6 |
| 功耗/低时延 | 按目标二选一：省电 scheme 或全关 idle | M7 |

## 第 2 步 · 调优顺序（性价比降序）[经验]

1. NUMA 三点一线对齐（改配置即得，收益常最大）
2. 核隔离三件套 + 中断压到 housekeeping
3. 大页（1G 优先）预留给足
4. governor=performance / 关 idle（吞吐或低时延目标时）
5. 队列-核映射与 RSS 分流合理性
6. rxd/txd/burst/mbcache 按 imissed/burst stats 实测调
7. offload 裁剪 + vector 路径确认
8. 代码层（M6 纪律检查）——成本最高，放最后；确认需要改代码时移交
   code-optimizer 的 `dpdk-optimization` skill

理由：1-6 纯配置可回退，7-8 需要更多验证；按此序避免过早优化。

## 第 3 步 · 验证计划（强制）

1. 实施前：M8 基线（配置快照 + 命令 + 数字落档）。
2. 每层实施后：同流量模型复测，增量记录。
3. 最终：完整配置归档（能一键重放：脚本/yaml + 参数表）。

## 输出格式

```text
## 场景假设
<确认输入，列出用户未拍板的假设>
## 分层配置建议
<表格：项 | 推荐值 | 理由 | 出处 | 验证命令>
## 实施顺序
<编号步骤，标注哪些需要重启>
## 预期与验证
<各项预期指标方向 + 回归命令；禁止给未经实测的绝对 PPS 承诺>
## 风险与回退
<每项改动的回退方法>
```

## 红线

- 不承诺未实测的绝对性能数字（写"方向性预期 + 测量方法"）。
- 需要重启/BIOS 变更的项目显式标出，等用户确认再纳入实施计划。
- 建议 deployed 前先在测试环境跑完整验证计划。
