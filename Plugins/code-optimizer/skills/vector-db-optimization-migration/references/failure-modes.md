# 失败模式与假阳性清单

迁移结论出错通常不是“算法不成立”，而是配置、构建、ABI 或统计口径错误。本清单按排查顺序组织：先证伪配置与构建，再怀疑数值与算法。

## 1. 身份与配置类

| 失败模式 | 表现 | 证伪方法 |
| --- | --- | --- |
| A/B 两臂指向同一个索引或配置文件 | 差异恒为 0，或某臂“意外稳定” | 打印实际加载的 config/index 路径与 mtime |
| 实际加载了错误版本的目标引擎动态库 | 宏已编译但行为不变 | `ldd`、运行时打印库路径/SONAME、校验 sha256 |
| 工作树 dirty 或两臂 commit 不同 | 差异无法归因 | 记录 `git rev-parse HEAD` + `git status --porcelain` |
| 基线索引/数据集与契约不一致 | recall 异常或不可比 | 校验索引/数据集 SHA 与 `SOURCE-TARGET-IDENTITY` |
| 绑核/NUMA/线程数跨轮次漂移 | QPS 波动大、CPU 迁移 | 每轮记录 `taskset`/`numactl`/`nproc`/load |
| 跨窗口、跨机器比较 | 绝对值差异大但不可复现 | 同窗 ABBA；拒绝跨场次绝对值对比 |

## 2. 构建与宏类

| 失败模式 | 表现 | 证伪方法 |
| --- | --- | --- |
| CMake option 默认 OFF | “已移植但没效果” | `compile_commands.json` 查 `-DNAME`；运行时打印开关 |
| 宏只对部分 TU 生效 | 结果随调用路径变化、ABI 错位 | 检查所有相关 TU 的 `-D` 一致；见 `scripts/check_compile_flags.py` |
| public define / `-march` 未全项目传播 | 类布局或内联不一致 | 检查 CMake `target_compile_definitions`/`INTERFACE` |
| 宏改成无条件生效 | feature-off 与上游不等价 | 关闭全部迁移宏后做位级对比 |
| 死宏：源码无作用点 | 改了开关行为不变 | grep 宏名 + 检查包围块调用者 |
| 目标架构 guard 导致静默降级 | ARM64 上走到标量 fallback | 反汇编/采样确认实际内核；检查 `#ifdef __aarch64__` |
| LTO 下 `.o` 为位码 | 静态反汇编找不到调用点，误判未生效 | 用运行时探针、链接后库反汇编或 sampled symbol |
| 旧 `.o`/缓存未清理 | 改了代码但结果不变 | 干净重建；记录构建目录与时间戳 |

## 3. ABI / API 类

| 失败模式 | 表现 | 证伪方法 |
| --- | --- | --- |
| 公共类新增成员但部分 TU 不可见 | `SIGSEGV`、字段错位、随机崩溃 | 统一公共头与宏；`compile_commands` 全量核对 |
| 新增虚函数导致 vtable 不一致 | 调用到错误实现、崩溃 | 检查所有链接进目标库的 TU 使用同一头文件/宏 |
| 序列化字段与版本不匹配 | load 旧索引失败或结果异常 | 覆盖 save→load、旧索引 load；检查读写版本常量 |
| 拷贝/移动/析构语义变化 | double free、use-after-free | ASAN/valgrind；覆盖拷贝、移动、`reconstruct()` |
| 模板实例化缺少显式实例 | 未定义符号或走错特化 | 检查显式实例化列表与新类型的链接结果 |
| 下游头文件依赖未更新 | 大面积编译错误或链接失败 | 全量干净重建，不只 build 目标文件 |

## 4. 数值与算法类

| 失败模式 | 表现 | 证伪方法 |
| --- | --- | --- |
| 归约顺序改变（分块后逐块归约） | ULP 漂移、top-k 边界交换 | G2 位级探针；必要时改回单累加器 + 单次归约 |
| tie-break / 顺序改变 | top-k 标签集合相同但顺序不同 | G3 dump 同时比较标签与顺序 |
| 量化/重排/存储布局改变 | recall 漂移、距离不等价 | 默认 `OPT_IN`；位级证明或 recall 门禁 |
| 分块边界/尾部处理错误 | 小 batch、非对齐维度出错 | 覆盖尾部长度、维度门控两侧、batch 16/8/4/2/1 |
| 预取越界 | 偶发崩溃或数据竞争 | ASAN；检查预取地址范围与掩码 |
| OpenMP/BLAS 并行语义变化 | 结果不稳定、性能波动 | 固定线程数/BLAS 版本；单线程对照 |

## 5. 门禁与统计类

| 失败模式 | 表现 | 证伪方法 |
| --- | --- | --- |
| benchmark recall 不变但 UT/ST 失败 | 功能已坏但指标掩盖 | UT/ST 与 recall 分别给 verdict |
| top-k 差异被 recall 平均掩盖 | 个别查询错误 | 逐查询 dump 比较，报告 mismatch 分布 |
| 只跑单轮或未 warmup | 结论受冷缓存影响 | warmup + 多轮；A/A 噪声地板 |
| 用跨版本绝对 QPS 比较 | 结论不可比 | 只与目标版本未迁移基线同窗比较 |
| per-dataset floor 被 geomean 掩盖 | 某数据集明显回归 | 同时报告每数据集值与最低值 |
| 噪声地板未测 | 把小波动当收益 | A/A 交错测噪声；低于地板判为中性 |
| 只保留汇总日志 | 无法复核异常窗口 | 保留原始日志、所有有效轮次与剔除规则 |

## 6. 路径与范围类

| 失败模式 | 表现 | 证伪方法 |
| --- | --- | --- |
| 只验证 `load` 路径 | `save` 构建路径崩溃或结果不同 | 显式声明范围；需要时分别验证 load/save |
| 只验证 search，未验证 build | 索引构建时间/布局回归 | 覆盖 build/`add` 路径 |
| nprobe/efSearch 门控未覆盖 | 某些参数下机制不生效 | 覆盖门控两侧与边界值 |
| L2/IP 只测一种 metric | 另一 metric 回归 | 两种 metric 都跑 G2/G4 |
| 维度范围覆盖不足 | 高维数据集回归 | 覆盖 128/256/768/960/1536/3072 等 |
| 大数据集未覆盖 | 小数据上成立，大数据失效 | 使用冻结数据集矩阵，不只单数据集 |

## 7. 症状 → 首选排查

| 症状 | 首选排查 |
| --- | --- |
| 改了宏但 QPS 完全不变 | 宏是否默认 OFF、是否被编译、是否走到热路径 |
| 结果随机崩溃 | ABI/公共头/宏不一致；先用 ASAN 干净重建 |
| top-k 标签相同但距离有微小差 | 归约顺序/ULP 漂移；G2 位级探针 |
| recall 下降但 UT 通过 | 量化/重排/顺序契约；检查 opt-in 条件 |
| load 旧索引失败 | 序列化版本/字段布局；检查 `index_read` 分支 |
| 某数据集回归、其余持平 | per-dataset 结构差异；检查维度/码字/布局门控 |
| 性能提升但无法归因 | 配置漂移/构建 flags/布局效应；做单变量与 A/A |
| 反汇编看不到新内核 | LTO 位码或未被链接；用运行时/sampled symbol 证明 |

## 使用顺序

1. 先用本清单排除配置、构建与 ABI 问题。
2. 再进入 `equivalence-and-gates.md` 的 G0–G3。
3. 最后才讨论性能和收益；不要在配置未证伪前下算法结论。
