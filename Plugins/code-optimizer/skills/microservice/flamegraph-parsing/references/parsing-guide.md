# 火焰图 SVG 解析参考（帧树几何 / self 口径 / 去嵌套）

perf + flamegraph.pl 产物的 SVG 结构：每个帧一个 `<rect>` + `<title>`，title
格式 `name (N samples, P%)`。解析目标是重建帧树并计算 self 口径。本文档
同时是 `scripts/parse_flamegraph_svg.py` 的设计说明。

## 1. 布局方向判定（解析的第一步，判反全错）

SVG 的 y=0 在画面**顶部**；"root 在底部"= root 帧的 y 值全图最大，"root 在顶部"= y 值最小。

| 布局 | root 位置 | 父子 y 关系 | 来源 |
|------|----------|-------------|------|
| 火焰图（默认） | 底部（y 最大） | 父帧 y 更大 | flamegraph.pl 默认输出 |
| 冰柱图 | 顶部（y 最小） | 父帧 y 更小 | flamegraph.pl `--inverted`（坐标真实翻转，非视觉倒挂；标题变 "Icicle Graph"） |
| 倒置冰柱（其他工具） | 底部（y 最大） | 父帧 y 更大 | 部分商业/合并工具产物 |

**flamegraph.pl 的 `--inverted` 会真实翻转 SVG y 坐标**（源码内 if/else 分支计算
imaging 坐标），不是纯视觉变换——默认输出 root 在底部、叶子在顶部；`--inverted`
输出 root 在顶部、叶子在底部。判方向永远以 root 帧的 y 值实测为准，不要按
"工具默认是什么方向"的印象假设。

判定方法：取样本数最大的帧（root 的样本数等于总量）看其 y 值在全图的位置。
**不要**靠文件第一个 `<g>`、视觉印象或工具名判断。

## 2. 父子关系判定（几何覆盖算法）

同层帧不重叠。给定帧 F（rect x, y, w, h）：

1. 按布局方向确定父帧所在 y 层（标准布局父层 y < F.y；倒置冰刺父层 y > F.y）
2. 候选父帧 = 该层中 x 区间覆盖 F.x（或与 F.x 区间相交最大）的帧
3. 用二分加速：层内帧按 x 排序后二分找覆盖者

**热度排序输出的 SVG 非树序**：帧在文件里的顺序是热度排序（帧序），不是树序。
任何"顺序遍历 + 栈"的解析算法在这类图上直接失效。通用做法：先收集全部帧 →
按 y 分层 → 每层按 x 排序 → 几何覆盖建树。不要假设文件顺序（实测踩坑：
按栈算法解析热度排序 SVG，子帧挂错父帧，类别分解全错但 Σself 仍可能对——
自检抓不住这类错误，必须用覆盖算法）。

## 3. self 口径与自检

```
self(F) = samples(F) − Σ samples(直接子帧)
```

- **自检**：全树 Σ self 必须等于 root 样本数（100.000%）。不等 = 树构建
  错误（覆盖算法 bug / 方向判反 / 帧遗漏），**禁止引用任何数字**。
- self 回答"哪里热"，不回答"该处是否已最优"：隐形收益类型（指令选择/
  CPI/调用开销/编译选项）在采样图上完全不可见。真实案例：某 fork 自带的
  三项既有优化（SVE 编译选项、分配器对齐、编码快路径）在优化前的火焰图上
  均不可见——"self% 低"不能单独作为关闭方向的依据。

## 4. 同名帧去嵌套（de-nest）

递归调用、模板实例化、内联展开会让**同名帧在树上多处出现**，且可能嵌套
（递归）也可能分散（不同调用路径）。

**naive 求和的错误**：把同名帧样本直接相加会把"被调用次数"和"递归深度"
都算进占比。实测案例：某解析主循环在树上共 9 个实例（其中 5 个是递归
自嵌套），naive 求和 10.85%；正确的去嵌套口径（同栈内递归帧只计一次，
跨调用路径分别计）为 ≈3.0%——**3.6 倍虚高**。

**去嵌户口径定义**：对每个完整调用栈（root→leaf 路径），同名帧只计一次；
帧的 de-nested 份额 = **包含该名字的调用栈**的样本量之和（每栈只计一次，
与该名字在栈内出现几次、出现在什么深度无关）。实现上等价于：对每条
folded 栈先保序去重，再聚合。

**用途**：库占比、路径天花板（"这个路径的优化对 E2E 的理论贡献上限"）、
与调用方占比的对比，全部必须用去嵌户口径。**未去嵌套的占比只能用于
"热度排序"参考。**

## 5. folded 栈文本解析（perf script 之后的链路）

`stackcollapse-perf.pl` 产物每行 `frame1;frame2;...;frameN (count)`：

- 按**尾部计数**分割：正则 `' (\d+)$'`。帧名含空格、模板参数（逗号+空格）、
  lambda，按第一个空格 split 会把 `MapMergeFrom<..., AttrValue>` 切碎，
  分类全错
- self = 栈内最后（最深层）帧——folded 栈天然按深度排列，与 SVG 几何解析
  相互独立、可交叉验证
- folded 解析与 SVG 解析是同一事实的两个视图：两者算出的总样本数必须一致

## 6. 库帧定位

- 命名空间匹配：帧名形如 `void ns::lib::func(args)`，库名出现在返回类型或
  限定符中 → 用包含匹配（`lib::` in name），不锚定行首
- **误命中防护**：参数列表里出现库名（生成代码签名含库类型，如
  `CreateMaybeMessage<Foo>` 会命中任何含 `Foo` 的过滤）→ 匹配前先按第一个
  `(` 截断
- 类别分解：按函数名语义前缀/关键词分类（ctor/dtor/copy/serialize/
  lookup/alloc……），类别和 ≈ 库总 self；与"库占总进程比例"分开报数

## 7. 与微基的对接

生产图的类别构成 + 关键函数集合 = 画像对齐微基的验收基准（协议见
`protobuf-optimization` 步骤 2）。本 skill 的解析脚本输出这两项，作为微基
设计输入。
