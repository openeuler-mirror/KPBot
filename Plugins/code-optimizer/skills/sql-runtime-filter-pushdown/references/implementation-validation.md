# 下推实现与取证

## 一张映射表贯穿两条路径

每次记录查询/计划节点、探测输出 channel、投影输入 channel、CAST 源/目标类型、扫描原列句柄、连接器类型和过滤表示。先做纯映射判断，再让能力查询与真正安装使用同一结果；投影重排后不能照搬旧 channel。

对源域 D、保值转换 f 和目标谓词 P，源过滤 Q 至少满足：P(f(x)) 成立则 Q(x) 成立。不能直接截断目标常量再安装。整数扩宽的值集和区间与源域求交；开闭端点和空集用现有过滤 API 表达，避免计算 max+1/min-1 导致溢出。

Bloom 等近似过滤若对目标表示哈希，不能直接对源列不同宽度字节使用原位图；需证明哈希编码一致、按原转换哈希或回退。NULL 的通过规则独立保留。

该无假阴性条件只证明匹配行不会丢失，不能证明反连接的未匹配输出也安全。普通 `NOT EXISTS` 反连接保持探测侧未匹配行，正向成员过滤不得在扫描端丢弃它们；若将“确定不匹配”用作跳过查表的提示，仍将该行交给反连接输出。`NOT IN` 等空值感知变体另行处理。

下推还会改变整个投影的求值范围。核对所有按引擎契约必须在连接前执行的表达式及其错误、状态和副作用；不只分析连接键的 CAST。若非键文本转换在不匹配行上会报错，而过滤会提前删除该行，必须在能力查询与安装两处均拒绝下推。用同一输入比较原版和候选的异常类型及消息，不能只对比成功结果行。

## 运行时生命周期

构建表完整且过滤覆盖当前探测范围后才使用。晚到时保留此前交付行的正常连接处理，并核对活动扫描与新 split 是否接收过滤。查询重试、分区切换及连接器拒绝安装时，不复用无效状态；安装失败仍走正确的正常连接。

用两个构建批次核对此条件。首批只含键 101，末批才出现两条键 102。末批完成前交付一条键 102 的事实行，核对过滤应用次数为零。构建完成后，该行只进入连接一次，产生两条匹配。让后续探测批次也包含键 99 和 102，分两种过滤表示验收。

- 对精确值集，确认构建键中没有 99，再核对扫描端已应用值集并排除 99。
- 对编码兼容的 Bloom，记录它在后续批次上的实际应用次数。假阳性允许 99 通过扫描，由原内连接淘汰。随包用例在构建侧加入与 99 哈希槽相同的键 165，并在探测侧加入槽位未占用的键 98。核对 99 通过、98 被排除，便能区分碰撞放行和绕过过滤。

两种表示均与关闭过滤时的完整结果按行值及重数比较。前后两个探测批次中的键 102 各产生两条匹配。

## 必须看到什么

在生成、安装成功和实际应用三个位置分别计数，安装请求数不能当作应用数。记录节点及原列身份、过滤种类、接收 split/批次数、拒绝原因、扫描输入/输出行、探测行和完整结果重数。若要声称减少 I/O，另测读取字节及数据块，不能由行数推算。

审计验证投影重排、源域极值、空交集、NULL、重复匹配、保留侧、未知转换和过滤晚到。性能采集按相同配置执行，调试日志与额外计数关闭；没有目标连接器证据时标记 `awaiting_target_evidence`。
