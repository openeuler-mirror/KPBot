# TF 推理优化 - 结果验证与收益归因

优化完成后，用三个维度交叉印证收益，避免「单一口径误导」。

> **测试方法已在环境验证阶段确认**（见 `./AGENTS.md` 的测试样本集 / golden output / 压测配置 / 正确性口径）。本 skill 直接使用已确认的方法执行验证，禁止各自猜测测试样本、QPS 档位或资源约束。

## 1. 三个验证维度（缺一不可）

| 维度 | 回答什么 | 方法 |
|---|---|---|
| 正确性 | 结果对不对（正确性用例是否全部通过） | 业务硬约束，口径由用户在环境验证阶段定义，任何浮点重排不可接受 |
| op 级 | 融合生效没、哪个 op 省了多少 | trace 聚合（`tf-profile-collector`） |
| 端到端 | 真实延迟/CPU/容量提升 | benchmark（`tf-benchmark`） |

## 2. 正确性验证（正确性用例测试）

- 业务硬约束：**正确性测试用例必须全部通过**（口径/判据由用户在环境验证阶段定义，见 `./AGENTS.md`）。fused kernel 的数学顺序不能变，否则浮点重排导致正确性用例比对失败。
- 复用与独立 op 相同的 functor（bit 级等价）是最稳的做法；grouped GEMM 会改变并行归约切分、可能改变累加顺序，不能声明式假设「不改累加顺序」，需在正确性用例上实测。
- 对照基准：同一输入集，opt 与 baseline 的输出按用户定义的判据逐条比对（如 Top-K 一致率、逐元素误差、分数分布等，以用户口径为准）。

## 3. op 级收益归因

从 trace 算单个优化点的净收益：

```
op 级净节省 = 原 op 减少耗时 − fused op 新增耗时
```

例如 QKV 融合：
- opt 的 `MatMul` + `BatchMatMulV2` = 3543 μs/req
- opt+QKV 的 `MatMul` + `BatchMatMulV2` = 1437 μs + QKV-fused 489 μs = 1926 μs/req
- **净节省 1617 μs/req**

同时看 fused op 次数是否 = 请求数 × 融合位置数（如 QKV：22 次 = 11 请求 × 2 VCG，11 次 = 11 × 1 listwise）。

## 4. 端到端收益归因

限 QPS 压测下，收益体现在**延迟降低 + CPU 降低**：

| 对比 | 看什么 |
|---|---|
| 同样 QPS | P99 延迟差、CPU 差 |
| 容量上限 | 饱和点 QPS 差（CPU 逼近 80% + 延迟跳高 + 落后目标） |

关键解读：
- **限 QPS 场景下「CPU 降、延迟持平」是正常现象**——延迟主要受排队/调度影响，优化省的是 CPU 计算量，体现为「同样 QPS 用更少 CPU → 可支撑更高 QPS 上限」。
- **不同 binary 的端到端差异不能 100% 归因单一优化点**：其他优化可能也有版本差异。严格隔离用同一 binary + flag 开关。
- **单点异常先复测**，确认噪声再下结论。

## 5. 收益判定（含负收益根因分析）

### 5.1 判定规则

| 本轮阶段收益（相对上一轮有效配置） | 判定 |
|---|---|
| > 1% | `accepted`，保留变更 |
| 0% ~ 1% | `inconclusive`，保留但记录噪声 |
| ≤ 0% | **进入负收益根因分析（见 5.2），不立即回退** |

### 5.2 负收益根因分析（替代简单回退）

负收益（≤0%）→ 不立即回退，先分析：

```
① 复测确认（排除单次噪声）
② 仍负 → 根因定位：
   - 测试噪声？      → 标记 noise，保留并记录
   - 真实开销提升？  → 定位开销来源（如 grouped GEMM 破坏 inter-op 并发、kernel 锁竞争）
③ 分析开销能否消除（改调度策略 / 部分保留独立 op / 调 shard）
④ 给出完整证据链（复测数据 + 开销定位 + 消除分析）
⑤ 决策：可消除 → 追加修复轮次（计入同一优化点轮次）；不可消除 → rejected（有据可查）
```

目的：**避免简单回退导致错误丢失重要优化点**（如 QKV 在 A+E 基础上延迟持平但 CPU 明确下降，本质仍是有效优化，不应按「延迟负」简单回退）。

## 6. 多优化叠加的归因要点

1. **先各自单独验证**（每个优化点 op 级 + 端到端）。
2. **再合并验证**（确认互不破坏：fused op 次数不变、各优化点的 op 都生效）。
3. **重叠要说明**：如 A（MatMul 融合）和 QKV（也吃 MatMul）有重叠，A 的可融合 MatMul 减少，导致叠加收益 < 简单相加，这是正常现象，显式标 `confounded`。

## 7. 输出结论的格式

统一结论表格（供报告）：

```
| 维度 | 结果 |
|---|---|
| 图匹配 | 融合 N 处（...），无误融合 |
| op 级 | X op -xx%、Y op -xx%，净省 ~N ms/req |
| 端到端 | P99 -x%~y%，CPU -x~ypp |
| 容量 | +x%（baseline ~M → ~N QPS） |
```

## 8. 踩过的坑速查

- **只看延迟不看 CPU**：限 QPS 场景 CPU 才是容量上限的决定因素。
- **跨时段对比噪声**：baseline 和 opt 不同时段跑，负载差异会干扰，严格 A/B 同一时段。
- **外推偏乐观**：CPU 随 QPS 增长非线性，低负载线性外推会高估容量，必须实测高 QPS 档。
