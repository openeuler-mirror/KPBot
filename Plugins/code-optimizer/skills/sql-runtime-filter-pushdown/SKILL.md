# 把运行时过滤送到扫描原列

把哈希连接已经掌握的匹配条件传给事实表扫描。在扫描处尽早淘汰不能匹配的行，保留原查询的连接结果、行重数和错误语义。

## 输入

| 输入 | 核对内容 |
| --- | --- |
| 业务查询 | SQL、参数、实际物理计划、完整结果的比较方式 |
| 两侧数据 | 构建侧和探测侧、连接类型、键类型、空值规则、额外连接谓词 |
| 过滤及列路径 | 生成入口、可下推判断、过滤表示、投影或转换、扫描列和连接器 |
| 运行证据 | 实际加载库、已有 profile、过滤生成及安装计数、扫描和探测工作量 |

先按任务范围确定做源码诊断、实现还是验证。只有计划或热栈时，区分能从代码确认的问题与尚需运行数据确认的收益。

## 执行步骤

### 1. 分开画条件流和记录流

从真实入口确认两个分支。小表先筛选并建哈希表，探测侧通过它匹配事实表行。沿记录流找到扫描、投影、类型转换和连接，再沿反方向追踪过滤能否回到扫描。

```text
记录流  事实表扫描 → 投影或 CAST → 连接探测 → 下游
条件流  构建侧可匹配键 → 探测端检查下推 → 追踪列 → 安装到扫描
```

标出能力检查、生成过滤和安装三个位置。有的实现先检查路径，遇到不可追踪投影就不会生成过滤。核对计数和分派点后再判断断在哪一步。

### 2. 确认哪些记录允许提前淘汰

| 场景 | 处理 |
| --- | --- |
| 普通等值内连接，构建侧完整 | 可用必要的匹配条件筛探测行 |
| 左外连接的左侧等保留侧 | 缺失匹配的行仍属于输出，保留该侧行 |
| 普通 `NOT EXISTS` 反连接的探测侧 | 未匹配行是输出，不能安装构建键的正向成员过滤来丢弃它们；已证明不匹配时可跳过查表，但仍须进入反连接输出路径 |
| 空值安全等值或空值感知反连接变体 | 单独核对 NULL 和匹配规则，不能直接套用普通反连接的判断 |
| 构建侧尚未完成，或当前数据仅覆盖部分分区 | 保留原路径，除非能证明过滤覆盖探测行可能匹配的全部键 |

对允许提前淘汰不匹配行的内连接等路径，过滤可以保守放行额外的行，每个能产生匹配的探测行必须通过。连接仍负责真正匹配、输出构建侧字段和处理额外连接条件。普通反连接中，构建侧仅有键 1、探测侧仅有键 2 时必须输出键 2；把正向成员过滤装到扫描端会丢失唯一结果，须回退。

### 3. 逐段追踪列号和类型

在每段记录输出通道、输入通道、扫描列和物理类型。原样列可以重映射通道。遇到表达式时，先判断源类型上是否能表达安全的谓词。

以 INTEGER 扩宽到 BIGINT 为例，三种过滤分别处理：

- **值集**取与 INTEGER 可表示域的交集。目标域中超出 INTEGER 范围的值，不可能出现在原列。
- **区间**和原类型可表示域求交。按引擎的区间表示保留开闭边界，避免转换边界值时溢出。空交集按原有过滤接口处理。
- **空值**沿用当前等值或空值安全规则。过滤若无法表达该语义，保留已有路径。

缩窄、字符串解析、浮点变换、依赖会话设置的转换要分别证明。若原转换可能报错，提前筛行不能掩盖按当前引擎契约应出现的错误。

检查范围包括下推所跨过的整个投影及必须求值的其他表达式。即使连接键仅做保值扩宽，同一投影的另一列 `CAST(text AS INTEGER)` 也可能按契约在连接前报错；不能先过滤掉不匹配行而跳过该错误。无法证明这些求值可安全跳过时，不穿过该投影下推，并对照两条执行路径的错误类型和内容。

### 4. 将同一个判断用于规划和安装

用同一套列映射和谓词重写规则回答「能不能推」和「在什么列上安装什么」。检查扫描连接器是否接受该类型、过滤形式和使用时机。

安装失败、遇到未知投影或类型、过滤尚未准备好时，继续使用已有查询路径。已输出的批次仍由下游正确处理。复用当前查询作用域和重试机制，确认新 split 获得应有的过滤。

### 5. 用行数据核对前后路径

例如日期维表筛完月份后只有 `101、102`，销售表原始日期列交来 `099、101、101、102`。

```text
优化前  扫描送出 4 行 → CAST 4 行 → 探测连接 → 保留 3 行
优化后  扫描淘汰 099 → CAST 3 行 → 探测连接 → 保留 3 行
```

两个 `101` 对应两笔销售，均须保留。这个例子可核对行级语义，实际扫描还要看过滤形成时间和文件布局。

### 6. 运行正确性与命中检查

| 检查项 | 观察结果 |
| --- | --- |
| 原列与重排投影 | 过滤安装的通道确实指向当前扫描列 |
| 范围边界、空值、无任何匹配 | 查询结果、重数和错误行为前后一致 |
| 重复探测键和重复构建键 | 保持普通连接的多重匹配 |
| 保留侧、不支持的转换及过滤晚到 | 对应路径回退，先交付的行也得到正确处理 |

在正常查询入口记录过滤生成、安装及应用到多少批次。分别收集扫描输入、扫描输出和探测行。计数用于诊断，性能组使用约定的同一配置。

### 7. 对照完整查询的收益

用相同 SQL、数据布局、资源与计时边界运行原版和候选。完整结果用行重数及值校验。把行数、数据块与磁盘读取量分别统计。输出行减少可以解释下游节省的工作，磁盘读取、峰值内存和总耗时按实际测量报告。

## 输出

- 两侧调用链和过滤路径，标出阻断点与改动模块。
- 允许下推的条件、源列映射、过滤重写办法及回退范围。
- 正确性、实际安装、扫描与探测行数的前后证据。
- 完整查询配对样本、计时边界和收益解释。只有累计候选成绩时，标明包含的其他改动。

取证表可使用以下字段。

```text
模式 | 探测原列 | 过滤是否安装 | 扫描输入行 | 扫描输出行 | 探测行 | 完整查询耗时
```

## 约束

- 对可淘汰不匹配行的连接，下推后的过滤不得漏掉任何原本能匹配的行；反连接及其他保留侧不得用正向成员过滤丢弃应输出的未匹配行。
- 保留连接类型、空值、重复匹配、类型转换错误和精确比较语义。
- 能力判断和安装使用相同的有效性条件，具体列号按当前计划解析。
- 构建侧可见范围不足时，过滤不得越出已证明安全的范围。
- 过滤由正常入口命中后才能归因。磁盘读取量、内存和整体时延分别取证。

## 实施与验收细节

修改转换追踪和扫描安装时，读取[下推契约](references/implementation-validation.md)，按同一映射核对能力判断、安装列、晚到过滤及计数。局部合成用例只验证模型；真实连接器的安装和查询收益需目标环境取证。

## 本地用例

晚到过滤用例把探测数据分成前后两个批次。构建未完成时，前一批的过滤应用次数应为零；构建完成后，后一批才使用过滤，整个查询应保留末批构建键对首批探测行形成的全部匹配。

在 `cases/filter-contract/` 中执行 `python3 run.py`。合成用例检查整数域边界、重复匹配、保留侧和反连接回退、投影重排后的原列映射、整个投影的错误保留，以及 Bloom 哈希表示不兼容时不安装过滤并保留正常连接；兼容表示也有实际应用的正向对照。结果写入该目录的 `results/result.json`，`case.yaml` 对映射、应用和回退计数分别断言。模型评估规格放在 `evals/evals.json`。Velox 的源码位置和历史记录见 [Q67 案例](references/velox-q67.md)。
