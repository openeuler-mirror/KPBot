# 布局与转置

## 数据布局

以 L = f32 lane 数（256-bit 向量为 8）、tile = 子量化器分块宽度：

- scratch 布局 `scratch[r][m][l]`：第 r 组第 l 个码在第 m 个子量化器上的码字节；组内连续 m 使 gather 顺序读。
- 主循环每个 m：从 scratch 读 L 个码字节（零扩展到 u32 lane 索引），一次 gather 取 `sim_table + m*ksub` 行的 L 个 f32，加到该组累加器。
- R 组并行：R 条独立累加链掩盖 gather 延迟；R ∈ {1,2,4,8,16} 之类的小集合，模板展开。

## 转置构造

- 输入是 code 连续布局（每码 code_size 字节），需要 (code, m) → (m, lane) 重排。
- 整 tile（L 码 × tile 维）用三级 zip 网络完成 8×32 字节转置：每级两两交错，共 3×(L/2) 次 zip；产出按 (m, l) 连续的行。
- 残段（码数非整组、M 非 tile 倍数）用标量双循环填充，不强行向量化。
- 转置是纯数据搬动：只做字节重排，不改值，等价性由布局定义保证。

## 写回

- 每组结束时把 R×L 个距离从累加器 lane 提取到浮点数组，逐码加 dis0 后按 j 升序交给结果处理器；顺序与逐码路径一致，保证 tie 与替换语义不变。lane 内求和的浮点归约顺序须与基线路径一致（AVX2 为水平归约）：要求逐位一致时不得改为顺序累加，声明容差时单独验证近并列输入。
- 扫描计数按实际计算数累加，与原路径同口径。

## 与逐码路径的成本对照

| 项 | 逐码 | 分组 |
| --- | --- | --- |
| 表访问 | 每码 M 次标量读 | 每 (组, m) 一次 gather |
| 归约 | 每码一次水平归约 | 每组一次（写回时） |
| 数据准备 | 无 | 转置进 scratch |

上界 = 归约与寻址节省 − 转置与 scratch 成本；列表长度决定摊销，见 [阈值与尾部](threshold-and-tail.md)。
