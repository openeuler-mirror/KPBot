# SQL51 末端 Top 100

## 说明与范围

本 Skill 只处理 Q51 末端的有序结果选择。输入已经完成两列累计 MAX 和 `web_cumulative > store_cumulative` 过滤。适用候选是减少末端全量排序、验证当前引擎的有界 Top N，或用同一比较器合并本地候选。

## 输入

| 输入 | 核对内容 |
| --- | --- |
| 查询与基线 | 实际 SQL/参数、源码版本、加载库和最终执行计划 |
| 位置 | 分支累计、全外连接、后置 MAX、比较过滤及 LIMIT 边界 |
| 比较器 | 全部排序键、类型/collation、方向、NULL 顺序及并列约定 |
| 限制语义 | LIMIT、OFFSET、WITH TIES 是否与模板相同 |
| 分布与指标 | 过滤后行数、分区数/倾斜、局部输出、合并输入字节和最终返回 |

实际算子入口见 [实施细节](references/implementation.md)。SQL 未显式写明的 NULL 默认值由目标引擎和配置确定，不能使用另一引擎或 Python 的默认顺序替代。

## 实施步骤

### 1. 固定有序选择的输入

```text
完整累计 MAX → web_cumulative > store_cumulative → 局部 Top K
                                              → 全局合并/Top K → 返回
```

模板 K=100，其他参数按当前 SQL 解析。LIMIT 移到窗口前会改变累计输入；移到比较前可能选中最终被淘汰的行，使返回不足 K 条。

### 2. 确认基线是否已经使用 TopN

在最终计划定位 Spark 的 TakeOrderedAndProject、Gluten 转译、原生 TopN 或回退。一个节点可能同时完成选择与投影，不能仅凭文件中的 Sort 字样判断全量排序。

已命中等价 TopN 时先查全局合并输入、行宽、倾斜及内存，不重复添加相同阶段。记录实际节点的输入/输出，不按逻辑表达式数量估算工作量。

### 3. 证明局部选择和全局合并使用同一比较器

保持全部排序字段的类型、collation、方向和 NULL 规则，不以金额或近似分数替代 `item_sk,d_date`。每次丢弃必须能推出该行不影响合法的全局前 K。

普通 LIMIT 可在每个分区保留至多 K 条再全局选 K。OFFSET=M 通常要求每分区保留 K+M，再全局取 `[M,M+K)`；不支持的变体回到原路径，不能照搬模板公式。

### 4. 保持边界 peers 和限制变体的语义

同排序键的行可有不同非排序列。原查询没规定唯一顺序时，不擅自添加隐藏 tie-breaker，也不把允许的 peers 替换误判为错误；需要确定同一批行时先核对原契约。

WITH TIES 可能返回超过 K 的行，普通局部 K 条会丢失必需 peers。使用已支持的等价实现或回退，不能只放大最终输出行数。

### 5. 保留输出列与过滤的三值逻辑

可以缩窄中间表示，但最终须返回原 SQL 的全部列，包括原始渠道累计列和后置窗口列。NULL 不是 0，任一累计比较操作数为 NULL 的行按原规则处理。

实际日期类型、字符串排序与本地小样本不同的情况，要经目标比较器验收；未证明类型或比较规则一致时保留原实现。

### 6. 覆盖边界并独立统计记录数

验证 0、少于/等于/多于 K，空与倾斜分区，NULL、方向、边界并列、OFFSET 和提前截断反例。先比较完整过滤输入，再比较最终有序返回。

分别计数过滤后行、每分区局部候选、实际合并行/字节与最终行。函数调用数、分区数不等于处理行数。从真实入口确认执行，回退原因单列。

### 7. 对照末端和完整查询

固定数据、资源、缓存和结果消费方式交错运行，记录局部选择、全局合并/排序、内存及全部结果取回的查询耗时。较少候选可能被比较成本或其他阶段抵消，保留退化。

正式计时关闭额外日志/采样，保留算法与比较守卫。局部改善和端到端比值分别命名，不共用一项成绩。

## 约束

- Top N 位于窗口和累计比较之后。提前截断会改变累计值，或选中最终比较时被淘汰的记录。
- 局部和全局使用相同的排序方向、NULL 顺序和并列规则。确定性测试使用与原查询一致的排序约定。
- 已经命中等价 TopN 时先区分全局合并与其他阶段开销。当前证据不足时交回定位计划。

## 交付与验收

交付物理计划、排序契约、完整 Top 100 对照，以及排序或合并边界指标和整条查询配对结果。从 Skill 根目录运行 `python cases/topn-contract/run.py` 验证局部合并、NULL 顺序和提前截断反例。

```text
模式 | 过滤后行 | 分区数 | 局部候选行 | 合并输入字节 | 最终行 | 峰值内存 | 末端毫秒 | 查询毫秒
```

用例还覆盖不同 K/分区形状、方向与 NULL 组合、OFFSET 需要 K+M、边界 peers 和实际候选计数；断言在 `cases/topn-contract/case.yaml`，结果写入对应 `results/result.json`。

模型评估规格在 `evals/evals.json`。本地用例不验证真实原生 TopN 命中、目标比较器或性能，目标未执行时标记 `awaiting_target_evidence`。
