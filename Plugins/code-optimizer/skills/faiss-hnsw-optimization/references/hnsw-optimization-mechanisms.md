# HNSW 优化机制与适用条件

| 机制 | 需要的证据 | 语义与成本检查 |
| --- | --- | --- |
| 批量距离 | 距离调用及可用 batch 接口 | 邻居顺序、visited、候选更新与 metric |
| visited 复用/池化 | 清理或分配成本与表足迹 | 实际表示、代际回绕、所有权和并发 |
| 候选容器 | push/pop/clear 与阈值查询的频率 | tie、容量、维护索引的写放大 |
| 邻接/向量预取 | 实际随机访问与延迟 | 地址合法性、带宽、时序和污染 |
| 存储精度或节点重排 | 任务明确允许且目标实现支持 | 图/向量对应、ID 映射、序列化与质量 |

存储量化和布局变更可能改变搜索语义或保存格式，不能默认作为等价查询优化。若使用分层/分形状策略，阈值应根据本次平台、数据足迹和成本对照确定；不要把固定数据集或机器阈值写成公共常量。
每个机制使用独立开关、通用回退与实际路径测试。具体候选按 [候选规划](hnsw-optimization-candidates.md) 和 [验证计划](hnsw-validation-plan.md) 推进。

补充检查见[候选评估检查项](hnsw-optimization-lessons.md)。
