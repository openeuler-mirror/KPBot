# Go 缓存行争用识别与优化点分析 Playbook

本文件定义 Go 微服务中缓存行争用的证据采集、差分诊断、字段归属、假设验证和优化点判定方法。文件只保留识别方法，不展开具体修复方案；修复由下游 skill 或 code-optimizer 负责。

## 1. 适用范围

满足以下多数条件时，才把缓存行争用纳入分析：

- 目标服务是 Go 编写的在线微服务，短请求、高并发、请求路径相对固定。
- 热路径包含高频序列化/反序列化、对象/缓冲区复用或调度状态切换。
- 现场能拿到硬件缓存行为证据：cache miss、跨核缓存行迁移、true sharing 采样。
- 需要判断“是否存在缓存行争用、在哪个结构/字段、是否值得优化”，而不是已经知道具体改法。

不进入本方向：

- 没有缓存行为证据，仅凭函数热点猜测伪共享。
- 瓶颈是缓存容量、内存带宽、锁竞争或不可避免的真共享，且已有更直接解释。
- 不能重编译，且业务结构布局也无法调整。
- 目标是修复数据竞争；这类问题应使用 race detector、同步原语或并发模型改造。
- 已经明确具体修复方案，只需要执行构建、A/B 或改代码。
- 只有 GC 后池被清空、堆内存颠簸，没有缓存行竞争证据；交给 `go-syncpool-optimization`。

## 2. 证据体系

| 证据类型 | 看什么 | 用途 | 局限 |
|---|---|---|---|
| 硬件缓存事件 | cache miss、跨核缓存行迁移、true/false sharing 的分布 | 判断争用是否存在、集中在哪些地址/函数 | 计数器噪声；不能单独区分伪共享和真共享 |
| CPU/内存 profile | 分配/调度/同步路径的占比和调用链 | 把缓存事件落到热点函数和结构 | 只给热点，不给字段归属 |
| 字段归属 | 字段、偏移、核归属、读写比例、共享范围 | 判断同一缓存行是否被不同核分别读写 | 需要结构信息或调试符号；序列化/反射可能隐藏布局 |
| 受控实验 | 单核 vs 多核、隔离共享写、访问扰动、合成微基准、对照结构 | 验证“共享/布局”是否是原因 | 实验条件变化可能引入新变量 |

采集要求：

- 同一负载、同一绑核、同一采集窗口；空载和漂移负载不作为判据。
- 至少两类独立证据一致，才把假设升级为优化点。
- 记录反例：容量、带宽、锁、NUMA 远端访问、频率、负载不均。
- 证据共享前只保留必要字段；样本对象地址、进程和机器标识可脱敏或归一化，日志/火焰图按需采集。

常用采集（按现场 perf 版本和权限调整）：

```bash
perf stat -p <pid> -e cycles,instructions,cache-references,cache-misses,context-switches -- sleep 5
perf c2c record -p <pid> -- sleep 5
perf c2c report --stdio
```

权限：`perf` 需要 `perf_event_paranoid` 允许或 root / `CAP_PERFMON`；无权限且拿不到缓存事件时输出 `blocked_evidence`。

Arm64：`perf c2c` 依赖 SPE（内核 `ARM_SPE_PMU` + 固件中断描述）；无 SPE 时 `perf c2c` 常见报错 `Cannot find PMU arm_spe`。此时：

- 若 `perf stat` 的 cache 事件仍可用：降级为粗粒度计数（或 DevKit `tuner miss -m 1` 行级粗归因），状态标记 `degraded`。
- 若缓存事件完全不可用：`blocked_evidence` + 最小补采命令。

`cache-references`/`cache-misses` 在 Arm64 映射到 `L1D_CACHE`/`L1D_CACHE_REFILL`，不等同 x86 LLC；不做跨架构数值对比。

## 3. 差分诊断

| 类型 | 判据 | 常见混淆项 | 下一步 |
|---|---|---|---|
| 伪共享 | 不同字段被不同核分别读写；逻辑无数据竞争；缓存行频繁失效 | 真共享、容量 miss、NUMA 远端访问 | 字段归属映射 + 访问扰动/隔离实验 |
| 真共享 | 同一字段被多核读写，逻辑上必须一致 | 锁竞争、原子操作热点 | 记录共享范围和写频率，移交分片/批量类方案评估 |
| 容量 miss | miss 随工作集或数据规模上升，缓存层级逐级溢出 | 伪共享、带宽饱和 | 计算工作集，移交分块/布局类方案评估 |
| 锁竞争 | 锁等待、临界区或原子热点 | 真共享、调度延迟 | 走锁/并发分析，不按缓存行争用处理 |
| NUMA/远端访问 | 远端访问比例高，跨节点延迟主导 | 伪共享、容量 miss | 走绑核/NUMA 分析 |
| 频率/负载不均 | 核频率差异、负载倾斜、线程迁移 | 缓存行争用 | 先修环境和负载分布 |

诊断顺序：

1. 先排除容量、带宽、锁、NUMA、频率和负载不均。
2. 再区分伪共享和真共享：不同字段跨核读写 vs 同一字段多核读写。
3. 无法区分时输出 `undetermined`，并给出下一步最小实验，不直接下结论。

## 4. 字段归属映射

1. 从热点函数回溯到被读写的结构。
2. 记录结构大小、字段顺序、字段偏移和缓存行分组；字段偏移只说明相对位置，必须结合现场缓存行大小和样本对象地址核验所属缓存行。
3. 记录每个字段的读/写、核归属、访问频次和共享范围。
4. 标注序列化、反射、`unsafe`、ABI 和 GC 扫描约束，判断布局是否可改。
5. 输出结构-字段-缓存行-核归属的映射表，作为后续假设验证的输入。

字段归属不完整时，不把该结构标记为 `false_sharing`，最多标记为 `undetermined`。只有结构定义、无法证明实例起点对齐时，也保留 `undetermined`。

## 5. 假设验证实验

实验目标是验证原因，不是验证最终修复。每个实验记录预期、实际、反例和置信度。

| 实验 | 做法 | 能支持什么 | 不能支持什么 |
|---|---|---|---|
| 单核 vs 多核 | 同逻辑在单核和多核下对比 | 共享/并行是否是必要条件 | 不能单独区分伪共享和真共享 |
| 隔离共享写 | 把共享写改成每核独立副本或独立实例 | 共享写是否是主要来源 | 副本本身可能改变容量和工作集 |
| 访问扰动 | 改变字段访问顺序或分组，观察事件变化 | 布局敏感性 | 不能证明线上结构同样敏感 |
| 合成微基准 | 复现结构并控制共享/非共享两种版本 | 机制层面的因果 | 不能直接外推到业务负载 |
| 对照结构 | 同负载对比共享模式不同的相似结构 | 共享模式的影响 | 结构差异可能引入其它变量 |

实验判定：

- 预期与实际一致，且反例无法解释：提高置信度。
- 结果不能复现或与其它证据冲突：降低置信度，保留 `inconclusive`。
- 实验改变了负载、容量或绑核：标记 `confounded`，不作为单独归因。
- 隔离共享写/独立副本会同时消除真共享；要归因伪共享，必须保持访问者不变，只改变两个字段是否同处一条缓存行，否则结论保留两种解释。

## 6. 置信度与判定

| 置信度 | 判据 |
|---|---|
| `high` | 至少两类独立证据一致，受控实验可复现，且没有更直接解释 |
| `medium` | 证据一致但只有一类来源，或实验只做了一次/条件不完全受控 |
| `low` | 只有 `runtime.MemStats`、单一事件或没有调用链，仍是假设 |

判定：

- `confirmed`：仅 `high`；证据能落到具体结构/字段，且反例已排除。
- `inconclusive`：`medium` / `low`，证据冲突、字段归属不完整或实验不可复现；需要补证后再升级。
- `degraded`：缓存事件可用但只有单一来源，或压测客户端/固定负载缺失；补最小验证实验，不进入 `confirmed`。
- `blocked_evidence`：拿不到缓存事件（无权限、Arm64 无 SPE 且无粗粒度计数、事件计数不可用）；只保留假设并给最小补采命令。
- `rejected`：容量、带宽、锁、NUMA、频率或负载不均能更直接解释。

## 7. 常见误判

- cache miss 高不等于伪共享；容量 miss、带宽和 NUMA 远端访问也会推高 miss。
- race detector 不是伪共享检测器；没有数据竞争不代表没有缓存行竞争。
- 单核基准无法暴露跨核缓存行失效。
- 没有字段归属就判断伪共享，等于用方案偏好代替证据。
- 只看事件总量、不看分布和热点，容易把环境噪声当成结论。
- 采集窗口、绑核、负载或频率变化后做前后对比，收益不可归因。
- 把真共享当成伪共享，会得到“隔离无效”的错误结论。

## 8. 优化点卡片

每个卡片至少记录：

```text
finding_id:
structure:
fields:
contention_type: false_sharing | true_sharing | capacity_miss | undetermined
evidence:
  - 硬件事件:
  - profile/热点:
  - 字段归属:
  - 受控实验:
confidence: high | medium | low
counterevidence:
impact_scope:
validation_plan:
remediation_direction:
recommended_next_skill:
not_a_finding_reason:
```

卡片只描述“哪里有问题、证据是什么、下一步该谁处理”，不写具体修复方案、字段偏移改法或补丁内容。

同一结构存在多个争用点时分别建卡片，不合并归因；无法落到字段的只输出 `undetermined` 和缺失证据。

## 9. 修复方向与移交索引

识别确认后只给方向级建议；具体实现、参数、字段偏移和补丁由下一跳 skill 设计。

| 识别结果 | 大致方向 | 下一跳 | 不展开 |
|---|---|---|---|
| 伪共享 | 缓存行隔离、字段重排、热冷分离、写路径 owner 化 | `code-optimizer` / `go-runtime-patch-build` | 字段偏移、隔离粒度、补丁 |
| 真共享 | 分片、批量合并、延迟合并、只读快照 | `code-optimizer` | 具体分片数、同步实现 |
| 容量 miss | 减少工作集、分块、调整遍历顺序、压缩 | `code-optimizer` | 具体块大小、重写代码 |
| 锁竞争 | 缩小临界区、分片、无锁/批量 | `code-optimizer` / 并发分析 | 锁实现代码 |
| NUMA/远端 | 绑核、NUMA 亲和、实例布局 | 对应系统 skill | 具体绑核命令 |
| 频率/负载不均 | 环境修复、负载均衡、频率策略 | 系统/运维 | 具体参数 |
| sync.Pool 参数或 GC 后池清空 | 池参数和内存风险 | `go-syncpool-optimization` | 具体参数值 |
| GC 参数、并行度或容器适配 | 运行时参数取舍 | `go-runtime-tuning` | 具体参数值 |
| 需要验证候选变更 | 单变量 A/B | `microservice-ab-testing` | A/B 步骤细节 |

方向级建议不包含字段偏移、隔离字节数、参数取值、补丁内容或代码；移交只写 skill 名和需要对方回答的问题，不复制对方的执行细节。

## 10. 拒绝与边界

- 没有缓存行为证据，或无法采集 profile/缓存事件。
- 无法做字段归属或对照实验，只能形成猜测。
- 无法区分伪共享、真共享和容量 miss。
- 不能重编译，且业务结构布局也无法调整。
- 结构布局受序列化、反射、`unsafe` 或 ABI 约束且无法评估。
- 目标是修复数据竞争，或已有更直接解释。
- 用户要求直接给具体实现、补丁或参数，而不是识别和方向级思路。

本方向只输出识别方法、证据、置信度、方向级修复思路和优化点卡片；不展开具体实现、参数或补丁，不定义 A/B 协议，不写机型和历史数据。
