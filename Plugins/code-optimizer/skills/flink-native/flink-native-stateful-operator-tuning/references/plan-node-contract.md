# 计划节点与跨语言契约

本文是 `flink-native-stateful-operator-tuning` 的扩展指南参考：**给该栈新增一个
有状态算子时，计划节点（StatefulPlanNode 派生族）要承载什么、契约边界在哪里**。
锚点用类名与机制描述（grep 可定位），不引行号与 commit hash。

## 计划节点是翻译链的必经载体

翻译链双平面：Java 侧影子翻译类把 Flink ExecNode 构造成计划节点树 → 序列化为
JSON **一次过 JNI** → C++ 侧 planner（StatefulPlanner 类）把 JSON 反序列化回计划
节点树 → 按节点类型分派构造成执行算子链。计划节点同时是三个链路的载体：

1. **计划面**：承载算子语义（分区键、排序规格、limit、字段选择），每个字段必须有
   算子侧消费者——无消费者的字段是设计事故；
2. **keyed 状态握手面**：KeyedStateSpec 结构声明分区键与状态形态，是 keyed 状态
   双向握手的"计划侧一半"（另一半在 JVM 壳算子的 state key selector 注册）；
3. **checkpoint 面**：snapshotState 沿计划展开的算子链快照，节点字段变更即快照
   schema 变更。

## serde 注册名是跨 JNI 契约

计划节点经 serde 注册表按类型名反序列化。**注册名一旦发布即是对外契约**：

- 新增算子 = 新节点类型 + 新注册名 + 新 serde 条目；
- **禁止占用既有注册名改字段语义**——等价于撕毁契约，旧计划 JSON 反序列化即错；
- 既有节点类即使"当前无生产者"也不要改名复用——死代码保持死路径，新功能走新名
  新类，回滚与审计才隔离（改旧类 = 级联激活死代码链，波及面不可控）。

## 新增有状态算子的承载清单

新增节点时逐项确认（缺一即返工）：

- [ ] 每个计划字段都有算子侧消费者，且方向单一（计划只声明、算子只消费）；
- [ ] 分区键与排序键各自独立声明（分区键给 keyed 握手，排序键给算子内核）；
- [ ] keyed 语义算子：KeyedStateSpec 声明 + Java 侧 key selector 注册回 Flink
      Transformation 双侧配对；
- [ ] 状态值形态在计划侧声明（这一步就该选定紧凑编码，见主 skill Core finding 1）；
- [ ] checkpoint 链路验证：heap 后端快照回 Java、RocksDB 共享活实例两条路径都过；
- [ ] serde 新注册名 + 单测覆盖 JSON 往返；
- [ ] 不修改任何既有节点类——差异化语义只扩展（新节点、新注册条目、新文件）。

## 影子翻译类的纪律

- 影子类与 Flink 同名 ExecNode 平行存在：**Flink 原生类的行为、签名、结构一律不动**；
- Flink 侧推导出的策略（如 rank 处理策略）可以忽略，但必须在翻译处显式记录
  "忽略了什么、为什么安全"——忽略不可静默；
- 翻译产物是三层节点：算子语义节点（如 TopN 类）→ 流式 keyed 壳节点（按 key 切批
  机制）→ StatefulPlanNode 根（JNI 与快照锚点）。

## 反例：三个"看起来可以复用"的候选为什么被否

新增 rank 类节点时，既有嵌套式节点（StreamRankNode/StreamTopNNode 类）曾有三条
复用路径，全部被设计否决——否决理由是本契约的实例教材：

1. **改嵌套结构**：旧节点用"嵌套子节点"表达流式壳，新语义需要扁平类型字段；
   "修改"名义下实为整类重写；
2. **改旧类字段**：serde 注册名是契约（见上），占旧名改字段等于撕毁契约；
3. **复用死代码激活**：旧节点无生产者、消费链残缺、零单测——级联激活的波及面
   不可评估。

结论模式：**新语义 → 新节点 + 新注册名；旧类冻结**。
