# GLM-5.2/5.3 场景备注

> 本文件只保留公开 Mode A 的行为级约束，不记录机型、固定拓扑或历史测试数据。实际部署以现场 `kv_caches.keys()`、group 数和版本为准。

## 已记录形态

- 模型变体：GLM-5.2 W8A8C8、GLM-5.3-W4A8
- 连接器：`MultiConnector[MooncakeLayerwiseConnector, AscendStoreConnector]`
- P2P：`MooncakeLayerwiseConnector`
- Store：`AscendStoreConnector(use_layerwise=false)`
- `kv_load_failure_policy`：默认 `fail`；只有确认非 hybrid 场景时才评估 `recompute`
- 结论：公开版优先 Mode A

## 关键观察点

1. 标准 DSA 可能同时存在 main attention 与独立 indexer/tail cache；如果同一物理 layer index 出现多个 `kv_caches` key，当前 connector 可能断言。
2. 公开 v0.30–v0.32/main 不把 Store layerwise range 或 `layerwise_host_kv_offload` 作为标准 Mode A 字段；不要按这些字段“已开启”继续验证。
3. `use_ascend_direct` 属于 Mooncake V2 路径的配置项，不要写进 `MooncakeLayerwiseConnector` 子项。
4. Store layerwise 是否可用，取决于目标版本的官方能力，不按模型名推断。

## 可行顺序

- 先跑 Mode A，确认 P2P 逐层传输、精度和失败处理。
- 需要 Store layerwise 或 host offload 时，先确认目标公开版本是否包含对应契约；不包含则另开专题，不要套用内部字段。
- 最后才评估高级 Store offload 路径；无法定位公开实现时停止。

## 不要做

- 不要因为“请求成功”就判定精度通过。
- 不要把内部 fork 字段当成公开标准配置。
- 不要在未确认 `kv_caches.keys()` 的情况下承诺标准 DSA 一定支持同 index 多 cache key。
