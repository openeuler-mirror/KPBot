# 基准门禁：0 miss + 校验和 + 结果等价

## 三道门禁

1. **模型调用**：`cache.miss == 0`，**写入与检索两个阶段都要查**。search 若重新调用 embedding/rerank，miss 会让检索耗时混入网络抖动，甚至因候选集变小而显得更快。
2. **写入完成度**：记录 `(节点数, 关系数)`，与期望值比对。实测中"图是 235/720 而不是 225/492"
   这类静默脏库，会伪装成约 20% 的性能收益。
3. **查询结果指纹**：对每条查询输出 `(edge/node UUID + 分数)` 排序后拼接再 hash；优化前后必须逐字节一致，search 每条查询都要比对（结果变少、字段缺失、命中率下降都会触发不一致）。

## 实现要点

- 每次运行**按 stage 自动判定**（ingest / search 各自检查），任一失败即退出非零并打印原因；
- 失败允许重跑，最多 3 次，仍失败则整批作废，不挑好看的样本；
- 指纹只覆盖结果内容，不覆盖耗时，避免把时钟差异当成行为差异；
- 校验和与指纹都要写进报告第 1 节，作为"行为等价"的唯一证据。

## 典型误判

| 现象 | 真因 |
|---|---|
| 性能提升 20% 但候选集变小 | 查询被截断或过滤条件变了 |
| 指纹一致但吞吐暴涨 | 结果被缓存/短路，实际没查库 |
| 图规模正确但结果不稳 | 并发交错导致判重顺序变化 |
