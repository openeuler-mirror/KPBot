# 最终 Top 100

先核对最终计划是否已把 `ORDER BY item_sk,d_date LIMIT 100` 降为 `TakeOrderedAndProject` 或 Velox `TopN`。如果仍存在末端全量排序，可评估在后置两列窗口和比较条件都已完成后，先做局部 Top 100 再按相同键合并成全局 Top 100。检查末阶段送往全局合并的记录量、运行时间和峰值内存。

排序方向、NULL 顺序和输出列沿用原查询。遇到第 100 行边界存在并列，先核对测试框架允许的等价规则及原查询是否需要稳定的排序键。不可把 Top N 送到前缀窗口或比较条件之前，较早日期的行可能影响后续累计结果，或在比较时被淘汰。

## 源码定位

### 选择条件和回退

核对原 SQL 的 K、OFFSET 及 WITH TIES。普通 LIMIT 且比较器一致时，每分区前 K 的并集中包含合法全局前 K；有 OFFSET=M 时应保留 K+M 后全局跳过 M。若只支持模板的 LIMIT 100，其他变体显式回退，不把其余参数悄悄忽略。

例如两个分区为 `[1,2,3]`、`[4,5,6]`，K=2、OFFSET=2 的全局结果应为 `[3,4]`。局部各截 2 后只能选到 `[4,5]`，局部各保留 4 才能恢复正确序列。该数字例子单独验证候选覆盖，不是实际 SQL51 的参数。

若存在边界 peers，普通 LIMIT 允许的行集合与确定的唯一排序不同。WITH TIES 必须保留阈值上全部 peers；本地模型对未支持的变体走完整参考路径，不以普通 Top K 代替。

### 比较器与输出

局部和全局使用同一组完整排序字段。DESC 不表示可以简单反转一个 NULLS FIRST 的整个结果，否则 NULL 顺序也会被反转。明确每个字段方向与 NULL 位置，测试覆盖 ASC/DESC 与 NULLS FIRST/LAST 的组合。

保留所有非排序输出列，尤其原始渠道金额与后置窗口列。比较谓词任一累计值为 NULL 时，不满足普通 `>`；把 NULL 变零或先截断再比较都需要独立证明，不能作为当前候选的一部分。

### 工作量和验收

逐分区记录过滤后行、保留候选数，按实际缓冲区记录合并输入与字节；合并候选上界通常为分区数乘局部保留量，但实际有空分区和短分区时应报告实数。最终输出 K 条并不说明合并只读了 K 条。

本地用例对空/短/长输入、不同分区数、排序方向、NULL、OFFSET 和提前截断做参考对照。模型正确不意味着原生比较器、执行路径或性能通过；正式对照核对加载库、候选命中、完整结果及相同计时边界。

从计划中的 `TakeOrderedAndProjectExecTransformer`、Substrait `TopNRel`、Velox `TopN.cpp` 分别确认 Spark 转译与原生算子命中。分区局部有界选择和最终合并分别取证。
