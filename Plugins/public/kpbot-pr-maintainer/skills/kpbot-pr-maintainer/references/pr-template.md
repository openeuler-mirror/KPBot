# 创建 PR 时填写标题和正文

优先使用目标仓库当前 PR 表单，保留栏目、勾选格式和社区政策链接。标题按最终改动的功能和所属模块填写。页面不可读时，按以下 openEuler KPBot 栏目生成同一份 Markdown 正文。用本次分支相对目标的实际差异、提交和测试记录填全各项。

- **当前PR是否有AI参与**：在“否”和“是”中仅勾选一项。有参与时填写 **AI Agent 平台**、**AI 模型**和 **Prompt 上下文**。给出能核实的平台与模型名称、版本，用一两句话概括任务意图和 AI 实际完成的工作；未知信息如实注明。提交前核对 AI 参与生成内容的提交，其 `Co-Authored-By` 模型名称及版本应与正文一致，并保留用户指定的签署行。附上模板中的[社区 AI 政策](https://www.openeuler.org/zh/community/ai-coding-assistants/)。
- **PR功能描述 / 为什么需要这个合入**：说明改动解决的具体问题、主要行为变化以及对使用者的影响。
- **该PR关联的issue**：确认本次贡献关闭相应 issue 时填写 `fixes #编号` 或 `resolves #编号`；仅相关时写普通引用。没有关联时填写“暂无关联 issue”，删除空的 `fixes #`。
- **希望检视人员了解**：指出最值得核对的路径或行为，列出实际运行的测试、结果和仍待验证的部分。人工检视情况仅按已确认的事实填写。

创建受阻时，直接在当前回复说明阻塞原因，列出源分支、目标分支和可用的创建入口，给出可复制的标题，并用一个 Markdown 代码块交付**已填好的完整正文**，让用户可以直接粘贴。若提交请求超时且结果未知，先查重；仍无法确认时，明确请用户先核对 PR 列表。用户提供链接后直接接管该 PR。
