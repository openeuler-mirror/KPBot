# SQL51 累计窗口与排序复用

## 说明与范围

Q51 两个销售分支按商品和日期做累计 `SUM`。全外连接后，同一个后置窗口规格计算 Web 和门店的累计 `MAX`。本 Skill 检查同规格窗口共享和有序输入复用，适用于保留原结果及窗口状态语义的实现。

## 输入

| 输入 | 核对内容 |
| --- | --- |
| 查询与构建 | SQL/参数、源码版本、执行配置、加载库和最终物理计划 |
| 窗口规格 | 分区键、全部排序表达式/方向/NULL 顺序、ROWS/RANGE 和 frame 边界 |
| 输入属性 | 哪个节点保证顺序，经过哪些 Exchange、连接、投影和批次边界 |
| 函数状态 | SUM/MAX 的类型、NULL、溢出和目标窗口实现支持范围 |
| 分布与证据 | 长分区、并列日期、空/全 NULL、Sort/Window 数、内存、spill 与查询样本 |

源码入口及排序证据见 [实施细节](references/implementation.md)。相同列名不构成排序证明，没有实际计划时先交付定位方案。

## 实施步骤

### 1. 列出四项计算及所在边界

```text
Web 日结果   → 累计 SUM ┐
                        全外连接 → 两列累计 MAX → 比较过滤
门店日结果   → 累计 SUM ┘
```

逐项记录 frame 和输入列。后置 MAX 的输入是各渠道原始累计值，缺侧仍为 NULL，不能把累计求和、历史峰值和缺值填充混成一个未证明等价的步骤。

### 2. 确认是否已经共享窗口和排序

对两列 MAX 比较完整窗口规格，核对最终计划是否已经共用一个窗口节点。统计实际排序构建及其输入行；两个表达式不一定意味着两次排序。

共享执行仍须保留两列独立的值、有效性和输出槽位。函数类型、frame、确定性或错误行为不相容时保留原算子组合。

### 3. 对每条边建立排序和分区证明

记录顺序提供节点、属性范围和输出分区。同一商品的数据须按目标实现要求聚集，完整比较器一致。普通哈希连接、Shuffle 及连接后的键合并不能继承未声明的顺序。

属性不明、分区不完整或中间节点破坏顺序时保留原排序。测试可用小样本发现反例；生产准入使用引擎已有属性，不能先完整排序热输入来“证明可以省掉排序”。

### 4. 核对流式粒度和 frame 支持

按实际版本检查行级流式、整分区缓冲或排序路径的选择条件。`ROWS ... CURRENT ROW` 逐行推进；`RANGE ... CURRENT ROW` 可能包含全部同键 peers，不能直接采用逐行算法。

有并列键时保留原查询的 peer 规则及允许的不确定性，不擅自添加 tie-breaker 使测试稳定。函数、frame 或属性不支持时回到原窗口路径。

### 5. 明确跨批次状态和重置条件

同一商品跨输入批次时保留 running sum、历史最大值和 NULL 状态，仅在真实商品分区边界重置。spill 恢复和重试按引擎状态协议处理，不沿用其他分区或请求的状态。

日金额 `100,NULL,-70` 的累计 SUM 为 `100,100,30`，累计 MAX 为 `100,100,100`。最后非 NULL 值 30 不能替代历史峰值 100；全 NULL 商品分区不能接续上一商品的峰值。

### 6. 从真实入口核对结果和分派

覆盖单批/跨批、商品切换、全 NULL、累计下降、并列日期、ROWS/RANGE 和乱序，逐行比较值及 NULL。原始渠道列不能被前向填充结果覆盖。

记录实际候选、原排序路径、回退原因、排序构建数和处理行数。源码中存在流式实现或开关开启不等于实际查询命中。

### 7. 分别测排序、窗口和完整查询

固定 SQL、资源与缓存交错对照，记录排序/窗口耗时、峰值内存、spill 及完整结果取回后的查询耗时。基线已共享排序时，不能按“两列各排一次”虚构节省量。

保留长分区退化。采样占比用于定位，不当作精确墙钟分段；正式计时关闭额外诊断。

## 约束

- 保留 `PARTITION BY item_sk ORDER BY d_date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` 的结果。
- 历史累计 MAX 保留峰值。负金额让累计 SUM 下降时，上一条非 NULL 值可能低于历史峰值。
- 复用排序必须证明当前算子边界实际继承顺序，并处理并列和 NULL 顺序。条件不成立时沿用原排序路径。
- 保留精度、分区重置和输入原始渠道值。单次算子提速需要完整查询复测才能归因。

## 交付与验收

交付算子对应图、排序属性证明、反例和实际命中记录、局部及端到端配对耗时。缺少计划时把窗口分支与收益标为待验证。从 Skill 根目录运行 `python cases/window-contract/run.py` 验证累计下降、历史最大值、分区重置和输入乱序反例。

```text
模式 | 窗口节点 | 实际路径 | 排序构建数 | 排序输入行 | 窗口输入行 | 峰值内存 | spill | 查询毫秒
```

交付 frame/支持矩阵、状态延续和回退规则。用例还覆盖跨批次、全 NULL、peers 的 ROWS/RANGE 差异和未知排序属性回退，契约在 `cases/window-contract/case.yaml`，结果写入对应 `results/result.json`。

模型评估规格在 `evals/evals.json`。本地 SQLite/标量用例不验证真实窗口回退、原生流式命中或性能；这些逐项列为已测或 `awaiting_target_evidence`。
