# 调优判定与验收

## 判定表：现象 → 先查什么 → 动作

| 现象 | 先查 | 动作 |
|---|---|---|
| 端到端慢，profile 里 fft 的 plan 阶段占比高 | plan 是否每次调用都重建 | 建一次 plan，换指针执行复用（C2C `execute_dft`、R2C/R2R 用 `_r2c`/`_r2r` 变体，02 章） |
| 建 plan 本身很慢 | 是否用了 PATIENT | 一次性场景改 ESTIMATE；重复场景保留 PATIENT 但只建一次 |
| 开了线程没加速 | `plan_with_nthreads` 与建 plan 的先后 | 改到建 plan 之前，重建 plan（05 章） |
| 小尺寸开线程更慢 | 单线程基线 | 小尺寸 1 线程，大尺寸才开；拐点自己测 |
| 多进程结果与单进程不一致 | 本地尺寸/偏移、TRANSPOSED 标志 | 按 06 章排查四条 |
| 3D 大规模扩展不满速 | 进程排布、分解方式、转置算法 | 07 章：PROC_GRID 对齐拓扑 → DECOMPOSE_TYPE → A2A_ALGO 逐段 |
| 结果与 FFTW 参考差在末位 | 是否归一化、单/双精度差异 | 按 08 章验收口径比，不追 bit 级一致 |
| 建 plan 返回空 | rank/n/缓冲 | 02 章四条排查 |

## 调优顺序（按收益/成本比）

1. **plan 复用**（最大且最确定）：同形状只规划一次；PATIENT + 复用是标准组合。
2. **缓冲区**：全部走 `kml_fft_malloc`/`kml_fft_free`，避免热路径 malloc。
3. **线程数**：先建 plan 再谈线程；按尺寸分档（小尺寸 1 线程）。
4. **批量接口**：多帧/多通道换 `plan_many_*`，省掉 N-1 次规划与调用开销。
5. **MPI 布局**：能用 TRANSPOSED/SCRAMBLED 省一次转置就用，但必须与实际布局严格对应。
6. **3D 扩展接口**：最后才动环境变量，且一次只动一个。

## 验收口径

- **数值**：与参考实现（单进程 KML 或 FFTW）比对，口径按精度给阈值：
  单精度相对误差按单精度机器精度量级取，双精度按双精度量级取；**不要求 bit 级一致**——不同分解/归约顺序
  通常会有末位差异（若两侧落到同一分解与同一累加顺序，也可能逐位相同，别把「相同」当成正确性证据）。
  正反变换对：先确认归一化约定（KML 文档未声明 c2r 归一化，须实测确认），否则会差一个常数因子。
- **性能**：区分两种口径并分别记录——
  1. 含规划的一次性耗时（对短作业有意义）；
  2. 稳态耗时（plan 已建，只 execute；对长作业有意义）。
  混用这两种口径得出的结论会自相矛盾。
- **必须记录**：KML 版本（`KFFTGetVersion`）、HPCKit 版本、进程数×线程数、矩阵尺寸与分解方式。

## 反模式

- 每次调用都建 plan（最常见的性能事故，规划开销常大于变换本身）。
- 先建 plan 再设线程数（设置静默无效）。
- 把 FFTW 的 `FFTW_MEASURE`/wisdom 当存在（编译不过，或以为能复用）。
- 用 `free()` 释放 `kml_fft_malloc` 的内存。
- 在 MPI 下按 `n/nproc` 估算本地缓冲（必须用 `mpi_local_size` 的返回值）。
- 3D 扩展接口一次改多个环境变量（无法归因）。

## 待实测项（不要当成结论）

- 线程数拐点、是否超线性、与核绑定的相互作用。
- `AUTO_TUNING` 与手动 A2A 算法的实际差距。
- r2c/c2r 的归一化常数。
- 半复数布局在 in-place 复用缓冲区时的 padding 需求。
