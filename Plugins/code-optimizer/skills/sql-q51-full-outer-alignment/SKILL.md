# SQL51 全外连接与双渠道对齐

## 说明与范围

Q51 用商品键和日期把 Web 与门店的累计结果全外连接，然后再做两列累计 MAX。本 Skill 评估外连接的数据交换和替代路径。仅在用户允许修改 SQL 时提交手工查询重写。源码范围内只评估实际命中的外连接实现或可证明等价的通用规则。

## 输入

| 输入 | 核对内容 |
| --- | --- |
| 查询与基线 | 实际 SQL/参数、源码提交、加载库、最终计划及结果校验方式 |
| 两侧键 | 累计已完成的 Web/门店结果，item/date 的类型、唯一性和非空证据 |
| 输出契约 | 键合并规则、原始渠道列、缺侧与已有 NULL、金额精度和错误行为 |
| 后续操作 | 累计 MAX、比较过滤、排序和 LIMIT 的准确位置 |
| 工作量 | 两侧输入、匹配/单侧输出、交换字节、内存、spill 与 task 倾斜 |
| 修改范围 | 保持 SQL 的实现优化，或用户允许的手工查询重写 |

模板来源和实现入口见 [实施细节](references/implementation.md)。抽样未出现重复不等于约束成立；缺少键证据时保留原连接。

## 实施步骤

### 1. 固定累计完成后的连接输入

```text
Web 日聚合 → 累计 SUM ┐
                      FULL OUTER JOIN(item_sk,d_date)
门店日聚合 → 累计 SUM ┘
                      → 两列累计 MAX → 比较过滤 → ORDER BY/LIMIT
```

确认输入是各渠道累计值而不是日金额。把对齐提前到累计 SUM 之前属于另外的算法，不能套用这里的等价证明。

### 2. 优先定位原连接的真实开销

核对连接策略、双侧 Exchange、传输列、spill 与恢复。可先裁剪确实无用的列、利用已有分布属性，或优化实际命中的外连接实现，不预设聚合替代总会更快。

全外连接保留双方未匹配行，不能借用内连接的正向成员过滤在扫描端丢弃这些行。运行时过滤的独立实现不属于本 skill 的重写内容。

### 3. 将全部条件收在替代路径入口

采用保守准入：用户允许改 SQL；两侧各自按 `(item_sk,d_date)` 最多一行；两个键均非空；键合并、类型、相等比较与额外谓词保持原义。

普通 `=` 不匹配 NULL，GROUP BY 会归并 NULL；任一侧重复都会影响重数，不能只检查构建侧。未知约束、不支持的条件或仅有抽样时，返回原连接及明确拒绝原因。

### 4. 用相同类型的两路记录按键对齐

每个渠道保留自己的原始累计列，另一位置填该渠道实际输出类型的 NULL，再按两个键取回每侧至多一个值。可执行形状和类型填入要求见 [实施细节](references/implementation.md)。

Web 的 `(商品1,日期1,100)` 与门店的 `(商品1,日期2,60)` 对齐后分别是 `(日期1,100,NULL)`、`(日期2,NULL,60)`。存在但金额为 NULL 的记录也必须保留，不能以金额是否非 NULL 判断渠道存在。

### 5. 保持后置窗口和原始渠道列

对齐后继续原两列累计 MAX。Web 原始累计值从 100 降为 30 时，其历史峰值仍为 100。缺侧行的原始 `web_sales` 保持 NULL，不能用填充或峰值覆盖原输出列。

比较过滤继续使用 SQL 三值逻辑。最终 LIMIT 保持在窗口和比较之后，不能提前删除某个渠道独有的日期。

### 6. 对完整结果和拒绝路径建立反例

覆盖双方匹配、仅一侧、两侧空、全 NULL 金额、负金额，再用单侧/双侧重复键与 NULL 键确认拒绝。先按完整行多重集核对重数，再按原排序与 peers 规则比较返回。

不能只比最终 Top 100，它可能隐藏中间行丢失。核对完整对齐、原始渠道列及后置窗口结果；未准入时确认真实执行原连接。

### 7. 计入替代路线新增的工作

记录新增聚合、Exchange、排序，以及两侧输入、匹配与单侧输出、传输字节、内存和 spill。计数审计与正式计时分开，用相同参数、资源和数据交错测量完整查询。

组合候选需列明其他改动，不能把累计收益归给这一项。局部交换下降不代表端到端一定改善，保留长尾和退化样本。

## 约束

- 分组会合并 NULL 键，普通等值外连接会保留为各自不匹配的行。双侧重复时还可能产生多重匹配，守卫必须覆盖这两种情形。
- 缺少一个渠道的日期仍应进入后置窗口。保留当日渠道值为 NULL、输出列的实际类型和精度，以及原后置累计 MAX 的位置。
- 组合收益按实际运行比较。替代路线引入新的 Shuffle 或排序时，以完整查询数据决定保留。

## 交付与验收

交付键守卫证据、原与候选计划、结果对照、命中证据和配对数据。缺少键证据时保留原连接并交回待核验项。从 Skill 根目录运行 `python3 cases/q51-semantics/run.py`，覆盖正向对齐、NULL 和重复键反例以及后置窗口结果。

```text
模式 | Web 行 | 门店行 | 匹配输出 | 仅 Web | 仅门店 | 总输出 | Shuffle 字节 | spill | 查询毫秒
```

用例需要 SQLite 3.39+，还核对空侧、全 NULL 金额、单侧重复及未允许重写时的回退；断言在 `cases/q51-semantics/case.yaml`，结果写入对应 `results/result.json`。

模型评估规格在 `evals/evals.json`。SQLite 整数分不验证真实 decimal、原生外连接实现或加速比，缺少目标记录时标记 `awaiting_target_evidence`。
