# RaBitQ 候选规划

## 输入与选择

读取当前源码、[热点检查项](rabitq-performance-hotspots.md)、冻结 manifest 和可用实验记录。按可移除成本、实现范围、数值/平台风险及验证成本排序，选择一个主要机制。

| 方向 | 适用证据 | 验证重点 |
| --- | --- | --- |
| 查询预处理复用 | 对象生命周期支持减少重复变换 | 每 query 状态、并发、query/list 切换 |
| 解码与归约组织 | 位运算或水平归约占比显著 | 位序、权重、宽度、FP 顺序及字节尾 |
| 受保护的维度特化 | 公共参数可低成本判断形状 | 非命中形状、内存足迹、cache 与回退 |
| 存储/查询缓存 | 节省解码高于缓存构建和读取成本 | 格式兼容、训练/add、序列化与 load |

## 每个候选需要说明

1. 目标调用链、文件/符号、实测占比及机制假设。
2. guard、默认关闭的特性宏、fallback 和最小改动范围。
3. 是否改变布局、距离、候选集合、比较顺序或精排；纯实现优化保留既定语义。
4. 基于占比的理论上限和额外成本。上限不是收益预测。
5. 实际路径的 UT/ST、开关与边界矩阵、冻结性能对照及停止条件。
6. 已有记录的来源与适用差异；缺少资料时说明依据，不虚构已验证/已否定状态。

## 结果

结论来自本次证据，记录到 `run_dir/candidates/<id>/VERDICT.md`。不把某个数据集、处理器或单次候选的结果改写为通用技能的固定推荐或禁令。
